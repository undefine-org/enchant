# Beam Lisp v2026.11

This release introduces canonical Datom index keys and explicit offline generation
conversion, hardens writer ownership and recovery, and carries forward main's
SDK preparation, memory and incremental production improvements.

[Complete commit list](https://github.com/undefine-org/enchant/compare/v2026.10...v2026.11)

## Datom and durable data

- Index format 2 gives equal sequential and numeric values equal index keys,
  including nested and metadata-bearing values. Stored payloads retain their
  original representation. Canonical values also govern temporary claims,
  reverse indexes, transaction lookup and current-value projections.
- Durable `datom.identity/value-v1` hashes and credential-v2 associated data
  retain the frozen version-1 encoding. Existing migration seals remain valid.
- Admission checks the reserved format descriptor before schema, counter or
  writer effects. Empty-store admission requires bounded `Count`; writable
  empty stores stamp their descriptor atomically. Read-only empty connections
  defer initialization until write admission.
- Nonempty unversioned databases require explicit offline conversion into a
  separate generation. Unknown formats, unsupported metadata and uniqueness
  collisions refuse conversion or activation; existing stores are not relabeled.
- Offline preparation uses bounded resumable pages, atomic data/cursor commits,
  exact history and payload preservation, counter/schema/blob conservation,
  independent reconciliation, and a content-bound READY receipt. Original
  generations remain unchanged.
- Successful offline preparation and reconciliation wait for native ownership
  to retire before returning. Bounded cleanup uncertainty refuses success;
  original claims remain protected by the native custody checks.
- Native generation custody covers database and filesystem-blob writers,
  readers, retained handles, maintenance loans and stores created on demand.
  New-store intents publish atomically and reconcile after abrupt process death
  or power loss.
- Sealed startup binds code, runtime and selected data. The activation journal
  controls read-only readiness and durable write admission. Compatible runtime
  cohorts, offline tasks and backups use the selected generation. Recovery
  after admission preserves current data.
- Malformed batches and unsafe transaction-counter recovery refuse before
  publication. MapStore implements bounded range counting. Finite query and
  codec operations avoid unnecessary lazy admission.
- Plan-cache hits use private native counters without republishing retained
  plans; learned result-cache hints publish once. Derived caches retain store
  identities without pinning native stores.
- The disposable Codebase facts cache advances to `facts-8` and rebuilds
  automatically.

See [index admission and conversion](../datom-index-key-format.md) before opening
an existing database with the new default.

## Preparation, memory and build efficiency

- SDK production retains completed units and validates their complete bytes,
  constructor evidence and runtime identity before reuse. Compiler proof
  generations remain independent.
- Complete-unit and byte evidence is shared within metadata lookups. Owner
  cleanup selects its rows without copying inert SDK metadata.
- Constructor and Loader metadata share reader evidence within a bounded
  Source pass. Exact bytes, compiler/kernel identity, guard accounting and
  publication checks remain enforced. The qualified paired SDK-producer run
  saved 32.6% wall time while all 5,223 target files matched byte-for-byte.
- Bounded constructor cost walks use native traversal while retaining the same
  data domains, fuel accounting and refusal behavior.
- Retired diagnostic closures are collected at the ownership boundary so a
  released native database does not remain locked on the Source owner's heap.
- Preparation carries content-addressed source parts and shares pinned package
  evaluation. Empty validated selections leave native production cold.
- SDK assembly copies and relocates verified artifacts in one pass. Independent
  CI recipes stay outside SDK/platform invalidation. Unproven production timing
  instrumentation is removed.
- Checkout commands share one checked byte snapshot and fingerprint cold
  selections under the preparation lock. Runtime and project source identity
  checks remain enforced.
- `scripts/ci-check-committed` qualifies a verified immutable Git export through
  the normal bounded Build worker. It checks every exported blob, executable
  mode and inventory entry; export rewrites, omissions, escaping links and
  source overrides refuse. Memory-backed staging avoids busy checkout I/O.
- The preparation coordinator admits up to 512 application source paths, with
  the existing 1 MiB operation envelope, path validation and worker limits.
- Application artifact admission checks the complete frozen source pool before
  compilation and permits an explicit 512-source ceiling. Builtin constructor
  macros use authenticated phase libraries; application helpers and exact source
  identity remain scoped to the compilation world. Pure syntax list append
  reserves copied cells and checks its complete output bound before allocation.
  Source facade declarations preserve private/generated ownership and exact
  provider bytes. Application units use independent bounded scopes over the
  frozen source selection, retaining the standard per-unit limits and producer.
- Operator-owned builder descriptions accept Nix's pinned public host key field.
  The selected backend retains normal SDK unit verification and byte-for-byte
  reuse; the qualified backend integration restored 533 of 534 SDK units.
- Release CI stages and inventory partitions execute serially. Real host Nix
  checks accommodate the existing nested producer lifetime within their
  unchanged memory, swap and overall time limits.

## Other fixes and qualification

- Portable runtime caches publish durably and repair incomplete publication
  after abrupt shutdown. Actual process-death and VM power-cut controls cover
  cache repair, offline conversion, generation publication and activation.
- Android containers retain layout weight and alignment.
- Qualification records distinguish process startup, compiler phases, unit
  reuse and per-file assertions. SDK and portable candidates are reused by
  exact identity across release consumers.
- Linux x86_64 remains the qualified publication target. The requirements
  sidecar binds the measured libc floor, compiler, candidate digest and source
  revision. The application version remains stable to preserve SDK reuse.
