# Beam Lisp v2026.10

This release provides retained SDK production, Source-described Nix backends,
and a first-party bidirectional Nix codec. Native SDKs, applications, and
portable releases share the same verified compiler and unit-cache contracts.

[Complete commit list](https://github.com/undefine-org/enchant/compare/v2026.9...v2026.10)

## Incremental production and caching

- Producer capsules retain the loaded units, runtime requirements, and actual
  constructor-input closure. Restoration verifies the runtime identity,
  canonical Source, complete unit bytes, and constructor receipts before
  populating the normal AOT cache. The normal loader owns activation.
- Parser frames and input observations are shared across producer stages with
  generation and content checks. Complete unit proofs run in bounded batches
  with one metadata publisher.
- The native SDK image is an independent product. Portable ELF retargeting and
  packing run on demand, and bind the exact image and compiler. Repeated
  publication reuses the retained portable product and verifies its bytes.
- Cache hints retain native SDKs even when later packaging or qualification
  fails. Portable products receive separate roots. Recognized predecessor
  capture policies keep their original fingerprints and admission checks.
- Checkout prerequisites resolve the pinned toolchain directly from the
  repository lock. Generated Python bytecode does not rotate the platform.
- Cold native bootstrap has a bounded one-hour window. CI cache retention
  makes transient store locks readable while preserving their inode, ownership,
  and active locks, so completed dependency work survives failed production.

## Source-owned Nix backends

- Backend kinds, Nix worker policy, and optional evaluation transports are
  declared in `.bl` data. The first-party codec generates the adjacent Nix
  projection; consumers verify the Source digest before applying it.
- Local workers, configured builders, SSH builders, and nixbuild.net share
  the same product recipes. Addresses, credentials, host keys, and capacity
  belong to operator configuration.
- Optional remote evaluation handles SDK, native, application, and portable
  products through a finite immutable endpoint. Requests retain separate roots
  until the client has retained the verified result.
- Ordinary clients import the returned derivation, verify its declared output,
  and retrieve the completed product through the authenticated Nix builder.
  Signature checks remain enabled; local build jobs are disabled for retrieval.
- User station configuration takes precedence over system configuration.
  `scripts/build-backend.py --station-out` installs the transport from the
  checked Source description. Explicitly selected descriptions must exist,
  and configured transport failures preserve the request for diagnosis.

## First-party packages and tools

- `nix` and `nix.native` provide bidirectional Nix data and syntax-tree
  conversion, backed by the repository's `native/bl_nix` product. This codec
  represents Nix syntax and data; Nix itself evaluates build expressions.
- The durable job implementation lives in `packages/job-runner`, with its
  provenance retained. Existing protocol namespaces remain compatible with
  Foundry consumers. Preparation coordinators package their environment helper
  independently of the predecessor SDK framework.
- `scripts/build-status --history` reports SDK selections, previous attempts,
  failures, and truncated diagnostic records without starting a BEAM. Its
  output distinguishes persisted state from worker liveness.

## CI, release, and operating scope

- CI workers and publication jobs consume the same Source-described backend
  setup. Nixbuild.net configuration uses the pinned provider action and an
  operator-supplied token. A live provider run requires those credentials.
- Release qualification and publication consume the exact registered SDK and
  portable bytes. Tags identify provenance without restamping the compiler.
- Initial checkout capture and bootstrap coordinator selection remain client
  operations. Running qualification from a Build checkout places those phases
  there as well. Remote worker routing alone places realization, not evaluation.
- Compiler-floor changes retain fresh P/B/C qualification. Unchanged units
  remain reusable under their actual input and ownership evidence.
- Developer documentation covers backend schemas, codec operations, placement,
  durable preparation, storage migration contracts, and the retained-producer
  qualification reports.
