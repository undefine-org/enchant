# Beam Lisp v2026.9

This release brings incremental SDK production, shared CI qualification,
Android build repairs, and an **experimental scene renderer**. The canonical
repository and release channel are [undefine-org/enchant](https://github.com/undefine-org/enchant).

Changes since v2026.8:

## Incremental builds and releases

- Checkout commands and `self-build` select one retained immutable SDK through
  the same preparation path. Compiler production, dependency compilation,
  native crates, and SDK library compilation have separate inputs.
- SDK production verifies and reuses complete AOT units from its predecessor,
  including the macro inputs they read. Ordinary library changes preserve the
  compiler floor; changing one native crate preserves its siblings.
- Application products bind to one exact SDK. Repeated builds within that SDK
  reuse verified units, prune removed units, and keep unchanged artifacts.
  Selecting a new SDK starts a new application base. Compiler generation still
  requires fresh P/B/C boots and exact B/C reproduction.
- Application units retain the complete bytes emitted by that producer,
  including its real replay coverage and constructor input inventory. Packaging
  avoids compiling a second staged version of each application namespace.
- Generated Python bytecode and CI-only recipes do not invalidate SDK selection.
  Launcher compilation uses its declared source inputs.
- Ordinary local qualification runs on the configured Nix build station in
  bounded workers. Real-Nix checks use a host with the daemon and offload source
  builds through its worker policy. Hosted CI and releases use Blacksmith.
  Consumers use the exact produced SDK, pinned tools and models, with per-file
  receipts.
- Tagged publication reuses a fully successful main CI run for the exact
  commit. It verifies the candidate bytes and retains cold startup and
  concurrent first-launch checks. Release tags identify provenance without
  changing the application version or rebuilding the compiler for a label.

## Runtime and analysis

- SDK ownership evidence survives packaging, startup, and framework adoption.
  Native init callbacks retain their actual starter receipts. Retention fences
  yield outside the environment owner; proof caches reuse authenticated image
  metadata and forwarder export indexes.
- Queue families route through their exact active logical graph leases.
  Shutdown resolves the owned server without loading unused reconciliation
  code. Datom returned-opening evidence survives preflight until its atomic
  native custody check.
- Datom's private query plan cache avoids repeatedly traversing a growing
  captured cache. Query profiling no longer calls the database value.
- Lazy capture caching evicts one old identity at its fixed bound, preserving
  the rest of a live render's working set. Dependency discovery still detects
  resources hidden in wrappers and sibling values.
- Growth analysis reads explicit invocation arguments. SMT map variants decode
  canonical literal keyword keys. JavaScript compilation supports current
  compiler data boundaries and native Decimal metadata.
- Macro collection results retain bounded form metadata. Source-less ordinary
  namespaces remain outside SDK admission. Application production modes are
  explicit values.
- Document extraction resolves its hard-kill wrapper from the request's PATH;
  bounded workers provide declared OCR and process prerequisites.
- Managed evolution checks vector request migrations and original-request-aware
  reply conversion from actual published callbacks. Unsupported predicates,
  effects or conversion bounds refuse before publication. Standalone owners can
  select `:message-domain :bounded-first-order` at startup; existing owners keep
  their payload contract, and upgrades cannot mint or change the initial scope.
- Fixed SDK metadata readers retain the actual callback's code and context while
  inspecting passive compiler data. Mutable publication rows are validated
  before identity analysis; application callback limits remain unchanged.
- State conversion can use a closed stored-data query on an actual SDK ETS or
  Fjall connection. Custom providers and supplied query callbacks stay outside
  this fragment. Native custody, fences and runtime state checks still apply;
  these checks do not prove business migrations or future database contents.

## Android

- Erlang boot modules and NIF stubs compile inside the selected VM, avoiding
  packaged `erlc` boot-script failures. Cached output is checked against both
  compiler inputs and actual bytes.
- Runtime staging uses the selected SDK's exact Elixir application bytes with
  Android's OTP and native runtime. It renders the device application resource
  into an owned cache and preserves unchanged files and inventory timestamps.
- Dependency staging selects the exact locked name and version. `--abi` and
  `BL_ANDROID_ABI` select `x86_64` or `arm64-v8a`; an empty environment value uses
  the project default. Each ABI has its own build workspace.
- Application compilation uses the managed Nix product path without forced
  rebuilds. Staging preserves unchanged files and Gradle/native build caches.
  Complete compiled units retain their source witnesses for strict replay.
  Zig bridge compilation and Gradle assembly use the local pinned toolchain;
  Beam Lisp and Rust product compilation use the configured Nix worker.
- Android native products bind the SDK's Rust source and NIF interface to the
  selected ABI and library hash. Stale or modified products refuse before
  staging. Manifest changes stay outside Cargo's compilation inputs.
- Native cache custody uses Android's kernel file locks. Shared readers and
  exclusive writers retain the same descriptor ownership and release rules;
  strict application replay remains mandatory.
- Device updates and standalone runtime installation preserve unknown user
  files, prune only unchanged files from the previous ownership receipt, and
  retain conflicting content in persistent backups. App data reset is an
  explicit operation, separate from the mobile app's normal run command.
- Launcher-owned ERTS and SQLite links stay outside the copied runtime
  inventory. Obsolete receipt entries whose file kind or parent changed are
  preserved without following links; incoming symlink collisions still refuse.

## Scene renderer — experimental

The reusable `scene.*` library authors deterministic scenes with ordinary
values and explicit time samples: escaped SVG, structured geometry, measured
layout, seeded materials, scoped object identities, clips, cameras,
choreography and Hermite score tracks. Generic examples include postcards,
editorial layouts, an atlas and a local preview studio.

Text shaping uses Pango metrics and Cairo outlines from the same layout.
The optional tools are pinned in `nix/scene-tools.nix`. Bundled DM Sans,
Instrument Serif and Patrick Hand fonts retain their OFL licenses. Render
receipts record font and backend identities.

**The API, scene formats and rendering behavior are experimental.** Language
and graphics checks cover finite scenes and selected frames; they do not
establish full-film quality or browser interaction across platforms. See the
[API guide](https://github.com/undefine-org/enchant/blob/v2026.9/priv/lib/scene/README.md)
and [example setup](https://github.com/undefine-org/enchant/blob/v2026.9/examples/scene-renderer/README.md).

## Data compatibility

This release does not automatically migrate or reindex business stores. Offline
reindexing remains a separate investigation: safe conversion requires a sealed
copy, writer fencing, lossless decoding, independent validation and an atomic
activation receipt. Existing data is never a disposable build cache.

## Download and host requirements

The qualified desktop artifact is **Linux x86_64**. It includes ERTS, Beam Lisp,
Datom's Rust libraries, Z3 and Explorer; host Erlang/OTP is unnecessary. macOS
and ARM desktop binaries remain pending qualification.

Check `minimum_glibc` in `bl-linux-x86_64.requirements.json`; the current producer
requires **glibc 2.44** plus the standard C++/OpenSSL/ncurses/zlib/brotli/zstd
runtime libraries. Stock Ubuntu 24.04 and 26.04 do not meet that libc requirement.
CI executes the unchanged binary with its pinned FHS loader and libraries.
That qualification does not establish stock Ubuntu compatibility.

```sh
ldd --version
sha256sum -c bl-linux-x86_64.sha256
chmod +x bl-linux-x86_64
./bl-linux-x86_64 --cold version
./bl-linux-x86_64 --cold eval '(+ 1 2)'
```

For the SDK with its pinned Nix runtime:

```sh
nix shell github:undefine-org/enchant/v2026.9#sdk --command bl --cold version
```
