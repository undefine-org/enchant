A self-extracting launcher unpacks a version into `<dest>.tmp-<pid>` and publishes it with `rename`, so `<dest>` should only ever be absent or complete. A reboot (or a `kill -9`) in the middle of a *first* run leaves the case that breaks the world:

* the install check is `dest/bin` → a tree without `bin/` reads as "version missing";
* so every later run re-extracts, and every later run loses the same `rename` with `ENOTEMPTY`;
* ∴ the tool is **permanently** dead — `drop: first-run extraction failed: Directory not empty (os error 39)` — and re-running never fixes it, which is exactly the advice the comments gave.

Observed on this workstation after a reboot: `~/.local/share/drop/df3bf671/{lib,releases}` with no `bin/`, plus a stale `df3bf671.tmp-155168` (~100 MB) from the killed extractor.

**The rule.** Presence is not completeness. When a cache directory is the *marker* for "this version is installed", the marker must be something only a finished install has (a file inside it), and the publisher must be able to REPLACE debris instead of tripping over it:

```rust
match rename(tmp, dest) {
    Ok(()) => Ok(()),
    Err(_) => {
        if dest.join("bin").exists() { remove(tmp); return Ok(()); }  // lost a race: fine
        if dest.is_dir() { remove_dir_all(dest) } else { remove(dest) }  // debris: clear it
        rename(tmp, dest).or_else(|e| if dest.join("bin").exists() { Ok(()) } else { Err(e) })
    }
}
```

Safe because a tree with no `bin/` cannot have anything running out of it, while the tree another process may be executing from always has one. Two siblings clearing at once is handled by the second bin-check, not by a lock.

**Corollaries worth carrying to any staging/publish design:**
- staging dirs are named per-process (`<dest>.tmp-<pid>`) so concurrent extractors cannot eat each other's work; publishing is a rename, never a copy-over.
- sweep staging dirs on a *much* shorter window than the things they stage (an extraction takes seconds → 24 h is generous), because a killed one is dead weight; sweep lazily when the slow path next runs.
- reproduce in a scratch root first: the install dir honours `XDG_DATA_HOME`, so `XDG_DATA_HOME=/tmp/probe bl version` with a hand-made half-tree is a 5-second, non-destructive reproduction.
