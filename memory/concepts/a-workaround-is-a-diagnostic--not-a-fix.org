** ITEM A workaround is a diagnostic, not a fix

When a subagent reports "I worked around X", read it as **"X is a root-cause
bug"**. The workaround is the diagnostic signal. Fix the cause, then delete the
workaround — never ship both.

## Evidence from beam-lisp
Three parallel workers building libraries each hit a bug and routed around it.
Every one turned out to be a root cause affecting *ordinary* code:

1. **Closures died after three `defn`s.** The BEAM keeps exactly two module
   versions; regenerating a namespace module on every `defn` purged the third,
   invalidating any closure whose code lived there. Presented as "a stale
   closure in optics"; was actually "any file with three `defn`s can invalidate
   a stored function". Fixed by splitting the churning layer (forwarding shims)
   from the code-holding layer (immutable per-definition body modules).

2. **A lazy-seq thunk could not return a seq** — which Clojure's do routinely.
   Two workers hit it *independently*, each restructuring their code with inner
   loops. **When two independent callers break on the same invariant, the
   invariant is wrong, not the callers.** Fixed at the one choke point every
   thunk value passes through.

3. **A require resolved by filename, not namespace**, so a demo file could
   hijack a library's name. Fixed by reading the candidate's declared `(ns …)`.

## The corollary
Ask workers to **report** out-of-scope bugs precisely (repro + observed vs
expected) rather than fix them, then triage centrally. This converts scattered
local patches into one root-cause fix, and makes the pattern visible: two
independent reports of the same friction is the strongest signal available.

## Related failure mode
"A moduledoc is a claim, not proof." Twice in this project a documented
mechanism had never actually worked (`FormMeta.form_shape?`), or a load-bearing
invariant was never written down at all (the LazySeq thunk contract) — and the
absence of that sentence was precisely why the bug existed.
