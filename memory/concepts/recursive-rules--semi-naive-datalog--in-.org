Added user-defined recursive rules to the datom query engine — the primitive that makes it a real Datalog (was a documented gap: docs/datomic-in-beam-lisp/main.typ:936).

## Design
- Rule = [(head args) body-clauses...]; a body clause (name args) is a recursive INVOCATION.
- Supplied via :in % (Datomic spelling), invoked as [(rule ?a ?b)] or bare (rule ?a ?b).
- priv/datom/query/rules.bl: bottom-up fixpoint materialisation. Two evaluators:
  - derive-naive: recompute whole relation each round (reference oracle).
  - derive-semi-naive: join only the DELTA (last round's new tuples) against base each round. The efficiency win.
- materialise threads through engine/q BEFORE the main query; rule invocations then read the materialised relation like any source. run-clauses/eval-clause/eval-rule carry a rules-rel map (name->relation-set).

## Why bottom-up
Terminates on cyclic graphs (derived set finite + monotone) where top-down expansion loops forever. Verified on 1->2->3->1.

## Efficiency (measured, chain of length N)
naive O(N^3), semi-naive O(N^2). Speedup grows with depth: 3x@N=10, 7x@N=20, 15x@N=30, ~23x@N=40. naive infeasible past N~50. The delta restriction is the whole gain.

## What's now expressible AS Datalog (examples/datom/12-recursive-rules.bl)
- transitive closure / reachability (linear recursion)
- connected components: recursion + min label in outer stratum (Zaniolo Example 4). Verified to induce IDENTICAL partition to the analytic union-find verb.
- shortest path: arithmetic [(+ ?dx ?w) ?d] in the recursive body + min (Zaniolo Example 1). Correctly picks 1->2->3=3 over direct 1->3=10.
- same-generation: non-linear doubly-recursive rule (reaches cousins).
All compose with ordinary patterns/filters/aggregates in one query.

## Key gotchas hit
1. Rule invocation has TWO spellings: [(name ...)] wrapped and (name ...) bare. Support both (rule-invocation-call normalises).
2. Validation runs BEFORE rules materialise and can't know rule names (runtime % arg). Fix: when has-rules-input?, treat every call-form :where clause as binding its arg variables — else legit recursive queries reject as :unbound-find-variable.
3. eval-plain callback for rules.bl = eval-clause with EMPTY rules-rel (invocations expanded by rules engine against in-progress relations, not via the callback).
