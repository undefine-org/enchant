Verified 2026-09-04 on main @ 998bac5 (post PLAN-086 E1): editing priv/boot/*.bl AND running a full `mix compile.beam_lisp` toolchain rebuild WHILE `mix test` is running does NOT flake the suite. Experiment: appended a comment to priv/boot/sugar.bl 150s into a full run, rebuilt the whole toolchain mid-run (ebin replaced under a rotated key); result 1358/1381 — identical count and failure classes to the interleaved baseline run. Why it holds: (1) compiler_key is memoized per VM in persistent_term, so the running suite VM's drift gate compares against the key from ITS boot — replacement beams are simply not adopted; (2) namespaces already interned serve from memory. Residual hazard (unproven, low): a test that lazily loads a never-yet-loaded namespace AFTER your rebuild gets the NEW beams/source mid-run — did not materialize in the experiment. Consequence: during PLAN-086 E2–E4 do NOT serialize work behind suite runs; edit and rebuild freely.
