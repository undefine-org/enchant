The self-hosted reader priv/reader.bl was brought to feature parity with the live Elixir reader (lib/beam_lisp/reader.ex) on all surface a parity harness covers. Test: test/bl/reader_parity_test.bl (15 tests, 45 assertions, reads same source with both readers via `(BeamLisp.Reader/read_all src)` as answer key vs `(reader/read-all src)`, asserts `=`). reader.bl is NOT yet the live reader (nothing requires it; only self-hosting/tests use it), so blast radius of edits is contained.

6 gaps found empirically by running BOTH readers and diffing (not assumed):
1. STACKED DISCARD: `[1 #_ #_ 2 3 4]` -> reader.bl gave [1 3 4], answer key [1 4]. Fix: the `#_` branch in read-dispatch must LOOP reading forms until a non-:reader-discard form is consumed (a `#_ #_` = discard-of-a-discard still owes a real form).
2. %& LAZY-SEQ PARAM: `#(apply + %&)` param vector held a BeamLisp.LazySeq (unforced `concat` thunk) in desugar-fn, so structurally != answer key's plain list even though forced contents matched. Fix: `(apply list (concat ...))` to realize it.
3. STRING-AFTER-TAG DATA READER (the worst — SILENT MISREAD): `#time"2026-06-15"` -> reader.bl read `#time` as a bare symbol + the string as a SEPARATE form (TWO forms), because read-dispatch only routed tags followed by `[`/`{`. Answer key: (datom.time/read-iso8601 "..."). Fix: new read-tag fn resolves the tag via the SAME registry (BeamLisp.RT/data_reader, seeded by priv/data-readers.bl), wraps a following `[`/`{`/`"` payload as (reader-fn form).
4. RECORD LITERALS `#Name{...}` / `#ns/Name{...}`: were a "not yet ported" stub. read-tag now builds (rn/->tuple [:record tag kvs]) when no data-reader tag matches and a `{` follows.
5+6. READER CONDITIONALS `#?(...)` / `#?@(...)`: were stubbed. Ported: CONDITIONAL-FEATURE="clj" (beam-lisp answers to :clj not :bl, so `#?(:bl 1 :default 2)` -> 2), select-conditional walks feat/expr pairs (:default last-resort, no-match raises), and #?@ splicing uses an ERLANG TUPLE sentinel {:reader-splice items} (NOT a bl vector [:reader-splice ...] which is %BeamLisp.Vector and would collide with a real vector node / fail erlang/is_list) that read-until AND read-all spread into their surrounding sequence.

GOTCHA: a docstring containing `#time"..."` has an embedded `"` that PREMATURELY CLOSES the docstring, mangling the defn -> "internal compiler step received a value of the wrong shape" at node-items. Keep tag-with-string literals OUT of .bl docstrings (use plain prose).

REMAINING before reader.ex can be deleted (NOT covered by this suite, deliberately): SOURCE POSITIONS (reader.bl is position-free by design; read_all strips them so the two compare equal here; the compiler REQUIRES {:meta form {:line :col :file}} for diagnostics) and the ATOM-SAFETY GUARD (reader.ex samples the atom table, raises AtomLimitError before a full table aborts the VM uncatchably). Then swap 5 live call sites (compiler.ex:60/2809/2819, aot.ex:115, compile.beam_lisp.ex) + add reader to bootstrap seed.

UNRELATED PRE-EXISTING BUG (verified NOT mine — my diffs touch zero metadata code): reader_meta_test.bl fails 5/5 in this working tree. `^{:key (:slug t)}` inside `for` -> keys are nil (reproduced via plain `mix beam_lisp.run`, not just the harness). Single-literal `^{:key "s1"}` works. This is the datum/data_to_form macro-arg metadata boundary (commit 36fd5bb W0) regressed by other uncommitted tree changes (mock.bl/fuzz.bl deleted, aot.ex/veritas.bl modified before this session).
