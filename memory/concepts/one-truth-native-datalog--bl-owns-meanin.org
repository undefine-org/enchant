Resolved the two-sources-of-truth problem in the beam-lisp datom recursive-rules engine. The prior state had TWO fixpoint drivers (bl derive-* in rules.bl AND native eval_seminaive in eval.rs) — "native not wired into q" was NOT one truth, it was a dead second truth that rots.

## The principle
A source of truth = a place that DECIDES something two places could drift on. A Datalog fixpoint decides 5 things: unify, novelty, termination, semi-naive delta, what-a-value-is. Put ALL FIVE in one place (native), split the OTHER responsibilities to bl by disjoint kind:
- bl owns: value<->integer (codec), what-a-pattern-means (retraction/as-of, produces base relations), decode.
- native owns: the WHOLE fixpoint.
bl grows NO join loop, so nothing in bl can disagree with the join loop in Rust. Responsibilities don't overlap = one truth. NOT "two kernels behind a port" (that's still two impls that must agree) — bl literally has no join.

## Why one kernel, not two
The store is ALREADY a NIF (datom_redb=redb), so requiring native costs zero new dep — the "bl fallback for no-Rust" justification is bogus. And you verify one truth against its SPEC (closed-form math), not a bl twin — keeping a bl copy "to check" manufactures the second truth.

## Key mechanism
A pattern clause is a FIXED base relation across the whole fixpoint (bl computes it once via its real engine). Only rule-invocations iterate (pure integer joins) + arithmetic-in-recursion (computed atoms). So:
- Native IR: BodyItem = Atom | Computed. Op = saturating +/-/*/min/max + 6 comparisons (universal integer math, pinned semantics, can't drift). This makes native a COMPLETE datalog evaluator — shortest-path (+  in recursion) runs natively.
- rules-native.bl/materialise-native (drop-in for rules/materialise): bl evals patterns->base relations, rules->IR, native fixpoint runs ONCE (one boundary crossing per query, NOT per round), decode.

## The exact boundary (native-compatible?)
Native handles: rule-invocations, native primitives, patterns (EVEN patterns joining a recursive var — it's a fixed relation the kernel joins against). The ONE incompatible case: arbitrary bl PREDICATE (similar-to, bl fn) consuming a recursive var — value exists only mid-fixpoint, meaning lives in bl. Those run all-bl. Dispatch is DISJOINT: a program is fully-native OR fully-bl, never two evaluations of one input.

## Verified (spec, not twin)
6 tests/14 assertions vs closed form: transitive closure n(n-1)/2, cycle terminates n^2, shortest-path=Dijkstra (3 beats direct 10), same-generation, boundary classification. End-to-end benchmark (incl base-rel build + marshal + decode): 18x/46x/58x/75x at N=20/40/60/100, EVERY row bit-identical to all-bl. Boundary once per query so marshalling doesn't eat the win.

## Cutover (docs/datalog-one-truth-cutover.md)
