A datalog query answers correctly whether or not it is fast, so cost bugs are invisible without a plan.

Two facts decide the cost, both in beam-lisp's `datom`:

1. **AVET is written only for `:db/index`, `:db/unique` and `:db.type/ref` attributes** (`priv/lib/datom/index.bl indexes-for`). A clause with a BOUND VALUE over any other attribute cannot prefix-scan; the planner (`datom.query.plan/index-for`) falls back to `[:aevt [attr]]` — the whole column — and filters.
2. **`:not` / `:not-join` / `:or` / `:or-join` sub-clauses are evaluated once per OUTER ROW** (`datom.query.engine/eval-rule`). So a column scan inside one is not one scan, it is one per row. That is the quadratic: `codebase/arity-mismatches` ran `[:not-join [?callee ?n] [?d :fn/name ?callee] …]` per call row over an unindexed `:fn/name` — 62 s for 28 files.

## Reading a plan

- `datom/explain` (query + db-or-schema) → `{:find :in :order :steps :nested :smells :verdict}`; `datom/explain-str` renders it. Per step: index, bound components, cost. Per smell: `:kind :datalog/nested-scan`, the clause, the index it resolved to, and a note.
- `plan-trace` is DERIVED from the planner's own greedy walk (`order-clauses*` with an on-pick hook), not re-simulated — the trace and the plan cannot drift.
- `bl lint` carries the same check as an advisory rule (`datalog/nested-scan`, tier idiomatic): a restructure has no local rewrite, so it prints a `note` instead of an `after`. It resolves `datom.explain` lazily.

## Remedies, in order

1. **Hoist** the sub-query's relation out of the loop: one `datom/q` for the relation, put it in a set/map keyed by the join values, then filter the outer rows in beam-lisp. Fixes the shape without touching write cost. Watch the pair case: a row matching two different clauses' halves must be KEPT (the join is on the tuple).
2. **Index the attribute** (`:db/index true` / `:db/unique`) — a prefix scan, at the cost of one extra write per datom for that attribute.

## False-positive shapes (the rule has no schema)

A schema-less rule assumes the worst, so it also flags clauses that are already prefix reads: anything over a `:db.type/ref` attribute (VAET), and anything over an attribute indexed elsewhere (AVET). Confirm with `datom/explain` against the live conn before changing a query the rule names.
