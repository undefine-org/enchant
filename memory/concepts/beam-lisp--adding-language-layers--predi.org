How to extend beam-lisp itself, verified shipping 5 fixes (PLAN-038) that closed Clojure-superset gaps + interop traps found building a downstream service.

## Default-loaded macro layer (sugar)
- init/0 in lib/beam_lisp.ex loads a LAYERED LIST: [{"core",@prelude},{"multi",@multi},{"sugar",@sugar}], AOT-first (AOT.ensure_loaded) with source fallback (Compiler.eval_string). Add a layer here + its @sugar_path/@external_resource/@sugar constants.
- For unqualified availability everywhere: extend BeamLisp.Env `candidates/2` fallback from `[{"core",name}]` to `[{"core",name},{"sugar",name}]` (both split branches). macro_for uses Env.fetch so macros resolve through this.
- CRUCIAL: give the file its OWN (ns sugar), NOT (ns core). AOT maps ns→module (emit.ex module_for: ns→BeamLisp.Ns.<Camel>), so two files sharing (ns core) collide/clobber at AOT. A separate file with its own ns AOT-compiles to BeamLisp.Ns.Sugar cleanly.
- Only `core` is auto-referred by default; multi/datom need explicit require. The Env fallback is what makes sugar auto-referred like core.

## Predicates (rt.ex)
- Register in BOTH tables: the fn map (~L2174 "name" => &fn/1) and the arity map (~L2401 "name" => 1).
- map? is TRUE for bl map + bl record, FALSE for foreign structs — deliberate (rt.ex:813-815, record? gate). This causes silent wrong-branch interop bugs.
- struct? must EXCLUDE bl-internal value structs (BeamLisp.Vector/Set/SortedMap/SortedSet/LazySeq) + ref types (is_ref_type), else [1 2] (a %BeamLisp.Vector{}) reports struct? true. struct? = bl record ∪ foreign struct.
- associative? = struct? ∪ map? ∪ vector? (SortedMap covered by map?; Set/SortedSet/LazySeq excluded free). The interop guard "a foreign struct" = (and (struct? x) (not (map? x))).

## Reader forms (reader.ex)
- Main dispatch is form/2 (~L200): pattern-match the char list head. Add a clause BEFORE atom_form (the catch-all). `[?" | rest] -> string(...)`, `rest -> atom_form`.
- Quoted keyword :"..." (BUG-004): new clause `[?:, ?" | rest] -> quoted_keyword(...)` that reuses string/3 for the body then wraps {:keyword, name} and runs check_atom_safety! (atom accounting). Also makes :"Elixir.Foo" read as a usable module atom.

## Process
- Native test runner: `mix beam_lisp.test [PATH|DIR]` (bl deftest suites). Elixir: `mix test`.
- AOT beam staleness: an isolated `mix test <one_aot_file>` can fail with "module not available" from a stale _build; a full `mix compile`/`mix test` rebuilds fixtures and it passes. Don't trust a lone AOT-test failure — rebuild first.
- Multiline `git commit -m` with (), *, or newlines breaks the harness shell parser — write the message to a file and `git commit -F`.
- When another session's WIP is uncommitted in-tree: build on top, commit ONLY your own files, leave theirs untouched (don't commit someone's unfinished work under your name).
