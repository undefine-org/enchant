mock.bl / mock/fault.bl / fuzz.bl UNIFIED into the veritas.* family (PLAN-065, DONE). One quantifier core, each capability a named layer built on it, separate files.

LAYOUT:
- priv/veritas.bl — core: Gen protocol, check escalator, exists/for-all/covers/faults, parse-model (owns it now), samples helper. 
- priv/veritas/mock.bl (ns veritas.mock) — the mock SERVER: contract {:fields :ensures}, make-mock/answer (deterministic input→response, same key⇒same value), synth-boundary (z3 minimize/maximize optimize path), synth-invalid, contract-from, contract-decls (public, reused by fault). Reuses core parse-model.
- priv/veritas/fault.bl (ns veritas.fault) — fault space as DATA: isolate (modality-tagged, :implied when z3 proves a law redundant), build-db + datalog queries (uncovered-clauses via [:not-join [?c] …], faults-per-clause, redundant-mutants by violation signature, independent-laws), serve/error-for/errors on the mock server. Violations MEASURED not assumed.
- priv/veritas/property.bl (ns veritas.property) — hypothesis: RUN target fn, assert predicate over its OUTPUT `result`, SHRINK counterexample to minimal. Domain from veritas generators via v/samples.

WHY THIS SHAPE (the audit that overturned a wrong call): I first claimed "veritas subsumes them, thin-wrap them" — FALSE, twice: (1) zero test/bl suites existed for mock/fuzz/fault (only demos), so "green tests as safety net" was hollow; (2) veritas only generalizes their quantifier CORE — each module had a UNIQUE capability veritas lacked (mock: server+optimize; fault: datalog analysis; fuzz: output-hypothesis). Thin-wrapping would DELETE capability. Correct move = rewrite-in-terms-of: keep core once, preserve each unique half as a layer. LESSON: count real callers + check for tests BEFORE proposing delete/merge; "green tests" may be demos only.

RESULTS: 30 tests / 76 assertions / 0 failures across veritas/mock/fault/property. 6 examples/veritas demos end :ok. Old files deleted, no dangling requires, docs re-pointed.
