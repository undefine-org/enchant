The self-hosted beam-lisp reader (priv/reader.bl) can now replace the live Elixir reader (lib/beam_lisp/reader.ex) via a config-gated seam, mirroring the compiler's compile/2 ↔ compile_elixir/2 split exactly.

SEAM (lib/beam_lisp/reader.ex):
- read_string/2 is the ONE backend switch (all readers + 5 live call sites funnel through it). use_bl_reader?() reads :reader_backend app-env (:auto|:bl|:genesis); :auto delegates to BeamLisp.Ns.Reader once Env.loaded_ns?("reader"). Genesis body renamed read_string_elixir/2 (kept forever as bootstrap seed + oracle yardstick). read_all_elixir/1 is the genesis-pinned oracle answer key — parity/position tests + priv/self/oracle.bl MUST use it, else they self-compare once the reader ns interns. read_string_bl/2 translates reader.bl's ExInfo/AtomGuard.LimitError back to the public Reader.SyntaxError/AtomLimitError. enable_bl_reader/0 mirrors enable_bl_backend/0 (forces :genesis while interning reader.bl so its tail isn't read by the half-built reader). NOT wired into init/0.

KEY LESSON — the 45-case parity suite was too weak. The real gate is a CORPUS DIFFERENTIAL: read every real .bl file (408) with both readers, position-bearing, assert byte-equal. It exposed 3 divergence classes the snippets missed, all reader.ex QUIRKS reader.bl must reproduce bug-for-bug (else diagnostic columns shift after the construct):
1. fn-literal #(...) returns a position 2-col undercount (reader.ex feeds the body collection pos0=# while the stream is past #() → the SIBLING after #() is 2 off. Fix: pass pos0 not the advanced pos into read-until.
2. #tag"..." data-reader and #Name{} record: same returned-pos undercount (tag/name length). Fix: read payload from pos0.
3. BIG: ^ author metadata. reader.bl DROPPED it (built to match read_all which strips everything). But read_string (live compile path) must ATTACH it as {:meta, form, author-map} — the compiler reads it via name-author-meta for :private/:doc/:args/:ret and the type checker. read_all still strips. Rewrote read-meta to attach (metadata-spec/attach-meta/metadata-key mirroring reader.ex meta_form/metadata_spec/attach_meta).

PERF FLOOR (why opt-in): bl reader is LINEAR but ~27× slower than genesis (core.bl 68KB: 3.7ms vs 57ms; clean 27× constant factor at n=100..800). reader.bl IS AOT-compiled — the tax is inherent self-hosting overhead (compiler.bl is 5× and ships default-on). By FUP-016's floor principle ("migrate only WITHOUT a benchmarked perf loss; keep regressers as thin wrappers earned by a number"), the flip stays config-gated until the 27× is closed. Correctness is DONE; only perf gates default-on.

Tests: reader_parity 15/45, reader_position 16/38, reader_atom_guard 4/7, reader_cutover 8/14 (NEW — forces :bl, proves seam transparent + exception contract + read_all/read_one inherit + :genesis override). Corpus 408/408 byte-identical. 120 Elixir reader units + 50 metadata/def units green. Pre-existing self_hosting 2 failures (try/catch, defserver) are compiler.bl-vs-oracle drift, NOT reader-related.

reader.ex is NEVER deleted: genesis seed + differential oracle, exactly like compiler.ex.
