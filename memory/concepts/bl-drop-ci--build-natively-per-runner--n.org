beam-lisp release drops (`.github/workflows/release.yml`, docs/native-bundler.md §14).

Matrix (native runner per target):
- linux-x86_64 → ubuntu-24.04  (glibc floor 2.39 = the pinned z3 asset's floor)
- linux-aarch64 → ubuntu-24.04-arm
- macos-arm64 → macos-15
- macos-x86_64 → macos-15-intel  (macos-13 retired 2025-12)

WHY native, not `--target` cross-pack: cross-packing onto the beam-machine linux
"any" bundles is musl, so every Rust NIF (datom_*, lazy_memo, wry_webview) would
need `cargo zigbuild` musl artifacts AND the pinned z3 linux assets are glibc-only
— a pure-musl payload could not carry the solver. Native per runner makes libc
matching free. Deferred cross-target NIF staging is the FUP for the other path.

Sequence per leg: mix deps.get → mix compile (creates the _build/<env>/lib/beam_lisp/priv
symlink the next step writes through) → mix beam_lisp.z3.fetch → mix bl.build.
MIX_ENV=prod at job level; BL_VERSION stamps the version.

Gotchas found:
1. Elixir's Version is X.Y.Z. A CalVer tag `v2026.0` is rejected by `mix release`;
   CI normalizes to 2026.0.0 (GitHub release keeps the tag name).
2. Rustler/cargo naming: cargo emits lib<crate>.dylib on macOS, but OTP's
   load_nif and Rustler's installer both use `<crate>.so` on every unix — the
   Mix native compiler must map dylib→so.
3. wry_webview is Linux-only (gtk3 + webkit2gtk + wlr-layer-shell). Target-gate
   its Cargo deps and crate-level `#![cfg(target_os = "linux")]` so macOS builds
   an empty cdylib and `wry/*` reads ABSENT instead of failing the build.
4. Linux legs need libgtk-3-dev libwebkit2gtk-4.1-dev libgtk-layer-shell-dev.
5. drop pack used host_arch() in the trailer; with --target it lied about arch.
6. Smoke must run outside the checkout (copy the drop to $RUNNER_TEMP), or the
   checkout's own .bl sources can paper over a payload missing a namespace.
7. macOS: ad-hoc sign the fetched z3 binary before packing (arm64 will not exec
   unsigned pages).
