Found five times in one session while making spell's chat→define loop work
live against a real provider (glm-5.3). Every failure had the same shape: a
layer enforced or assumed a rule that was never stated to the model, or
rebuilt only part of what an accepted definition invalidated. Every one was
green in 1092 tests and visible only in a browser.

## The five

1. No system prompt. The model had a tool for editing a machine and no
   knowledge of the machine. Its own words: "since I can't inspect the
   machine, I should define a view that binds to a standard chat contract
   shape". It invented four names and was correctly refused.
   → `machine-briefing`, derived FROM the machine, rebuilt every turn.

2. Tool schema under-described the reader. `each`/`on`/`view` declared as
   bare `{"type":"object"}` while `bind-form` throws unless `on` carries
   `fire` or `value`.
   → publish the sub-shapes; the either/or rule as prose (JSON Schema
   `required` cannot express a disjunction).

3. Publish rebuilt page + bundle, never the HOST module carrying the shell.
   Generation ran once, at boot, in the serve script. Machine grew; page
   could not change, through hard reloads, with no error anywhere.
   → `regenerate_host` moves into `publish`; the boot script reports.

4. Accepted definitions reported bare success. Three `unrendered-assign`
   warnings existed; the model was told none, and the page shipped showing
   literal `{@partial}` / `{@error}`.
   → `warning_note`: acceptance carries what the machine noticed.

5. camelCase CSS (`textTransform`) and a light background with no `color`.
   Both silently dropped by the browser; both invisible to every rung AND
   to verse's own W201 lint (which compares fg/bg only within ONE rule).
   → normalise camelCase (total, lossless mapping); warn on light-luminance
   backgrounds without a foreground.

## The rule that falls out

Publish before you enforce. A rung that refuses on an unstated rule is our
defect, not the model's — the refusal is correct and the silence is ours.

## Refuse vs normalise vs warn

- NORMALISE when the mapping is total and lossless (camelCase → kebab).
  Refusing punishes a spelling difference carrying no information.
- REFUSE when the value cannot be repaired without knowing intent (a
  `{@hole}` in the shell — nobody but the author knows where it belonged).
- WARN when the shape is legitimate in some designs (a background on a
  container whose children set their own colour).

## Where a check belongs

Not always in the rungs. A `no-shell` errors-level rule refused the partial
machines `spell.machine.test` builds (16 failures) — being unhostable is a
PUBLISH-time fact, not machine incoherence. Put a check where the fact is
known: `regenerate_host` knows how the shell is hosted; the rungs do not.

## A check that fires on the working page is worse than none

First cut of the contrast warning flagged four rules on the SEED, all
correct (light text on dark boxes IS the design). Narrowed from presence to
luminance. A check that fires on a correct page teaches its reader to
ignore it.

## Only a browser finds these

Tests verify what we EMIT; only a browser verifies what RENDERS. Three
earlier bugs (no reload trigger, unbound template params, attribute
interpolation) plus these two CSS ones were all found by `getComputedStyle`
and by reading the DOM — never by a suite. Assert rendered facts
(computed style, absence of literal `{@...}`) in the browser step.

## Operational

Use the running node, not `mix run`. beam-lisp ships a Tidewave MCP endpoint
on 127.0.0.1:9837 in the same OS process as the live server — absorb it with
`define_mcp` and `project_eval` runs inside the live node: zero cold boot
(~50s saved per probe), and it reads the ACTUAL state of the server under
test. Caveat: `:code.purge` kills processes running old code, and turns run
in a bare `spawn` — do not hot-reload mid-turn. `.bl` source changes are NOT
picked up by `init!`; restart for those.
