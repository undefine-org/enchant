** ITEM A bl namespace reload replaces the whole namespace: its state does not survive

Measured 2026-09-17 in beam-lisp (`!tasks/evidence/PLAN-117-prototype/k10.bl`): a live service in ONE OS process — a listener the harness owns, and a namespace on disk that decides what a request answers.

The reload protocol is `(reload/abort)` · `(reload/stage src)` · `(reload/commit)` → `{:status :applied | :held, :errors [...]}`, and a pre-compiled file reaches a runtime-created namespace through `(env/eval "(ns/fn)")` (it cannot name a var that does not exist until the reload creates it).

What it gives a long-lived service:

| step | observed |
|------|----------|
| load, then `GET /` | `svc says: v1  hits=2  pid=398381` |
| edit the namespace on disk (`greeting` → `"v2-EDITED-LIVE"`), commit | `svc says: v2-EDITED-LIVE  hits=0  pid=398381` — live, no restart, no build step |
| edit it to call `(no-such-helper)` | `:held` with `{:kind :dangling, :msg "undefined var: svc/no-such-helper — nothing in the bundle or image defines it"}`; the OLD code kept serving |

Two consequences that matter more than the feature:

1. **A namespace reload is a WHOLE-NAMESPACE replacement — its state does NOT survive.** `hits` went **2 → 0**. Anything a service must keep across an edit (listeners, tables, caches, a CA, the route table) has to live OUTSIDE the reloaded namespace: a separate process, ETS, or a registry. Design the supervision tree around that, and have the reload say which state it kept.
2. The coherence gate's report is already a sentence worth printing to a human: "undefined var X — nothing in the bundle or image defines it", with a `:kind`.

Incidental: bl has no `@` reader macro — `(deref x)` is the spelling (bl sources use `(deref state)`); `@(x)` fails as `cannot call %BeamLisp.Atom{} — a reference is not a function`. And an exception inside a connection handler is logged with a full stack while the rest of the service keeps serving.
