beam-lisp ships two self-contained packaging tiers, both entering via priv/bl/cli.bl (beam-lisp, no Elixir floor):

1. `bl` escript (4.1 MB, needs OTP): mix.exs `escript: [main_module: BeamLisp.Ns.Bl.Cli]` — the AOT-compiled CLI namespace IS the escript main. main/1 boots substrate itself (AOT.boot → ensure_loaded "bl.cli") and System.halts with the dispatch exit code (escripts ignore main/1's return).

2. `blbundle` (tooling/blbundle, Rust): self-extracting release bundle, full native tier (lang+datom+z3+explorer ≈ 98 MB). Launcher execve's `bin/bl eval BeamLisp.Ns.Bl.Cli.main(System.argv()) <args>` — trailing args after `eval EXPR` land in System.argv verbatim; a `--` separator LEAKS into argv.

Hard-won facts:
- mix release STRIPS beams by default → AOT drift gate (aot.ex stale?/2, compiler_key comparison) rightly rejects them → every AOT ns returns :no_module. Fix: `strip_beams: false` in the release + cli.bl pairs AOT.ensure_loaded → Loader.ensure_loaded on :no_module.
- escript :code.which returns virtual archive paths (no filesystem backing) — aot_cache compiler_key must degrade like the priv_dir fallback. Elixir Application delegates (get_key/2) don't survive escript trimming; use erlang modules (application/get_key).
- `native/` dir is reserved for Rustler NIF crates (beam_lisp_native Mix compiler assumes cdylib); non-NIF Rust tooling goes in `tooling/`.
- beam-lisp `map` is LAZY — side effects in an unrealized seq never run; use reduce-based `each`.
- ERTS reuse verified: Burrito's CDN (beam-machine-universal.b-cdn.net) serves OTP-29.0 macOS universal + linux x86_64/aarch64; windows via official OTP GitHub release exe. spec: docs/native-bundler.md.
