A beam-lisp `lazy-seq` thunk (and any `BeamLisp.LazySeq` thunk) MUST return either `nil` or a `[h|t]` cons cell whose tail may itself be a LazySeq — it must NEVER return a bare LazySeq. The walk loops (`LazySeq.to_list_loop`, `LazySeq.prefix_loop`) only match `nil` and `[h|t]`; `realize/1` does not re-normalize a thunk value, so a bare-LazySeq return crashes with `no function clause matching in prefix_loop/3`. Clojure tolerates a lazy-seq body returning any seq; beam-lisp does not. Consequence: skip-branches in lazy fns (distinct's already-seen path, keep/keep-indexed's nil path) must `recur` inside an inner `loop` within the thunk, or return `nil`/cons — never return the recursive lazy-seq call directly. (Found writing prelude `distinct`/`keep`/`keep-indexed`.)
