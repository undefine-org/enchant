The beam-lisp "application shutdown" cross-suite test contamination (a suite that stops :beam_lisp or purges a module kills the shared Env/Loader.Server/Refs singletons other suites depend on → cascade failures) is dissolved STRUCTURALLY by a pure-bl runner built on the coherent-reload machinery (priv/reload/ward.bl, mix beam_lisp.ward).

Four structural properties, each a reuse of a reload building block:
1. ISOLATION — each test file runs in env/isolated (own var-registry ETS namespace, destroyed on exit). No shared mutable singleton for one file to tear down under another. Proven: a var def'd in file A is invisible to file B.
2. CRASH-CONTAINED — a top-level throw at LOAD time is caught inside the fork's try (becomes a reported :load-crash result); the sibling still runs. The ExInfo caught by `catch` must be rendered via `ex-message` (str on it triggers Enumerable protocol errors).
3. ALWAYS-LATEST — the file SOURCE is read fresh and evaluated; no beam in the loop to go stale (closes the origin stale-beam class by construction).
4. WARM — the test lib loads once into a warm base (ensure-test-lib! self-loads it so ward works under mix run / beam_lisp.ward, not only the test task which pre-loads it); each file forks off the base.

KEY DESIGN CALL: coherence is ADVISORY, not a gate. reload/coherence is tuned for whole-namespace top-level defs and does NOT scope-track let/destructuring locals, so a hard reject false-flags valid test files (e.g. prelude_test's `(let [g (fn…)] (g))` → g flagged dangling). Findings ride as :warnings; the file runs; a genuine dangling ref surfaces as a caught runtime error. Safety is structural (isolation + crash-containment); coherence is a heuristic heads-up. Also had to add catch/finally/after/receive to deferred/collect's special-forms set (their heads are syntax, never calls).

Verified warm+isolated on real files: prelude 295, optics 54, core-additions 153, all green. The ExUnit reload_watcher_test still fails in-full-suite from the SAME Refs contamination (passes 3/3 alone) — it's an Elixir GenServer test that can't use ward; the bl suites built ON ward are the ones immune.
