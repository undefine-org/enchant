A dev server in beam-lisp answers at a NAME, never at a number a human reads.

THE RULE (one implementation: `BeamLisp.Daemon.Names`)
    host(port-name) = "<port>.<base>.<suffix>"   and, for :ui, "<base>.<suffix>"
    base = slug(env.bl :name, else the directory's name)
           <> "-" <> slug(:instance)  when one exists
    :instance = env.bl :instance, else the git branch when it is not main/master/trunk
    suffixes = .test (reserved testing TLD; one dnsmasq line points all of it at loopback)
             + .localhost (nss-myhostname and every browser answer it — no resolver work)
Two suffixes per claim, because whichever spelling a machine resolves, the gateway answers the same route: no install is on the critical path of a first run.

WHY A GATEWAY IS UNAVOIDABLE
DNS maps a name to an ADDRESS, never to a port. Only a listener can demux. `BeamLisp.Daemon.Gateway` is ONE per USER (the whole point is one port), binds loopback v4+v6, reads the request HEAD for `Host:`, and splices both sockets opaquely — so WebSocket upgrades, SSE and chunked bodies work without the gateway knowing what they are.

THE REGISTRY IS THE ROUTING TABLE
A claim (`BeamLisp.Daemon.Ports`, a file under the runtime dir, per-user and cross-tree) carries `:hosts` — written by the process that holds the port, which is the one that knows its name. The gateway therefore never reads `env.bl` and there is no cache to invalidate: a claim appearing or dying changes routing on the next request.

THE ONE PRIVILEGED PIECE
Port 80 is the only HTTP port a URL may omit, and a user cannot bind it. `net.ipv4.ip_unprivileged_port_start=80` (one sysctl, root once) makes it the user's; without it an UNPINNED gateway falls back to 7777 and prints the fix, while a PINNED port that cannot be bound is an error, never a silent move.

APP SIDE
`(bl.serve/port :web 4043)` answers the project's `:ports {:web 4000}` (or 4043, or `--port N`), claims it with the name's hosts, and returns the number to hand to the web layer. `bl ports` lists name → address → port; `bl open NAME` opens it; `bl ui` is `bl open ui` (one implementation).

GOTCHAS THAT COST TIME
- `:gen_tcp.controlling_process(client, handler)` after `accept`, or the handler never receives what the client sends after the head: active-mode messages go to the socket's CONTROLLING process, which accept leaves as the acceptor. Passive reads keep working, which makes the bug look like "the backend stopped responding".
- `u/kw` takes ONE PAIR PER VECTOR (`(kw [:a 1] [:b 2])`); a flat `[:a 1 :b 2]` used to silently keep only `:a`. It now refuses that shape — an option that goes missing without a symptom is the failure mode this whole feature is about.
