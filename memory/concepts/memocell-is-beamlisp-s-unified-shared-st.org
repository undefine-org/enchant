The native lazy_memo cell (native/lazy_memo/src/lib.rs, hosted by
lib/beam_lisp/lazy_memo.ex) is not just lazy-seq memoization. It is a
GC-owned, atomically-swappable off-heap term cell with a dependency graph +
cycle rejection, byte accounting, off-scheduler reclaim, and (as of PLAN-096)
two scheduler lanes chosen by the cell's own retained_bytes.

PLAN-096 unified BeamLisp's shared-state primitives onto it:
- delay/force/realized?/memoize (lib/beam_lisp/deferred.ex + core.bl) reuse
  LazySeq's force machine, inheriting thundering-herd protection.
- atom/swap!/reset!/compare-and-set!/add-watch (lib/beam_lisp/refs.ex) became
  {value cell, watches cell}; the per-atom Agent PROCESS was deleted. swap! is
  a compare-exchange retry loop.
- derived (lib/beam_lisp/reactive.ex + core.bl) is pull-based value-diffing:
  a derived remembers the dep values it last computed from and recomputes on
  deref only if one changed. swap! pays nothing.

KEY DISTINCTION: lazy cells (create/exchange) scan the value for embedded
handles and REJECT cycles (a cycle = infinite force). Atoms are EAGER and use
create_ref/exchange_ref: NO dependency scan, NO cycle check, because Clojure
atoms legally hold mutual references. Mixing these up raises "reference cycle"
on ordinary atom data.

Two scheduler lanes: a small value's read/CAS/create/cursor-chunk runs on a
regular scheduler (~90-350 ns); a large value takes the DirtyCpu lane. The
fast CAS is self-guarding (returns :reroute for a large current/replacement or
a NEW dependency edge). This is why cell reads are ~150 ns not ~4 us, which is
what makes derived signal graphs and cheap memoize viable.

BOOTSTRAP CONSTRAINT: lazy_memo CANNOT be cut over to a .bl defnative like
datom-fjall/wry, because the bl compiler itself uses lazy-seq (even (+ 1 2)
makes 24 cells) and LazyMemo is a compile-time dep of the Elixir phase. Every
other defnative is a leaf in priv/lib; lazy_memo is the substrate the compiler
runs on. Self-hosting it needs a seed-hosted native host: PLAN-097.

Measurements live in scripts/memocell_prototypes.exs and
scripts/memocell_cas_breakdown.exs (re-runnable).
