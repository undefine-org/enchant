beam-lisp runs unmodified Clojure/Babashka stdlib via a priv/compat/ load-path tier (registered in lib/beam_lisp/tiers.ex + mix.exs source_dirs). 9 namespaces: clojure.string (reimpl over Elixir String+Regex), clojure.set (VENDORED byte-for-byte, pure Clojure over core), clojure.walk (reimpl, pure fns verbatim), clojure.edn (realizer over the reader — reads nodes, builds data values, NEVER evals), clojure.re (core regex over Elixir Regex), clojure.core-ext (missing core fns), clojure.io (slurp/spit/*command-line-args*), clojure.java.io (path subset), babashka.fs (over File/Path).

KEY TECHNIQUE: clojure.core fns (re-find, slurp, conj-variadic, char, integer?, empty, vector, …) are interned into `core` at load via a CAPTURED VALUE-DEF `(def ^:private _x (install!))` — AOT __bl_init__ replays value-def initializers, so bare calls resolve everywhere WITHOUT editing any boot seed (compiler.bl/core.bl untouched, per constraint). A bare top-level (install!) call is NOT replayed; must be a value-def.

Canonical ns→path: (ns clojure.java.io) lives at priv/compat/clojure/java/io.bl; loads via (require [clojure.java.io]). Precedent: clojure.core.async at priv/std/clojure/core/async.bl.

GAPS CLOSED in beam-lisp by running real Clojure (fixes in lib/, not the vendor): (1) maps/sets callable as fns — rt.ex invoke clauses after struct clauses; (2) variadic conj — core-ext folds through RT/conj; (3) conj accepts raw 2-tuple map entry — rt.ex, map iteration yields tuples; (4) sort/sort-by accept BOOLEAN comparator (>) not just 3-way numeric — rt.ex comparator_le, (sort-by val >) was garbage; (5) shebang strip in loader.ex doc_content; (6) *command-line-args* bound live by run_file (clojure.io does NOT intern it — loads in Loader.Server process with empty argv).
