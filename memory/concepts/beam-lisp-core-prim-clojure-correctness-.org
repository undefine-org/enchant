Wave 14 (jank compat, gaps #1/#5/#6) lessons for beam-lisp `RT` prims:

1. **`not` must be truthiness-based, not `Kernel.not/1`.** `Kernel.not(nil)` raises ArgumentError; Clojure `(not nil)`=true. Use `x == false or x == nil`. `not-any?` (jank slice) calls `(not (some ...))` where some returns nil — this surfaced the pre-existing bug.

2. **`map?` must exclude structs.** Elixir structs (`%BeamLisp.Vector{}`, `%LazySeq{}`) ARE maps (`is_map` → true). `(map? [1])` must be false. Guard: `is_map(x) and not is_struct(x)`. (`coll?` is safe because its vector/lazy clauses precede the `is_map` catch-all.)

3. **`find` must return a `[k v]` VECTOR, not a list**, because beam-lisp structural `=` distinguishes `[]` from `()` — a list entry would fail `(= (find m k) [k v])`. Construct `%BeamLisp.Vector{items: {k, v}}` (MapEntry semantics).

4. **`next` over a LazySeq must not over-realize**: force exactly one cell (`LazySeq.cell/1`), return the tail via a `next_tail/1` helper that returns a LazySeq tail untouched (forcing it = realizing a 2nd cell) but seqs a realized list tail (nil if empty). Test via a counter atom in a lazy `(map f (range))` — asserts `1`.

5. **Vector `next`**: `next(v) = seq(rest v)` — do NOT call `next(rest v)` (double-drop). `next_tail(BeamLisp.Vector.rest(v))`.

6. **Multi-arity/variadic prims need BOTH a `multi_fn` tag value AND an explicit `seed_links` entry** `{RT, %{fixed_arity => fn}, {min, variadic_fn}}` (2-arity `apply` links to `apply_to`, ≥3 to `apply_variadic`; `list*` 0-arity to `list_star_0`, ≥1 to `list_star`). The generic `rt_fns` map loop only produces fixed-arity links and mislinks variadic handlers.

7. `next_tail`/`seq_to_args` must handle a list cell whose tail is a LazySeq (from `cons(x, lazy)` → `[x | LazySeq]`).
