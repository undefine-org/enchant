STEP 1 — SOURCE POSITIONS (test/bl/reader_position_test.bl, 12 tests / 23 assertions) — the keystone:
- Shape the compiler consumes (observed empirically from BeamLisp.Reader.read_string, NOT guessed): {:meta, {:list, items}, %{line col file}} where the map is read by compiler.bl env-from-meta (maps/get :line/:file). ONLY LIST forms are wrapped; scalars/symbols/keywords/vectors/maps/sets stay BARE. Nested lists each carry their own position. Constructed lists (quote/deref/unquote/syntax-quote, #() fn-literal desugar, #d[…] data-reader call) ARE wrapped, at their prefix/# column. #{} set and #Name{} record are NOT wrapped.
- Implementation: pos = Erlang tuple {line,col,file}. Every read-* fn gained a pos param and returns [form remaining pos'] (pos' = position at head of unconsumed source). Primitives: advance-pos (newline->line+1,col=1 else col+1); advance-to pos from to (walks the consumed prefix until identical? shared-tail OR [] — O(consumed), stays linear because every step returns a rest-suffix; verified identical? works on shared tails and on the [] singleton); skip-pos (position-aware skip-ignored). wrap-list-pos = rn/meta-node node (pos-meta pos).
- reader.ex QUIRK matched for parity: after a reader prefix char it skips whitespace with the count starting at pos0 (the PREFIX char's column, NOT one past it). So `(a ~b)` positions the inner list at the backtick column and ~b one past. wrap-prefix must pass pos0 UN-advanced (this was the single failing assertion; off-by-one until fixed).
- Architecture mirrors reader.ex exactly: a shared read-forms* threads positions; read-string returns wrappers intact (compiler entry); read-all deep-unwraps via ported unwrap-deep (position-free, keeps parity suite comparing like-with-like). GOTCHA repeat: unwrap-deep's (map …) over node items returns a LazySeq -> wrap in (apply list …) or the tree compares unequal (same trap as the earlier %& desugar-fn bug).
