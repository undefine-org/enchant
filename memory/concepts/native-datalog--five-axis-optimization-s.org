Investigated "better than semi-naive" for the beam-lisp datom recursive-rules engine across 5 literature axes, built a native Rust spike, measured all five, reconciled with the one-representation principle.

## The measured bottleneck (why this started)
bl semi-naive materialises the WHOLE least-fixpoint ignoring query bindings: reachable-from-1 on chain-60 computes 1770 tuples to answer 59, and the bound query (2102ms) is SLOWER than a bare materialise (772ms) because it materialises twice.

## The 5 axes (literature: Abiteboul Ch.13 semi-naive; Tekle-Liu SIGMOD11 subsumptive-tabling-beats-magic-sets; Zaniolo PreM; DDlog/FlowLog differential; Souffle compilation)
- Axis 1 Magic Sets (demand): source-to-source rule rewrite, goal-directed.
- Axis 2 Indexed joins: hash index vs nested-loop.
- Axis 3 Incremental: maintain fixpoint under +delta (differential).
- Axis 4 PreM: push min/max INTO recursion (aggregate-in-recursion).
- Axis 5 Native execution: run the fixpoint in Rust over integer tuples.

## Measured results (native spike, native/datom_datalog)
- Axis 5: native semi-naive 32x@N20, 65x@N40, 139x@N60 vs bl, closures bit-identical. Grows (bl super-linear from per-tuple interpretation). REAL constant-factor win.
- Axis 2: indexed 4x on branchy graph (52->12ms @m800), grows. NO win on chain (out-degree 1) - correct. Bug fixed: build index once per atom per round, not per partial.
- Axis 1: magic 105 vs 8400 tuples (80x fewer) + 27x faster on a forest where query touches 1 of many chains. Cost independent of irrelevant graph. GOTCHA: on a pure chain rooted at query node, demand==full closure (everything downstream reachable) - magic only wins when query is SELECTIVE (sink/branchy/forest). Seed must be a FACT RULE (magic pred is IDB, an EDB seed is ignored).
- Axis 3: break-even AS SPIKED - NIF re-materialises before-state each call, dominating the cheap delta. Real design needs RESIDENT materialised relation across calls. Reported honest, not faked.
- Axis 4: PreM converges on CYCLIC graph (shortest path node=3 via 2-hop beats direct 10) where stratified path() diverges.

## THE CRITICAL DECISION (one-representation, from PLAN-042 + auth NIF decision)
Building a full rules-IR + unify + fixpoint in Rust = the "second engine that must agree" anti-pattern. PLAN-042 rejected a columnar rewrite (flat-into fixed the real O(n^2) accumulator bug bl-side for 9x, far lower risk). Auth rejected wrapping biscuit-rust because the value is ONE datalog shared across token-checks and RLS.
KEY INSIGHT: magic sets + PreM are RULE REWRITES (rules->rules), pure datalog, no engine needed. They belong in bl (priv/datom/query/magic.bl, prem.bl) composing with the real engine. Only the CONSTANT-factor fixpoint is a native matter, scoped like datom_resolve (representation-preserving, knows tuples-not-rules), NEVER a second brain.
