In beam-lisp, a method postcondition (:ensures, SMT-LIB predicate over response fields) run as a z3 SAT query yields a MODEL that IS a concrete response value. Every prior z3 caller in the tree (verify-process, abduce, prove-equiv) asks UNSAT (proof); the SAT direction was unused — it is the mock generator. One relation, two directions: forward verifies a real impl, backward synthesizes a mock that satisfies the same contract, so the two can never drift.

Implemented in priv/mock.bl. Modes (all proven vs real z3 4.16): synth (valid), synth-seeded (deterministic pure fn, pin a field = seed — keep linear, no mod on synthesized var), synth-boundary (min/max via z3 optimize = free edge cases), synth-invalid (negate ensures = adversarial values the contract forbids, by construction), satisfiable-status (sat/unsat/unknown), check (forward round-trip: pin fields, ask ensures-negation unsat).

CRITICAL: nonlinear integer arithmetic (total = price*qty) is undecidable — z3 answers SAT fast but spins forever on UNSAT. Must prepend (set-option :timeout N); treat "unknown" honestly (not a false proof). Real theory returns exact rationals (/ 1.0 2.0) — parse them. Model text is valid s-expr; read with BeamLisp.Reader/read_string then project define-fun nodes.

Selection: mock vs real is chosen by env caps (env/allowed? module), NOT an if-branch in the caller. Ungranted module unspeakable at compile time → fail-closed becomes fall-back-to-mock. Demos: examples/mock/00,01,02.
