A test that passes alone and fails in the suite (or fails on some seeds) is
almost never flaky. It is a **shared-state leak**, and the intermittency is
just the scheduler sampling different orders. Chase it; do not re-run until
green.

## Three instances found in one session, same root shape
All three were writes into a **process-global or long-lived namespace** that
outlived the test file that made them:

1. **An obsolete shim.** A test `defn`'d `keys`/`vals`/`merge`/`into` into the
   shared `user` namespace because none shipped yet. Once they shipped, the
   shim SHADOWED the real ones — whichever ran last won. `(keys nil)` returned
   `()` instead of `nil` in ~2 runs in 3.
2. **A rebinding shadowed globally.** Transducer arities were added by
   rebinding `map` in the prelude and delegating to a captured primitive. A
   *fixture* defining its own `map` (the fidelity target's stdlib is full of
   `defn map`) shadowed the capture globally. Symptom: `BadArityError` in a
   file that had not changed.
3. **A leaked "current namespace".** `current_ns` was a process-global that
   survived across evaluations, so an earlier test running an example left it
   pointing at that example's namespace. A later assertion about namespace
   qualification then saw `server.demo/x` instead of `user/x`.

## Diagnosis technique
- Run the file ALONE (passes) then with suspected neighbours (fails) → confirms
  a leak rather than a bug in the file.
- Fix the seed and vary it: deterministic-per-seed ⇒ order dependence.
- `grep` for who else writes the shared name. Look in FIXTURES too — vendored
  code defines ordinary names like `map` and `for`.
- Once found, make the failure DETERMINISTIC before fixing it. Deterministic
  beats intermittent even while still red.

## Rules that prevent it
- A rebinding is only safe when **nobody else can rebind the same name**. If
  the codebase's whole purpose is loading third-party code that defines
  `map`, that promise cannot be made — define on the primitive instead, so
  there is nothing to shadow.
- A test that mutates shared state must PIN what it depends on, not assume a
  default (e.g. explicitly set the namespace).
- Shims for "not yet implemented" functions are time bombs: they keep working
  after the real thing lands, silently shadowing it. Delete on ship.
- Retire the workaround when the root cause closes, or it becomes the next bug.
