** ITEM req_llm normalizes usage before the caller sees it (relay caching trap)

In req_llm 1.9.0, the usage map a caller receives is NOT the provider's raw usage — it is ReqLLM.Usage.Normalize output. Streaming: StreamServer.enqueue_chunks runs normalize_streaming_usage (Usage.normalize + Cost.apply) before metadata settles, so StreamResponse.usage/1 returns normalized. Non-streaming: normalized at Response build.

Normalization REMAPS the keys a naive codec reads:
- raw Anthropic cache_read_input_tokens  -> flat cached_tokens / cached_input
- raw Anthropic cache_creation.{ephemeral_5m,ephemeral_1h}  -> COLLAPSED cache_creation_tokens (the TTL split is DROPPED — unrecoverable from the response)
- raw OpenAI prompt_tokens_details.cached_tokens  -> flat cached_tokens
- raw input_tokens / prompt_tokens  -> flat input
- adds an explicit input_includes_cached boolean (authoritative — honor it over re-derivation)

Consequence for the relay: a usage codec that reads only RAW keys records ZERO cache tokens in production while unit tests (fed raw shapes) pass green. Fix: read the widest alias set (raw AND normalized) per quantity; honor input_includes_cached; keep a :cache-write TOTAL because the 5m/1h split cannot be recovered through req_llm. Attribute the collapsed write total to a TTL bucket by the REQUEST's own intent (anthropic_prompt_cache_ttl the relay set), not the response — the relay chose the TTL, and 5m (1.25x input) vs 1h (2x) price differently, so the bucket is what cost reconciliation needs.

Enablement trap (verified via NimbleOptions.validate!): anthropic_prompt_cache / prompt_cache_key options on an OpenAI model raise "unknown options" — they are NOT harmlessly ignored. Cache options MUST be provider-gated (emit only from the provider adapter that owns them). The relay's provider-port -call-opts (per-provider select-keys) is the structural cure.

Verify caching accounting by running real ReqLLM.Usage.Normalize.normalize(raw) output through the codec — hand-written "normalized" maps can drift from what req_llm actually emits.
