Root cause of the `mix compile --force` host-OOM (2026-09-06, PLAN-086 E2): `BeamLisp.LazySeq`'s realization cache (`beam_lisp_lazy_cache` ETS) is insert-only with make_ref keys — every forced seq's realized chunk is retained VM-wide forever. The bl-ANF compiler pipeline amplifies this ~4x over the quoted pipeline (quote-node/normalise roundtrip forces giant lazy trees per top-level form: ~160MB/form; compiler2.bl alone = 6.9GB). Fixed (ea78b32) with whole-table eviction over a budget (default 512MB, `:lazy_cache_budget_bytes`) — memo loss is explicitly non-semantic per the BUG-011 design note.

Diagnostics that located it: `:erlang.memory()` per category per form (ets grew, processes flat) → `:ets.info(t, :memory)` census → table name. Stdout from an OOM-killed scope is LOST (block buffering) — sample via `File.write!(..., [:append])`.

Second bug found en route: `Bootstrap.fresh_generation?` inherited the shim's provenance verdict for Body/Init beams unconditionally; interrupted builds leave a fresh shim beside a stale/missing body → File.read! crash / stale Init.Anf. Fixed by requiring dst to exist and not predate its shim (emit order is shim-first).

Host protocol: ANY mix/beam run that might stress memory MUST run under `systemd-run --user --scope -p MemoryMax=XG -p MemorySwapMax=YG --collect --unit <name> sh script.sh`, never foreground — an uncapped run OOM-kills the whole session (ghostty terminal dies). Check outcome via `journalctl --user | grep <unit>` (oom-kill / memory peak) and Result=success.
