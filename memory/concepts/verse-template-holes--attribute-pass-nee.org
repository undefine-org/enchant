A `@template` body's holes are interpolated at RUNTIME by two regex passes in
the emitted spacetime.js, not by the compiler:

    attribute:  /(\w+)=\x22([^\x22]*\$[\w.]+[^\x22]*)\x22/   ← \x22 = DOUBLE quote, literally
    text:       />([^<]*\$[\w.]+[^<]*)</                     ← only between > and <

∴ an attribute hole MUST be double-quoted. A single-quoted value
(`data-role='`$m.role`'`) matches NEITHER pass and reaches the DOM as the
literal characters `$m.role`. The element still renders and its text still
interpolates (text position works), so the page looks nearly right while every
attribute-keyed CSS rule silently misses.

The only symptom is a console warning from a debug branch that runs AFTER both
passes give up:

    [ST Template] <name> - Uninterpolated variables: ["$m.role"] Available params: ["m"]

"Available params" listing `m` is NOT the problem — `m` is bound; the FIELD
access never ran. Reading that line as a missing-param bug sends you to the
wrong layer (that was the earlier `html-params` fix, a different bug with the
same-looking console output).

SECOND, INDEPENDENT BUG, found only by fixing the first (verse d9015d1e):
`src/edn/ingress.rs` read `:html`/`:selector` with a raw `(*val).to_string()`,
skipping `unescape_edn`. A construct body is the one string that travels
edn → ast → `.st` SOURCE, so the missed decode writes a literal backslash into
program text: `data-role=\"`$m.role`\"`. Single-quoted bodies carry no escape,
so raw ≡ decoded and 3220 verse tests passed over a decoder never called on
that path. The bug was UNREACHABLE until a document used double quotes.

Pattern worth keeping: fixing a bug at layer N can expose a latent bug at
layer N+1 that no test could reach, because the input that triggers it was
never producible. Expect the second failure; do not read it as the fix being
wrong.

CHECKING THIS: `getComputedStyle(el).backgroundColor` on a bubble of each role.
Equal values = the attribute never interpolated. Asserting on the emitted
string instead re-states the emitter and cannot fail (both tests here did
exactly that and passed throughout).
