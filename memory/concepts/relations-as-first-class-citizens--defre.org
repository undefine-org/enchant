Built the full "relation is a first-class citizen" abstraction in beam-lisp datom (undefine repo), extending the one-truth native Datalog work. A relation is not "a set of tuples" but a citizen with 7 axes a stored attribute always had: extension (stored/derived/computed), schema-as-data, access modes (bf/bb/fb adornment), basis (pure fn of db value), maintenance, provenance, cost.

## Architecture (priv/datom/query/)
- relation.bl — THE CATALOG. register-relation!/defrelation macro register a COMPUTED relation with a universal provider (fn [db mode bound args] -> tuples). relation/computed?/idents/all-specs lookup. mode-of/supported-mode = adornment with graceful degrade. eval-relation = single dispatch. catalog-datoms = relation describes itself as :relation/* datoms (schema-as-data, axis 2). Provider registry is a named Agent (mirrors datom.conn); the DESCRIPTION is datoms, the closure is in the Agent.
- relations.bl — provider LIBRARY (the "not married to k-NN" payoff): knn-adjacency (bf/bb/fb), threshold-adjacency (business rule, no vectors), fn-adjacency (any pair scorer), union-adjacency (hybrid/ensemble). Swap the provider, query unchanged.
- analytic.bl PROMOTED: similar-to/cluster/community/components/project-2d now register THEMSELVES; eval-op's 5-way cond DELETED -> registry dispatch. Built-ins are first citizens, not exceptions.
- parse.bl: ANALYTIC-OPERATORS hardcoded set DELETED; analytic-clause? + arity check consult the registry -> user defrelation recognized automatically.

## Key wins
- Both spellings: [?a :~similar ?b] (attribute, eval-pattern routes to provider) AND [(:~similar) [?a ?b]] (call). Attribute-spelled args fixed at defrelation :args.
- THE UNLOCK: recursion over a computed relation runs on the NATIVE fixpoint (fp/compatible?=true). Provider fires during base-relation construction, edges intern, native kernel produces closure. Semantic transitive closure at native speed.
- Relation-POLYMORPHISM: [?a ?rel ?b] with ?rel a VARIABLE. resolved-attr resolves it through bindings (from :in, catalog query, upstream). Quantify over relations. Far-dream: query asks catalog which relations are :semantic, binds ?rel, traverses polymorphically.

## Gotchas hit
- Lazy ns load: engine :require of analytic does NOT run its body/register builtins. Fix: q calls analytic/ensure-registered! on entry (idempotent).
- run-clauses has a SEPARATE hash-join fast path (pattern-scan-once) bypassing eval-pattern; must exclude computed patterns there too.
- Planner: a pattern with unbound VARIABLE attribute [?a ?rel ?b] must be DEFERRED until attr binds (else runs first with ?a bound, ?rel nil -> empty). Added attr-ready? filter in order-clauses.
- Shortest-path over CYCLIC weighted graph (mutual kNN edges) does NOT terminate in plain Datalog -> use acyclic citation DAG or PreM. Example 05 uses citation DAG weighted by semantic distance.
- cardinality/many attr in transact: pass the WHOLE collection as one value, not repeated assoc.
- core has conj/list but NOT vector as query predicate.
