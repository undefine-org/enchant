The beam-lisp reader now lives in beam-lisp source (priv/reader.bl) and is the DEFAULT live reader, VM-wide, since session 156c5bab (2026-08-30).

MECHANISM (mirrors the compiler cutover exactly):
- Seam inside `BeamLisp.Reader.read_string/2` (lib/beam_lisp/reader.ex): backend switch via `use_bl_reader?()` reading `:reader_backend` app-env (:auto|:bl|:genesis). :auto delegates to `BeamLisp.Ns.Reader` once `Env.loaded_ns?("reader")`. All 5 call sites funnel through read_string/2 — one seam, not scattered.
- `read_string_elixir/2` + `read_all_elixir/1` = the genesis body, kept FOREVER as bootstrap seed + differential oracle (answer keys pin to genesis so the flip can't degrade to self-comparison). Same policy as compiler.ex.
- `read_string_bl/2` translates BeamLisp.ExInfo→Reader.SyntaxError, BeamLisp.AtomGuard.LimitError→Reader.AtomLimitError (public exception contract survives the flip).
- FLIP: `BeamLisp.Reader.enable_bl_reader()` wired into `BeamLisp.init/0` after the compiler `enable_bl_backend` block. Idempotent; forces :genesis while interning reader.bl's own source (language never reads its tail half-built); degrades to :genesis on failure (never breaks boot). Escape hatch: `:reader_backend :genesis`.

GATE = differential corpus (strongest): every priv/**+test/bl/**+examples/** .bl file, read position-bearing by BOTH readers and byte-compared. 421/421 identical, 0 DIFFS. Plus reader_position/parity/atom_guard/cutover suites + wave14_reader.exs, all green under the flipped boot.

PERF: reader.bl was 27× genesis; simple opts closed per-token categories to 3-7× (symbols 7.4×, strings 3.7×), structural categories (lists/nesting) stay ~18-20× (cost is read-until recursion + per-node position wrapping, not token scanning). Opts: (1) take-token via :string.cspan over hoisted codepoint charlist; (2) tuple-free advance-to (integer accumulation, one make-pos); (3) deleted to-list waste in chars->string/whole-number. Every opt parity-proven against the corpus.

KEY TRAP (cost a real bug): since source positions landed, EVERY list node is `{:meta …}`-position-wrapped. Any tree walk that dispatches on node tag (e.g. rewrite-fn-arg for #() literals) MUST have a `:meta` clause that recurses inside and re-wraps — else it silently skips the whole subtree. reader.ex's rewrite_fn_arg has this; reader.bl's lacked it → `%` inside nested (fn) in #() stopped rewriting. Corpus missed it (no file nests % in #()); only wave14_reader.exs caught it, and only once the flip routes it through reader.bl. Lesson: the corpus is necessary but not sufficient — unit tests that exercise rare grammar under the FLIPPED backend are the second net.
