beam-lisp `concat` crashes (CaseClauseError "no case clause matching" in `BeamLisp.RT.concat_from/1`, rt.ex:681) when one of its seqs is a LazySeq whose thunk body returns a bare LazySeq (not a cons cell / nil). Root cause: `BeamLisp.LazySeq.realize/1` normalizes only `[]`→nil, Vector→list, Set→list; a thunk returning a bare LazySeq passes through, and `concat_from`'s `case LazySeq.cell(s)` only matches `nil` and `[h|t]`.

Minimal repro:
```clojure
(println (reduce conj [] (concat (lazy-seq (concat (lazy-seq (list 1)) (list 2))) (list 3))))
```
Observed: CaseClauseError (unmatched bare LazySeq, printed `(1 2)`). Expected: `(1 2 3)`.

Found via jank fixture slice_44_for (nested `for`): its `(concat fs# (giter (rest gxs)))` produces exactly this shape. Blocker for nested `for` in beam-lisp. Fix location: LazySeq.realize should also unwrap/normalize a bare LazySeq result.
