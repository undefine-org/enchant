## The failure

Wrote an 8-page design doc (docs/edn-spacetime/self-evolution.typ, verse 143393f5)
naming two "gaps" in a self-evolution loop. Both were already solved in the repos.
User's reMarkable annotations caught all of it.

**Gap A — "no stable identity, so a program can't say THIS construct becomes THAT."**
Already solved twice:
- `verse/stdlib/migrations/entries/*.st` — `%rewrite name { %drops(...) %match {...} %into {...} }`,
  the template language, written IN Spacetime, as data. `src/migrate.rs` (1879 lines):
  `instantiate_template`, `plan_file_apply`, `render_pending_hunk`, `write_apply_plans`.
  `FileApplyPlan { old_source, new_source, changed, content_hash }` — the diff IS the
  log record, with a staleness guard.
- `beam-lisp/priv/optics.bl` — self-hosted van Laarhoven optics: `in` `idx` `traversed`
  `filtered` `optional`, `*>` composition outside-in (Specter order). Plus
  `examples/optics.bl` and `test/bl/optics_test.bl`. `compiler.ex`/`rt.ex`/`reader.ex`
  carry Specter comments.

**Structural addressing needs no identity.** A template says what SHAPE to match; an
optic rewrites every match. Nothing is REFERRED to, so nothing needs a stable name.
The diff is the audit record. Identity solved a problem the addressing model lacks.

**Gap B — "verification is advisory."** Same error one level down: structural rewriting
is verifiable by construction; the plan carries old+new source.

Also invented syntax in a doc arguing "the grammar is data, read the registry":
wrote `@data user from /api/user;` and `@set expanded = true` — `@set` HAS NO %form.
Real: `@data fetch $name:binding $type:typeref? : $src:expr ;` and `$pane <- "list"`.

## Root cause

Ran ~15 verification calls on things I BELIEVED (FormMatch fields, absent stable-id,
contract_hash_of, fence) and marked them `#verified[]`. Never once searched for what
ALREADY SOLVES THIS. The guess-gate caught claims and missed framing.

Worse: I had written, THAT SESSION, in `src/syntax/registry.rs:266`: "`%match` patterns
(migration rules) are FormClauses built by the same code, but their optionality means
something different — what to MATCH, not what a form permits." I edited the line naming
the exact mechanism and drew no conclusion. Evidence in hand ≠ evidence consulted.

## The rule

Before designing a mechanism, search for the mechanism:
1. grep the repo for the CAPABILITY (`%rewrite`, `optics`, `migrat*`), not just the
   absence you suspect (`stable_id`, `node_id`)
2. `ls` the sibling dirs — `priv/`, `stdlib/`, `examples/`, `test/` — read what's there
3. re-read your OWN comments from this session before treating a question as open
4. verifying "X is absent" is worthless until "is X needed?" is asked
5. an example in a doc about a grammar MUST come from that grammar (grep `%form`),
   never from memory

`#verified[]` on the claims made a doc with invented syntax and a fabricated gap LOOK
checked. Rigor on details is camouflage for an unexamined frame.
