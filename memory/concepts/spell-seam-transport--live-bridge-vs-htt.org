The spell chat page's conversation is stuck in static-serve mode by construction: the emitted seam declares `@host $chat : live("SpacetimeLvWeb.ChatLive")`, so `$send()` compiles to `doLiveRequest` which requires `window.__stLiveBridge` (a Phoenix LiveView hook from verse's spacetime_lv app). No bridge → Promise rejects "live bridge unavailable" → nothing consumes the send. Two exits: (1) mount verse's spacetime_lv Phoenix app as the transport (heavy: second app, and ChatLive doesn't even exist there — only counter/board/signup); (2) verse ALSO supports `@host $chat : http(url)` → `doHttpRequest` → plain fetch to `host.url + target` via `window.__stHosts` — so beam-lisp can answer the seam with plain HTTP endpoints (Bandit already a dev dep), no Phoenix. The two-step (beam-lisp emits files, python http.server serves) exists because Live driver (lib/beam_lisp/spell/live.ex) only publishes files + report.json; it has no HTTP request handling. Static serving from beam-lisp is trivial; the real missing piece is the seam's server half.
