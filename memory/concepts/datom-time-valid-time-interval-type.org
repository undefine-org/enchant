beam-lisp's datom.time gained a VALID-time axis (tempo/ex_tempo maximalist), complementing its existing transaction-time filters (as-of/since/history). Design + impl:

REPRESENTATION: a temporal value is a bounded half-open interval [from,to) at a resolution, stored as :db.type/time — a VALUE type (defrecord Interval {:from :to :resolution :calendar}), NOT an entity-with-datoms. from/to are integer SECONDS on one monotone proleptic scale (civil-day arithmetic, Hinnant's days-from-civil), so Allen's algebra + set ops are integer comparison. This mirrors priv/datom/vector.bl's choice: a value type + packed shape for storage/meaning/safety, never the :db.type/term lane (which round-trips but forfeits range-scan, fixed-width column, validation).

KEY FILES: priv/datom/time.bl (valid-time library appended after the tx-time fns), priv/datom/schema.bl (:db.type/time in VALUE-TYPES + structural valid-value clause — schema is a LEAF, checks structurally, never imports datom.time), lib/beam_lisp/reader.ex (accept STRING after a data-reader tag, so #o"..." works like #inst), lib/beam_lisp/rt.ex (data_reader_default("o") for first-boot bootstrap, same pattern as #d).

GOTCHAS HIT: (1) year-of on pre-epoch (negative) seconds needs FLOOR division, not quot (truncates toward zero) — off-by-one in mask expansion. (2) closed interval A/B is [from(A), from(B)) — the end point is EXCLUSIVE its START per EDTF, not to(B). (3) index-of is a STRING fn (byte offset of substring), NOT vector member-search — use a rank map. (4) minikanren run takes a SINGLE symbol q not a vector: (run n q goals). (5) map-form datom transactions need explicit :db/id. (6) scalar find [:find ?x .] and collection find [:find [?x ...]] are UNSUPPORTED — use vector find + (map first ...). (7) datom default (map) store holds raw bl terms; value-codec/redb is a separate durable path, so a defrecord round-trips with zero codec work (ESC-lane-first, like the DVec).

ENGINE BRIDGES (all LIVE, already ship): masks/one-of enumerate via minikanren disj* of === goals; overlap 3-valued verdict + chronology consistent? via z3/check (sat/unsat). z3/open exists, no z3/close (GC).

DEMOS: examples/datom/time/00-README + 01..08, all run green. TEST: test/bl/datom/time_valid_test.bl 39 assertions.
