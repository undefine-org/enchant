An embedding per function is one more fact — `[?e :fn/embedding ?v]` — in the
same conn as `:fn/name` and `:call/callee`, so similarity is a datalog clause
(`[(similar-to :fn/embedding ?q 10) [?e ?score]]`) that joins with the call
graph and the type facts. No vector database, nothing to keep in sync.

MODEL. `minishlab/potion-code-16M-v2` — Model2Vec *static* embeddings: 16M
params, 256-d, 32 MB fp16 on disk, ~84 MB resident (64 MB of it the f32 matrix
in the NIF). Not a transformer: an embed is token lookup + mean, so 159 000
characters of real beam-lisp source embed in 306 ms (1.7 ms/function).
CoIR NDCG@10: 39.1 static, 42.3 BM25, 43.4 hybrid — so it is a COMPLEMENT to
grep, not a replacement, which is why it is an optional clause.

NATIVE BOUNDARY. `native/code_embed` (rustler, `defnative`) holds the matrix in
a resource, so the weights are never BEAM terms. A batch crosses once as packed
little-endian f32 — already the shape `datom.vector`'s `DVec` stores — so the
rows are sliced straight into vector bodies.

OPTIONALITY. The weights are downloaded (`mix beam_lisp.embed.fetch`,
sha256-pinned) into `$BEAM_LISP_MODEL_DIR` or `$XDG_CACHE_HOME/beam_lisp/models`.
`available?` answers whether it can run; `require-model!` raises with the token
`code embeddings unavailable`, which `reload.ward` classifies as an absent
optional dependency → SKIP, not failure. Requiring `code.embed` loads nothing
(the handle is a `delay`).

WHERE. `priv/lib/code/embed.bl`, `priv/lib/code/semantic.bl`,
`lib/beam_lisp/model.ex`, `examples/code-semantic/`,
`test/bl/code/semantic_test.bl`, `docs/code-semantic-search.md`.
