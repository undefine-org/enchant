** ITEM Core Erlang raw stacktrace: element(2) for normalize, raw wrapper for raw_raise

Core Erlang c_try E-vars bind {class, reason, RAW-stacktrace}. The raw stacktrace is a wrapper tuple `{_, frame_list, _}` — NOT a plain list. Two rules follow:

1. `Exception.normalize/3` (Elixir) wants the FRAME LIST: unwrap with `:erlang.element(2, raw)`. Passing the wrapper builds a fieldless `%UndefinedFunctionError{module: nil}` whose message degenerates to "undefined function" — losing the module name (broke ward's optional-dep skip on "module Bandit").

2. `primop raw_raise(class, reason, stack)` wants the RAW WRAPPER. Passing the unwrapped frame list SEGFAULTS the BEAM VM (primop does not validate). This crashed `mix test` at wave6_errors "typed catch falls through and re-raises".

Also still true: `erlang:raise/3` as a plain call from :from_core-compiled code RETURNS :badarg instead of raising; the remote must be intercepted and emitted as the raw_raise primop, and a MODULE-LEVEL fun containing raw_raise needs a `[function: {name, arity}]` anno (via cerl:set_ann) or it degrades to a returned :badarg. Nested funs are unaffected.

Elixir's own compiler handles this by rewriting __STACKTRACE__ reads to element(2, raw) and raise/3 calls to raw_raise with the raw form — mirror exactly that split.
