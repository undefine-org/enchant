PLAN-057 extended ward (the beam-lisp warm/isolated pure-bl test runner) from "runs tests" to "verification substrate", in three waves. Grounded in verified substrate facts, with a strict two-tier honesty rule.

TIER SPLIT (the load-bearing honesty constraint): Tier A = structured expected/actual/form/context per failing assertion — universal, no z3, always available (run_ns already returns :reports; ward just had to stop discarding them). Tier B = an SMT verdict (repair-process guard, or upgrade-safety) — powerful but NARROW: only for stateful-process forms (defserver, lowered by model/system-model) AND only when z3 is present. When Tier B cannot run (non-process, no-z3, unmodellable) it degrades to Tier A / :unknown, flagged — NEVER a faked proof. A proof you could not run is not a pass.

W1 diagnostics: ward result carries :reports (fail/error only); report renders per-failure blocks. diagnose-processes finds defserver forms in a FAILING file and runs sys/repair-process for the synthesized missing guard. z3-guarded (try (z3/open) (catch _ nil)); repair-process self-returns :checked false for unmodellable shapes.

W2 upgrade rehearsal: priv/reload/upgrade.bl verify-upgrade[old-src new-src] rides repair-process — the NEW version's ^{:invariant} must HOLD under every transition (:holds true) → :safe; a broken transition → :unsafe carrying the guard that fixes it; else :unknown {:reason :no-z3|:not-a-process|:unmodellable}. assert-safe-upgrade is the in-test verb, recording via BeamLisp.TestRT/record with BeamLisp.Env/current_ns. This proves a property no finite inputs can: invariant preserved for EVERY reachable state.

W3 live dashboard: ward run/run-sandboxed gained an OPTIONAL on-event callback (2-arity; default 1-arity unchanged — backward compat), fired {:phase :file-done :ns :status :result} per file via a guarded emit!. reload.monitor/render-ward-view renders a ward result as a hiccup tile grid (green/red-with-diff/amber-contained). tooling/test-dashboard.bl (in tooling/, first-class dev tooling — NOT examples/) is a pure-bl web server that runs a dir through run-sandboxed pushing a frame per file. Concurrency-sound because run-sandboxed prefixes namespaces per run.

GOTCHAS discovered: (1) FUP-013 — a real evaluable defserver REQUIRES an (init …) clause, but state-shape takes the init PARAM name as the state var, mismatching the handler's state binding → repair returns nil. So a defserver that BOTH runs as a test AND is repairable is currently blocked; Tier B fires + degrades honestly. (2) `File` as a bareword VALUE fails (undefined var); must use slash form File/read! / File/ls! or it silently breaks inside a spawn. (3) the `create` tool double-escaped quotes in a large bl file with inline CSS/JS strings — writing via a bash heredoc avoided it. (4) FUP-014 filed: ward --upgrade (git baseline vs working tree for CI) left out of scope per user steer.
