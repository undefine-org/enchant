beam-lisp wave 18: unlocked 7 more jank-compat slices (28 select-keys, 31 name, 32 namespace, 33 keyword, 50 flatten, 58 merge-with, 59 sort-by) → 58/64. slice 30 `set` remains gated on the reader `#{}` literal (reads as symbol `#` + empty map).

Key decisions:
1. Set type = `BeamLisp.Set` (struct wrapping Elixir MapSet) in lib/beam_lisp/set.ex. Struct-is-a-map hazard is real: EVERY `when is_map` clause in rt.ex must get a `%Set{}` clause BEFORE it (count/first/rest/next/seq/contains?/coll?/print_str/get/assoc). `map?` already excludes structs so set→false. `assoc` on a set raises (prevents silent field corruption); `get` on a set returns member-if-present (set-as-function).
2. `#{}` literals NOT wired (reader.ex is a separate owner). Sets built via `(set coll)` prim. Slice 30 needs: reader `#{` → `{:set, items}` datum + compiler `%Set{}` emission + set transients in transient.ex.
3. cpp/* interop: honest mapping. jank writes `(cpp/jank.runtime.name x)`; beam-lisp `Env.intern("cpp", "jank.runtime.name", &name_of/1)` etc — same qualified-name-to-primitive mechanism jank uses, upstream slices load unchanged. Also fixed `to_str` for `{:symbol, name}` → name (needed by keyword ctor's `(str sym)`).
4. compare = total order nil<false<true<numbers<strings<symbols<keywords<collections<other; sort uses stable Enum.sort with `<=0`. tree-seq realized (not lazy), sequential? excludes maps/sets/strings. conj map-entry `(conj m [k v])` for select-keys.
5. prelude gained key/val/some/complement. `some` must avoid `or`/`when` macros (they're defined later in core.bl) — use loop+if.
