** ITEM Extended priv/flow.bl with MULTI-RATE demand arithmetic (flat-transform + expand-stage/mapcat-stage). Key insight proven: a stage that changes the rate (expand: 1 in N out, or contract: 1 in 0 out) CANNOT forward demand 1:1 — it would overrun (expand) or starve (contract) downstream. Correct impl = a state machine {:buf :want :up-out :done?} that meters output to outstanding downstream demand, buffers surplus, pulls upstream in chunks only when buffer drains. This is what a channel fundamentally cannot model (a channel has no demand value to do arithmetic on). Proven by examples/clojure-compat/async-channels/09-multi-rate.bl: source 1..6 → expand×3 → filter even → consumer demand batch 2, produced 15 evens byte-identical to eager computation, expand stage never delivered more than the demanded 2 despite producing 3× internally. All flow examples (07/08/09) green. NB: running 3+ examples sequentially after editing flow.bl hits the 300s wall timeout due to cold AOT recompiles — run singly to confirm, not a regression.
