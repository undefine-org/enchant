** ITEM beam-lisp boot cost: the ~4-8s "slow load" is NOT datom (loads via AOT in ~150ms). It is BeamLisp.init() recompiling priv/core.bl (65KB, 152 defs incl 20 defmacro) from source on EVERY boot via Compiler.eval_string(@prelude). Root cause: (1) core.bl has no (ns …) head so AOT emits its defs into Ns.User.beam, never Ns.Core; (2) init/0 hardcodes eval_string(@prelude/@multi), never consulting AOT.ensure_loaded like Loader does for datom. PROVEN fix: add (ns core) head → AOT emits Ns.Core.beam with __bl_init__/0 → init/0 calls AOT.ensure_loaded("core") before source fallback. Measured: 6-8s → 18ms, all defns/macros/HOFs correct (inc=42, when=:yes, ->=12, map, reduce). CRITICAL SHADOW TRAP: mix compile.beam_lisp calls BeamLisp.init() (line 86) which via Link.defvar does Module.create(Ns.Core, ignore_module_conflict:true) IN MEMORY without __bl_init__, shadowing the disk beam within that VM (:code.which returns [] not path). Had to use `mix run --no-compile` to observe the disk beam working. Any fix must ensure init() prefers AOT so the compile-phase init() AOT-loads core rather than source-seeding+shadowing.

** ITEM beam-lisp AOT emitter rework (PLAN-036) COMPLETE & verified green: mix test = 1243 passed, deterministic. Boot 6-8s→1ms. OPERATIONAL GOTCHA discovered during verification: the cold AOT build (35 namespaces × 3 modules each = ~92 beams) takes ~6-7min and writes its Mix manifest ONLY at completion. Interrupting it (timeout/kill) leaves a PARTIAL ebin with NO manifest, so the next mix test runs against a half-populated beam set → nondeterministic UndefinedFunctionError failures (saw 30, then 49) as shims forward to body modules whose beams weren't emitted yet. The fix is operational, not code: let the cold build finish (run detached via setsid, poll patiently ≥7min) before testing. Once the manifest exists, incremental rebuilds are ~1s. Dev env stayed complete (92 beams) throughout; only test env kept getting interrupted. Symptom of partial build: `ls _build/<env>/lib/beam_lisp/ebin/Elixir.BeamLisp.Ns.* | wc -l` well under 92, and no _build/<env>/lib/beam_lisp/.mix/compile.beam_lisp manifest file. Also: `mix run -e` output is sometimes swallowed under app boot logs — write results to a /tmp file to read them reliably.
