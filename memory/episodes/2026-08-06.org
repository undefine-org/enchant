Implemented as Clojure's PersistentVector (32-way bit-partitioned INDEX trie: cnt/shift/root/tail + tail buffer), not a hash trie — the plan's "HAMT" name was imprecise; index tries are what vectors want, hash tries are for maps. Plan assumption corrected on contact: compiler.ex both constructs AND pattern-matches %Vector{items: tuple} by field, and compiler_test asserts eval("[1 2 3]") == Vector.new([1,2,3]) — so a fields-only rewrite was impossible. Design: items holds EITHER a raw element tuple (all vectors ≤32, i.e. Clojure's tail-only state, which is also exactly what literals produce) OR a tagged {:bl_vec, cnt, shift, root, tail} for >32. Dispatch disambiguates on tuple_size==5 ∧ elem(0)==:bl_vec ∧ cnt>32. to_list/Enumerable.reduce walk leaves in chunks, not nth-in-a-loop. BENCH (real, mix run): conj-build 100k 9219ms → 12ms (756×); random nth 100k 7ms → 13ms (~130ns/elem, the expected constant-factor cost of trie descent vs bare tuple elem).
