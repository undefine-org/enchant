#+title: A Cargo workspace through the normal native build

From this directory, use the checkout launcher:
#+begin_src sh
../../../bin/bl --cold run showcase.bl
#+end_src
The project env.bl selects rust/ as a complete source closure and
crates/engine as its Cargo member. The configured host transparently delegates
production to its build station. No Cargo invocation or backend option is
needed by the example.

The first run prepares and selects priv/native/workspace_demo.so, loads it
through artifact.workspace's ordinary defnative declaration, and prints JSON
containing answer=42 and supportMessage="workspace support is captured".

The identities deliberately differ:
- workspace source root: rust/
- selected member: crates/engine
- Cargo package: artifact-workspace-engine
- Cargo library: workspace_engine_nif
- BL publication alias: workspace_demo
- native BEAM host: Elixir.BeamLisp.Native.Artifact.Workspace

The member depends on sibling crates/support. That sibling uses include_str!
for support/answer.txt and support/message.txt outside both crates' src trees.
Change support/answer.txt to 43, then start a fresh invocation:
#+begin_src sh
BL_WORKSPACE_EXPECTED=43 ../../../bin/bl --cold run showcase.bl
#+end_src
Its answer must become43 and its selected immutable product must change.
Restore the file to42 after the experiment. Changing the sibling Rust code or
message support file similarly becomes part of the workspace snapshot. Each
invocation uses a fresh NIF host process; do not infer hot replacement behavior
from this showcase.

Cargo.lock is rooted at rust/, with registry entries/checksums retained from
native/bl_json/Cargo.lock and only the Rustler dependency closure. The workspace
package entries were assembled without running Cargo. Main-thread qualification
must confirm Cargo accepts this lock with --locked, then exercise actual Nix
production and the BL NIF call before treating this example as qualified.
