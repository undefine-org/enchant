# live — the browser proof

The headless `.bl` tests (`test/bl/live/`) prove the whole server-side loop:
render, diff, socket, auth, session, two-tab convergence. This directory closes
the one thing they cannot — **does a real browser apply these patches?** — by
driving a real Chromium with Playwright against the JS client.

## What it proves

1. **`client.spec.js` › real ops** — loads `priv/lib/live/client.js` into Chromium,
   mounts the fixture's first HTML, then applies the **exact patch ops the
   beam-lisp differ produced** (from `fixture.json`, generated by
   `gen_fixture.bl` — the same `priv/lib/live/diff.bl` the server uses). After each
   step the DOM's HTML is asserted equal to the server's rendered HTML. So the
   JS client is proven against the *real wire*, not hand-written ops:
   insert · move · text · remove all round-trip.

2. **`client.spec.js` › keyed reorder preserves nodes** — tags a DOM node, applies
   a `move` op, and asserts the *same node* survived the reorder (its marker
   rides through). This is the property a string diff structurally cannot
   achieve: a reorder moves DOM nodes instead of rewriting them.

3. **`connect.spec.js` › the socket lifecycle defaults** — the differ's client is
   only half of `client.js`: `connect()` also owns liveness. With a fake
   WebSocket (no server) it pins the defaults every shell relies on — a
   `["ping"]` heartbeat within `heartbeatMs` (30 s by DEFAULT, which is what
   beats the server's 120 s idle timeout in `web/upgrade`) and auto-reconnect
   after a close with no opts — plus the two opt-outs (`{heartbeatMs:0}`,
   `{reconnect:false}`), and the SESSION id (`live-sid`) that makes a reconnect
   RESUME the server-side session instead of re-mounting it: it rides on every
   socket URL and is identical across a reconnect, while a fresh `connect()`
   mints a new one. Against the pre-heartbeat client, the three default claims
   fail and only the two opt-outs pass — which is the point.

4. **`connect.spec.js` › navigation survives a reconnect** — the lifecycle claims
   above stop at the socket; this one ties the socket back to the DOM. A
   reconnect SWAPS the socket object, so every per-socket seam has to be
   re-attached on the new one. `__navigate` was not: it was attached once, to
   the first socket only. So on the socket a drop brought back, every in-app
   `<a href="/…">` was `preventDefault`'d and then dropped — the URL never
   moved, the page never repainted, nothing reached the wire, and the shell
   reported itself `live` throughout. Dead links, only after a disconnect, was
   the whole shape of the report. Against the pre-fix client this claim fails
   (the click sends nothing at all); the click handler now also refuses to
   `preventDefault` a link it cannot navigate, so the failure mode is a real
   page load rather than silence.

5. **`connect.spec.js` › a link clicked while the socket is DOWN still navigates
   on reopen** — claim 4 covers a socket that came BACK before the click; this
   covers a click DURING the down window. A navigation moves the URL bar
   synchronously (`pushState`) but the page only changes when the server
   receives the navigate event and re-projects. If the socket was not OPEN the
   frame used to be dropped (`sendFrame`'s CLOSED branch buffers only
   CONNECTING), so the URL moved and the page did not — and since a reconnect
   RESUMES the same server session at its now-stale route, the divergence
   survived the reconnect: only a full reload recovered. Navigation now
   CONVERGES — the desired route is buffered (`pendingNav`, last-wins) while the
   socket is down and flushed in `onopen`, so the page always catches up to the
   address bar. The test closes the socket, clicks a link while CLOSED, asserts
   nothing was sent, then waits for the same-closure reconnect and asserts the
   reopened socket receives the buffered navigate. Against the pre-fix client
   the reopened socket never receives it (the frame was dropped at click time).

6. **`repl.spec.js` › shipped REPL workspace** — serves the actual
   `priv/std/vm/repl/page.html` and vendored CodeMirror bundle to Chromium with
   a protocol-shaped fake socket. It checks the starter prompt, balanced
   evaluation via Run and Enter, busy/Stop/interrupted states, disconnect
   without losing a draft, doc replies interleaved with eval results, and a
   320px layout without horizontal overflow.

7. **`mount.spec.js` › the server-rendered page survives the socket** — the
   socket's `["mount"]` replaces the first paint. Text typed, boxes ticked,
   options picked, the focused field and its caret survive it (matched by id,
   else name, else child path); a restored field the view binds re-sends its
   value so the session agrees; `<html data-mounted="1">` marks the mount.
   Against the pre-fix client the typed values come back empty. And live's
   `["style"]` rules go INTO the page's `<style id="live-style">` (the SSR
   sheet, where the app's `:shell` placed it), or before the first stylesheet
   when there is none — never after the app's own sheet, which used to lose to
   live's base reset on source order.

8. **`connect.spec.js` › a refusal is a DOM event** — `["denied", why]` used
   to reach only `opts.onDenied`, so a shell that passed none (live.app's
   default) swallowed refusals. It is now also `live:denied` `{why}` on
   `document`, beside the callback.

9. **`connect.spec.js` › one bad op does not sink a patch** — an op that
   throws used to abort `applyPatch`, losing every later op in silence. Each
   op is guarded: the rest lands, `live:patch-error` reports the failures, and
   the client sends `["remount"]` (once, until the mount arrives) so the page
   converges. (`client.spec.js` › the tbody-less table is the case that made
   ops throw: the parser's `<tbody>` is now part of the model.)

## Run it

```sh
# 1. regenerate the fixture from the real differ
bl run test/browser/gen_fixture.bl > test/browser/fixture.json

# 2. install the Playwright test runner matching the cached browser
cd test/browser
npm install --no-save @playwright/test@1.62.0

# 3. run against a real Chromium
PLAYWRIGHT_BROWSERS_PATH=~/.cache/ms-playwright npx playwright test
```

Expected: `17 passed` (3 differ + 9 lifecycle + 5 REPL workspace).

## Why not Phoenix here

`beam-lisp` is the language repo; the Phoenix/LiveView transport lives
downstream (the spell `:interface` app). This proof needs neither — it exercises
the client and the wire directly, which is exactly the seam a downstream host
would wire to a channel. The server half (mount → patch push → event) is proven
in `test/bl/live/socket_test.bl`; this proves the client half in a real browser.
The two meet at the JSON op protocol, which `interop/->json` serializes and this
test replays.
