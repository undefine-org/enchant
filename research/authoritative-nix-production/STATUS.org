* Verified controls

The per-crate identity control in
scripts/tests/test_native_product_derivations.py passes using actual Nix
derivations for all six server crates. Application edits and ignored target
outputs leave identities unchanged; a Rust edit changes only its own crate;
an additional source input changes only the affected crate.

The prepared-input Source control passes nine assertions. It consumes an
existing immutable native product without invoking preparation, and refuses
ABI mismatch, executable-bit changes, additional inputs/directories, symlinks
and mutable set roots. The recorded driver, execution log and result belong
to that narrow component run, not the full acceptance gate.

A real Nix KVM worker control succeeds with 512 MiB guest RAM, zero swap and a
finite disk-backed build directory. The real bl_json Rust product also builds
inside a 3072 MiB guest, observing 3045996 KiB RAM and zero swap. The manifest
and worker control are recorded alongside this file. These qualify the tested
worker configuration, not every future recipe revision or full SDK production.

* Host and remaining qualification

The daemon has unlimited aggregate memory, use-cgroups=false and max-jobs=16.
The user cannot apply the proposed administrator change. Therefore worker
resource isolation uses Nixpkgs vmTools.runInLinuxVM with fixed guest RAM and a
finite scratch disk. The configured KVM builder successfully realizes these
workers through Nix without operator SSH or sudo. Client cgroup limits alone
are not worker limits. Aggregate admission and cancellation/retention controls
remain explicit work; arbitrary parallel VM realizations are not qualified.
