* Requests, jobs and product verifiers
[[../../priv/build/artifact-jobs.bl][artifact-jobs/submit!, status!, events!, cancel!, recover!, await!]] is the
Source client for the packaged [[../../nix/preparation-operation.bl][fixed preparation dispatcher]]. The Rust
client uses the same packaged command protocol. A request contains enumerated
native/application/SDK data, not caller expressions, commands or environment
maps. Public SDK-family products are sdk, compiler, dependencies and bl-drop;
coordinator is an internal bootstrap recipe product, not a public dispatcher
operation. Framework HOME/user-manager identities come from startup context.

Dispatcher submit! binds operation bytes, private directory identity and pinned
coordinator in handle.json. Foundry owns ledger state, detached managed worker
identity and lifecycle. Status/events are observations. Cancellation checks
actual managed worker identity; recover reconciles that identity rather than
adopting a persisted arbitrary PID/PGID. Neither a successful status nor a job
receipt authorizes namespace execution or output publication.

Dispatcher worker! realizes a fixed trusted recipe remotely and verify-output!
checks the selected product kind before recording result.json. Independent
frontend verifiers still run afterward:
- Native: [[../../priv/build/artifact.bl][artifact/verify!]] and [[../../tooling/drop/src/nix_artifact.rs][Rust verify]].
- Application: [[../../nix/application-inventory.py][application-inventory.py verify]], followed by AOT unit authentication at
  [[../../priv/std/application-product.bl][application-product/select!]].
- SDK/release: [[../../scripts/prepare-checkout-sdk][prepare-checkout-sdk]] selection/coordinator checks and
  [[../../priv/build/artifact.bl][artifact/verify-release!]] for portable release publication.

The manifest remains provenance/data. BL host admission, source invocation,
unit verification and execution grants retain their original authorities.
Rust v2 consistency checks do not independently parse TOML or prove compilation
causality; the pinned fixed recipe owns Cargo package/library selection.

The SDK bootstrap clears active-job after observed failed/cancelled/interrupted
terminal state so a later ordinary invocation can attempt again. It preserves
old job directories and roots. Deadline/unknown states keep active-job for
reconnection. No automatic live-consumer root pruning or general GC policy is
claimed. Rooted-deletion refusal is a narrower positive control than complete
consumer-crash/GC-race qualification.

All normal target realizations use remote-only Nix scheduling (--max-jobs 0).
Client cgroup limits bound clients, not aggregate remote worker memory. Fixed
[[../../nix/bounded-build.nix][bounded-build.nix]] KVM recipes and [[../../nix/artifact-host.nix][artifact-host.nix]] policy address
separate worker/host concerns; evaluated module policy is not a host deployment
receipt. See STATUS for the actually observed station and per-control bounds.

* Workspace declarations and actual consumers
[[../../priv/std/bl/native-declarations.bl][bl.native-declarations/normalize, discover!]] supplies the shared data
contract used by [[../../priv/std/bl/env.bl.md][bl.env]] and normal discovery. An explicit declaration is:
#+begin_src clojure
{:build {:native [{:source "rust" :member "crates/engine"
                  :package "artifact-workspace-engine" :crate "workspace_demo"
                  :abi "beam-lisp-native-workspace-demo-v1"}]}}
#+end_src
This expands to closed native v2 request fields
version/source/member/package/crate/abi/target. Cargo package selection, actual
Cargo library and BL alias remain separate. Legacy path/glob declarations use
the compatible v1 path. Normal frontend behavior has no backend opt-in.

[[../../nix/native-source.nix][native-source.nix]], [[../../nix/native-snapshot.nix][native-snapshot.nix]] and [[../../nix/native-workspace.nix][native-workspace.nix]] capture
and validate the root lock, selected package, reachable path dependencies and
support bytes; unused invalid TOML fixtures need not be interpreted as active
packages. [[../../nix/native-artifact.nix][native-artifact.nix]] uses fixed locked package selection and records
member/package/cargoLibrary while publishing lib/<crate>.so.

[[../../priv/std/application-product.bl][application-product/prepare!]] includes full declared native source roots in
the application snapshot and projects canonical native-products relative to
project root. [[../../nix/application-artifact.nix][application-artifact.nix]] prepares that selection and
[[../../nix/application-worker.bl][application-worker.bl]] supplies admitted prepared native inputs to the same
normal build path. Runtime refresh hashes support closure changes and exact
alias/member/package/ABI selection; it does not borrow consumer declarations
for the platform root. Generated target/.git/.bl state is excluded. Traversal
is bounded after legacy discovery; glob expansion itself is not separately
prebounded. Actual selected source directories reject unsafe root/symlink scope.

The real example is [[../../examples/artifacts/workspace/README.org][examples/artifacts/workspace]]: sibling support crate,
include_str! support inputs, package artifact-workspace-engine, library
workspace_engine_nif, alias workspace_demo and ordinary defnative invocation.
The source-only fixture is separate from generated native selections/caches.

* Replay, impact and execution authority
[[../../priv/std/artifact/impact.bl][artifact.impact/explain, explain-files!]] compares provenance and selected
bytes, including v2 member/package/library identity. Its explanation is a pure
report. Equality or differences do not establish runtime compatibility,
execution grants, test qualification or code activation.

[[../../priv/std/artifact/replay.bl][artifact.replay/capture!, validate, plan!]] captures bounded immutable test
inputs and recorded identities as closed data. [[../../priv/std/artifact/replay-runner.bl][artifact.replay-runner]] observes
actual SDK/runtime/tools, retains closures, checks capture correspondence and
runs selected explicit .bl files through [[../../priv/std/bl/test.bl.md][bl.test]]'s existing isolated test path.
Outcome and qualification records attach to observed aggregates; capsule fields
do not become commands or execution grants. Strict [[../../priv/std/artifact/json.bl][artifact.json]] parsing and
private no-overwrite publication bound machine inputs. Product retention does
not prove the selected tests activated/consumed its compiled code. Data-format
support for literate/ExUnit selections is broader than the live .bl receiver.
