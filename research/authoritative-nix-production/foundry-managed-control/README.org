#+title: Foundry ledger with a managed artifact worker

* Recorded component experiment
These files preserve the exact local experiment, including its SDK/store
addresses and workspace paths. They are evidence fixtures, not an installation
script. inputs.json freezes the Foundry commit and relevant source hashes.
The Foundry checkout itself was not modified.

The existing deployment-runner submits a real native realization, stores its
job/events and deduplicates repeated submissions. A worker wrapper requests an
explicit cold SDK invocation inside its own systemd service. It supplies the
working directory and the closed non-secret worker environment explicitly;
services do not inherit those settings from the submitting process.

The submitting VM exits while the job is running. Its containing service exits
successfully after23.910 seconds, 129.7 MiB, zero swap (parent.log). The worker
continues compiling Rust on the build station, finishes successfully and keeps
its own Nix result root. A fresh VM reconnects through the actual Foundry status
and event APIs, confirming success and retention in1.168 seconds, 126.4 MiB,
zero swap (observer.log).

unit-properties.txt records the active worker's actual service: MemoryMax=2G,
MemorySwapMax=0, RuntimeMaxSec=240 and KillMode=control-group. Its MainPID matches
the worker PID in the durable ledger. The remote native producer separately
reports its bounded3072 MiB KVM guest and zero swap in native-product.json.
These are different execution domains; a client service does not constrain the
remote daemon's aggregate workers.

* Failures that informed the integration
The unmodified worker invocation attempted a warm realm and failed with a
vm-manager noproc error. An explicit --cold invocation completed the real Nix
job and deduplication control in25.788 seconds, 663.2 MiB, zero swap. The native
transport does not read the legacy BL_DAEMON environment flag.

The first managed wrapper omitted the service's working directory and Source
search-path environment. The worker could not find deployment-runner. The
recorded wrapper fixes both without inheriting arbitrary caller variables.

A separate attempt using Nix --rebuild with max-jobs=0 refused with local builds
disabled. The successful disconnect experiment instead declares a fresh native
source input and realizes it normally on the station. Application force
production now has its own qualified normal-realization request; see the
application-force receipts.

* Integration obligations
- Package this pinned Foundry ledger closure and a verified coordinator runtime;
  distinguish that runtime from the target SDK. Keep compiler/SDK worker
  platforms independent so SDK preparation does not depend on itself.
- Add an artifact-specific managed worker adapter to Foundry. Keep the explicit
  cold invocation, closed environment and actual service containment.
- Submit one durable preparation operation per requester, with separate result
  roots. Let Nix share producer realization. Qualify independent cancellation,
  escaped descendants, restart/recovery and retention before normal routing.
- Keep preparation separate from claimed output publication. Stored job JSON
  supplies observations and requests, never language execution authority.
- Wire normal native/application/SDK preparation only after those controls pass,
  then qualify the combined SDK and update the execution writer inventory.

The experiment establishes real ledger reuse, detached containment, requester
exit/reconnection and retention. Cancellation isolation, crash/GC races and
production routing remain open. The semantic session remains paused.
