#+title: Bounded pages and structural guarantees: implementation plan
#+date: 2026-10-26
#+status: Proposed implementation; no application changes or rollout performed

* Objective and baseline

Make Backdesk pages small, deterministic projections over authorized immutable
data, and make the ordinary Beam Lisp authoring path reject or bound the
mistakes identified in the [[file:PAGE-WIRING-AND-DATOM-AUDIT-2026-10-26.org][30-item audit]].

The [[file:../evidence/page-wiring-audit-2026-10-26.json][isolated probes]] establish excessive candidate work in the current Guests
path:100/1000 conversations return100/1000 query candidates and process300/3000
profiled store rows for40 displayed rows. They do not establish a full-page
latency ratio. The native readiness probe exceeded240seconds; its cause remains
to be separated into loading, compilation, store preparation and actor startup.

The pinned53aeb399 artifact is absent on this workstation. The default =bl=
rejects the current loading configuration. The retained experimental SDK has
served the narrow probes, but is not an implicitly approved replacement.
Upstream was inspected through =f85743b1= with ongoing unrelated build work;
record exact source bytes again before implementation. Preserve existing WIP.

This plan supersedes no hotel authority, consent, PMS, disclosure, uncertainty
or delivery contract. It refines the page/read-model portions of
[[file:STRUCTURAL-REPAIR-PLAN.org][the structural repair plan]] and complements
[[file:HARDENING-AND-NATIVE-TESTING-PLAN.org][the existing hardening/testing plan]]. Do not duplicate their money, transport,
mode-policy or test-framework work in a competing implementation.

* Target design

#+begin_example
Composition owns stores, execution journals, clocks and provider capabilities.
    |
Authenticated HTTP/socket identity
    -> captured hotel basis + explicit independent journal bases + explicit now
    -> authorized page query, admitted order and bounded storage work
    -> selected IDs -> bounded, access-checked batch hydration
    -> feature read model
    -> deterministic screen -> Live realization/diff -> browser patch

Gesture -> typed existing command admission -> original durable receipt/effect
        -> Datom publication -> Live projection
#+end_example

The hotel database remains authoritative. Read projections may cache or derive
facts, but cannot become a second command or authorization authority.

Proposed responsibility boundaries, not a new framework:

#+begin_example
reception.application         owned composition and public read capabilities
reception.web                 thin compatible entry and Live app factory
reception.web.routes          route/capability declarations
reception.web.session         HTTP/socket principal policy
reception.web.http            existing commands, uploads, callbacks and webhooks
reception.web.assets          versioned static asset responses
reception.read.context        immutable bases, explicit time, authorization
reception.read.guests         list/search/page read model
reception.read.conversation   staff workspace and guest disclosure projections
reception.read.today          aggregates and bounded attention sections
reception.read.connections    public PMS/Meta/Instagram/capacity views
reception.ui.<feature>        pure screens and reusable presentation components
#+end_example

Retain existing module names as thin adapters only while real consumers migrate.
Remove adapters when their consumer inventory and equivalence checks close.
Loom components consume presentation values; procedure schemas continue to own
command validation. =live.app= continues to own the web transport. Desktop
=loom.surface= does not replace Live's keyed web reconciliation.

* Acceptance contract

** Correctness and authority
- No cross-property or cross-conversation disclosure, including through search,
  counts, raw pulls, cursors, caches, reconnect or changed permissions.
- One hotel basis per projection; independent journal bases are named explicitly.
  No invented atomic snapshot across independent journals.
- Query rewrites preserve ordering, tie-breaks, audience, active membership,
  unknown-versus-clear, consent and original receipt/basis semantics.
- Rendering cannot acquire resources, perform commands, acknowledge delivery,
  launch OS processes, sample randomness or read ambient time/configuration.
- Unknown provider outcomes retain their original identity. Navigation and
  reconnect never silently repeat a mutation.

** Bounded work and visibility
- Every ordinary page read declares limits on rows, seeks, bytes and returned
  entities. Bulk export/admin work is a separately declared operation.
- Page-size40 means bounded page work, not40 rows after reading everything.
  Search, exact totals and active membership have their own explicit plans.
- An unsupported or exhausted query reports its actual refused/incomplete state.
  It cannot silently fall back to an unlimited scan or report an empty success.
- For a fixed visible page, add10x/100x unrelated same-property history and
  foreign-property data. Costs must remain within the declared envelope, or the
  supported read plan must explicitly refuse. Record real store rows and seeks.

** Proposed latency targets
- Ready-instance initial usable page: under2seconds.
- Warm navigation: p95 under500ms for the declared reference dataset/host.
- Local browser-only interactions: under100ms.
- Packaged app readiness: under30seconds, excluding build/import/migration work
  that is separately measured and completed before publication.

These are acceptance targets, not achieved results or proofs of arbitrary host
latency. Establish exact dataset sizes, row fan-out and resource limits in Phase0.
Measure at least100 warm navigation samples per critical route; keep cold and
first-use samples visible. Server enqueue time does not include browser paint.

* Delivery phases

** Phase0 — Reproduce the environment and establish a baseline
Inputs: current source/WIP inventory, exact SDK identity, frozen synthetic data.

1. Restore the verified pinned artifact or qualify an explicitly selected
   candidate in isolation. Do not silently change pins to make a check pass.
2. Qualify the needed runtime surfaces in small groups: ordinary execution,
   native page entry, admitted paging, auth query contexts, incremental analysis,
   effects, Live deadlines, Veritas and literate source extraction.
3. Repair the lifecycle harness's missing fake DOM =matches= API. Separate its
   deterministic gesture checks from real browser acceptance.
4. Capture loader/compiler/store/actor readiness phases. Enable =live.measure=
   for worlds/screen/realize/diff/styles/serialize/queue, plus actual browser
   route application and Datom row/seek counters.
5. Freeze small, representative and growth datasets with original IDs and
   semantic expectations. Include foreign properties and long histories.
6. Inspect compiler emission-growth diagnostics on heavy UI functions before
   assuming query cost explains the cold-start delay.

Deliverables: replayable baseline drivers, runtime/source/dataset receipts,
phase timings, query plans and explicit unresolved blockers.

Exit gate: one real native page is measurable on an owned isolated instance;
basic tool capabilities are qualified. If runtime initialization blocks it,
fix/qualify that upstream boundary separately before making page-speed claims.
Keep ordinary source refactoring independent where it does not need that gate.

** Phase1 — Establish contracts and a small executable architecture gate
Depends on Phase0's source inventory; can precede successful full browser startup.

1. Specify record shapes for read contexts, feature read models, page results,
   route declarations, form-attempt state and diagnostic/evidence results.
2. Declare permitted dependencies: UI -> read-model data/presentation helpers;
   read modules -> immutable database/auth/query helpers; command/IO/lifecycle
   modules -> explicit capabilities. Identify trusted primitive leaves.
3. Extract compiler-resolved facts for the changed feature's dependency closure.
   Use =codebase= and =system.analyze=; do not require the entire code-MCP index.
4. Add Datalog boundary checks and effect/determinism checks. Unresolved edges,
   missing summaries or exhausted analysis budgets remain visible obligations.
5. Run existing =live.lint= on extracted executable source cells. Add targeted
   schema/component checks for namespaced IDs and declared route coverage.
6. Extend =bl check=/existing analysis plumbing rather than building a second
   parser, call graph, type lattice, effect registry or test framework.

Deliverables: documented interfaces, scoped coverage report, negative fixtures
and an initial gate in report mode for legacy code, strict for migrated entries.

Exit gate: deliberate render-to-owner, render-to-process, unknown dynamic call,
missing row key and duplicate-ID examples are detected or explicitly unknown.
A silent checker is never interpreted as a complete proof.

** Phase2 — Migrate Guests to bounded Datom reads
Depends on Phase1; this is the first complete vertical feature slice.

1. Separate list, active-membership, text/reference search and count queries.
2. Define stable order, tie-breaker and actual schema/index support. Inspect
   =datom/explain=, then measure =datom.profile= on the real store backend.
3. Use =q-page= for admitted cursor plans or =q-window= for supported numeric
   windows. Handle =:unsupported-plan=, =:rank-not-ready= and =:incomplete=
   according to their real contracts. Do not conceal an unbounded fallback.
4. For active/search shapes outside admission, implement a bounded native read
   plan or a causally maintained derived membership/search projection. Keep the
   existing canonical activity function as the semantic authority.
5. Select authorized IDs first, then batch only required fields. Derive latest
   messages, returning-guest context, insight freshness and processing state
   for those IDs. Exact counts remain separately budgeted.
6. Remove full property-world hydration and =d/indexed= from this route.

Deliverables: =reception.read.guests=, pure Guests screen, required schema
migration/backfill if any, real query receipts and differential fixtures.

Exit gate: all current list/search/activity semantics pass; changed permissions
invalidate cursor/cache authority; fixed-page growth is bounded; no owner call
or provider capability is reachable from the migrated screen. Partial search
support is not a completed Guests migration.

** Phase3 — Migrate staff conversation and guest disclosure views
Depends on Phase2's context/query/hydration contracts.

1. Query one conversation's authorized related facts directly.
2. Page the timeline with the existing sequence/timestamp/ID order and explicit
   older-history loading. Bound ancillary offers/work/retrieval sections.
3. Keep staff read models and guest disclosure read models distinct. A guest
   receives public parts and authorized choices, not the full hotel world.
4. Give messages/stays/operation rows stable Live keys and namespaced DOM IDs.
5. Preserve original browser-applied disclosure receipts as authenticated events;
   neither SSR nor a read-model build can acknowledge delivery.

Exit gate: private/internal/foreign data remains absent; historical ordering,
drafts, reconnect, consent and disclosure timing pass in the real browser;
new unrelated hotel history does not expand this conversation's page reads.

** Phase4 — Migrate Today and connection/settings reads
Depends on Phase2; use Phase3's shared components where appropriate.

1. Split Today aggregate facts from bounded rendered attention sections.
2. Share canonical attention, coverage, arrival and judgment inputs once per
   immutable read. Remove redundant discarded work after verifying its purpose.
3. Replace render-time =store/read!=, =store/custom!= and =communication/open!=
   in Meta/Instagram/capacity/settings with composed public read capabilities.
4. Capture all hotel reads from the same basis; expose each execution journal's
   independent basis and unavailable state explicitly.
5. Derive route-specific next visible deadlines for stalled work, freshness,
   activity expiry, guest state, Instagram and media using the existing clock.

Exit gate: Today retains unknown-versus-clear and exact blockers; an intentionally
held writer/provider operation does not block read-only page access; virtual
clock transitions render without artificial hotel writes or polling.

** Phase5 — Make rendering deterministic and form state explicit
Can start after Phase1; complete before final page/browser acceptance.

1. Replace per-label =date= subprocesses with qualified timezone-aware in-process
   formatting, preserving Morocco tzdata/Ramadan behavior. Share exact formatting
   results where appropriate; retain boundary tests around transitions.
2. Mint request IDs once when a form/attempt opens. Capture its original basis,
   payload and expected revision; rotate only for an explicit new attempt or
   confirmed completion. Password/file contents stay out of durable draft state.
3. Namespace field/label/form IDs by stable component/record identity; remove
   =document.forms= ordinal identity. Keep component identity distinct from
   request identity.
4. Choose one owner for each draft: Live locals/private session for appropriate
   non-secret state, browser-only handling for ephemeral secret/file values.
5. Remove global revision/basis attributes that have no remaining consumer,
   after inventory; do not remove command fences or disclosure tokens.

Exit gate: identical finite render inputs produce identical tree/HTML; unchanged
state produces no content patch; multiple inline editors retain independent
values through insert/reorder/navigation/reconnect; uncertain commands are not
resubmitted or silently retargeted.

** Phase6 — Consolidate UI, route and browser boundaries
Depends on the migrated feature interfaces; perform incremental feature commits.

1. Split =web.bl= and =screens.bl= along the target responsibilities. One route
   declaration supplies screen, access policy, HTTP/socket policy and capability
   requirements; preserve original403/404 and public callback behavior.
2. Introduce Backdesk presentation components built on =loom.ui=, =loom.box=,
   =loom.parts= and one brand token map. Adapt procedure schemas to fields;
   preserve domain schemas/validation as the single authority.
3. Make controller mount/update/dispose explicit and root-local. Replace broad
   JSON/controller reinitialization and document scans with targeted lifecycle
   handling supported by the existing client.
4. Consolidate command fetch/pending/outcome plumbing, preserving each typed
   endpoint's captured attempt and uncertainty semantics. Keep uploads/OAuth/
   secret operations at their required HTTP boundaries.
5. Serve versioned CSS/JS/fonts with tested cache policy; retain request-collected
   dynamic Loom styles. Isolate catalogue and synthetic fixture composition.
6. Inventory compatibility HTTP/Python/MCP consumers before retiring duplicated
   transports or reads. Delete only after their actual consumers migrate.

Exit gate: original user journeys and keyboard/phone layouts pass; no duplicate
route policy, business-rule schema, reconnect loop or revision poll is introduced.

** Phase7 — Promote proven patterns into Beam Lisp authoring guarantees
Start the scoped analysis work in Phase1. Final API design follows the real
Guests/conversation migrations rather than a speculative universal framework.

Implement the first structural avenues in the companion document:
1. Strict checked screen/read roles on the existing declaration/compiler path.
2. One canonical primitive contract source for types, effects, determinism,
   suspension and explicit ambient dependencies.
3. Checked bounded-page descriptors and access-aware selected-ID hydration.
4. Stable keyed component/form identity and form-attempt lifecycle primitives.
5. Obligations with exact source/SDK/policy/schema provenance and honest statuses.

Every mechanism needs an escape-path/unknown test, stale-code test and real
consumer qualification. A lint warning or user annotation is not native authority.
Extend existing analysis/Live/Datom mechanisms; do not create a parallel page DSL,
solver wrapper, ownership system or proof cache.

Exit gate: one second small non-Backdesk consumer demonstrates the same guarantee
without hotel-specific patterns. Malformed/opaque/unbudgeted examples cannot
enter the declared strict path without an explicit unresolved obligation.

** Phase8 — Optimize invalidation, caching and ownership from measurements
Depends on bounded reads and actual fan-out measurements.

1. Keep Live's ordinary complete subscriptions and ordered coalescing initially.
   Do not use rejected manual =:attrs= filters to disguise expensive projections.
2. If fan-out still dominates, design a supported scoped derived read-world or
   proved dependency seam. Cover authorization/revocation, all journal inputs,
   time transitions, retractions, reconnect and acquisition gaps.
3. Avoid recomputing a heavy =:worlds= context for deadline rearming: add an exact
   projection-context reuse contract upstream if measurement justifies it.
4. Key finite caches by complete immutable basis/view, principal/policy, query/
   schema, journal versions and relevant time/deadline inputs. Retain bounded
   memory accounting; prove invalidation or decline reuse.
5. Use owned subscription/timer/session lifetimes. Test journal replacement,
   detach/grace expiry, failed acquisition, shutdown and generation changes.
6. Replace broad periodic rediscovery only where causal scope wakes and deadlines
   have equivalent startup/recovery behavior; reuse existing worker authority.

Exit gate: suppressed invalidations have an explicit dependency justification;
missed-notification/restart tests converge; no leaked watcher, timer, socket or
provider work; no cache reuse can bypass authorization or source identity.

** Phase9 — Qualify, cut over and delete retired paths
Depends on the changed paths' previous gates, including exact SDK qualification.

1. Run focused pure/native query and contract regressions before expensive films.
2. Run seeded generated histories plus real process/browser failure checks.
3. Run100-sample warm navigation measurements, separate cold readiness, and the
   fixed-page growth matrix on the exact package/backend/resource configuration.
4. Compare old/new read results on the same frozen authoritative data. Read-only
   shadow comparison is allowed; commands/provider effects are never run twice.
5. Build a source-free package and qualify framework initialization, analysis
   modules, timezone/assets, ordinary entry and first real callback/browser frame.
6. Produce a source/runtime/schema/dataset-bound receipt with every required
   obligation's status, coverage, budgets, witnesses and replay command.
7. Apply the repository's existing runtime promotion/deployment policy only after
   qualification. Keep schema/read-model rollback compatibility and a retained
   previous package. Rollback never erases new authoritative business facts.
8. Remove retired full-world page adapters, duplicate controllers/queries/assets
   and compatibility paths whose consumers are proven migrated.

Exit gate: functional, authority, bounded-work and declared latency targets pass
together. Untested features, unknown proofs and startup failures remain open.

* Dependency order and commit shape

#+begin_example
P0 -> P1 -> P2 Guests -> P3 conversation/guest -> P4 Today/settings
       |       |                                  |
       +-> P5 determinism ------------------------+-> P6 consolidation
       +-> P7 scoped checks; stronger API design follows real feature slices
P2/P3/P4/P5 + measured fan-out -> P8 invalidation/lifecycle
all changed-path gates + exact packaged SDK -> P9 qualification/cutover
#+end_example

Each feature slice should contain its read contract, schema/backfill if needed,
implementation, removal of the replaced route read path, targeted negative and
equivalence tests, row/seek evidence and a short receipt. Keep cosmetic rewrites
separate from query/authority changes. Do not mix unfinished upstream build work
into these commits. No calendar estimate is reliable until Phase0 closes.
