#+title: Native conversation selection and mixed-kind qualification
#+date: 2026-10-26

* Executed counterexample
The first100-sample Chromium run after the deadline/cache fixes passed the warm
route targets and real draft/server-patch/reconnect checks, but its populated
All guests check was refused. The default active view contained zero rows, so
its timing alone could not qualify populated selection.

An owned direct native diagnostic found index readiness true and selection
=:native-scope-mismatch=. Both q-window and ordinary bounded q-page emitted
room-type identities with a nil order for this shape:

#+begin_src clojure
[:find ?e ?id ?order :in $ ?property :where
 [?e :hotel/property ?property]
 [?e :desk.conversation/order ?order]
 [?e :hotel/id ?id]]
#+end_src

The diagnostic observed41 returned rows, starting with room types, although
those records had no conversation order. This is an observed behavior of this
selected SDK/read-plan shape, not a claim about every Datom query or an assertion
that projected field presence universally supplies an existence predicate.
The existing boundary rejected the invalid result before hydration/disclosure.
No Beam Lisp implementation was changed.

* Product correction
All/search queries bind a dedicated =:desk.conversation/property= scope,
projected only for native conversation records. A matching scope/order composite
supports direct ordered seeks. Activity retains its existing typed activity
scope. Both are maintained transactionally and by owner reconciliation, with
semantic facet version2 and a source/facet checkpoint before page admission.

An initial literal =:hotel/kind "conversation"= correction fixed membership but
added a second bound scope. Inspection found the existing numeric rank planner
requires a single bound scope, so that shape would impair deeper pagination.
The dedicated conversation scope establishes membership independently of sparse
presentation projections, avoids unrelated-record search work, and retains the
single-scope native window plan. No runtime change is needed.

Before hydration, every admitted ID must have the same native eid, property,
kind and nonnil order value as the query result. A nil search projection refuses
rather than being passed to substring matching. Missing/stale evidence cannot
be certified by that value check alone; the captured checkpoint remains required.

Real seed and mixed-kind regression checks complement homogeneous conversation
fixtures. Warm/cold query results and populated browser views must be qualified
separately; a valid empty active view is insufficient evidence for All guests.
The initial failure remains in browser-final-r1.json for provenance.

* Structural implication
A scoped typed read contract must establish native membership independently of
its projected presentation columns. Source-level shape and an index checkpoint
alone cannot prove that a runtime adapter preserves query semantics. Keep an
executable mixed-kind/foreign-scope oracle, actual plan/metric evidence, and a
refusal boundary before turning these contracts into compiler/solver claims.
