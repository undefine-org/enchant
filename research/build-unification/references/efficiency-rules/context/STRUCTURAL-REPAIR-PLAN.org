* Decision
Keep Datom as the authority and native queue journals as the authority for
external work. Move UI reads to guarded, bounded, immutable projections. Stop
copying and repeatedly rebuilding the whole hotel as the normal interface
between these components. Replace repeated global repair with scoped causal
notification and native deadlines. Consolidate the remaining duplicate paths
after proving their callers and stored-data contracts.

A newer compiler cannot repair application access patterns by itself. The
v2026.8 distribution also has an independent compiler-inventory failure, which
must be fixed upstream before this application has a qualified AOT artifact.

This plan complements COORDINATOR-QUIESCENCE.org and NATIVE-RUNTIME-LIFECYCLE.org.

contains proposed work, not evidence that those defects still exist unchanged.

** Loader correctness: one actual namespace dependency cycle
The completed native =source-graph= scan (the same graph kernel used by
=codebase/require-cycles=) finds 313 distinct namespaces and one closed path:

#+begin_example
meta.instagram-login.readiness
 -> meta.instagram-login.publication
 -> meta.instagram-login.operation
 -> meta.admin-work
 -> meta.instagram-history
 -> meta.instagram-login.readiness

This is a verified source dependency cycle and a cold-loading/AOT hazard, not
proof that it caused any particular measured timeout. The focused function
index does not contain all five modules; use the whole-corpus graph result for
this finding, not an empty focused-subgraph cycle answer.

Concrete cut: extract shared operation schema, immutable fields and principal
identity predicates into lower-level data modules. Extract read-only original
publication/capability verification from the publication mutation module into
one proof reader. Readiness and history depend on that reader and state;
publication writes depend on operation orchestration and reuse the same reader.
The proof reader must not depend on admin-work, history, queue mutation or
provider execution. Move existing proof checks intact, including original
transaction, lease, principal, generation and receipt constraints; do not copy
or weaken them. A data/schema module must not import a coordinator merely to
obtain its schema. Gate: zero require cycles across the complete owned corpus,
plus independent cold loads in different orders with a clean cache.

** 1. The record-index fast path depends on physical heap sharing
=booking.domain/indexed= stores the entity map again at =:of=. =index-of=
accepts the index only if =erts_debug:same= says both maps are the same physical
term. That is not a stable identity for a value crossing actors or ETS.

The native v2026.8 probe =index-boundary.bl= uses the actual domain functions:
| Boundary                        | Index guard |
|---------------------------------+-------------|
| Local freshly indexed value     | true        |
| Real actor message round trip   | false       |
| ETS insert/lookup               | false       |
| Erlang binary round trip        | false       |
| Property filter used by renderer| false       |
| Explicitly reindexed filter     | true        |

The records remain correct through the fallback, so ordinary result-equality
tests do not establish that the index is used. The earlier top-level-var probe
already lost sharing before its positive control; the local-let positive
control above is the valid boundary experiment.
The existing =tests/runtime/world_index_test.bl= is weaker still: its base is
constructed with =reduce d/put= and never calls =d/indexed=. Its seven passing
checks exercise the scanning fallback, not the index fast path.

=reception.web/render-tree= additionally replaces the entity map when scoping
to a property, retaining the index for the old map. Every such render loses
the fast path even if sharing had survived to that point. The probe does not
measure how much of the observed UI latency comes from this defect.

Replacement: query typed native attributes, keyed by property/conversation,
with batched pulls. Pure derivations can use =datom/memo-by-basis= with a key
including the scope and every other non-db input. Its =db-revision= includes
the store, basis and historical/filter view. Never cache clock-dependent
results as if they were pure database facts. A full structural equality check
on the entity map would add another scan to each lookup and is not the repair.

** 2. UI reads wait behind arbitrary writer work
=reception.store/owner= serializes snapshot, execute and arbitrary custom
callbacks. =read!=, =run!= and =custom!= use infinite call timeouts. Snapshot
also carries a whole hydrated world, plans/capabilities and execution views.
Screens and settings routes repeatedly enter this boundary. One slow callback
can delay otherwise independent UI reads. Passing these large values between
actors also has copying costs.

Replacement: publish an immutable read context after committed writes, read
native databases/projections outside the command owner, and keep the writer's
critical section bounded. Capture related db values and their revisions
explicitly; do not pretend independent journals share one atomic basis.
Retain serialized authorization, expected revisions, transaction checks and
publication fencing. Bound reads and report busy/unavailable distinctly.
Writes need durable request identity and a completion lookup before introducing
timeouts; blindly retrying a timed-out write is not safe.

** 3. Small screens demand broad hydration and repeated scans
=booking.native-world/load-world= selects every hotel record, unpacks its
representation, hydrates typed fields and builds world indexes. =world-at=
starts with an empty cache. =refresh-world= rebuilds the derived index on
ordinary writes and reloads the full world on removals.

=reception.ui.screens/latest-message= filters and sorts all messages for each
conversation row. =reception.procedures.desk/find-guests= computes activity and
search context, sorts the full result, then takes 40 rows. Dashboard and
conversation helpers repeat per-conversation reservation, message, insight and
work scans. Existing native queries in those functions do not bound the
subsequent work over the hydrated world.

Replacement: one explicit read model per route; query page identities first,
then batch related messages, requests, stays and summaries for those identities.
Use =datom/q-page= only for its admitted indexed plans and handle budget/refusal
results. Use =q-window= where its qualified rank support is appropriate, rather
than hiding a full sort behind a new helper. Search and exact totals need an
explicit bounded/indexed design too. Aggregate dashboard counts independently
of rendering every record. Query and pull counts must follow the page, not the
total number of historical conversations.

The writer has the same scaling problem: =reception.store/transaction!= loops
over all messages, diffs the entire entity map, and queries all hotel IDs even
for a small mutation. Thus a page becoming cheaper does not automatically make
form submissions cheaper. Move commands toward explicit bounded native
transactions/changed identities, maintaining canonical field retractions,
reference resolution, derived guest state, expected-basis checks and the
idempotency/audit receipt in the same committed boundary. Verify these effects
before retiring the old world-diff path. This is a separate command migration,
not permission to remove correctness checks to shorten the critical section.

Pending communication attention also hydrates related entities per candidate.
Batch it without discarding malformed/foreign-peer evidence that is necessary
to detect ambiguous ownership. Faster reads must preserve the existing refusal
of uncertain participant alignment.

** 4. Polling repeatedly rediscovers work
=reception.goal-execution/coordinator= re-arms after each repair with a
one-second pause. Repair queries every conversation and invokes native
reconciliation for every scope. Communication runs its phase pipeline every
two seconds; knowledge scans for extraction work every ten seconds.

These loops already have some good ownership/coalescing properties: the goal
timer re-arms after work, communication yields between phases, provider work
already has native queue owners, and hotel reminders use actual deadlines.
Keep those guarantees while narrowing what triggers and constitutes a repair.

Replacement: =datom/listen!= with attribute filters or =datom.watch= with a
guarded query; coalesce changed scope identities; use existing
=datom.projection=/=datom.reconcile= enrollment and =proc.queue= journals.
Subscribe before initial reconciliation, and reconcile current state on reopen
so a lost notification cannot lose work. Keep infrequent bounded recovery
sweeps where required. Retry/lease/expiry use native queue or =proc.sched=
deadlines. The existing Meta progress subscription is a useful local pattern.

Native queues are at-least-once execution: moving work to them does not grant
exactly-once provider delivery. Preserve effect identity, uncertainty, fences
and authentic receipt settlement.

** 5. Native Live is wired to expensive, broad read contexts
=reception.web/app-value= ignores route params in =:worlds= and reads the
whole store snapshot. =:observe= includes several execution journals for every
authenticated route. Native Live reprojects on observed commits; it cannot
make an opaque whole-world reconstruction selective automatically.

Replacement: route-specific, already-guarded immutable worlds and explicit
small projection dependencies. The current Live =:observe= API is connection
level and has no attribute-filter option. Narrow connections where possible;
for attribute/scope filtering use native watches and owned read projections,
or make a separately qualified upstream Live enhancement. Do not invent an
unsupported option or a second browser patch protocol. Preserve authorized
guest membership and property/system-record visibility before handing a
screen any values. Retain mounted-browser delivery acknowledgments as events;
rendering itself must remain read-only.

Extend the existing pure =:clock=/=:deadline= integration to Today/guest time
transitions as well as Instagram/uploads. Keep real time outside basis memo
keys unless represented by an explicit temporal input/window.

** 6. Startup and failures obscure the boundary that failed
=reception.web/serve!= performs developer catalog initialization on every
non-live launch and derives a sibling Knowledger resource path from cwd.
Source execution, development catalogs, store opening/recovery, optional
providers and HTTP readiness are intertwined. Several catch-all paths turn
unexpected errors into generic unavailable/false/500 results. PID liveness
alone does not establish a worker is progressing or a projection is current.

The resource boundary also needs explicit inventory: domain/policy/migration
digests read relative =src/= or =packages/= files, procedure loading lists
=procedures/= relative to cwd, and signup/interaction code reads JS or literate
source files. Retaining implementation digests is useful; their bytes must be
declared release inputs and available through a deterministic package root,
or computed into an authenticated build product. A build passing inside this
checkout would not prove these resources work from a deployed artifact.
Root =env.bl= also resolves three source roots through =../knowledger/=. Declare
and package that shared dependency closure with pinned provenance; qualify the
artifact where the sibling checkout is absent. A dependency being reachable on
this workstation is not a release resource contract.

Replacement: one release entry and startup configuration, separate explicit
init/migrate/catalog tooling, packaged resources and a staged readiness report.
Resolve environment/mode/provider configuration once into an instance-owned
value and pass capabilities explicitly. Keep synthetic/live egress admission
at the existing transport boundaries; an available .env/API key must not choose
the execution policy. Eliminate process-wide =System/put_env= initialization
and duplicated mode decisions as each caller migrates.
Use the existing owned application/resource lifetime, instance-scoped process
identity and native supervision. Retain reverse-order joined shutdown and
unknown-effect recovery; replacing them with forced kill would regress the
existing lifecycle qualification. Record typed internal causes through native
diagnostics without exposing credentials, full worlds or stack traces to UI.

Specific current examples: =reception.pms-execution/settle!= catches every
settlement failure and returns the operation; this can leave provider-confirmed
state distinct from successful hotel publication without surfacing that cause.
=pms.operations/readback!= and submission convert every adapter exception to
=:uncertain= while discarding its cause. Uncertainty is the right conservative
effect classification after a possible write, but it needs a separate safe
diagnostic. =reception.contact-ingress-repair= similarly classifies every
exception as a business refusal. Preserve authentic provider outcome separately
from local publication failure; retry only the idempotent publication when its
fences still hold, and rethrow unexpected internal faults at their owned
supervision boundary. Do not resubmit a confirmed/uncertain provider write.

** 7. Duplicate behavior remains executable
Rechecked at current main: =reception.channel/deliver-whatsapp!= and its
=transport= server, plus =hotel.providers.whatsapp/send-text=, coexist with
the canonical =communication.dispatch= / Meta delivery path. They maintain a
different send/grant/error policy. The channel namespace also contains useful
canonical publication/receipt code, so deleting the entire namespace is wrong.

Delete the legacy sender/worker after native codebase caller analysis plus
exported-callback/test/launcher inspection; redirect meaningful checks to the
canonical dispatcher. Keep authentic historical evidence. =booking.claims=
still parses amounts via Float then round, while HTTP form coercion already
has an integer-cents parser. Consolidate on one exact parser with explicit
locale/precision/range rules and retain boundary tests.

The separately running Python guest application and legacy-store compatibility
cannot be retired merely because a local static caller query is empty. Inventory
