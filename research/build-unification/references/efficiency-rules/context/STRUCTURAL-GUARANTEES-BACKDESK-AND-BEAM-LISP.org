#+title: Structural guarantees for Backdesk and Beam Lisp
#+date: 2026-10-26
#+status: Design avenues and enforcement plan; proposed mechanisms are not shipped APIs

* Purpose and meaning of a guarantee

This is the structural companion to [[file:BOUNDED-PAGES-IMPLEMENTATION-PLAN.org][the implementation plan]] and
[[file:PAGE-WIRING-AND-DATOM-AUDIT-2026-10-26.org][the page/Datom audit]]. It addresses Backdesk's current mistakes and the language
design choices that should prevent the same mistakes in a new application.

For the supported strict authoring path, aim for one of four concrete outcomes:
1. The invalid construction cannot be expressed through the ordinary constructor.
2. Publication rejects it using complete, current compiler-owned evidence.
3. The native operation enforces a finite budget or authority check before work.
4. Behavior outside the proven fragment is explicit unknown/refused, with a
   witness or missing obligation, rather than an implied success.

No combination of these modules proves arbitrary BEAM/interop code fast, pure,
secure or terminating. Unrestricted reflection, dynamic loading, host calls and
external systems remain outside a closed proof unless admitted through qualified
contracts. A source annotation is a request to check a property, not proof that
the property holds. Runtime custody/identity/deadline/authorization checks remain
necessary even when static verification passes.

The objective is to make these failures impossible to publish unnoticed within
the declared supported path, while enforcing hard runtime limits where static
proof is unavailable. Absolute wall-clock latency on arbitrary hosts cannot be
made a theorem by attaching a metadata tag to a function.

* Structural avenues

Every new name or role below is a proposed contract, not an existing environment
option or a promise that the current macros already enforce it. Extend the
existing owners of these concerns rather than maintaining parallel implementations.

** A1. Checked screen and read roles on existing declarations
Backdesk: screens take only finite read models, presentation inputs and explicit
time. Read modules take authorized immutable query capabilities. Commands and
composition own mutation/IO/resource handles.

Beam Lisp: extend =live.app/defscreen= and publication analysis with checked roles
such as render, read and command. Render requires input-only deterministic
behavior, covered callbacks and no ambient dependencies. Read permits only
declared immutable reads and finite budgets. Do not infer admission from an
author-written =^:pure= marker.

Enforcement: compiler-resolved ANF -> summaries -> complete current publication
obligations; qualified runtime primitives enforce actual capabilities. Raw
reflection/dynamic calls that defeat closure are unknown and cannot enter the
strict role without a supported checked contract.

Negative checks: hide =System/cmd=, clock/randomness, =store/custom!= or provider
access behind an alias, helper, callback or macro. Each must be rejected or
explicitly unknown, never silently pure. A callback closure's creation and its
later execution must be analyzed separately.

** A2. Bounded page results as a checked value
Backdesk: list/search/activity/count paths declare order, selected fields,
authorization, row fan-out and resource limits before rendering.

Beam Lisp: extend the existing Datom page/window plan descriptor and result
envelope. The ordinary page constructor accepts only an admitted plan or a
named unsupported state. Carry returned rows, basis, cursor/continuation,
authorization freshness and actual work counters together. A =PageResult=
concept is a proposed checked representation, not a nominal type available now.

Enforcement: native row/seek/byte ceilings; coverage-checked plan composition;
explicit refused/incomplete UI states. Add type/lint diagnostics for unbounded
=q -> filter/sort -> take= on a strict page path, including helper calls, but
do not pretend a pattern matcher proves every algorithm's complexity.

Negative checks: very selective filters, long histories, deep windows, expired
cursors, missing order indexes and an attempted unlimited fallback. Preserve
semantic equivalence and expose refusal instead of returning false completeness.

** A3. Authorized ID selection and hydration as one boundary
Backdesk: select scoped IDs before paging/enrichment and validate all raw entity
hydration against the same property/conversation policy and basis.

Beam Lisp: build an access-aware selected-ID hydration primitive on the existing
=auth/query-context= and query/pull APIs. Its checked result ties identity, policy,
basis, selected IDs and allowed fields together. A query context alone is not
a scoped raw database: current raw =pull=/=entity= does not inherit query policy.

Enforcement: actual policy/revocation and basis checks in the primitive, supported
opaque/custody handling at publication and runtime boundaries. A user-created
record with the right shape does not grant authority. Count/search/paging must
use the same policy, including joins and shared system rows.

Negative checks: foreign ID injected after selection, stale permission, cached
guest data reused for staff, forged branded value and a raw-pull escape path.

** A4. One immutable projection context, including time and journal identity
Backdesk: capture one hotel basis, explicit now, principal/policy and named
independent journal bases, then derive the entire page from that context.

Beam Lisp: extend Live's projection contract so render, deadline calculation,
measurement and cache admission can reuse that exact context. Currently deadline
rearming resolves worlds again. Any reuse must preserve clock-crossing behavior
and explicitly independent journal snapshots; it cannot invent a distributed
atomic transaction.

Enforcement: checked context construction and versioned evidence/cache keys.
Negative checks: hotel commit during rendering, journal change during rearm,
virtual clock advance during realization and an expired authorization epoch.

** A5. Bounded batch enrichment and relational projection contracts
Backdesk: one page-level enrichment request supplies latest-message, current
summary/judgment, processing state and returning-guest context for selected IDs.
Replace full-kind scans and repeated per-row history hashing.

Beam Lisp: extend query projection/cardinality metadata so batch shape and
maximum relationship fan-out are explicit. Reuse =codebase/nplus1= as a useful
diagnostic, qualify its coverage, and combine it with actual query traces.
Do not build a hotel-specific ORM or accept a fixed operation count as a cost
proof: three ranges processed3000rows in the measured example.

Enforcement: plan composition plus runtime budgets and exact field/relationship
contracts. Negative checks: a hidden per-row query, unbounded to-many join,
all-message latest fold and foreign-history growth with a fixed selected page.

** A6. Stable keys, unique IDs and form attempts from component constructors
Backdesk: every repeated row uses entity/component identity; field IDs include
form/component/record identity; attempts hold original request ID/basis/payload.

Beam Lisp: extend Loom field/form/list primitives and Live checks to derive
consistent key/label/DOM-ID namespaces and expose explicit attempt creation.
Keep rendering itself pure: a constructor called during render cannot allocate
an unpredictable ID. Use session/command lifecycle boundaries for that work.

Enforcement: compile/lint evidence for static lists, checked component contracts,
and duplicate-ID/key checks for realized dynamic trees. Stable namespaces alone
do not prove arbitrary caller-supplied keys injective.

Negative checks: two arrival forms, reordered rows, duplicate logical IDs, focused
input during insertion, equal-state renders and unknown mutation outcomes.

** A7. First-class command-attempt lifecycle with a single transport envelope
Backdesk: consolidate pending/result handling while preserving typed procedure
admission and provider uncertainty. Keep secrets/files ephemeral.

Beam Lisp: extend existing Live intent/outcome/session and procedure receipt
mechanisms with a standard attempt contract rather than inventing a second
business state machine. A closed model distinguishes drafting, submitted,
confirmed, refused and unknown outcomes; allowed transitions preserve captured
identity and prevent automatic new-effect replay after uncertainty.

Engines: =system.model/core= for covered inductive invariants and finite phase
analysis; =minikanren= may propose guards, then verification discharges them;
=veritas.model= generates actual patch/reconnect/response-loss histories.

Negative checks: socket drop between commit and response, changed draft with an
old request ID, lost acknowledgement, stale basis, provider acceptance followed
by local publication failure. A model proof does not prove the real provider
adapter conforms; run the adapter and process/browser failure checks too.

** A8. One canonical model for effects, determinism, suspension and primitive shapes
Backdesk: remove render-time =date= processes, random IDs and ambient environment
reads; supply explicit locale/timezone/time/configuration inputs.

Beam Lisp: audit and extend the existing footprint/primitive metadata consumed
by effects, summaries, typing and emission. Classify clock, randomness,
environment, process-local state, files and reflective calls conservatively.
Do not add a separate handwritten purity table in Backdesk.

Distinguish: read-only; deterministic over declared inputs; non-suspending;
terminating; bounded work; portable. None is a synonym for another. In particular
=footprint/pure?= allows read resources, whereas =system.evidence= separately
tests state independence. A pure loop may still be expensive.

Negative checks: known leaf aliases, callback latent effects, clock sampling,
unrecognized host operations and an incorrectly declared trusted primitive.
Qualification must exercise the actual host operation/contract pair.

** A9. Native timezone-aware time presentation as a pure operation
Backdesk: retain Casablanca timezone behavior and move formatting off the OS
command path; explicit time drives deadlines and labels.

Beam Lisp: reuse a qualified timezone implementation and expose immutable
formatting inputs, including locale/timezone rules version where relevant to
retention. Generate one visible next-deadline from actual time predicates.
This is an infrastructure gap to qualify, not a reason to hard-code UTC+1.

Negative checks: Morocco Ramadan transitions, midnight, ambiguous/nonexistent
local input, cache reuse after rules/locale change and a clock crossing while
rendering. Runtime budgets still apply to large formatting batches.

** A10. Proved invalidation and owned temporal projection
Backdesk: first keep complete Live subscriptions and make reads cheap. Later
optimize only demonstrated fan-out and idle rediscovery costs.

Beam Lisp: extend =live.projection= and read dependency evidence so a skipped
projection has a guaranteed later projection or a proved unchanged dependency
set. Query watches may be inputs to this design; they are not inherently free
because full-query watches rerun before/after queries.

Engines: Datalog for dependency closure, frame/resource reasoning for independent
changes, finite =system.gfp=/AF or bounded counterexample search for scheduling
abstractions, and generated plus real socket histories for implementation
behavior. State the fairness, delivery, time and finite-domain assumptions.

Negative checks: revoke access on an attribute a view did not previously read,
change an independent journal, retract the last row, clock-only expiry, reconnect
after several commits and a projection coalesced before a command barrier.
Do not permit guessed =:listen {:attrs ...}= filters as a shortcut.

** A11. Ownership-aware application/read/subscription lifetimes
Backdesk: composition returns stable read capabilities; rendering never calls
=open!=. Watchers, timers and journals have explicit acquisition and shutdown
order, including later/replaced journal connections.

Beam Lisp: apply =system.ownership= to admitted acquire/use/release protocols,
with actual native lifecycle guards and qualified adapters. Borrowed resources
must not be closed by a screen or socket. Add declaration-driven lifecycle
support to the existing application/Live runtime rather than app-owned registries.

Negative checks: partial initialization failure, duplicate acquisition, use after
close, actor death, detached socket grace expiry, failed unlisten and generation
replacement. A finite abstract refusal is a possible violation, not necessarily
a concrete exploit; distinguish its witness from an executed failure.

** A12. Executable module boundaries and one route schema
Backdesk: declare page routes with their access, screen, HTTP/socket behavior and
read capabilities, deriving allowlists/adapters from one value. Separate reads,
views, commands and composition by responsibility.

Beam Lisp: use resolved codebase/contextual phase facts and actual emitted edges
to check layer rules, require cycles, callback closure and lifecycle boundaries.
Use existing contextual refactor support for eligible symbol moves/renames;
unexpanded recipes, generated bindings and unknown external references refuse
rather than allowing a destructive negative caller claim.

Negative checks: helper reaches a forbidden owner, macro-generated call, exported
callback absent from the local graph, route403 becoming a200 refusal component,
and a required namespace that starts actors during analysis.

** A13. Typed read-model and result shapes without a second schema authority
Backdesk: define closed presentation/results for pages, unknown states, attempts
and capabilities. Derive field presentation from procedure schemas and retain
all command validation at its current owner.

Beam Lisp: compose existing records/schema constructors, tag/arity diagnostics
and qualified runtime boundary checks. Rich branded/refined authorized page
types would be new work: the current tag-set checker does not provide them.
SMT can discharge supported constraints such as nonnegative remaining budgets
or page-size limits, but only under explicit correctly modeled sorts.

Negative checks: missing field, unknown enum status, wrong arity, nil journal,
forged role/ID, incorrect numeric sort and silent top/any propagation.
Authorization is an actual checked capability/policy, not merely a field named
=property= in a typed record.

** A14. Honest, current evidence as a build input
Backdesk: one result manifest links source, exact SDK, schema, policy, data,
query plan, diagnostics, solver assumptions and real browser/package receipts.

Beam Lisp: connect =veritas.ledger= to contextual publication and incremental
evidence identities. Record each obligation, input coverage, model domain,
budgets, status, witness and invalidation cause; reuse the existing bounded
finite cache/provenance infrastructure. Do not create a second proof ledger
that disagrees with the first.

Release policy: all mandatory obligations must have an accepted modality and
complete applicable coverage. Typed silence, aggregate =system/verify :ok=,
skipped rules, timeout, stale receipt and solver =unknown= never count as a
successful required check. Store measured performance as measurement, not proof.

Negative checks: edit a callee/schema/policy/SDK without editing the screen,
change macro expansion/primitive model, drop a callback edge, truncate the
analysis and replay a receipt from another source-free package.

** A15. Deodorant as a disciplined migration assistant
Backdesk: add named diagnostic rules for suspicious render IO, random IDs,
unbounded page idioms, repeated index building and duplicate transport plumbing.
Semantic decisions remain in resolved analysis/query/runtime contracts.

Beam Lisp: register rules with existing =deodorant=/=rewrite=/=span-rewrite=;
share canonical source extraction and known type/effect evidence. Mechanical
value-equivalent idioms can use their qualified safe tier. Changes requiring
type assumptions need those assumptions discharged. Structural query/state/
authorization migrations remain reviewable migration-tier changes, with
prerequisite resolution and retained source spans.

Never automatically rewrite =take (sort (q ...))= into a page call without
proving order, ties, filtering, scope, count, refusal and cursor semantics.
Never hoist =open!= or replace =date= with an assumed equivalent just because
the source shape matches.

Negative checks: shadowed names, unsupported target namespace, comments/literate
cells, floating-point versus integer semantics, duplicate evaluation of an
effectful expression and a rule cycle. =minikanren= synthesis and SMT equivalence
are optional bounded checks for eligible rules, not arbitrary codemod approval.

** A16. Affordable incremental developer tools and solver scheduling
Backdesk: analyze changed feature closures directly, avoiding the whole-corpus
MCP index as an obligatory startup step. Keep a cheap check useful during edits.

Beam Lisp: reuse the compiler's prepared source/ANF/identity snapshots across
typed, arity, effect, codebase, lint and proof consumers. Keep first MCP
initialization independent of full project indexing. Index groups explicitly;
the audited engine-only path currently attempts =code.index/ensure-tree= and
needs a separately tested correction before making a startup claim.

Run cheap lattice/graph/plan checks first; solve only changed covered obligations
through bounded reusable =oracle=/=z3pool= conversations. Retain complete cost/
unknown diagnostics in =system.ledger= and attributable per-task counters.
Do not run solvers or compiler analysis in each page invocation.

Negative checks: absent solver, cancelled analysis, partial index, changed SDK,
opaque callback and concurrent result attribution. Source-free SDK distribution
must include and initialize the actual tooling constructors/DSLs it advertises.

** A17. A safe default page scaffold and source-free acceptance
Backdesk: new features follow the already-qualified Guests/conversation slice:
route declaration, bounded authorized read, pure component, command attempt,
deadline reader and focused tests.

Beam Lisp: ship that pattern through existing templates/declarations with strict
defaults once the mechanisms are qualified. Generated examples must pass the
same analysis, negative tests, query budgets and source-free SDK startup as
handwritten applications. Make bypasses explicit named unsupported/unsafe
boundaries; do not let a friendly default become an unverifiable second stack.

Negative checks: a fresh app importing only the public distribution, two
independent consumers, optional module load order, immutable resource paths,
first SSR/socket callback, missing capabilities and analysis with no app actors.

* Small formal models worth building first

1. Form attempt: confirmed/unknown outcomes, original ID/basis/payload, explicit
   new attempts, patch/navigation/reconnect ordering. Prove identity preservation
   in the covered abstract transitions; execute the real submission adapter.
2. Page budget: nonnegative remaining row/seek/byte counters; every storage step
   either charges before work or refuses; hydration follows admitted IDs. SMT
   handles counter arithmetic; actual substrate tests prove metering coverage.
3. Projection scheduler: commit, navigate, assign, intent barrier, detach/attach
   and deadline crossing. Exhaust finite abstract schedules and retain traces;
   specify fairness before using any eventuality claim.
4. Scope/cursor state: permission epochs, changed principal, revoked row and
   expired continuation. Prove fail-closed transitions, then test actual native
   query/hydration/cache implementations against the model.
5. Resource ownership: partial acquire, borrowed handle, watcher/timer registration,
   cleanup refusal and death. Use ownership protocols plus actual runtime guards.

Keep models derived from real transition definitions where the extractor covers
them. Otherwise record and test the abstraction relation explicitly. A hand-built
model with no connection to the implementation cannot certify that implementation.

* Enforcement ladder and migration policy

1. Existing APIs remain usable while the migrated feature has an explicit strict
   entry. Legacy unknowns are inventoried, not grandfathered as proved safe.
2. Diagnostic mode establishes coverage and false-positive/unknown behavior.
3. Migrated strict entries reject known violations and unmet mandatory coverage.
4. Native boundaries enforce scope/budgets/lifetime even for accepted static code.
5. Compiler/SDK publication binds accepted evidence to actual code and dependencies.
6. A second consumer and source-free package qualify the general language feature.
7. Ordinary app scaffolds select the qualified path by default; remove superseded
   local workarounds and duplicate registries only after consumers migrate.

Required tests for each guarantee: positive construction, deliberate violation,
opaque/dynamic case, exhausted budget, changed dependency identity, qualified
primitive/adapter behavior and a real end-to-end consumer. Snapshot hashes are
provenance, not substitutes for authority or modeled semantics.

* Recommended upstream delivery order

1. Coverage/status normalization and shared primitive-model audit: A8,A14,A16.
2. Strict existing screen/read roles and module checks: A1,A12,A13.
3. Admitted page/hydration composition: A2,A3,A5.
4. Component/attempt lifecycle: A6,A7, with Backdesk's migrated feature as consumer.
5. Pure time, exact context and owned clocks/resources: A4,A9,A11.
6. Proved invalidation only after measured need: A10.
7. Safe migrations and public scaffold/distribution qualification: A15,A17.

This is a dependency order, not a requirement to delay the application fixes
until an entire language redesign ships. Backdesk can migrate through existing
qualified APIs while the reusable guarantees are developed and admitted.
