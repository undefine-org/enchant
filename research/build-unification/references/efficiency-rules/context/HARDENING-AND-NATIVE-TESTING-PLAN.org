* Why
The focused booking delivery (F1–F6) is accepted locally. This plan addresses
what the review of that implementation found, in three areas:

1. Small correctness defects at the PMS and communication boundaries.
2. Duplicate implementations of the same behaviour: two senders, two money
   parsers, two ways to decide live versus synthetic, two guest apps and two
   booking roles. Each pair is a place where a fix lands in one copy only.
3. A test setup that works around the language instead of using it. Every
   check is a cold ~150 MB VM run one at a time behind a global lock, inside
   a Python/bubblewrap sandbox. Tests use 217 hand-written =check= helpers
   instead of =deftest=. =veritas.model= serves fakes in 58 places but checks
   state machines in only 3, each with 6–20 histories.

Goal: one path for each behaviour, an offline guarantee inside the
application itself, and a test suite that runs in one VM, in parallel, and
uses =veritas.model= to generate the failure orderings currently scripted by
hand.

* Changes to the current working rules
These items deliberately override rules in [[file:FOCUSED-BOOKING-COMPLETION.org][the focused plan]] and need the
user's sign-off, which was given in conversation on 2026-10-16:
- "All behavioral tests run in Veritas": that rule refers to the bubblewrap
  sandbox. Under this plan, ordinary tests run in the VM with the
  in-application offline guard (Phase 2). The sandbox remains only for
  browser and real-process-death checks.
- "Do not build a new testing framework": no framework is built. The plan
  adopts the stdlib's =deftest=, =bl test --async=, =veritas.model= and
  =veritas.ledger=, and deletes repo-local test machinery.
- "No runtime pin promotion": stays in force. Phase 0 checks the pinned
  runtime. If a required feature is missing, a pin change is a separate,
  explicit decision.

* Phase 1.D — remove duplicate paths
Order: lowest risk first. Each item ends with one implementation and deletes
the other, together with the tests that existed only for the deleted path.

** D1 Legacy WhatsApp sender (low risk)
=reception.channel/deliver-whatsapp!=, its =transport= server and
=hotel.providers.whatsapp/send-text= form a second sender. That sender has no
policy checks, treats any mode other than the exact string ="sandbox"= as
live, and records every failure as =uncertain=. Only tests/reception/workers.bl
starts it. The canonical path is =communication.dispatch= + =meta.whatsapp=.
- Delete the sender functions, the =transport= server and =send-text=.
- Keep only the pieces of =reception.channel= that the application imports.
  Five src namespaces require it; check each one's use before deleting.
- Point workers.bl at the dispatch worker.

** D2 One money representation (low risk)

* Phase 2 — the offline guarantee inside the application (half a day)
New namespace =hotel.mode=, read once at startup:
- =:synthetic= is the default. =:live= requires =RECEPTION_MODE=live=, plus
  =RECEPTION_AUTH_SECRET= and =RECEPTION_PROPERTY=; startup refuses otherwise.
- Expose =(mode)=, =(live?)= and =(outbound-allowed? url)=.

Enforcement points. All outbound traffic already passes through these:
- =hotel.integrations.http/request!=
- =meta.graph/request!=
- the model endpoint construction in reception/agent.bl:199,
  goal_execution.bl:86, knowledge.bl:42 and insight_execution.bl:84

Rules in =:synthetic= mode:
- Only loopback URLs are allowed. Anything else throws =:synthetic-egress=
  before any network I/O.
- Do not read =.env= (packages/meta/src/meta/config.bl:12).
- Do not read =OPENROUTER_API_KEY=; use the controlled model service.
- =meta.connect/configured-token!= refuses to run.
- Remove the default real Graph base URL (meta/config.bl:15); a URL must be
  configured explicitly.
- Refuse any listener other than loopback: =RECEPTION_TAILNET_IP= requires
  =:live=. This fixes the open Tailscale preview.
- The non-live =staff:amina= default actor remains only on loopback.

Rules in =:live= mode:
- Refuse modelled or sandbox connections. This is the existing check in
  =hotel.integrations.core/save!=, moved here.

Also derive the media cache root (communication.bl:449) from the route's
sandbox flag, not the environment.

Verify:
- a deftest asserts a non-loopback request throws in synthetic mode before
  any I/O;
- a deftest asserts the live-mode startup refusals;
- grep confirms no remaining direct =System/get_env "OPENROUTER_API_KEY"= or
  =RECEPTION_MODE= reads outside =hotel.mode=.

* Phase 3 — move tests onto the stdlib (1–2 days, mostly mechanical)
** 3.1 Convert to deftest
Current state:
- 74 files use the identical one-line helper
  =(defn check [label value] (when-not value (throw …)) (println "PASS" label))=;
- 9 use the =yes= variant;
- 24 use a multi-line variant;
- 4 append to a local check list.

Conversion:
- Script the rewrite: wrap each file's top-level =try= body in a =deftest=
  named after the file, and turn =(check "label" x)= into =(is x "label")=.
- Convert the 33 non-standard variants by hand. Keep any recorded check list
  only where a receipt depends on it.
- Rename files to =*_test.bl= so =bl test= finds them.

Expected result: each failure is reported with its label, and the run
continues past the first one.

* Phase 4 — state-machine checks with =veritas.model= (1–2 days)
The fakes are already models. Drive the real code with generated command
histories instead of hand-scripted sequences.

** 4.1 PMS effects model (highest value)
- System under test: =pms.operations= + =pms.pluriel= against
  =(vm/serve (pms.fake/model {}))=, with a file-backed store so restarts are
  real reopens.
- Commands: =:enqueue= (create, amend, cancel), =:execute=, =:fault=
  (none, accept-then-error, lost-response, read-unavailable, change-price,
  read-profile-mismatch), =:restart= (reopen the store and run =recover!=),
  =:amend-elsewhere= (provider-side change, using the fake's existing control
  commands) and =:drain= (repair and readback) as =:settle=.

Invariants, checked after every step:
- the number of provider creates equals the number of distinct create keys;
- every =:confirmed= operation has a receipt that matches readback;
- no operation reports =:confirmed= while its provider state differs;
- a confirmation is never announced from an =:uncertain= state.

Checked after the settle step:
- no operation is still =:submitting=;
- every =:uncertain= operation carries a recorded cause (item 1.2).

Run with ={:histories 300 :max-len 20}=, with fixed seeds in CI and a random
seed nightly. Expected to catch items 1.3 and 1.9 before their fixes. Run it
before the Phase 1 fixes to confirm it detects them, then after.

** 4.2 Communication send-admission model
- System: =communication.store= + =dispatch= + =policy= against
  =(vm/serve (meta.fake/model …))=.
- Commands: inbound (with duplicate ids), send, window expiry (clock tick),
  STOP, START, staff takeover and release, route change, content edit,
  restart, settle.

Invariants:
- no send is admitted after STOP, outside the window without an approved
  template, or under staff control by the agent;
- one provider message per send intent;
- duplicate inbound is processed once;
- every quarantined event is visible (item 1.7).

** 4.3 Approval authority model
Commands interleave the agent proposing terms, the guest approving, a terms
change and staff override. Invariant: no PMS write is enqueued without a guest
approval of the exact current terms fingerprint. The agent cannot produce one.

** 4.4 Retire the scripted tests these models cover
Mark each scripted test that a model covers. Delete it after the model has run
green for a week of nightly seeds. Keep the few that pin a specific historical
regression.

Each model file stays under about 150 lines. Shrunk failures replay with
=vm/replay= from the recorded seed and history.

* Risks
- Converting tests could hide a behaviour change. Mitigation: compare
  per-label outcomes before and after (3.3) and change no assertions in the
  conversion commit.
- Some suites depend on named singletons that cannot run async. Mitigation:
  mark them serial explicitly; parallelism is an optimization, not a
  requirement.
- Deleting duplicate paths removes tests that pinned historical behaviour.
  Mitigation: delete only after the surviving path's model or deftest covers
  the same claim, and list each deleted test in its commit message.
- Model checks sample histories. A pass is =:witnessed=, not =:proven=, and
  reports must say so.
