#+title: A small application vocabulary with explicit authority and evidence
#+date: 2026-10-26
#+status: Proposed direction, conditional on qualification; no production implementation

* Recommendation and its limits
Use ordinary functions and immutable composition values as the public foundation.
Add a feature description to link existing routes, read plans, command schemas,
presentation and lifecycle references where this demonstrably removes duplication.
Add compiler-checked profiles over those same values and functions incrementally.
Do not require a new DSL, universal workflow engine or whole-corpus proof before
an application can be built. [[file:DESIGN-ALTERNATIVES.org][Four alternatives]] explain why this is conditional.

The smallest coherent vocabulary has six concepts:
1. An application instance owns resources and immutable code-generation selection.
2. A feature links named routes/operations and their dependencies; it owns no data.
3. A read runs a scoped plan over captured immutable inputs under a work budget.
4. A command admits a captured attempt against current authoritative state.
5. A screen renders finite presentation values and stable identity.
6. An evidence result states a claim's modality, coverage, identity and limits.

Policy, clock, schema, native capability and lifecycle protocol remain existing
specialized values, referenced by these concepts. Job, draft and controller are
compositions with existing queue/private-state/browser owners, not three new
universal authorities. A tiny application need not explicitly declare a feature
when a direct app map is clearer. Strict profiles are additive entry contracts.

This is not an implemented API. Every =application/=, =feature/=, =read/=,
=command/=, =attempt/=, =component/=, =draft/= and =controller/= constructor in
examples below is proposed pseudocode. Existing module/API names are identified
in [[file:CURRENT-MODEL.org][CURRENT-MODEL]]. Example schemas, types, budgets and errors illustrate contracts;
they have not been parsed, compiled or executed. Names are design placeholders,
not a request to reserve a large new standard-library namespace family.

* End-to-end flow and boundaries
#+begin_example
immutable feature descriptions + exact compiler/reference identities
    -> validated composition -> startup/resource plan -> owned app instance
    -> authenticated request/socket identity -> route admission
    -> capture {DB view, policy epoch, explicit now, named independent journals}
    -> scoped bounded select -> checked bounded hydration -> finite read model
    -> screen + Loom presentation -> Live realization/key checks -> keyed patches

edit -> one chosen draft owner -> explicit submission captures immutable attempt
    -> transport admission -> current domain command admission
    -> atomic authoritative transition + original receipt / external-work intent
    -> owned queue/provider protocol -> confirmed, refused or uncertain evidence
    -> Datom/clock publication -> projection; reconnect resolves original attempt
#+end_example

HTTP SSR and Live share feature access/read/screen functions, not a duplicated
permission condition. HTTP status/headers and socket refusal remain explicit
transport policies. A read cannot acknowledge browser-mounted delivery. A browser
receipt is a separate authenticated command/event with its original fences.

SSR may capture basis b1 and socket startup b2. That is a legitimate newer read,
not a reason to replay a command or assume the DOM and server tree already agree.
Initial hydration must establish which tree the client has seen and reconcile
before accepting frame acknowledgements. Cookie/session/principal resolution must
be consistent across SSR and WebSocket, including CSRF/origin rules where relevant.

Descriptions use stable IDs and original references; modules export small pieces.
Composition rejects missing/ambiguous bindings and duplicate paths before serving.
The compiler emits an inspectable linked application inventory. Individual adapters
consume only their portion: route adapter, read admission, schema presentation,
ownership planning, packaging and tests. The inventory indexes these contracts;
it neither reinterprets all their semantics nor grants native runtime authority.

* Read contracts: selection, hydration and total budgets
** Capabilities and context
A scoped reader is a native/qualified abstract interface with fixed policy inputs,
not ={:database raw :tenant id}= passed to arbitrary clients. Do not advertise an
opaque unforgeable authorized-reader until it exists and has native/runtime
custody. Initially an app-owned function with explicit policy checks is honest
but belongs to the trusted application code boundary. Keep the raw DB out of
strict screens; seal/qualify reachable read leaves for the stricter profile.

The proposed context carries DB store/view/basis, verified principal, policy
identity/epoch/expiry, named journal view keys, schema/query/model versions,
locale/tzdata configuration, explicit now, selected code identity and read/attempt
budget identity. The response may expose a safe subset; store handles, secrets,
principal tokens and internal evidence never become browser model fields.

Historical data reads and current authorization are separate: policy must decide
whether historical visibility is permitted. A command always revalidates current
preconditions and permission; an old read receipt does not authorize a write.
Independent journal reads can be causally annotated with a =through= hotel basis
only when such a relation is actually maintained; otherwise show separate bases
and possibly unavailable/stale state. Never return a falsely unified revision.

** Result algebra
#+begin_example
ReadResult = exact {items, view, next?, deadline?, work}
           | incomplete {continuation?, reason, work, progress}
           | refused {reason, alternatives?}
           | unavailable {safe-cause, retry-policy}
Count      = exact {value, view, work}
           | estimate {value-or-range, method, view, error-bound?}
           | omitted {reason}
#+end_example

=:exact= refers to one admitted page, never automatically to a global count.
Search status carries semantics, e.g. prefix/title versus full text. Refusing
substring search must not silently return title-prefix results labeled "search".
Partial results are exposed only by a separately specified partial-result contract;
existing q-page incomplete results intentionally expose no rows. Preserve that.
Policy rewrite exceptions are adapted into safe refusal/error causes explicitly,
without losing diagnostics or classifying an internal failure as "no matches".

Cursors are opaque server-held provenance. They bind query/order/basis/policy/code,
have TTL/capacity, can invalidate on change, and are not durable offline bookmarks.
If product needs navigation across changing snapshots, choose a specified refresh
or keyset-anchor UX; do not weaken cursor binding to fake continuity. Stable order
includes a deterministic tie-breaker; collation/null/retraction semantics must be
part of the admitted plan and oracle fixtures. Per-field declassification must
happen before serializing related records, not by hiding columns in CSS.

** Typed membership and owned derived closed inputs
Entity-domain membership must be explicit and independent of sparse presentation
fields. A dedicated conversation scope/composite is one valid application approach;
an explicit kind/property filter may instead preserve semantics while losing a
single-scope rank capability. A future multi-scope native plan is a separate
engineering/qualification choice. Descriptor admission, index readiness and a
checkpoint cannot establish runtime query semantic fidelity by themselves. Retain
mixed-kind/foreign-scope canonical oracles and pre-hydration eid/kind/property/
conversation/order checks for actual returned AND omitted membership.

A requested read contract links semantic domain, scope, projection/order, policy,
view/basis, count/window capability, readiness and actual budget coverage. It must
not confuse "correct query" with "rank-admitted query" or silently use an unbounded
fallback when a correct extra predicate loses the fast plan. Current rank planner
constraints remain in CURRENT-MODEL; no upstream extension is delivered here.

Exact count/window facets maintained in canonical transactions/owner repair are
owned derived inputs, not disposable optional caches. A source+ALL-facet complete
checkpoint, exact same-property/conversation/kind universe, derivation/schema/code
identity and current provider evidence can authorize a narrow zero skip. Missing,
partial, stale or malformed counts mean unknown/refused, never zero. Positive
counts retain bounded reads and parity; incomplete empty results do not prove
absence. Packed key order/version is a storage contract, not a truth certificate.
13 keys and 24 IDs bound shape only; per-kind populations, ID/record bytes, history,
maintenance and two remaining global queries still need independent budgets.

The all-message window includes internal/evidence/revoked messages in the described
parent implementation. It does not mean 24 public messages after filtering, nor
replace separately checked latest-public/current-input pointers. Validate window
membership/order and completeness against canonical semantics before hydration.
Do not disclose raw internal counts/IDs to clients merely because server proofs
need them. Resource-free and authorized-to-disclose are separate properties.

In-read reuse of full canonical coverage is limited to exact COMPLETE admission,
same DB/basis/property and matching entity-map witness. Skip only provably EMPTY
attempt candidates; keep each input's unknown/reviewable classification and the
original current/historical proof body for every positive candidate. Do not expand
this optimization to speculative proof suppression, historical/current equivalence
or cross-render cache reuse. An unforgeable constructor/native boundary is still
needed wherever a receipt could otherwise grant authority.

** Work composition
A page budget has dimensions: physical datoms/rows, seeks, bytes decoded, entities
hydrated, fan-out/depth, CPU/reductions or elapsed cancellation ceiling, output
bytes/tree nodes, and aggregate continuation allowance. Not every dimension is
currently natively metered. Reports name each dimension's actual enforcement.

For maximum k selected IDs and per-ID bound h, storage admission must account
for select cost S plus at most k*h hydration and fixed context/policy costs P.
Related data hydration needs the same charge-before-work budget, not merely one
=pull-many= call. A to-many join cannot be assumed h=1; admit a nested page or a
proven finite cardinality bound, otherwise refuse. Max document size and string
length matter even at constant entity count. Short-circuit joins must preserve
set semantics, scope and duplicate handling, not just operation count.

Bound invocation AND user operation: at most N continuations or cumulative work
B for the same logical page; cancel superseded reads; cap retained cursor state.
A no-progress continuation stops with a specific actionable state. It must not
loop automatically, reset the budget each patch, or raise limits without policy.
Sparse selective filters are correct incomplete outcomes. An admitted compound
scope/order plan may remove unrelated population work; arbitrary filters cannot
promise 40 matches in fixed physical work for every dataset.

A derived membership/search product is optional. Require exact derivation,
source basis/through coverage, atomic publish or clearly labeled lag, bounded
backfill, recovery and deletion/retraction semantics. Writer-maintenance and
storage budgets count alongside read savings. Current q-window opportunistic
maintenance must either be separately preprepared for strict invocation or be
explicitly admitted as an owned background effect. Exact counts are optional and
budgeted; a slow cold count cannot hide behind an apparently cheap list.

** Caching and invalidation
Cache reuse is optional unless a separately owned prepared resource is explicitly
required for readiness. =memo-by-basis= must not be interpreted as once-only:
current bounded-cache/value computes on each miss and returns the computed value
even if put! declines. Concurrent misses need not share a computation. A correct
pure answer and a successful retained publication are different outcomes.

Use four separate evidence dimensions: semantic validity, finite retention
admission, actual publication/hit, and admissible uncached fallback. A stable
basis addresses only part of the first. Attribute/schema/provider/code evidence
must describe actual reads: computed shadows and unknown dependencies refuse
reuse; schema/policy/clock/callee changes invalidate affected claims. Cache
availability never establishes authority. Backdesk's added guard checks are
user-supplied implementation evidence, not requalified by this research.

The proposed diagnostic shape is a bounded receipt over those dimensions, with
charged bytes/ceiling, safe reason, relevant identities and observed computation/
publication cost. Existing false/miss interfaces may leave the reason unknown;
do not invent precision. Preflight fit is not an aggregate reservation or a hit.
Instrument without serializing whole worlds or evaluating captured thunks.

Separate canonical retained data from capture-local time/journal overlays and
heap-identity indexes. The supplied repair removes a second full-entity reference
from the retained cache representation and creates its index locally after the
overlay. A transported heap-identity index is neither a durable cache identity
nor useful proof of semantic validity. Charge conservatively across actor/ETS
boundaries; charged bytes are not measured RSS or guaranteed sharing savings.
Do not raise limits or weaken native admission merely to retain a growing world.

Finite screen inputs need size, eagerness and lifetime contracts, not only a
finite tag or pure summary. A one-scalar deadline can hide a whole-world closure.
Strict folds avoid some deferred captures but may still scan unbounded population.
Small ID sets narrow captured context only if their own size is bounded. Prefer
page-selected IDs and admitted batch reads for bounded routes. A compiler may
identify free-variable captures/escapes with unknowns; exact retained bytes and
whole native work still need metering and execution evidence. Latent effects,
capture size, emission growth and lifecycle remain separate properties.

Budget cold/miss computation, normalization/charging, copies and concurrent duplicate
work independently. If an interactive limit holds only with a hit, choose an
explicit prepared read product with readiness/backpressure, or a bounded/refused
cold read. Calling it an optional cache cannot justify unbounded fallback.
Lexical sharing within one captured read is the cheapest reuse; a single-flight
service adds owner/waiter cancellation, recursion/error and capacity protocols.
Neither is a durable effect receipt or an unspecified lifetime once-only promise.

Cache only finite values, with bounded entries/bytes/TTL and actual dependencies:
DB view/store, principal/policy/expiry, schema/plan/code identity, journal bases,
explicit time interval, locale/tzdata and any other configuration read. Larger keys
have costs; reuse already authenticated immutable identity rather than rehashing
full worlds. Clock-dependent results may reuse only until their earliest relevant
deadline. Policy epoch/expiry is checked at use, including cache hits and cursors.

Default to complete Live subscriptions with cheap reads. Later suppression must
account for negative dependencies (absence of facts, empty joins), retractions,
permission changes, independent journals and time. A query watch is a computation,
not proof of cheapness. Rebind replaced resources under an owner protocol:
subscribe to replacement, capture/reconcile current state, switch, then unlisten
old; make any non-atomic gap recoverable by reconciliation. Do not infer a safe
attribute set merely from the last rows returned.

* Commands, attempts, forms and drafts
** One schema owner per semantic boundary
Command schema owns coercion/normalization and input validation. Domain handler
owns current business and authorization admission. Storage schema owns persisted
facts. Presentation hints derive fields/widgets without redefining command meaning.
Use the same normalized input and domain handler for HTTP/MCP/socket adapters.
They retain their own size/content/auth/CSRF rules, safe errors and receipts.
Never assume an HTML constraint is command validation.

** Attempt state machine
#+begin_example
editing draft -> capture attempt(id, operation, normalized payload, basis,
                                 principal/scope, expected revision)
ready -> submitted -> confirmed | refused | unknown
unknown -> lookup/reconcile same identity -> confirmed | refused | unknown
refused -> explicit edit/new attempt
confirmed -> explicit new attempt
#+end_example

Identity allocation occurs at an explicit opening/submission boundary. Before
capture, editing is allowed; after submission, payload/preconditions are frozen.
Changing either requires a new attempt after resolution/explicit workflow rule.
A deterministic component ID is not an idempotency key: multiple real commands
on one component need distinct attempts. Durable duplicate handling checks payload
binding; a repeated ID with changed payload refuses. Deduplication retention/window
is a protocol choice, not an infinite exactly-once theorem. Expired receipts must
not silently permit an old request to create another external effect.

Lost connection after acceptance is unknown to the client until receipt lookup.
A cancelled observation or navigation does not undo accepted work. Server/provider
confirmation and local publication may differ: retry eligible publication using
its original authentic receipt; do not resubmit the provider effect. A provider
with neither idempotency nor trustworthy readback may require manual reconciliation.

** Identity and browser controllers
Stable component namespace = feature + role + entity/form instance. Keys identify
siblings; DOM IDs/label targets use an injective encoding of that namespace plus
field. A realized-tree guard catches duplicates and caps output. Hash collisions
must be handled, not assumed impossible. Do not use array position or render UUID.
Loom field constructors could accept an explicit scope and draft path; existing
flat assign paths need a compatible adapter for multiple simultaneous forms.

Choose exactly one editable-state owner per field: socket locals for ephemeral
connected state, application private world for persisted private sessions, or
browser storage for offline drafts. Browser-focused input buffers may temporarily
own unacknowledged edits; that is a documented reconciliation protocol, not an
extra authoritative copy. Files/passwords remain ephemeral and out of generic
persistent drafts. Rendered command basis is not overwritten during patch restore.

A proposed controller island has =mount(root, public-data)=,
=update(handle, public-data)= and =dispose(handle)=; root identity and code version
are explicit. Targeted patch hooks dispose removed roots once, update retained
ones and mount inserted roots. Native Live hooks must first be checked/extended;
this exact general controller API is not asserted to exist today. Avoid arbitrary
scripts as feature data. Root-local controllers release listeners/timers/observers
on removal, navigation and generation replacement, and preserve focus/input ack.

* Five realistic authoring examples
These sketches exercise one proposed vocabulary. Each app supplies real domain
functions; declarations never replace their validation or provider semantics.
A complete future example must include constructors' signatures and executable
fixtures before appearing in a scaffold. This research supplies design contracts.

** 1. Tiny CRUD: personal notes
#+begin_src clojure
(def save-input
  {:id :note/save-v1
   :fields [{:name :id :type :uuid} {:name :title :type :string :max-length 200}
            {:name :expected-revision :type :int}]})
(def save-note
  (command/describe {:id :note/save :input save-input :perform notes/save!
                     :receipt :note-attempts :access notes/owner?}))
(def notes-page
  (read/describe {:id :note/list :plan notes/by-owner-title
                  :limit 40 :fields [:note/id :note/title]
                  :budget {:rows 1200 :seeks 800 :bytes 1048576}
                  :count :omitted}))
(defn notes-screen [{:keys [items edit]}]
  [:section
   [:ul (mapv (fn [n] [:li {:key (:id n)} (:title n)]) items)]
   (component/form {:scope [:notes :edit (:id edit)]
                    :schema save-input :hints {:title {:label "Title"}}
                    :draft (:draft edit) :attempt (:attempt edit)})])
(def notes-feature
  (feature/describe {:id :notes
    :routes [{:path "/notes" :read notes-page :screen notes-screen
               :access notes/signed-in?}]
    :operations [save-note]}))
#+end_src

Composition opens one store and command owner, binds principal resolver and
read/command adapters, and serves the ordinary Live app. No worker, solver,
materialized product, global index or private database is required for one
inline draft. SSR can render a blank editing state; opening/submitting captures
attempt through a handler. Save atomically checks owner/revision, writes title
and receipt, then publishes. Positive: a response-loss retry returns the same
receipt. Rejected: same attempt ID with changed title, foreign note ID, render
calling UUID or owner. Unknown: dynamic renderer reaches an unmodeled host op;
ordinary diagnostic mode remains available, strict render publication does not.
Unsupported: arbitrary regex search under this title-order page plan.

Contrast: current plain Live maps/functions can already build most of this;
the proposed support adds finite scoped reads, reusable attempt/identity adapters
and checked evidence. A feature description should remain optional for this size.

** 2. Multi-tenant catalogue: search/list/detail
#+begin_src clojure
(def catalogue
  (feature/describe {:id :catalogue
    :requires {:reader :catalogue-read :writer :catalogue-command}
    :routes [{:path "/teams/:team/items" :access membership/read?
               :read catalogue-page :screen catalogue-list}
              {:path "/teams/:team/items/:id" :access membership/read?
               :read catalogue-detail :screen catalogue-editor}]
    :operations [rename-item]}))
(def catalogue-page
  (read/describe {:id :catalogue/page :source :catalogue-read
    :plan catalogue/authorized-title-page
    :search {:mode :normalized-title-prefix :max-length 120}
    :order [:normalized-title :id] :limit 40
    :hydrate {:fields [:item/id :item/title :item/status]
               :max-entities 40 :max-bytes 262144}
    :budget {:rows 1600 :seeks 1200 :bytes 2097152 :continuations 3}
    :count :omitted}))
#+end_src

Policy constrains root and related entities before selection/count; checked
hydration accepts only selected IDs and allowed fields at the same data view,
with current authorization freshness. Detail independently checks the requested
ID, including a forged route parameter and cross-tenant reference. Counts over
joined shared rows follow disclosure policy too. Search normalization/collation
and prefix semantics are pinned plan/schema inputs, not inferred from a text box.

Positive: a compound tenant/title order returns the same fixed page and bounded
physical work as foreign history grows. Incomplete: too few allowed rows found
within budget; UI offers a bounded explicit continuation or narrower search.
Refused: authorization joins make plan unadmitted, cursor from another principal,
or policy expired. Unknown: a custom membership callback cannot close static
coverage. Unsupported: substring/full-text/ranked search until a qualified plan
or causally maintained index exists. A permission-revocation event invalidates
cached display and continuation even if item rows did not change. Revocation
latency is a stated session contract; no claim erases already disclosed bytes.

Contrast: B links routes/policies once; C can check covered render/read closure.
Neither creates a bounded full-text engine. The data-product option is justified
only if independently budgeted maintenance wins the workload comparison.

** 3. Hotel-style external effect: approve and book
#+begin_src clojure
(def accept-offer
  (command/describe {:id :booking/accept :input booking/accept-input
    :perform booking/admit-approval! :receipt :booking-attempts
    :effects [:enqueue-booking]}))
(def booking-worker
  {:entry booking/execute-original-operation!
   :queue :booking-operations :owner :booking-executor
   :provider-contract :pms-booking-v1
   :outcomes [:confirmed :refused :uncertain]
   :reconcile booking/readback-original!})
(def booking-feature
  (feature/describe {:id :booking
    :routes [{:path "/offers/:offer" :access booking/guest-scope?
               :read booking/guest-offer :screen booking/offer-screen}]
    :operations [accept-offer] :background [booking-worker]
    :deadlines booking/next-visible-deadline}))
#+end_src

Admission validates authenticated guest disclosure/consent, exact terms
fingerprint, current offer/version and original attempt. In one local transaction
it records approval and durable work intent; no UI render performs the effect.
The native queue owns execution identity, lease, retry/cancellation and journal.
The provider adapter enforces actual credentials/mode and idempotency/readback.
Its result can be provider-confirmed while hotel publication failed: preserve
both facts and retry only the eligible local publication with original fences.

Positive: duplicate guest submit returns original local receipt and does not
enqueue a second provider create. Refused: stale terms or absent guest approval.
Uncertain: provider accepted but response vanished; show reconciliation pending.
Rejected: agent supplies a forged guest approval or new effect ID after uncertainty.
Unknown: solver cannot model provider consistency; a model proof covers only the
local abstract transitions. Unsupported: exactly-once delivery to a provider
without a sufficient idempotency/receipt contract. Mounted-browser disclosure
acknowledgement remains separate from SSR or socket enqueue.

Contrast: workflow graphs can explain phases, but should derive from the native
operation contract rather than introduce a second hotel operation state machine.

** 4. Long-running job: tenant export
#+begin_src clojure
(def request-export
  (command/describe {:id :export/request :input export/input
    :perform export/enqueue! :receipt :export-attempts}))
(def export-job
  {:queue :exports :entry export/run-chunk!
   :reads export/scoped-snapshot-plan
   :chunk-budget {:rows 2000 :bytes 4194304}
   :total-budget {:rows 2000000 :bytes 536870912 :duration-ms 1800000}
   :progress export/public-progress
   :cancel export/request-cancel! :owner :export-supervisor})
#+end_src

Submission returns a durable job ID; navigation does not keep an HTTP request
alive. Each chunk persists progress with original snapshot/policy semantics and
output artifact identity. Snapshot retention and maximum job lifetime are explicit.
A long export can require continuing permission and halt on revocation, or may
have an explicitly authorized captured-scope policy; choose one, do not inherit
it accidentally from a frozen DB. Progress is a small read model observed through
Live; numeric progress does not require rereading every exported row.

Positive: process dies after writing a chunk; resume adopts the existing chunk
identity/checkpoint, without duplicate output. Cancel means future admission is
closed and accepted chunk drains; completion/cancel race has a specified outcome.
Refused: export scope exceeds admission or artifact quota. Unknown: destination
accepted upload without response. Unsupported: cursor TTL used as a durable job
checkpoint without a separately qualified durable snapshot protocol. A job can
complete after its socket dies; socket-owned cleanup must not close job resources.

Contrast: the same six concepts compose, but interactive page budgets and job
budgets differ. C's nonsuspension check is useful for some actor callbacks; the
whole worker may legitimately block/yield at qualified queue/IO boundaries.

** 5. Private offline draft: inspection report
#+begin_src clojure
(def report-draft
  {:id :inspection-draft-v2 :owner :browser
   :fields [:title :observations :base-revision]
   :storage {:scope [:principal :team :report :device]
              :max-bytes 262144 :expiry-ms 604800000}
   :merge inspection/three-way-merge
   :on-revocation :lock-and-purge :secrets :excluded})
(def submit-report
  (command/describe {:id :inspection/submit :input inspection/input
    :perform inspection/submit! :receipt :inspection-attempts}))
#+end_src

Browser is the editable draft owner; SSR shows authorized saved state plus a
placeholder until local draft reconciliation. A compatible versioned draft loads
only for its principal/team/report namespace. Reconnect retrieves current read
model and compares base/current/draft; conflicts become explicit choices before
capturing a submission attempt. Neither navigation nor reconnect auto-submits.
Two tabs need a specified lock/version protocol or conflict handling. A private
server world can store connected drafts instead, but that is a different owner.

Positive: disconnected edits survive refresh and merge nonconflicting fields.
Refused: new authorization denies submit even if draft exists locally. Unknown:
server committed but acknowledgement lost; resolve captured attempt first.
Unsupported today: generic framework offline synchronization, remote erase of an
offline device, secure persistence of files/passwords, or arbitrary conflict-free
merging without domain semantics. Lock-and-purge happens on next contact/logout
where code runs; it is not proof that a revoked offline browser deleted data.
If offline data is too sensitive to retain, select connected private drafts.
Client encryption/key management is a separate qualified design, not a schema flag.

Contrast: C may justify portable pure merge code over its supported model, but
it cannot authorize shipping private fields or guarantee storage security.

* Writer transactions, retained DTOs and identity precision
Read budgets do not bound writer normalization, retraction/index folds or owner
repair. Parent reports strict folds/small-record normalization repaired native
lazy-retention budget failures; 512MiB lazy-cache admission differs from the 8MiB
optional value-cache entry limit. Pure/strict folds may still traverse full worlds.
Budget charged retained bytes, transient allocation, record/relation/history work
and accepted turn duration, not only transaction input count.

Parent's one 80-record transaction exceeded 30s; ten 12-record fixture transactions
are a bounded multi-commit workload, not proof unbounded bulk now works. Do not
silently split an all-or-none command. Prefer bounded deltas or explicit resumable
imports with durable partial-progress/readiness semantics, source/facet checkpoint
consistency per commit and idempotent receipts. Staging plus atomic switch is a
separate qualified design. Timeout after accepted work does not authorize replay.

Renderer DTOs should contain eager, bounded, authorized presentation values,
completeness/result state, explicit time and safe scalar journal bases. Keep DB/
worker handles, plans and command/provider capabilities in owned composition/read
adapters. Remove unused resources only after consumer/deadline/fallback inventory;
the reported final cleanup's rerun remains pending, with no extra speed claim.
DTO shape/purity alone establishes neither size nor disclosure authorization.

Separate exact data-view identity, normalized relevant attribute/schema evidence,
actual code/dependency identity and fresh provider-catalogue semantics. Opaque
catalogue tokens can cause conservative false conflicts; narrowing them is valid
only with a complete dependency argument and fresh stored-provider proof. A new
computed shadow, changed schema/helper or stale checkpoint still refuses reuse.
Do not equate equal rows or a hash of outputs with unchanged computation meaning.

* Ownership, startup, supervision and deployment
The app instance is a lifetime boundary. It binds configuration once, opens
stores/clocks, initializes required read products, registers providers/queues,
prepares exact generation callbacks, and starts web transport only after required
readiness. Optional capabilities report disabled/unavailable explicitly; they do
not trigger lazy =open!= during rendering. Readiness distinguishes compiled,
resources acquired, migrations complete, read plans ready, worker ready and
serving. A boolean PID-alive check is insufficient.

Acquisition records owner, borrowed inputs, native registration, code graph,
children/timers/subscriptions and cleanup outcome. Reverse-order cleanup runs for
successfully acquired owned resources; borrowed stores are not closed. Partial
failure is classified before-effects, observed partial resources or uncertain.
An initializer that may have started external work cannot be blindly rerun.
Shutdown closes future admission, joins/drains accepted work, unlistens timers,
releases code and closes owned stores. Supervision/recovery policy is per owner,
not a general "restart every failed callback" rule. Timed-out callers cannot infer
that the callee did nothing. Cancellation status must separate observation,
admission and effect settlement.

Reload keeps old sessions/workers on captured immutable callback generations
until drain or an explicitly compatible handoff. New requests use the newly
published generation; old callback + new schema/policy needs an explicit
compatibility story. Resource handoff transfers native authority under existing
owner/epoch rules, not by copying a descriptor. Reconnect must not silently switch
an old private session's original callbacks to latest ambient code.

Source-free packaging captures compiler/SDK identity, generated declarations,
primitive models, selected source/compiled units, schema/migrations, policy,
assets, timezone data, provider protocol versions and explicitly declared resources.
Resource roots cannot rely on cwd or sibling checkouts. Analysis constructors
advertised in SDK must initialize in a fresh consumer with no app actors. Do not
regenerate SDK just to inspect this design; qualification is future work.
Rollback changes executable selection, not durable business history, provider
outcomes, journal receipt identity or irreversible schema changes.

* Assurance and unknown semantics
| Level | Meaning | Suitable gate |
|-------+---------+---------------|
| Described | Well-formed linked values, declared requirements | Composition consistency only |
| Checked | Current complete supported structural/type/effect evidence | Selected strict roles; exact claim scope |
| Enforced | Qualified native authority/budget/lifetime checks | Runtime admission on all entry paths |
| Verified in model | Finite exhaustive/symbolic claim under named semantics | Specific invariant with abstraction/domain assumptions |
| Observed | Executed native/browser/property/process/package evidence | Behavioral/performance qualification for exact cohort |

These are complementary dimensions, not a single total order. A model proof can
have narrower implementation coverage than a sampled adapter test. A runtime cap
can hold even when a compiler proof is unknown. A successful benchmark says
nothing about permission correctness. Gate requirements are per claim.

Normalize each obligation to claim ID, entry/original reference, exact input
identities, domain/model/assumptions, engine/version, requested budget, status,
coverage denominator and excluded sites, cost, witness/replay, and invalidation
reason. Status distinguishes proved, refuted, unknown, unsupported/unchecked,
error, stale, cancelled and witnessed. Refusal of execution is an operational
outcome, distinct from logical refutation. Do not conflate page-incomplete with
solver-unknown. Preserve original raw engine result alongside normalized meaning.

Required strict obligations accept only their specified modalities and full
applicable coverage. No warning, no counterexample, empty target inventory or a
supervisor aggregate :ok cannot pass a missing obligation. Absence of a solver
is an explicit unknown/unsupported result. Native contracts remain checked at
runtime even if all static obligations pass. Ledger receipts need current
transitive identity binding; existing historical rows cannot be upgraded by fiat.

* Allocate analysis without duplicating systems
Use contextual compiler Source/ANF identities as prepared input and reuse existing
IR/summary/type/arity/effect consumers. Datalog computes architectural dependency
closure and negative reachability obligations over complete facts. Structural
query/cardinality admission and native meters answer bounded-data work first.
Ownership analyzes resource paths, suspension handles callback blocking, linear
handles emission growth, and place proposes target eligibility. They remain
separate predicates with a shared provenance wrapper.

Finite AF/GFP models investigate scheduler/attempt/resource protocols with explicit
finite domain and fairness assumptions. SMT proves translated arithmetic/transition
obligations with explicit sorts, overflow/float/exceptions constraints; a finite
counterexample search is one-directional evidence. miniKanren proposes guards;
accept only after independent verification. Veritas executes behavior/generated
histories and records seeds/shrunk witnesses; process/browser/package tests check
native conformance. Deodorant and span-preserving contextual refactors assist
eligible migrations; semantic query/auth/workflow changes remain reviewed edits.

Bootstrap trusted leaves once: compiler extraction/identity, primitive semantics,
backend metering, policy evaluation, native custody and adapters. Do not prove the
role checker using its own unqualified =:pure= claims. Do not make native execution
import a source-analysis graph; compilation/publication produces evidence and
native runtime consumes fixed authenticated identities. Avoid keeping one
handwritten effect table per subsystem: evolve canonical exact operation/arity
contracts and qualify every consumer projection against it.

* Incremental tooling/MCP contract
Initialization advertises cheap capabilities, SDK identity and index status only.
No project import/actor startup/index-tree/solver is mandatory for handshake.
Analyze a requested entry/file/feature closure; broaden only when a claim actually
needs whole-owned-corpus coverage. Unindexed callers remain unknown for a global
negative claim. Keep separate costs for parse, extraction, expansion, ANF, flow,
summary, graph, solver, serialization and retention; warm/cold samples distinct.

Prepared snapshot identity includes source bytes, reader/compiler/SDK, selection
and transformer phases/revisions, primitive model and target. Feature evidence
adds schema/policy/query/adapter identities. Edits invalidate old AND new reverse
dependency cones, deletions, macro expansion and latent callback uses. Stable
immutable cache entries have finite memory/TTL and generation fences. Unchanged
source identity avoids parsing when supported; current system.incr only avoids
some summary work and should report that honestly.

Proposed tool operations: describe-feature; analyze-entry with scope/budget;
explain-obligation with origin/callee/unknown; inspect-read-plan without execution;
inspect-current-runtime-receipt through existing native metadata scope;
compare-source-to-emitted; list-stale-evidence; run-selected-negative-fixture.
They return partial progress and cancellable IDs with exact task attribution.
They never mint native admission by returning facts, execute application code to
discover a description, or repeat provider writes to collect evidence.
