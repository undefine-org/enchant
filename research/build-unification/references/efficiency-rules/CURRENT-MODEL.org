* Datom: exact immutable views do not imply bounded reads
** Ordinary query and authorization
S: [[file:../../priv/lib/datom.bl::(defn query-context][query-context]] is a map containing =:query-db= and a scope function.
=run-scoped= calls that function, executes the rewritten query, and releases
scope resources in =finally=. Policy refusal throws; it is not universally
returned as a page result. =q= otherwise executes the ordinary query engine.
Its count optimization falls back to ordinary execution when ranked count is
unavailable. An exact ordinary count therefore has no general bounded-work claim.

S: [[file:../../priv/lib/auth.bl::(defn query-context][auth/query-context]] invokes =rls/scope-all= for each query, evaluating a
functional policy against the captured database. [[file:../../priv/lib/auth/rls.bl::(defn scope-all][scope-all]] discovers variables
reading configured protected attributes and refuses shapes it cannot scope.
Protection is relative to that attribute/path policy. A newly introduced
sensitive attribute omitted from the policy is not magically protected.
This is query rewriting, not a native unforgeable read capability.
The handle is ordinary data. Its embedded DB is available to application code.

S: [[file:../../priv/lib/datom.bl::(defn pull][pull]] and =pull-many= delegate directly to =datom.pull=; =entity= likewise
reads the supplied DB. They do not dispatch through =run-scoped=. =pull-many=
is not an authorization proof or a composition-wide hydration budget. Nested,
reverse, recursive and to-many pull patterns need separate admission and costs.
T: [[file:../../test/bl/auth/query_context_test.bl][query-context assertions]] exercise policy changes, cleanup on failure and
scoped pages; a compound-index test compares profiled foreign-population growth.
They do not establish a sealed scoped-pull abstraction.

** Cursor pages
S: [[file:../../priv/lib/datom/query/page.bl::(defn- descriptor][descriptor]] admits a deliberately closed fragment: relation results projecting
an entity root, ordered indexed value/entity ID, cardinality-one functional
forward clauses, safe comparisons, 1–16 clauses, current filter mode, no
since/valid-time view, variable input forms and no =:with=. Joined clauses must
be evaluable from already bound entities; arbitrary fan-out, reverse expansion,
aggregation and user predicates are outside this fragment. Physical compound
paths and complete index coverage can bound scope selection.

S: [[file:../../priv/lib/datom/query/page.bl::(defn page][page]] checks substrate capability, limit 1–1000, exact context identity,
integer positive row/seek/byte budgets, token shape, authorization expiry and
namespace generations. Defaults are 4096 rows/seeks and 8MiB; these defaults
are not an end-to-end page budget. =complete-attribute= reads whole history
groups to establish current facts, charging physical datoms, seeks and bytes.
The query evaluates permission clauses before accepting a row.

Results are =:exact=, =:incomplete= or =:refused=. Incomplete exposes no partial
rows; retained accepted rows accompany a server-held retry cursor internally.
=:exact= means this admitted page is valid, not that all matches were counted.
At exactly the requested row limit =:more?= can be true before checking the next
candidate: it is a continuation hint, not proof that another visible row exists.
Tokens expire within five minutes and bind DB view, query, inputs, order, limit,
authorization data and code identity through a fingerprint/cache context.
Cache eviction, source generation change or changed DB can invalidate a token.

I: =:authorization= is caller-supplied context, not an independent proof of fresh
permission. Rewriting incorporates current policy only to the extent its captured
basis/policy source is current. Permission revocation outside that basis needs a
separate freshness fence. Retaining an old immutable basis can preserve historical
facts; it does not decide whether a user is still entitled to see them now.

I: every invocation can be bounded while total continuation work is unbounded
with population. More subtly, if =evaluate= exhausts its budget inside one
attribute group, page returns a continuation with the previous driving position,
not a partial attribute-group offset. Repeating the same insufficient budget
can repeat that work indefinitely. This follows from =complete-attribute= and
the =:incomplete evaluated= branch; it is a source-derived progress risk, not
an executed liveness failure. Require cumulative attempt budget and no-progress
handling; do not promise that every incomplete page eventually becomes exact.

T: [[file:../../test/bl/datom/query_page_test.bl][page tests]], [[file:../../test/bl/datom/query_page_joins_test.bl][join tests]], [[file:../../test/bl/datom/compound_page_test.bl][compound tests]] exercise admitted/refused plans,
historical group budgets, old basis versus changed cursor, sparse filters and
functional joins. They are useful specifications; no passing execution is
reported here. Metering at the language loop does not alone establish that
backend iterator setup, decoding, cache identity and policy construction have
bounded CPU/allocations. Qualify the actual substrate and whole path.

valid abstract model for explicitly constrained exact money operations; it is
not an honest proof of arbitrary BEAM float arithmetic.

* Tooling cost and integration seams
S: [[file:../../priv/lib/mcp/server.bl::(defn- codebase-registry][MCP registry]] requests =engine-conn=; [[file:../../priv/lib/mcp/tools.bl::(defn- index-groups!][index-groups!]] calls =code.index/ensure-tree=
before deciding whether the requested groups fit the shared index. Thus engine-only
initialization can attempt project indexing. This independently supports the
frozen report's suspected eager path; no causal timing experiment was done here.

There are several legitimate representations: reader/spans, expanded contextual
bindings, ANF, interprocedural summaries, emitted entries, native loaded code,
and domain/query models. They should share identity/provenance and reuse prepared
work, not be collapsed into a graph that erases phase or authority distinctions.
=system.incr= alone does not solve repeated parsing/expansion for every consumer.

Avoid a circular bootstrap: the footprint checker imports compiler/IR; checked
application declarations may need those summaries; generation sealing imports
proc contracts; native execution must not need a fresh application analysis at
each call. A bounded trusted compiler/primitive substrate must produce immutable
evidence; publication consumes it, native admission checks exact runtime custody.
The root manifest is a composition index, not a new authority over all subsystems.
