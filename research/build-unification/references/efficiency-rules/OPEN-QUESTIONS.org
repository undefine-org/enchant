* What this research establishes
The current code has complementary useful mechanisms but no single checked
application contract. Ordinary values/composition can unify authoring without
making a feature manifest a new authority. Source inspection supports the
specific contracts in [[file:CURRENT-MODEL.org][CURRENT-MODEL]]. [[file:RECOMMENDATION.org][RECOMMENDATION]] specifies a falsifiable
supported path, not an implemented or qualified API. No runtime performance,
formal proof, browser pass or package qualification was newly obtained by this
review. Later supplied executed read evidence is assessed separately in
[[file:EXECUTED-FINDINGS.org][EXECUTED-FINDINGS]]; it narrows some cache-cost uncertainty without closing
browser latency, scaling, or final native regression gates.

* Soundness boundary and residual trust
The trusted base includes compiler expansion/resolution and emitted identities,
primitive/host semantics, storage/index/schema correctness, budget metering,
policy and authentication implementation, native execution custody, provider/DOM
adapters, packaging verifier and solver/tool version where used. This list is
not a theorem that those components are correct. Each accepted claim should
name which leaves it relies on and which conformance tests qualify them.

Overapproximate reachability can reject a safe program; underapproximation can
falsely certify a dangerous one. Opaque host/dynamic callbacks must not disappear
from the denominator. Proving no forbidden edge in a selected subgraph only covers
that subgraph. Descriptor presence proves no effect property. A branded value
constructed by caller data grants no authority. Type =any= and warning silence
cannot close a required shape obligation. A finite safe-region proof relative
to a hand-written graph cannot certify an unconnected native scheduler.

Repeated evidence identities are not execution admission. A hash is useful for
provenance/cache lookup but does not replace exact identity/custody validation.
Every proof has a domain and translation; missing assertions, default sorts,
float/Real abstraction, exception behavior and unchecked children must be explicit.
The decision ladder's native SAT witness establishes only existence in its parsed
fragment; absence never proves nonexistence. miniKanren guards need independent
checking. Ledger success without freshness binding remains historical evidence.

* Alternatives deliberately not recommended as defaults
- Whole-application page DSL: high semantic centralization and adapter burden;
  offer small explicit composition and inspectable expansion instead.
- Mandatory materialized views for every read: expensive maintenance/backfill,
  recovery and lag for tiny or low-demand applications.
- Inferred attribute subscriptions from observed rows: misses negative dependencies,
  authorization and clock-only changes; preserve complete Live subscriptions.
- Universal "pure" flag: confuses read-only, deterministic, bounded, synchronous,
  terminating, portable and authorized. Preserve separate checked predicates.
- Automatic q/filter/sort/take-to-page rewrite: ordering, ties, scope, count and
  unsupported semantics differ; migration requires a reviewed plan.
- One schema for storage, commands and forms: distinct invariants; derive presentation
  from operation schema and reference storage schema deliberately.
- Mandatory socket commands: HTTP uploads/OAuth/webhooks retain transport rules.
- Exactly-once provider abstraction: absence of provider idempotency/readback cannot
  be hidden; keep original identity and uncertain/manual settlement.
- A second checker/parser/effect registry/proof ledger or app-owned callback registry:
  integrate with existing compiler/Veritas/native custody seams.
- Automatic code deletion from no indexed callers: external/launcher/dynamic consumers
  are not disproved by a scoped query. Inventory before retirement.

failure or a reason to relax SDK memory ceilings. Below-limit r2 charge describes
this value/store only. Original source findings remain labeled S/T/P/I; supplied
JSON observations are E and the accompanying Backdesk change account is U.
Neither the JSON nor this review supplies missing app/source/dataset hashes.
See [[file:EXECUTED-FINDINGS.org][the detailed comparison and alternatives]] for all phases, including unchanged or
slower ones. A warm improvement is not proof of bounded work or browser acceptance.

Audit 1/2/8/13/30 now additionally require semantic cache-validity evidence,
retention/publication visibility, closure-retention cost and cache-independent
admission. Canonical data versus capture overlays/local indexes is a lifetime
boundary, not a new schema authority. An owned prepared model is a different
availability contract from an optional cache. Durable attempt receipts must
never depend on either's incidental cache availability.

* Additional risks beyond the page audit
Command writer full-world diff cost can dominate even after read improvements.
Do not double-run effectful commands for shadow comparison. Derived memberships
can add write amplification and break a writer latency budget. Stable component
identity does not prevent XSS or authorize public serialization; output escaping
and data disclosure still need tests. Offline state survives server revocation
until client contact and cannot be remotely erased by an abstract draft flag.

Publication/reload compatibility is not data migration compatibility. Old sessions
and long jobs may outlive schema/policy changes; model retained generations,
receipt lifetime and durable schema versions explicitly. Source-free artifacts
must preserve tooling declarations/resources as well as ordinary execution.
A fresh consumer smoke check is necessary and weaker than application acceptance.
