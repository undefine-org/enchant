* The small contract
#+begin_lede
*Yes: a light V1 → V2 → V3 system fits.* Extend Foundry's existing release
checks and activation journal. Keep conversion and verification in Datom.

This key correction is one production risk. Runtime compatibility, application
data, persisted work and rollback have their own checks.
#+end_lede

#+begin_rosetta
Version | Meaning | Current observation
Beam Lisp release | Executable, SDK, native libraries and OS requirements | v2026.9 targets Linux x86_64 / glibc ≥2.44; Hera pins SDK db92b849e5. A tag does not update that pin.
Datom format | How facts are encoded and indexed | Proposed format 2 fixes equal sequence/numeric keys. Hera's health does not report this format yet.

V1 → V2 → V3 uses ordered, immutable steps with code digests and durable
progress. Completed steps are not run again; page writes and their cursor commit together.

#+begin_rosetta
Change | What happens
Same versions | Open normally. No conversion or full database scan.
Datom format 1 → 2 | Rebuild keys; preserve original facts, transaction IDs and blobs; check collisions and regenerate derived indexes.
Application data change | Reuse datom.migrate's immutable step IDs, digests and transaction ledger.
Unknown format or missing step | Keep the installed generation selected; refuse the upgrade.
#+end_rosetta

A header alone grants no permission. Legacy format detection must bind to a
known predecessor; Foundry's existing storage.format describes cache layout,
not Datom encoding. Keep those meanings separate.

* Fit the existing release flow
#+begin_sequence :title "Existing Foundry deployment + one storage phase"
lanes Foundry · existing job | Hera · single writer | Datom · proposed converter
Foundry -> Foundry : Build and verify pinned app/runtime while Hera serves
Foundry -> Hera : Stop and drain writer; take quiesced backup
Foundry -> Datom : Convert into separate generation only when format changes
Datom --> Foundry : Independently verified READY for control, library stores and blobs
Foundry => Hera : Select matching code + data generation; start; verify identities and readiness
#+end_sequence

#+begin_principles
One owner | Native store admission checks format and writer generation. CLI, background work and application opens share that boundary.
One durable decision | Extend the existing activation journal to select code and data together; reconcile crashes and lost replies through the same path.
Original retained | Failed conversion leaves the original selected. After new writes, recovery must preserve them; an old backup is not automatic rollback.
#+end_principles

Hera has a control store, library stores and adjacent blobs. Convert the declared
data-root generation as a whole. A partial target cannot start. Uniqueness or
payload collisions block publication rather than discard records.

Foundry already verifies packages, leases the writer, backs up when configured,
switches releases and checks health. Its current restart path rejects migration
providers. Add a verified converter phase there; do not bypass those refusals.
Durable code/data selection and power-loss recovery still need qualification.

* Hot deployment and the first delivery
#+begin_rosetta
Change | Deployment rule
Code only, compatible runtime/data | Hot eligible through an accepted managed lifecycle. Hera currently uses exclusive restart.
Compatible new attributes/backfill | Existing expand/backfill mechanisms can run under the serving writer after product acceptance.
Field removal or incompatible meaning | Drain old consumers; apply the checked contract step.
Datom bytes or incompatible runtime | Staged restart; copy-convert only when the storage format requires it.
#+end_rosetta

The model below checks route selection only; it performs no conversion or deployment.

#+begin_src beam-lisp :id version-routes
(ns storage-release.review)
(defn route [from target steps]
 (loop [version from remaining 16 path []]
  (cond (= version target) path
        (or (<= remaining 0) (> version target)) nil
        :else (let [edges (filterv #(= version (:from %)) steps)]
         (when (= 1 (count edges))
          (let [edge (first edges)]
           (when (and (= (inc version) (:to edge)) (:code-identity edge))
            (recur (:to edge) (dec remaining) (conj path (:id edge))))))))))
(def steps [{:from 1 :to 2 :id :keys-v2 :code-identity "model-v2"}
            {:from 2 :to 3 :id :future-v3 :code-identity "model-v3"}])
(assert (= [] (route 2 2 steps)))
(assert (= [:keys-v2 :future-v3] (route 1 3 steps)))
(assert (nil? (route 1 3 [(first steps)])))
(assert (nil? (route 1 2 (conj steps (first steps)))))
(assert (nil? (route 1 2 [(dissoc (first steps) :code-identity)])))
(assert (nil? (route 2 1 steps)))
{:same-format :no-conversion :chain :ordered :missing-or-ambiguous-step :refused
 :missing-code-identity :refused :downgrade :refused}
