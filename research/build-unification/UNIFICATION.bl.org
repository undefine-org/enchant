#+begin_lede
*Keep one implementation on main.* The useful runtime, JavaScript, Android,
scene-library and readiness changes are already there. Twenty-two redundant
worktrees have been removed with their histories and local artifacts preserved.

The next build improvement is shared input analysis and bounded restoration of
cached units. Reuse the process patterns we have, keep one publisher, and let
the existing Nix worker policy place production on Build.
#+end_lede

#+begin_note :title "Two structural causes in today's code"
=unit-store/produce!= still uses a serial reduce over the SDK units.
The ordinary build's =pmap-ordered= runs bounded chunks and waits for a chunk
before admitting the next. A jobs setting above either boundary does not make
the serial SDK restoration loop concurrent.
#+end_note

** Start with input sharing and cached restoration
The first change should reduce repeated dependency hashing across the 505 reused
units. Then admit independent artifact verification and private staging as a
bounded stream, starting the next item whenever capacity is available. Measure
bytes read, sources parsed, units checked, active workers and phase times.

Compiler preparation can mutate Env and workspace state. Keep its current
ordering until independence is established. Private worker output is distinct
from accepted publication; a cancelled waiter does not imply an accepted effect
can be replayed.

** Keep the bootstrap able to build its own libraries
The compiler also builds =proc.task= and =proc.flow=. Bootstrap execution must
use primitives available in the committed floor. Adopt the richer process API
after admission; a build cannot require the new library it is still producing.

** Improve placement separately
Heavy production already follows the configured Build worker policy. The
remaining local Nix evaluation on Work is a separate placement cost; moving
compilation alone does not move evaluation. Reuse =artifact-jobs= and the
existing coordinator rather than introducing a second durable scheduler.

** Preserve all the identity checks
Runtime-image changes can still invalidate the SDK unit target conservatively.
Separating emitted-code reuse from runtime admission needs its own evidence.
Do not delete the runtime gate, relabel previous units, or substitute historical
SDK receipts to claim a faster build.

The next cell is a small model of the intended publication boundary. It checks
that an obsolete result, an input mismatch and a partial result cannot publish.
It does not execute or qualify a production scheduler.

#+begin_src beam-lisp :id publication-boundary
(defn publishable-result? [current result]
 (and (= (:attempt current) (:attempt result))
      (= (:inputs current) (:inputs result))
      (= (:target current) (:target result))
      (= (:expected current) (set (keys (:units result))))
      (every? :verified (vals (:units result)))))
(def current-request {:attempt "request-2" :inputs "captured-inputs"
                      :target "qualified-target" :expected #{"changed" "cached"}})
(def complete-result {:attempt "request-2" :inputs "captured-inputs"
                      :target "qualified-target"
                      :units {"changed" {:verified true} "cached" {:verified true}}})
(assert (publishable-result? current-request complete-result))
(assert (not (publishable-result? current-request (assoc complete-result :attempt "request-1"))))
(assert (not (publishable-result? current-request (assoc complete-result :inputs "changed-inputs"))))
(assert (not (publishable-result? current-request (assoc complete-result :target "other-target"))))
(assert (not (publishable-result? current-request (assoc complete-result :units {"changed" {:verified true}}))))
(assert (not (publishable-result? current-request
 (assoc-in complete-result [:units "cached" :verified] false))))
{:model "complete, current, exact inputs and target" :accepted 1 :refused 5}
#+end_src
#+RESULTS: publication-boundary
: {:accepted 1, :refused 5, :model "complete, current, exact inputs and target"}
