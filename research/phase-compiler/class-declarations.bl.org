#+title: One class declaration Source owner
#+date: 2026-10-30

* Discovering a class must not construct it
A class declaration names several bindings: the type itself, its positional
constructor, and, for records, its map constructor. Discovering those bindings
must not load the class module or execute protocol bodies. The compiler now
projects them from the same header used by ordinary class compilation/prelinking:

#+begin_example
(require '[compiler :as compiler])
(compiler/class-declaration-source
 (BeamLisp.Reader/read_one "(defrecord Packet [payload])")
 (compiler/new-env "example"))
;; :name Packet
;; :fields ("payload")
;; :bindings ({:name Packet :role :type}
;;            {:name ->Packet :role :positional-constructor}
;;            {:name map->Packet :role :map-constructor})
;; :descriptor is the exact original Record.declaration_descriptor result.
#+end_example

The two-argument API consumes actual Reader data and a checked compiler
environment. Its result also retains inert metadata/visibility and original
protocol Reader forms. Use positioned Reader forms when authored metadata matters.
The compiler's private class-source function is shared by compile-defrecord,
deftype, prelink-type and this projection. The original native Record owner still
constructs/validates the immutable descriptor. No second class representation,
registry or constructor implementation is introduced.

* What changes now
All three consumers reject malformed name/field-vector headers before publication
or prelinking. Duplicate fields retain their original descriptor behavior.
Prelinking installs only compiler-owned class-declaration metadata. Ordinary
compilation emits the same ANF as the prior immutable compiler for valid records
and deftypes; actual constructors retain native struct/map and tagged tuple ABIs.

* Remaining class integration is a custody obligation
The catalog must derive every generated binding from this Source owner, with
canonical phase-qualified identity, authored privacy and ordered initialization.
Defining macros must feed the same declaration inventory. Class initializers and
constructors must retain the original execution/generation owner.

Contextual v3 artifact verification currently permits only runtime and phase
members. Class code must become an exact admitted member through the original
generated-class preparation/verification path; an initializer must not create
unlisted class code. Preserve preboot validation, actual loaded schema/executable
checks and leases. A retained class cannot change schema merely because a newer
unit wants to reuse its physical module. Actual consumer retirement must precede
any collection or replacement. These remain required before contextual activation
and the single default compiler cutover.

* Catalog and archive inventories now consume this owner
A contextual catalog derives all generated names from Compiler's projection. A
record provides Packet, ->Packet and map->Packet; a deftype provides Packet and
->Packet. All slots share the original header's privacy and phase. A deterministic
ordinal extends each actual declaration path, so a generated slot has a separate
canonical binding coordinate without pretending it is separately authored text.

* Binding kind does not identify its declaration protocol
A constructor has binding kind function, while its Source form is defrecord or
deftype. The first causal run found it entering ordinary SDK function metadata
handling before the class-demand guard. The guard now runs immediately after
recipe selection, before metadata dispatch, phase interpretation or runtime
initializer preparation. Runtime and higher-phase demand both return
contextual-class-artifact-membership-required, leaving code/registry untouched.

This guard marks REQUIRED UNFINISHED integration. Replace it by exact generated
class inventory/verification and native generation custody, using the original
class publisher/schema/lease owners. Preserve protocol and phase semantics. An
ordinary publication fallback would erase the artifact membership obligation and
is not an acceptable completion of this path.

* One v4 byte-membership protocol, without circular hashes
Every new contextual unit now uses v4, including a mandatory class-members list.
The factory function ABI remains2 and portable Reader recipes remain3: these
numbers describe different formats, not selectable execution paths. Application
v3 units refuse under the new reader/cache.

A class row contains its actual physical module name, full byte SHA-256 and
logical declaration schema. Logical owner names do not prescribe physical naming;
revision-specific targets need that distinction. Class bytes carry compiler and
input-selection stamps. Runtime/phase metadata then records class hashes. The
class does not embed the completed record containing its own hash. General unit
manifest hashes bind the complete packet afterward.

Native validation bounds all bytes/modules and checks actual BEAM names, complete
factory/phase/class partitions, schema/owner/stamps/exports and hashes before code
loading. It consults no class registry or language compiler. This validates a
declared byte inventory; producer provenance and native admission remain separate.
Metadata alone cannot grant SDK/actor identity or canonical compiler provenance.

World's runtime-beams now contains the factory plus every class. Runtime packaging
keeps that whole set while dropping phase code. The original record descriptor
recognizer ignores the class stamp only when comparing the SAME canonical body.
Cache checks require exact integer protocol versions and mandatory compiler/input
stamps. Five causal failures showed numeric versions and namespace-floor labels
being accepted before the cache fix; that failed run is preserved.
