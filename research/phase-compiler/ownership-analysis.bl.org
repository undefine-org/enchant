#+title: Finite ownership checks over compiler ANF

* One compiler, separate claims

The compiler produces ANF once. codebase.phase validates the selected world and
projects its snapshot. system.phase returns that prepared fact set, its existing
binding report, and a separate ownership report. compile.world retains the
report and exposes ownership-check, ownership-scope and ownership-obligations
through describe and the existing bl world check CLI. An ownership refusal or
unknown result does not change the meaning of the binding proof.

system.ownership/check takes entries [{:id symbol-or-data :body ANF}], an inert
versioned protocol, and optional max-steps/max-states/max-paths/max-summaries budgets. It uses
anf's real grammar validator, system.ir's executable children and call views,
system.gfp's existing finite safety engine, and errors' location bridge. It
does not parse Source, resolve ambient namespaces or create native registrations.
analyze additionally binds its result to codebase.phase's existing snapshot.

* What the finite model says

A protocol maps exact remote MFA/arity or binding-reference ID/arity to a
declared action: acquire, borrow, move, accept, use, release, escape or pure.
These are assumptions about adapters, not extracted implementation conformance.
Use/pure contracts with scalar results promise no resource retention/return;
unmodelled retention, argument effects or callback effects require unknown.
Acquisition with captured resource arguments is conservatively unknown.

The analysis follows aliases, branch alternatives, normal/exceptional exits,
finally cleanup and captured aliases in latent closures. Contracts explicitly
state whether a call can throw before/after its action, never, or unknown.
Borrowed handles prevent owner release/transfer. Moves create pending tickets;
acceptance invalidates the source and creates the target obligation. An explicit
escape transfers the local cleanup obligation out of the checked entry.

The explored graph asks AG(no violation or unknown state) through the existing
greatest fixpoint. It is bounded to 128 entries, 256 protocol rules, 100000
visits, 4096 abstract states, 256 path alternatives and 512 call contexts. Exhaustion returns
unknown, never a partial proof. The current implementation deliberately keeps
exact path states instead of assuming an unproved widening.

proved is relative to the declared contracts and supported immediate control.
conditional additionally lists runtime obligations. refused means a possible
abstract violation; it is not a concrete counterexample. unknown covers opaque
calls/results, unsupported control and exhausted bounds. Every result says
native-admission false. Native admission, process custody, epochs, deadlines
and callback effects still belong to the actual execution owner.

* Real compiler example

The default compiler currently accepts native Execution calls. The closed
syntax-v1 escape grammar deliberately accepts only erlang/ names; this example
therefore uses the default compiler's actual ANF, without fabricated resolved
binding annotations or executing the registration during analysis.

#+begin_src beam-lisp :id registration-cleanup
(ns ownership.walkthrough (:require [system.ownership :as ownership]))
(let [compile (fn [source]
                (BeamLisp.Compiler/compile (BeamLisp.Reader/read_one source)
                                          (BeamLisp.Compiler/new_env "ownership.example")))
      protocol (ownership/execution-protocol)
      good (ownership/check [{:id 'balanced :body
                (compile "(let [r (BeamLisp.Execution/register! (fn [] 42))] (try 42 (finally (BeamLisp.Execution/close! r))))")}]
                            protocol)
      bad (ownership/check [{:id 'leak :body
                (compile "(let [r (BeamLisp.Execution/register! (fn [] 42))] 42)")}]
                           protocol)]
 (assert (= :conditional (:status good)))
 (assert (= :refused (:status bad)))
 (assert (= false (:native-admission good)))
 {:balanced (:status good) :leak (:status bad)
  :runtime (set (map :kind (:runtime-obligations good)))})
#+end_src
#+RESULTS: registration-cleanup
: {:runtime #{:native-context :native-registration-context :close-and-drain}, :balanced :conditional, :leak :refused}


The exact compiler self-application scaffold creates a latent function. Only
that validated scaffold is skipped as construction; an arbitrary let/do around
a function can still execute effects. Struct construction calls __struct__/1,
and map literals call the runtime hash-key adapter. Those calls remain unknown
without explicit contracts. Canonical ANF tuple/map/cons tests independently
verify that aggregation cannot erase resource aliases.
