#+TITLE: Artifact preparation in the real SDK build

* One build log, separate preparation and provenance

The ordinary =build/run= owner has an explicit =:sdk-artifacts? true= profile.
It requires the actual running SDK source root. That option selects compilation
semantics; it creates no SDK admission, source-origin receipt or execution grant.
The existing SDK inventory writer still checks genuine source and emitted bytes.

Preparation uses =AOT/open_workspace=, =prepare_unit=, =emit_unit= and
=verify_unit=, the same artifact-only APIs used by bootstrap production. The
workspace imports the existing Core/Sugar phase data. Each unit retains its
existing bounds and closes its temporary scope. Only verified captured bytes
reach materialization; no selected unit is loaded or initialized in the producer.

#+begin_src beam-lisp :id sdk-prepared-unit
(ns compilation.sdk.artifacts.walkthrough (:require [build :as build]))
(let [root (BeamLisp.Tiers/priv_root)
      temporary (Path/join (System/tmp_dir!) (str "sdk-artifact-doc-" (erlang/unique_integer (list :positive))))]
 (File/mkdir! temporary)
 (try
  (let [result (build/run {:sources [(Path/join root "std/errors.bl")] :root root
                           :out (Path/join temporary "units") :sdk-artifacts? true :jobs 1})
        entries (vals (:manifest result))]
   (assert (= [] (:errors result)))
   (assert (= 1 (count entries)))
   (assert (every? :preparation-key entries))
   {:units (count entries) :prepared-profile-recorded true :native-admission false})
  (finally (File/rm_rf! temporary))))
#+end_src

A preparation identity covers the actual SDK source inventory, compiler/build
keys, phase-support image and native runtime target. The initial policy hashes
the whole SDK source inventory: conservative invalidation avoids pretending an
ordinary require graph describes every compile-time value/macro dependency.
The inventory is bounded and checked again at the completed build boundary.
Each freshly prepared unit's actual inputs must belong to that captured inventory.
This does not claim minimal-cone invalidation or zero I/O.

The existing build fact gains an optional preparation key. Replay, compaction,
manifest projection and manifest migration preserve it. An ordinary Source build
and a prepared SDK build cannot call one another fresh merely because their
source keys agree. Existing facts keep their original shape and default semantics.

The prepared cache address includes this preparation identity and source key.
=AOTCache/prepare_fetch(key, cache-address, source-key)= validates genuine BEAM
source provenance independently of the address, matching the existing split
fetch/store APIs. A cache address cannot stand in for a source/compiler stamp.
The manifest's source key and the shipped precompiled index keep their existing
meaning. Unchanged builds and complete shared-cache restorations perform zero
unit preparations; ordinary Source APIs retain their compilation behavior.

* Physical publication stays with its owner

Captured byte materialization holds the existing output workspace's kernel
claim. It does not take the VM's global code-publication lock because it loads
no target code. The self-build library child selects this profile and no longer
prepends its output directory to the running compiler's code path.

A cold producer can lazily materialize its own framework functions and mutable
forwarders. The native trace observes those calls rather than declaring them
absent. It identifies actual selected target modules from the genuine completed
build manifest and proves none of their modules are published. It also records
zero legacy =compile_file= and zero target source initialization =load_unit= calls.

The sealed-image consumer remains the existing PackageAuthority/AOT owner. The
producer calls the real =write_sdk_inventory!=, precompiled-index writer and app
resource writer. No fixture inserts or amends SDK ownership rows by hand.

* Fresh process controls

=scripts/demo-sdk-artifacts --seed FLOOR --out ABSENT= creates a private image,
then exercises seven genuine compiler-produced SDK units. It includes actual
=typed=, =errors=, tasks, an actor and the owner registry, plus a macro/value
provider and its consumer copied from the explicit test source inputs.

The scenario checks cold preparation, unchanged reuse, fresh output restoration,
forced byte-identical emission and repair of one corrupt output from the shared
cache. Changing the provider's compile-time value from 40 to 50 invalidates the
profile. A fresh empty-cache receiver then returns 52 without a source compile,
and the registry class obtains an actual sealed-image class proof. Changed
sealed bytes refuse before target initialization instead of falling back to a
Source receipt.

=--all-sdk= selects the same namespace inventory as the self-build library child,
excluding actual floor files and fixture suffixes. This separate gate must pass
before the entire SDK producer migration can be claimed. Source-free SDK
activation, optional native closure, exact native product attestation and the
wider approved architecture retain their own evidence requirements.

The full inventory exposed two structural gaps. Literate files may contain
ordinary top-level vectors/literals; staging must retain them as deferred actions
rather than assuming every form has a symbol head. Generated public actor
bindings require actual provider expansion to determine visibility. The private
constructor world now obtains that declaration data without initializing the
provider. Nested expansion uses the compiler's own scoped fresh-name stream,
with exception-safe restoration. The existing Loader path owner also restores
its exact raw prior stack, including absent versus empty state.
