#+title: Ownership through functions and worlds

* Derive transitions from the compiler's functions

The initial finite entry checker stopped at every application. It now retains
known lexical functions as bounded ANF recipes with captured abstract values.
Creating a function remains latent. Applying it evaluates its arguments once,
binds the selected clause's parameters and follows the actual body, including
normal/exceptional returns and finally cleanup. Returned resources and closures
remain values in the caller; only the entry's exit closes its obligations.

No second parser, ambient definition lookup, native callback or manually authored
helper contract is involved. Imported functions already have lexical binding
identities in the expanded program; old/new worlds therefore use the same path.
Fixed native APIs still need their explicitly declared logical contracts and
actual runtime custody. Function recipes are analysis data and grant no authority.

#+begin_src beam-lisp :id helper-cleanup
(ns ownership.calls.walkthrough (:require [system.ownership :as ownership]))
(let [source "(let [close (fn [r] (BeamLisp.Execution/close! r)) r (BeamLisp.Execution/register! (fn [] 42))] (try 42 (finally (close r))))"
      node (BeamLisp.Compiler/compile (BeamLisp.Reader/read_one source)
                                     (BeamLisp.Compiler/new_env "ownership.calls.example"))
      report (ownership/check [{:id 'helper-cleanup :body node}] (ownership/execution-protocol))]
 (assert (= :conditional (:status report)))
 (assert (= 1 (get-in report [:summaries :contexts])))
 (assert (= false (:native-admission report)))
 {:status (:status report) :contexts (get-in report [:summaries :contexts])
  :runtime (set (map :kind (:runtime-obligations report)))})
#+end_src
#+RESULTS: helper-cleanup
: {:runtime #{:native-context :native-registration-context :close-and-drain}, :status :conditional, :contexts 1}


* Reuse only an equivalent abstract input

A summary is a relation from a function's captured values, actual abstract
arguments and complete resource state to its normal/exceptional outcomes. The
resource state includes ownership phases and outstanding borrows. Those inputs,
the function body and lexical identity determine the context. Distinct allocation
contexts receive distinct resource identities. Releasing a handle changes the
input, so an earlier successful use cannot be reused after release.

Issues, runtime obligations and opacity are report deltas: a callee computes its
own additions, which are unioned back into each caller. Prior report history does
not force repeated body analysis and cannot be erased by a call. Cached edges
still enter the same finite safety graph. Runtime obligations apply at actual
admission even when their analysis records are deduplicated.

The cache belongs to one check invocation. It never survives a program snapshot,
protocol change or native lifetime. The new max-summaries option defaults to a
hard ceiling of 512 contexts; exhaustion returns unknown. Existing visit/state/
path budgets remain in force. The report exposes contexts/hits, and the ordinary
world check description exposes ownership-contexts/ownership-summary-hits.

#+begin_src beam-lisp :id world-call-reuse
(ns ownership.calls.worlds (:require [expand :as expand] [system.phase :as phase] [lower :as lower]))
(let [program (expand/program
               [{:namespace 'helpers :revision 'old :file "helpers.bl"
                 :source "(ns helpers) (defn identity-value [x] x)"}
                {:namespace 'main :revision 'current :file "main.bl"
                 :source "(ns main) (import-world 'helpers 'old :only [identity-value]) (do (identity-value 1) (identity-value 2) (identity-value 42))"}]
               ['main 'current])
      analysis (phase/analyze program) report (:ownership analysis)
      actual (lower/eval-anf :Elixir.OwnershipCallsWalkthrough (:node program))]
 (assert (= 42 actual))
 (assert (= :proved (:status report)))
 (assert (= 1 (get-in report [:summaries :contexts])))
 (assert (= 2 (get-in report [:summaries :hits])))
 (assert (= (get-in analysis [:facts :snapshot]) (:snapshot report)))
 {:value actual :status (:status report) :contexts (get-in report [:summaries :contexts])
  :reused (get-in report [:summaries :hits])})
#+end_src
#+RESULTS: world-call-reuse
: {:status :proved, :value 42, :contexts 1, :reused 2}


* Coverage and its limits

The derived summaries cover known lexical functions with unguarded variable/
wildcard parameters, higher-order arguments, returned resource aliases/closures,
branch-selected functions and exception cleanup. Guarded or destructuring
predecessors, opaque callees and recursive control return unknown. This is
bounded contextual transition reuse, not an unbounded recursive fixed-point
proof, termination proof or native adapter conformance claim.

The regression suite independently enumerates all 63 balanced/unbalanced
use/release traces through helper boundaries. It checks changed resource phases,
captures, truth values, allocation contexts, budget exhaustion and actual native
API obligations. The ordinary compiler and contextual backend execute the
cross-world example. The early gate also runs these tests in a Source-free SDK.
Recursive summaries, deadlines, native trace conformance and complete type/effect/
impact integration remain on the canonical completion checklist.
