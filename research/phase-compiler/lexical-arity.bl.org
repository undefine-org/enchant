#+TITLE: One expanded world, lexical callable contracts

* Ownership and API

=system.arity.anf/check= consumes canonical ANF, follows actual lexical variable
names and returns a verdict, coverage, obligations, potential findings and
=errors= diagnostics. =system.arity/check-anf= is its compatibility entry point.
The explicit world adapter calls the pure pass directly, so it does not load
the legacy Source walker or resolve a callee from mutable runtime namespaces.

Function bodies are checked with their creation environment; parameters and
clause patterns shadow captured facts. Branch alternatives are joined. A call
is proved only if every known alternative accepts its count, refused if every
alternative rejects it, and unknown otherwise. Language invocation and native
application remain distinct. Exact self constructors introduce a lexical
factory fact so named recursive calls retain the inner function contract.

#+begin_src beam-lisp :id lexical-contracts
(ns phase.lexical-arity.walkthrough
 (:require [expand :as expand] [system.arity.anf :as arity] [bl.world :as world]))
(defn example [source]
 (expand/program [{:namespace 'example :revision 'current :file "example.bl"
                   :source (str "(ns example) " source)}] ['example 'current]))
(let [valid (arity/check (:node (example "(let [f (fn [x] x) g f] (g 42))")))
      invalid (arity/check (:node (example "(let [f (fn [x] x) g f] (g))")))
      dynamic (arity/check (:node (example "(fn [callback] (callback 42))")))]
 (assert (= :proved (:status valid)))
 (assert (= :refused (:status invalid)))
 (assert (= :unknown (:status dynamic)))
 {:alias-valid (:status valid) :alias-invalid (:status invalid)
  :callback (:status dynamic)})
#+end_src
#+RESULTS: lexical-contracts
: {:callback :unknown, :alias-valid :proved, :alias-invalid :refused}


* Two revisions cannot borrow each other's contract

The selected worlds bind two functions with identical namespace and member
spelling. Their compiled identities remain distinct. The checker follows those
bindings; it does not consult an ambient namespace or join signatures by name.

#+begin_src beam-lisp :id qualified-arities
(let [program (expand/program
               [{:namespace 'library :revision 'old :file "old.bl"
                 :source "(ns library) (defn answer [] 42)"}
                {:namespace 'library :revision 'new :file "new.bl"
                 :source "(ns library) (defn answer [x] x)"}
                {:namespace 'example :revision 'current :file "example.bl"
                 :source (str "(ns example) (import-world 'library 'old :as old :only [answer]) "
                              "(import-world 'library 'new :as new :only [answer]) "
                              "[(old/answer) (new/answer)]")}]
               ['example 'current])
      report (arity/check (:node program))]
 (assert (= :refused (:status report)))
 (assert (= 1 (get-in report [:coverage :proved])))
 (assert (= 1 (get-in report [:coverage :refused])))
 {:old :proved :new :refused :findings (count (:findings report))})
#+end_src
#+RESULTS: qualified-arities
: {:new :refused, :old :proved, :findings 1}


* Bracket syntax inherits analysis after expansion

The existing =bind [name initializer] body= macro is hygienic and introduces its
own temporary. It needs no arity-analysis plugin. After expansion it is the
same let/function/invocation vocabulary as handwritten code. A function bound
through the bracket form keeps its contract.

#+begin_src beam-lisp :id bracket-contracts
(let [provider {:namespace 'forms :revision 'current :file "forms.bl"
                :source (File/read! "test/fixtures/contextual-language/forms.bl")}
      program (expand/program
                [provider {:namespace 'example :revision 'current :file "example.bl"
                           :source (str "(ns example) (import-world 'forms 'current :only [bind]) "
                                        "(bind [answer (fn [x] x)] (answer))")}]
                ['example 'current])
      report (arity/check (:node program))]
 (assert (= 1 (count (:expansions program))))
 (assert (= :refused (:status report)))
 {:macro-expansions (count (:expansions program)) :arity (:status report)
  :refused (get-in report [:coverage :refused])})
#+end_src
#+RESULTS: bracket-contracts
: {:arity :refused, :refused 1, :macro-expansions 1}


* Ordinary CLI and bounds

=bl world check MANIFEST.bl --json= now includes =arity-check=, =arity-scope=,
=arity-coverage= and source diagnostics from the same immutable program as the
phase report. Preparation does not execute the native program. Findings are
potential sites, including latent/dead branches and errors that a program may
catch. This report does not change execution semantics or grant admission.

Native remotes, globals, arbitrary call results, callable data and higher-order
parameters remain explicit unknown obligations. The pass does not infer purity,
matching success, termination or exception escape. At most eight alternative
contracts are retained; larger joins widen to unknown. Defaults cap visits at
100000 and depth at256. Exhaustion has incomplete coverage and no fabricated
zero-site proof. Unknown grammar is an error. No boot dependency is introduced.

See [[file:lexical-arity-checks.json][scoped checks]]. Full effect/ownership qualification, broader callable values,
immutable compiler metadata and native execution migration remain separate work.
