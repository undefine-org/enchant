#+TITLE: A source-free release of bracket programs

* One release owner

=release/assemble-runtime!= projects verified contextual programs through the
existing =compile.world/package-runtime!= owner and uses the existing release
assembler for application copies, the actual OTP dependency closure, ERTS,
=systools= boot scripts and Elixir wrappers. It does not maintain another
release implementation or fabricate SDK membership.

The three-argument API selects programs with quoted symbols:

The two-argument form =(release/assemble-runtime! unit output)= selects ='main=.
Output must be absent; existing directories and dangling links refuse. The
existing kernel workspace claim owns assembly. A private stage contains all
build-only roots and claim anchors. The published product contains support
BEAMs, the original floor manifest/app, the mandatory native product, projected
programs and the usual release tree. It includes no BL source or phase archive.

The runtime app resource omits the full application's compiler-starting
callback. Its dependency closure comes from the running OTP applications for
Elixir and crypto. The Source-free profile explicitly omits the solver payload;
it is not a full compiler SDK or a promise to carry arbitrary SDK native hosts.
The bundled OTP compiler app supplies ordinary Elixir/OTP runtime support; the
BL reader/compiler/phase evaluator does no work at program entry.

=systools= receives the copied applications' actual =ebin= directories before
producer paths. Passing only a parent =lib= directory previously let the
producer's same-named app resource win. The runtime-only app exposed that bug
as undefined dependencies; the fixed owner now generates boot files from the
selected copies for ordinary releases too.

* Verify copied support before publication

The producer's loaded NIF identity does not prove the file currently at its
library path. After copying, the builder boots a fixed native support probe
through the staged tree's bundled launcher. It checks the actual captured
floor and loaded native target against the selected programs. It never runs a
program entry or invokes the BL Source compiler in that probe.

Only after that check does assembly publish =bin/run= and its completion record.
A changed native file refuses with =:runtime-release-target-changed=. An empty
refused workspace is removed; partial output or foreign files are preserved.
As with self-build, build commands belong under a whole-process-tree resource
and time cap. The synchronous trusted native probe does not add a universal
subprocess cancellation protocol.

The launcher delegates booting to the existing =bin/bl eval= path, forwards argv
and prints the returned value with the language printer. A product can be
renamed or moved; it locates its own bundled ERTS and support files.

* Full release control

=scripts/demo-runtime-image --release --native-variant PATH --out ABSENT= builds
all five real examples, assembles the runtime release, renames it, and runs the
existing eight-entry/restart gallery through its bundled launcher. The receiver
asserts its actual =/proc/self/exe= is the copied =beam.smp=, its OTP root is the
relocated release, and every code path is inside that root. It traces the BL
reader/compiler/phase evaluator and floor captures as before.

A separate real producer keeps its original native implementation loaded, then
atomically swaps the file that packaging will read. The new staged probe must
refuse before any completion receipt appears, and cleanup must remove its empty
workspace. The original native-owner, changed-target, caller-death, Env-epoch,
changed-floor and retained-support replacement controls remain enabled.

This gate covers this host's exact ERTS/native target, not a different-platform
release, final native binary attestation, a qualified compiler SDK or a minimal
support closure. Those and the remaining approved architecture stay open.
