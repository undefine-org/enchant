#+TITLE: Compiled-only bootstrap and explicit runtime targets

* The two identities

A compiler's producer key identifies the toolchain that emitted a program. A
receiver's runtime target identifies the support code that will execute it.
Recomputing the first from files missing on the receiver answers the wrong
question. Contextual artifact version 2 records an exact runtime-image identity
in the compiler's metadata and input selection. The ordinary build/cache path
includes it in the selected physical revision and cache address.

The initial target policy hashes the actual installed BEAM support-floor members
and OTP/Elixir versions. It is deliberately conservative: byte-identical support
images qualify; semantic ABI equivalence between different images is future
work. The program BEAM is not part of the support-floor identity, so no recursive
artifact hash is introduced. These hashes describe compatibility, not SDK
authority.

Native shared libraries are copied and independently hash-recorded by the
demonstration. Their ABI is not included in this initial BEAM-floor target
stamp. Complete native-product/SDK target coverage remains an explicit release
and platform obligation; this checkpoint does not claim it.

* A native entry, existing owners

=BeamLisp/run_runtime_artifact(directory, argv)= captures the installed floor
through AOT without reading compiler Source. Capture checks the seed schema,
native runtime versions, fixed bootstrap entry roots, each actual member's
SHA/module identity and absence of executable on_load. Member counts, per-file
bytes and aggregate bytes are bounded before publication.

Env adopts the exact captured bytes under its existing module fences, computes
the runtime identity from those bytes, and retains them for the actual Env
process lifetime with existing code leases. A private slot in existing custody
storage holds this proof. No caller-supplied target, second registry, compiler-key
memo injection or Source permission flag can substitute for it.

Only precompiled Rt and Core initializers run. Their values become available
without enabling a reader/compiler backend, evaluating tagged-reader Source or
marking the full compiler seeded. The native Loader captures ordinary artifact
bytes without treating a producer key as receiver compatibility. It checks the
contextual roles and target against actual Env custody, then uses the same
program publication, executing borrow and closure-aware retirement as ordinary
compiled entry. Initializers and user code run outside custody turns.

The current entry requires the global environment. It does not prepare an SDK
source admission inventory or claim that arbitrary managed actors are ready.

* Executable floor capture

#+begin_src beam-lisp :id contextual-runtime-floor
(ns compilation.runtime.bootstrap.walkthrough)
(let [floor (BeamLisp.AOT/runtime_floor!)
      members (count (:prepared floor))]
 (assert (= members (count (get (BeamLisp.Bootstrap/manifest) "modules"))))
 (assert (= 32 (erlang/byte_size (:identity floor))))
 (assert (= false (:native-admission floor)))
 {:runtime-members members :target-bytes 32 :native-admission false})
#+end_src

* Fresh-process proof

#+begin_example
scripts/demo-runtime-image --out /absolute/absent/output
#+end_example

The producer uses the normal world/AOT pipeline. The consumer receives only
actual support-floor BEAMs, native products and a runtime-only program unit.
It has no BL Source, phase archives, external dependency code paths or compiler
cache. Its current Source-derived compiler key demonstrably differs from the
producer key. The entry must nevertheless use the compatible actual runtime.

The native harness preloads observed reader/compiler modules before tracing and
checks that each trace pattern attaches. Exact-byte adoption preserves those
patterns. Module-info reads are metadata; all other functions in the host and
namespace reader/compiler modules, plus the macro constructor session, are
observed. The trace spans first entry, repeat entry and actual Env replacement.
It checks the result, refusal to retire leased Rt/Core code, fresh Env ownership
after restart and the compiler's still-unseeded state. A changed-floor byte
control must refuse before program output.

The same source-free consumer also runs the cross-world/bracket binding, query,
selective-receive and cleanup showcases. Their macro providers and phase
archives stay out of the image. Workspace claim anchors are producer state;
only complete selected runtime directories are copied into the consumer.

A real first-replacement control found that a legacy physical lease was not a
current-code immutability rule. Publishing an actual foreign Rt binary installed
it, then failed when Emit tried to call the now-missing Rt eqv function. Env's
existing publication fence now checks the privately held runtime-floor
fingerprints before graph mutation or loading. Its fixed owner turn reads only
selected fingerprints; byte hashing and all user code stay outside custody.
The corrected control requires refusal, an unchanged loaded fingerprint and a
successful subsequent program entry. The foreign proposal carries no fabricated
SDK origin, declaration or admission record.

An early cold control found a language <= call before Core existed. The new
preboot checks now use native operations. Native harness corrections for Elixir
charlist rendering and ambiguous != spacing are fixture issues, retained in the
scoped evidence; they are not successful qualification runs.

* Remaining release work

The demonstration currently supplies host Elixir/ERTS. It is a source-free
runtime bootstrap, not a bundled OTP release or a qualified standalone SDK.
Release assembly must reuse the existing release owner, and SDK packaging must
retain actual compiler-produced ownership inventories. Target minimization and
ABI equivalence, broader contextual forms and the other native/analysis gates
retain their separate obligations.
