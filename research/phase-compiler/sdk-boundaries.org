#+title: SDK boundary preflight and consumer map

The runnable gate is =scripts/preflight-sdk-boundaries=. Its authoritative
selection is =sdk-boundary-consumers.json= in this directory. The map includes
producers, direct Source references, transitive consumers, execution contexts
and real regression files. Discovery includes plain and literate Source plus the
other supported language suffixes; a changed reference set fails before boot. References are discovery evidence, not execution proof.

| Boundary | Producer -> consumers | Early refusal/positive control |
| Unit metadata | AOT facade/body/initializer -> byte decoder, inventory/seal, preload; Record descriptor validator; cache provenance/replay | Every role emits requires; canonical record accepted, changed schema/body denied; changed policy cannot reuse byte decode |
| Recorded Source/class proof | AOT -> PackageAuthority snapshots/privacy -> Env class issuer -> Server/Supervisor -> reload execution/Conn and queue-family storage/root, datom Conn | Present digest checked; absent file requires actual image row and bytes; no generic invocation in native proof; real owned pool |
| Preboot identity | Bootstrap floor manifest/files -> AOTCache keys -> early AOT membership -> SDK key validation | Core/Rt/Env remain unloaded; corrupt file and independently replaced loaded code refuse; actual bytes restored before normal boot |
| Loader | Actual Source resolution or sealed row -> complete member preload -> existing initializer/lease owner | Byte tamper/missing row refuse before init; virtual no-code aliases retain normal registry miss |
| Constructor/scope | Compiler declaration privacy/fresh names -> AOT staging -> Loader path/snapshot scopes | Private static denial, real generated classes and exact exception restoration |
| Artifact build/cache | build profile -> BuildLog replay/compaction/freshness -> AOTCache split address/provenance -> self-build/assembly/inventory/release | Profile-aware misses/hits, genuine Source provenance, artifact-only target preparation |
| Record representation | Runtime classifier/Record info -> native queue/Conn validators; language record lookup hides implementation tags | Real Fjall allocation plus record surface laws; tag alone grants no SDK ownership |
| Custody | Env class proof -> native Server/Supervisor -> managed starts/restarts/pending/ignore -> pool/Conn/queue | Real managed children own their graph; public descriptors/caller maps do not admit execution |

Execution contexts are part of the API. Preboot code cannot use Core/Rt/Env.
Native class proof can run while a private Source execution frame is active and
Env is temporarily global: generic invocation would re-enter the wrong scope.
The private metadata owner may decode fixed inert data; it cannot load code,
initialize namespaces or execute caller callbacks. Ordinary compiler work has
its own staging and Source execution rules. A test in one context does not
substitute for the others.

The gate runs selected files in one ordinary fresh candidate VM, serially. It
first runs a distinct small preboot VM because compiling the ordinary Elixir
driver can itself load modules named by later remote calls. Preboot and normal
VMs never overlap. Actual CLI status, file count and nonzero assertion counts
are required. The genuine BuildPlan-selected activation graph is then produced
and sealed once. The boundary profile adds the actual =data.bounded-cache= and
=bl.check= dependency closures, plus its actual =bl.cli=, =bl.test= and
=reload.ward= runner entry closures. Before removing Source it executes the sealed
branches of =sdk_loading_batch_test.bl= and verifies both roots have actual
inventory membership. Fresh Source-absent positive/negative receivers follow.
No full SDK build is performed by this gate.

The entire Source/test/script/native input inventory and selected floor are
hashed before the gate and compared before/after each stage, including newly
added or removed paths. Failed attempts retain logs and a failed receipt. Inputs
must remain frozen; a green result belongs to that exact manifest. Run under a
whole-tree memory/time cap, with the intended toolchain on the service PATH:

#+begin_src sh
systemd-run --user --collect --wait --pipe --setenv="PATH=$PATH" \
  --working-directory="$PWD" --property=MemoryMax=4G \
  --property=MemorySwapMax=0 --property=RuntimeMaxSec=1500 \
  ./scripts/preflight-sdk-boundaries --out .local/execution/ABSENT
#+end_src

A small activation image does not establish standalone SDK/ERTS/native closure.
Conditional tests that fall back to Source mode do not prove their sealed-image
branch. This gate therefore runs the loading-batch tests against the real sealed
image. Native bootstrap host tests run in the ordinary Source-present candidate;
optional Source-free native closure remains a final-candidate requirement. Full from-scratch reproduction, full inventory/native/backend regression
and installed checks remain mandatory for the final candidate. The canonical
remaining-work list is [[../../!tasks/plans/CHECKLIST-language-execution-completion.org][the completion checklist]].

The first expanded consumer run passed 20 files and failed both queue files.
The added controls caught a physical record-tag read through language lookup
and an assertion expecting an older, later refusal. A separate 63-unit sealed
probe produced correctly but its omitted CLI/runner roots fell back to Source
and exposed an unproved modified Core shim. These failed receipts are retained;
changing the verifier to accept that shim is not part of the repair. The revised
harness requires genuine inventory membership for all five entry roots.

The retained Core refusal reproduced with the complete CLI/runner root set and
an empty cache. Ward now establishes the existing SDK lifetime before evaluating
the test library into Core. This keeps all native byte/route checks intact and
prevents the unproved mutation; the actual sealed loader branch passes 16
assertions with this ordering. Queue validation uses =Rt/kind-struct-mod= for
physical representation, then separately checks exact class and actual SDK
membership. Its focused tests pass 127 assertions. Final frozen-gate status is
recorded separately rather than inferred from these focused results.

Final consumer checkpoint: eight boundaries / 466 recorded references, 1801
assertions across 26 files, and 16 assertions in the actual sealed loader branch
pass. The bounded image contains 76 genuine Source units and 286 modules. Fresh
Source-absent macro/class consumption and changed-byte/missing-row refusal all
pass. Frozen inputs remain identical; the complete gate takes 684.363s with 1G
peak memory and zero swap. See [[file:sdk-boundary-checks.json][the scoped receipt]].
This replaces neither full SDK reproduction nor final-candidate regression.
