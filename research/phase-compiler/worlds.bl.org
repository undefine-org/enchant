#+TITLE: Explicit compilation worlds through the ordinary CLI

* Use the compiler without writing a compiler driver

The CLI adapter delegates to the existing Loader source reader, contextual
expander, bounded ANF machine, =system.phase=, =codebase.phase= and native
lowerer. It owns file selection and presentation. A manifest is a bounded
Source expression, so namespace and revision values use ordinary quoted symbols:

#+begin_example
{:version 1 :profile 'syntax-v1 :entry ['showcase 'current]
 :sources [{:namespace 'validation :revision 'current :file "validation.bl"}
           {:namespace 'showcase :revision 'current :file "main.bl"}]
 :libraries []}
#+end_example

Paths resolve relative to the manifest. Revisions remain logical world labels;
the catalog binds them to the selected source digests. There is no ambient
namespace lookup. Manifests themselves use =expand/compile-expression= with an
empty selected world and run through the effect-denying constructor;
an attempted native write refuses before it happens. They have a 64 KiB input
bound. The combined source/archive table has 128 rows and 16 MiB of captured
file bytes, checked incrementally. These bounds do not classify runtime effects.

#+begin_example
./bin/bl world check test/fixtures/contextual-validation/world.bl --json
./bin/bl world run test/fixtures/contextual-validation/world.bl
./bin/bl world emit test/fixtures/contextual-validation/world.bl --out /tmp/ratios.beam
#+end_example

The other examples use exactly the same =world run= entry:

| Manifest under =test/fixtures/= | Result | Capability |
|--------------------------------+--------+------------|
| =contextual-language/world.bl= | =[42 102 42 42]= | Two revisions, hygienic expansion and phase-local helpers |
| =contextual-query/world.bl= | =(4 6)= | Checked bracket query grammar and lexical row bindings |
| =contextual-mailbox/world.bl= | =[42 107 99]= | Scoped receive patterns, guards and hygienic timeout names |
| =contextual-cleanup/world.bl= | =[42 100 40 200]= | Bracket resource extent, typed handlers and cleanup |
| =contextual-validation/world.bl= | =[42 99 42]= | Compile-time exception specialization into runtime literals |

=check= expands once and projects phase and codebase facts from that same
immutable program. =emit= writes a new file exclusively; it never loads its
target. =run= uses ordinary native evaluation and its existing framework check
and eval-module lifetime. The phase report proves binding resolution, not native
execution admission, resource ownership or complete effect coverage.
The report names its binding-resolution scope and unknown native effects.
=system.phase/analyze= returns the checked facts and report together;
=system.phase/check= retains its existing report shape. CLI preparation uses
the combined operation rather than rebuilding and hashing the facts twice.

The checkout's existing warm transport serves these commands in one VM. A
private-runtime probe on this host measured 0.538 seconds for repeated checking
and 0.515 seconds for execution, with the same process and analysis snapshot.
Its first request took 37.24 seconds including the native transport build.
This is one example's elapsed time, not a whole-compiler complexity claim;
the probe stops its own VM in cleanup.

* One prepared program, three consumers

#+begin_src beam-lisp :id world-inspection
(ns phase.world.walkthrough (:require [bl.world :as world]))
(def prepared-world (world/prepare "test/fixtures/contextual-validation/world.bl"))
(select-keys (world/describe prepared-world)
 [:profile :entry :worlds :expansions :phase-check :constructor-closed :native-admission])
#+end_src
#+RESULTS: world-inspection
: {:entry ["showcase" "current"], :profile "syntax-v1", :native-admission false, :worlds 2, :expansions 3, :phase-check "proved", :constructor-closed true}

#+begin_src beam-lisp :id world-emission
(let [module :Elixir.WorldWalkthrough
      _ (assert (= false (erlang/module_loaded module)))
      pair (world/artifact prepared-world module)]
 (assert (= module (elem pair 0)))
 (assert (= false (erlang/module_loaded module)))
 {:emitted true :loaded false})
#+end_src
#+RESULTS: world-emission
: {:loaded false, :emitted true}

#+begin_src beam-lisp :id world-execution
(let [value (world/execute prepared-world [])]
 (assert (= [42 99 42] value))
 value)
#+end_src
#+RESULTS: world-execution
: [42 99 42]

An archive-only provider needs only its encoded phase library in =:libraries=;
its source file can be absent. Two source rows may select different revisions
of the same namespace. Both use the same existing =import-world= grammar and
binding identities. Inputs are rechecked before emission or execution, so an
edited file cannot silently replace a captured program.
Literate/shebang decoding uses =Loader/doc_content= on the captured bytes;
it does not reopen the path. Raw file digests and decoded compiler input thus
refer to one capture, including prose outside a literate code cell.

* The lazy boot boundary

The first ordinary CLI probe failed at the native retained-code fence. SDK
dependency staging recursively recompiled a lazy boot namespace even though
its exact code was already authenticated by the current floor. Its private
declaration view produced a different initializer; the refusal was correct.
The staging walk now recognizes the existing exact seed/forwarder proof at
that boundary. It neither initializes the dependency nor invents a Source SDK
receipt. The existing closure walk checks emitted imports before execution.

The regression gate starts with a genuinely lazy dependency, invokes the real
SDK producer with initialization disabled, and verifies unchanged boot code,
load state and source receipts. Ordinary file compilation and native custody
continue through their own established APIs. Default mutable Loader migration,
closure-valued constants and compiled phase archives remain further work.

A subsequent cold use exposed =expand-source/describe= as a function value
looked up through mutable Env. The actual emitted ANF audit found sixteen
such contextual function reads across =syntax=, =binding=, =expand-source= and
=expand=. Explicit closures now call their compiled targets. The audit joins
global reads to those namespaces' actual declaration tables, including guards
and nested bodies. Core fallback names are a separate canonical kernel
boundary; they are not misclassified as local declarations.

Manifest expressions pass through the same closed expander before compilation.
That rejects =ns=, =require= and declaration forms before their compiler
handlers can run. The adapter introduces no second expression grammar.

The [[file:world-checks.json][scoped qualification receipt]] records the actual cold failures, the
declaration-backed red control, complete B/C reproduction, final CLI checks and
source-free demonstrations. It keeps the wider architecture's remaining work
separate from these passing gates.
