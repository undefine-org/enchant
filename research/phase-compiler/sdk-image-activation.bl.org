#+TITLE: SDK activation from sealed bytes

* Source provenance and executable identity have different lifetimes

The SDK producer checks real Source and emitted bytes before writing its sealed
inventory. Packaging may then omit Source. An absent file cannot itself prove
ownership: activation must find the exact module in the actual image inventory,
verify its bytes, check the complete unit and compare loaded code before running
an initializer. A present changed Source file still refuses; image evidence never
silently replaces a failed live-Source check.

The existing owners retain these responsibilities:
- =Bootstrap/packaged_keys!= verifies the complete installed floor and loaded
  stable members. It returns compiler/build keys as ordinary compatibility data.
- =AOTCache/compiler_key= selects that floor identity only for a sealed SDK with
  completely absent SDK/codegen Source. Partial source trees retain live hashing.
  The ordinary memo stores the selected identity; no tool injects a memo value.
- =AOT= authenticates image unit members, dependency metadata and complete bytes
  before publication. The existing Loader remains the initializer owner.
- =PackageAuthority= checks complete current units for declaration visibility,
  callable creation and class evidence. No image load fabricates Source receipts.
- =Env= retains code and owns publication through its existing fences and claims.

This cell exercises the floor reader in the current compiler image. The separate
fresh-process gate below proves actual Source-absent activation.

#+begin_src beam-lisp :id verified-packaged-floor
(ns sdk.image.activation.walkthrough)
(let [manifest (BeamLisp.Bootstrap/manifest)
      keys (BeamLisp.Bootstrap/packaged_keys!)]
 (assert (= (get manifest "compiler_key") (elem keys 0)))
 (assert (= (get manifest "build_key") (elem keys 1)))
 {:floor-members (count (get manifest "modules")) :loaded-stable-members-checked true
  :sdk-execution-admission false})
#+end_src

* Dependencies are compiler data

Each namespace emits its bounded requires list in a tagged BEAM attribute. The
inventory preserves it. The image decoder compares requires, role, source digest,
declaration owner and unit membership with authenticated bytes. Mutable forwarder
routes and declaration/callable policy retain their existing exact checks.
A changed inventory policy cannot turn a body into an actor or substitute a
provider dependency list. Loading captures and verifies every unit member before
publishing any missing member or replaying initialization.

* End-to-end gate

Run =scripts/demo-sdk-artifacts --all-sdk --source-free --seed FLOOR --out ABSENT=
under a whole-process-tree memory/time cap. It uses the real build profile and
inventory writer, removes SDK Source, then starts a fresh empty-cache consumer.
The consumer checks compiler/build identity, macro/value output and a genuine
sealed-image registry class proof. A second fresh process must refuse changed
artifact bytes before target initialization. Inputs remain frozen throughout.

This gate concerns SDK activation and ordinary compiler boot. It does not assert
standalone dependency/ERTS packaging, optional native closure, exact final native
product attestation, or Source-free contextual pipeline cache identity. Those
remain separate parts of the wider implementation plan.

* Activation checkpoint

The bounded activation graph is selected by the existing BuildPlan resolver,
not a second parser or caller-invented inventory. It prepares 49 actual Source
units and seals 180 code modules through the ordinary build/inventory owners.
After removing 587 SDK Source files, a fresh empty-cache process boots, returns
42 from the compiled consumer, compiles new project Source using the packaged
macro/value provider, and obtains a real registry class image proof. The producer
takes 51.184s; the receiver takes 2.259s. Changed artifact bytes refuse before
initialization in 1.311s. Removing the consumer's inventory row while retaining
all its BEAM files refuses before initialization in 1.322s.

The full 479-unit gate is separate and must also pass. These whole-stage host
timings are not isolated compiler throughput or a zero-I/O claim.

The early checks exposed several different identities rather than one generic
"missing namespace" condition:
- A recorded Source location can remain valid provenance after the physical file
  is omitted. It grants nothing without a matching actual image row and bytes.
- Preboot floor membership uses exact installed/loaded bytes before Core vars
  exist. Full declaration/forwarder policy remains the postboot owner.
- Virtual seeded namespaces such as =cpp= have no executable unit. They use the
  existing registry-aware miss path. An unlisted executable module refuses;
  the miss path does not perform a second code lookup that could race a load.
- A build-tier Source file is still present even though it does not use the
  library staging profile. Resolution presence and staging tier are distinct.
- The namespace facade, body and initializer must all carry their own needed
  metadata. A field emitted only on body/initializer artifacts cannot identify
  the facade used as the loader's entry point.

The complete inventory gate also passes: 479 compiled namespaces, 483 inventoried
Source units and 1,868 code modules. Production takes 636.473s. After removing
587 Source files, the fresh consumer takes 2.462s and passes the same new-project
macro and registry-class checks. Altered bytes refuse in 1.355s; a removed
inventory row refuses in 1.460s, both before target initialization.

The broader native-start regression gate also caught a metadata consumer outside
