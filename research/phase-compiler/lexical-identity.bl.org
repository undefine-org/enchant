#+TITLE: Captured bindings constrain reusable compiler analysis

* The missing distinction

Two closures can have the same code shape and different captures. Renaming a
free variable changes which binding the closure reads. The previous shared
identity renamed every variable on first sight; it also let a binder enter its
own initializer and leak across sibling scopes. Hashes could therefore point
at identical full identity terms for different open code.

#+begin_src beam-lisp :id captures-are-not-parameters
(ns phase.lexical-identity.walkthrough
 (:require [anf :as a] [system.ir.identity :as identity] [system.tier :as tier]))
(defn closure [capture] (a/fnn (list (a/clause (list) nil (a/var capture)))))
(let [left (closure "left-provider") right (closure "right-provider")]
 (assert (not= (identity/body-identity left) (identity/body-identity right)))
 (assert (= false (tier/alpha= left right)))
 {:same-capture false :equivalent false})
#+end_src
#+RESULTS: captures-are-not-parameters
: {:same-capture false, :equivalent false}


* Lexical scope owns renaming

The shared identity now introduces tokens only at actual let and clause
binders. A let's initializer uses the enclosing environment; its body sees the
new binder. Clause patterns, guards and bodies share one fresh scope; siblings
and cleanup keep their own environments. Repeated pattern variables remain
constraints. Map-pattern keys refer to the enclosing scope. Literal payloads
and qualified global targets retain their exact meaning.

#+begin_src beam-lisp :id initializers-use-the-enclosing-scope
(let [left (a/lett "x" (a/var "x") (a/var "x"))
      right (a/lett "y" (a/var "x") (a/var "y"))]
 (assert (= (identity/body-identity left) (identity/body-identity right)))
 (assert (tier/alpha= left right))
 {:same-free-initializer true :local-binder-renamed true})
#+end_src
#+RESULTS: initializers-use-the-enclosing-scope
: {:same-free-initializer true, :local-binder-renamed true}


* Reuse needs the whole binding context

A detached function body has lost its parameter binders. =system.incr/fn-identity=
retains them and passes shared seed tokens to =body-identity=. Caller-supplied
seed tokens and generated locals occupy different namespaces, and free binary
names cannot collide with either. These are identity terms, not executable ANF.
=tier/alpha== now delegates to this owner instead of maintaining a second
lexical walker. Unknown executable grammar refuses equivalence.

#+begin_src beam-lisp :id explicit-parameter-context
(let [left (a/var "old-parameter") right (a/var "new-parameter")]
 (assert (not= (identity/body-identity left) (identity/body-identity right)))
 (assert (= (identity/body-identity left {"old-parameter" :argument})
            (identity/body-identity right {"new-parameter" :argument})))
 {:detached-bodies :different :shared-parameter-context :equal})
#+end_src
#+RESULTS: explicit-parameter-context
: {:detached-bodies :different, :shared-parameter-context :equal}


This repairs a prerequisite for analysis reuse; it adds no proof cache or
admission handle. Matching identity alone still cannot justify reuse when a
captured value, callee summary, policy or analysis implementation changes.
Existing =system.incr= continues to bind reuse to implementation generations,
flow evidence and both dependency cones. Hash equality remains only a hint.
The explicit-world arity pass still rechecks its immutable program; its measured
small warm cost does not justify introducing another cache owner here.
