* One route
An SDK selection is an input adapter to the existing Source catalog. It does not
create a resolver, evaluator, callable registry or execution protocol. Expansion,
phase-qualified references, canonical ANF, facts and native instance admission
remain the existing owners. The generated forwarding definitions are application
Source; they never acquire SDK authority or pretend to be the SDK's original
Source. Their virtual filenames say =sdk-forwarding:=.

The manifest selects quoted names, including a logical revision label:
#+begin_src beam-lisp
{:version 1 :profile 'syntax-v1 :entry ['showcase 'current]
 :sources [{:namespace 'showcase :revision 'current :file "main.bl"}]
 :libraries [{:sdk 'clojure.string :revision 'selected
              :only ['upper-case 'join]}]}
#+end_src

The program uses ordinary cross-world imports and first-class functions:
#+begin_src beam-lisp
(ns showcase)
(import-world 'clojure.string 'selected :as text :only [upper-case join])
(let [format text/upper-case]
 [(format "hello beam") (text/join ":" ["a" "b"])])
;; => ["HELLO BEAM" "a:b"]
#+end_src

These cells are stored verbatim in =test/fixtures/contextual-sdk/=. The focused
component executes that fixture through real Source unit admission. Once the
batched immutable SDK is produced, the normal command is:

#+end_src

* APIs and ownership
- =BeamLisp.AOT/sdk_function_binding!(namespace, name)= reads bounded original
  SDK inventory and artifact literals. This framework-only query checks public function kind, fixed SDK
  refusals, actual forwarder/body relation, hashes, Source identities, compiler
  key, actual body exports and any loaded body MD5. It returns first-order evidence, with physical
  names as binaries. It never reads live namespace Vars, calls a provider's
  =__bl_ns_defs__=, loads a module or initializes a provider.
- =compile.sdk/capture(selection)= projects that evidence to an ordinary Source
  descriptor. =check!(capture)= recomputes and compares the whole capture. Exact
  provider evidence participates in generated Source/world and artifact selection
  identities. Fixed and variadic overloads are preserved through the existing compiler
  dispatcher. Variadic parameters forward the physical rest-list argument as
  recorded in the original SDK clause; fixed overload precedence stays canonical.
  Selected bootstrap primitive providers now use the same adapter (see below).
  Other boot functions, SDK macros/phase values and class carriers remain open.
- =compile.world= accepts the SDK map alongside existing phase-archive paths in
  =:libraries=. Both are inputs to the same catalog. Generated bytes count toward
  the existing aggregate Source budget. Existing analysis owners consume the same
  program and snapshot; no independent typed/errors/system/codebase fact table
  was added.
- =BeamLisp.AOT/contextual_sdk_namespaces!(verified)= compares every selected
  binding against the actual image before returning any provider names. Loader
  performs this whole-batch check before the first initializer, then loads those
  namespaces through =Env.load_sdk_library!= and its original global SDK lifetime.
  Original Execution/Generation instance preparation still admits the application.

The closed compiler recognizes fully qualified physical =Elixir.Module/function=
spelling alongside =erlang/function=, without ambient alias lookup. Compile-time
caps remain checked. Recognition grants no runtime authority: the native Source
owner still checks public SDK targets, exact loaded code and the actual execution
frame. Private SDK entries and raw Process effects remain refused.

* Archive identity and effects
Forwarding Source includes a constant-time executable MD5 pin using existing
Erlang metadata operations. A phase archive retains this check even when imported
without a manifest SDK row. A changed body cannot silently take over the archived
binding. Native public-MFA checks still apply; the pin only narrows execution.
An archive without a corresponding loaded provider may refuse rather than load
an unselected provider implicitly. Complete packaged/cold SDK archive activation
remains an integration obligation, not a claimed capability of this slice.

Preparation and emission remain passive. Runtime SDK functions do not become
compile-time capabilities: constructor interpretation retains its existing closed
effect policy. This slice does not qualify arbitrary SDK macros or phase effects.
Phase-zero values are runtime initializers, not constructor evaluation; the old
contextual-program test expectation was reconciled to that existing semantics.
The original immutable SDK independently confirms zero preparation effects/calls.

* Bootstrap primitives and managed cleanup
The bootstrap ABI table lives in authenticated RT seed bytes. It is separate
input data from an ordinary std-library declaration, but projects to the same
function descriptor and canonical Source catalog. Core declaration privacy may
only narrow the ABI table. Unknown/private/critical entries refuse.

Original seed manifest hashes and passive literal disassembly establish this
selection. No live =__bl_ns_defs__= getter or namespace Var supplies authority.
Bootstrap forwarding shims can legitimately gain unrelated functions: their
existing native owner verifies all protected routes. Selected RT callables use
the original stable implementation bodies, so the executable MD5 pin stays exact.
Source provenance absent from these ABI records remains absent; it is never
replaced with a BEAM hash. =:declaration-sha256= separately names the Core artifact.

Core was already booted and retained by the SDK owner. Loader verifies every
selected primitive before application effects and does not run a fictitious
std-library initializer for core. This does not add a bootstrap production fallback.
Only primitive entries with original seed artifact evidence are currently selected;
nonprimitive boot functions and OTP-only entries remain unimplemented/refused.
