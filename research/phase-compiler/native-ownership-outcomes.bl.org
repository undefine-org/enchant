#+title: Native ownership has outcomes, not unconditional moves

* Match the actual owner before proving callers

The initial logical native handoff rules were too strong: preparation does not
move the source, acceptance does not return a bare new registration, and repeated
acceptance is not a second move. Native protocol v2 now describes these actual
interfaces. Generic user-declared move/accept contracts retain their distinct
semantics and version-1 compatibility.

system.ownership/handoff-outcomes is a bounded relation over symbolic cleanup
obligations. The compiler transfer and the native trace checker consume that
same relation. Its IDs, states and return descriptions are ordinary data; they
cannot create a native registration or satisfy an owner/epoch/admission fence.

prepare-handoff! can return :cancelled or {:source registration :accepted target}.
Successful preparation leaves the source owned and adds an inactive target's
cleanup obligation. accept-handoff! can return accepted, busy or cancelled status
envelopes. Acceptance moves the source and activates that exact target; repeated
acknowledgement returns it again. Busy/cancelled outcomes do not erase pending
cleanup. Native close is idempotent for active, inactive and consumed addresses;
closing an inactive target leaves the original source intact.

The abstract value domain preserves those envelopes and keyword projections,
including an absent registration/accepted field. It does not execute arbitrary
collection hooks. Callback invocation remains unknown and records callback
effects, custody and deadline obligations; its exception may follow effects.

* Protect acquisition boundaries and both cleanup addresses

The source must already be protected when preparation begins: putting the only
finally inside the preparation's let body leaks it if preparation throws. The
following example is analyzed without executing registration. :owner is a
symbolic argument; actual native owner validation remains a runtime obligation.
The real native example below supplies a real PID.

#+begin_src beam-lisp :id handoff-cleanup-paths
(ns ownership.native.paths (:require [system.ownership :as ownership]))
(let [source "(let [r (BeamLisp.Execution/register! (fn [] 42))] (try (let [p (BeamLisp.Execution/prepare-handoff! r :owner)] (try (do (when (:accepted p) (BeamLisp.Execution/accept-handoff! p)) 42) (finally (when-let [target (:accepted p)] (BeamLisp.Execution/close! target))))) (finally (BeamLisp.Execution/close! r))))"
      node (BeamLisp.Compiler/compile (BeamLisp.Reader/read_one source)
                                     (BeamLisp.Compiler/new_env "ownership.native.example"))
      report (ownership/check [{:id 'handoff-cleanup :body node}] (ownership/execution-protocol))]
 (assert (= :conditional (:status report)))
 (assert (= 'native-execution-lifecycle-v2 (:protocol report)))
 (assert (= false (:native-admission report)))
 {:status (:status report) :protocol (:protocol report) :issues (:issues report)
  :runtime (set (map :kind (:runtime-obligations report)))})
#+end_src

#+begin_src beam-lisp :id real-native-handoff
(ns ownership.native.actual)
(let [source (BeamLisp.Execution/register! (fn [] 42))
      prepared (BeamLisp.Execution/prepare-handoff! source (erlang/self))
      target (:accepted prepared)]
 (try
  (assert (= :active (:status (BeamLisp.Execution/observe source))))
  (assert (= :pending (:status (BeamLisp.Execution/observe target))))
  (assert (= {:status :accepted :registration target} (BeamLisp.Execution/accept-handoff! prepared)))
  (assert (= {:status :accepted :registration target} (BeamLisp.Execution/accept-handoff! prepared)))
  (BeamLisp.Execution/close! source)
  (assert (= {:status :completed :value 42} (BeamLisp.Execution/invoke! target [])))
  (BeamLisp.Execution/close! target)
  {:source (:status (BeamLisp.Execution/observe source))
   :target (:status (BeamLisp.Execution/observe target)) :same-target-on-repeat true}
  (finally (BeamLisp.Execution/close! source) (BeamLisp.Execution/close! target))))
#+end_src

* A shared lookup defect, caught before full SDK assembly

get/3 on a vector ignored its not-found argument. That made a missing optional
operand return raw nil during abstract projection. RT coll-get now checks valid
integer membership before fetching; an absent index returns the default, while
present nil/false remain those values. Both flat and trie vectors, get-in paths,
macro constructor values and actual Source-free receivers are regression cases.
The repair changes boot Source, so it requires a coherent regenerated candidate
and complete B/C reproduction; a Source-only warm check cannot qualify it.

* Exact evidence scope

The native test replays actual preparation, acceptance/repetition, cancellation,
competing targets, source closure, target closure and owner death against the
same relation. It checks native return envelopes and observed registrations at
each event. Sender death is checked both before and after acceptance, including
actual invocation of the surviving target. These are bounded conformance traces,
not proof of all interleavings or capacity failures.

The busy outcome is conservatively present and retains cleanup obligations;
native capacity-fault conformance is still unverified. Future physical custody,
deadlines, callback effects, native cleanup/drain and general recursive analysis
remain separate obligations. No model report grants native execution authority.
