#+TITLE: Loaded native runtime compatibility

* The owner is the loaded library

A contextual program already binds its support BEAM floor and language runtime
versions into =:runtime-image=. That was insufficient for the mandatory
LazyMemo NIF: two native implementations could accompany identical support
BEAMs. Hashing a library pathname after loading also confuses the file now at
that pathname with the implementation already executing in the VM.

The Rust crate now generates a deterministic build fingerprint from its sorted
Rust sources, Cargo manifest and lockfile, build script, Cargo target/settings
and rustc version. The library reports that fingerprint through
=nif_runtime_identity/0=. =BeamLisp.LazyMemo/runtime_identity!= first ensures the
actual library is loaded, then calls that NIF. No public Env row, Source flag,
caller-supplied stamp or new custody registry selects it.

The existing =AOT/runtime_image_key_for= stamps the actual loaded fingerprint,
ERTS version, architecture and NIF version alongside the existing support floor
and OTP/Elixir versions. Producers and Env adoption use that same owner. Program
bytes remain outside the support identity; there is no recursive artifact hash.
A fresh receiver with a different native fingerprint must refuse before its
program executes. The old target schema is deliberately incompatible.

This is a declared native build identity, not a SHA of the final shared object,
a cryptographic attestation, or an ABI equivalence proof between builds. It
covers the mandatory LazyMemo kernel, not optional SDK NIFs; those keep their
existing inventory/selected-library owner. Linker inputs outside the recorded
Cargo settings are not authenticated by this fingerprint. Exact product
attestation and a complete SDK native closure remain separate obligations.

* Actual process controls

=scripts/demo-runtime-image --native-variant PATH= accepts a separately built,
callable LazyMemo product. The control build changes one comment in an isolated
copy of the crate: runtime behavior stays callable while its recorded producer
inputs differ. The normal real producer emits all five bracket-based examples.

In one fresh consumer, LazyMemo loads the selected original product. The test
atomically replaces its pathname with the control product and verifies that the
loaded fingerprint and runtime target stay unchanged, and an actual native cell
still returns42. It restores the original pathname afterward.

Another fresh consumer loads the control product at the same path alongside the
identical BEAM floor. It must refuse the original program with
=:compiled_runtime_image_changed= before any entry output. These controls run in
separate processes; they never attempt live NIF replacement. All previous
Env custody/death/retry and source-free gallery controls run afterward.

The crate freshness owner in =vm.native= now includes =build.rs=, so changing the
fingerprint producer cannot silently skip a native rebuild.
