#+title: Compiler-owned function declarations at the publication boundary
#+state: Focused component verified; complete contextual units and immutable qualification pending

* One owner before publication
The compiler previously produced an executable Link.defvar/Env.put_meta scaffold
for defn. AOT then recognized that scaffold to recover the clauses it needed.
This coupled artifact production to the shape of interactive publication code.

The compiler now prepares one version1 function-declaration descriptor containing
namespace, name, clause entries, source location and metadata. Interactive
compilation renders publication ANF from that descriptor. AOT stage-function!
consumes its entries and metadata directly. The old stage-scaffold recognizer and
its second clause-entry decoder are deleted. There is no selection flag or second
function compiler.

The boot compiler owns prepare-function-declaration(form, env); the pinned native
facade delegates prepare_function_declaration/2 to it. Preparation retains the
existing deterministic prelink operation in the selected compile environment.
It does not publish the function value or metadata, execute its body, load a target
module or grant SDK/Source authority. A nested capturing defn remains an expression
in ordinary compilation; the top-level declaration API refuses captured environments.

* Example
#+begin_src beam-lisp
(let [form (first (BeamLisp.Reader/read_string "(defn identity [x] x)"))
      env (BeamLisp.Compiler/new_env "example")
      declaration (BeamLisp.Compiler/prepare_function_declaration form env)]
 (select-keys declaration [:version :kind :namespace :name]))
;; {:version 1 :kind :function-declaration :namespace "example" :name "identity"}
#+end_src

Clause entries retain the established fixed/variadic ABI and ANF annotations.
Root Reader positions use the same pos-env owner as ordinary compilation.
Metadata on a declaration name is preserved; metadata on the publication result
requires expression compilation and refuses at this boundary before prelinking.
The focused test derives a local binding from actual expand/expression Source,
passes its authentic contextual reference table into declaration preparation,
and checks the exact identity on the compiled clause body. No binding table is
invented from ambient Env state. codebase/system/typed/errors still consume the
same canonical ANF and provenance; this slice adds no second fact schema.
