#+TITLE: Same spelling, different bindings

* A name needs a context

A quoted symbol such as ='temporary= is name data. An identifier combines that
symbol with lexical context. Two identifiers can print the same name and refer
to different declarations. That is how a macro introduces its own temporary
without capturing a temporary supplied by its caller.

The boot-owned =syntax= and =binding= namespaces implement a bounded, pure model
over the actual Reader. =expand/program= consumes them in the =syntax-v1=
compiler path, including =defsyntax= and source-derived imports. The fixtures
below isolate lookup from compilation; the [[file:language.bl.org][compiled walkthrough]] exercises the
whole path. These tables grant no native execution authority.

The scope rule follows [[https://docs.racket-lang.org/reference/syntax-model.html#%28part._.Identifiers__Binding__and_.Scopes%29][Racket's syntax model]]: a declaration applies when its
scopes are a subset of the identifier's scopes. Its binding must have a scope
set containing every other applicable candidate's scopes. Otherwise lookup is
ambiguous. This model also makes binding space explicit in the lookup key.

| Owner | Responsibility |
|-------+----------------|
| =syntax= | Reader-backed trees, contexts, source spans, explicit datum conversion and template substitution |
| =binding= | Canonical input/scope/declaration keys, immutable indexes, phase/space lookup and availability |
| =expand-source= / =expand= | Derive actual declarations, allocate scope coordinates and drive existing bounded macro evaluation |

* Watch a template avoid capture

Run from the repository root:

#+begin_example
./bin/bl --cold doc run research/phase-compiler/contextual-bindings.bl.org
#+end_example

This fixture gives one =temporary= a caller scope and the other an introduction
scope. Template substitution preserves the supplied syntax exactly. The table
is explicit fixture data; this cell tests name resolution, rather than claiming
that the production compiler already consumes contextual bindings.

#+begin_src beam-lisp :id avoid-capture
(ns phase.contextual.walkthrough (:require [binding :as b] [syntax :as s]))

(let [source "[temporary supplied]"
      selection {:version 1 :profile 'syntax-v1 :target 'beam-v1
                 :sources [{:namespace 'example :digest (crypto/hash :sha256 source)}]}
      module (b/scope selection 'example [0] :module)
      caller (b/scope selection 'example [1] :lexical)
      intro (b/scope selection 'example [2] :introduction)
      context {:world (b/world-key selection) :namespace 'example :space 'value
               :scopes {:all [(:id module)]}}
      supplied (s/identifier 'temporary
                 (assoc context :scopes {:all [(:id module)] 0 [(:id caller)]}))
      template (first (s/read source "template.bl" context))
      expanded (s/template template {'supplied supplied} (:id intro))
      declaration (fn [path scopes]
                    {:namespace 'example :name 'temporary :phase 0 :space 'value
                     :kind :value :visibility :local :available-from 0
                     :path [path] :scopes scopes})
      world (b/world selection [module caller intro]
              [(declaration 1 [(:id module) (:id caller)])
               (declaration 2 [(:id module) (:id intro)])])
      introduced (b/resolve world (first (:children expanded)) 0 0)
      substituted (b/resolve world (second (:children expanded)) 0 0)]
  (assert (= ['temporary 'temporary] (s/to-datum expanded)))
  (assert (= supplied (second (:children expanded))))
  (assert (= :resolved (:status introduced)))
  (assert (= :resolved (:status substituted)))
  (assert (= '(2) (get-in introduced [:declaration :path])))
  (assert (= '(1) (get-in substituted [:declaration :path])))
  (assert (not= (get-in introduced [:reference :id]) (get-in substituted [:reference :id])))
  {:same-spelling true :same-binding false :caller-context :preserved})
#+end_src
#+RESULTS: avoid-capture
: {:same-spelling true, :same-binding false, :caller-context :preserved}


* Phase, space and position answer different questions

=binding/resolve(world, identifier, phase, position)= first looks in the
=name/phase/space= bucket, then checks scopes and declaration availability.
A runtime value at phase 0 and a helper at phase 1 are distinct bindings.
A type and a value can also use the same symbol in separate spaces.

Syntax contexts carry separate scope sets for each phase, plus =:all= scopes
that apply at every phase. An introduction scope therefore survives a phase
shift, while each module phase can retain its own context.

Lookup returns =:resolved=, =:unbound=, =:ambiguous= or =:not-yet-available=.
Selecting an inner declaration before its authored availability point returns
=:not-yet-available=. It does not silently choose a less-specific outer binding.
No lookup consults Env, reads a file or executes a transformer.

* Import a provider into another phase

The =binding/import-view= API connects modules in one selected logical world;
=binding/select= connects distinct worlds, including revisions of one namespace.
An import view preserves the original declaration. =:alias= and =:rename=
change its visible spelling; =:phase-shift= changes the reference's phase.
The consumer must carry the explicit import scope. Only public declarations
can enter this view. Two aliases at the same phase refer to the same binding;
a reference at a different phase has a different reference key.

#+begin_src beam-lisp :id phase-import
(let [selection {:version 1 :profile 'syntax-v1 :target 'beam-v1
                 :sources [{:namespace 'provider :digest (crypto/hash :sha256 "provider")}
                           {:namespace 'client :digest (crypto/hash :sha256 "client")}]}
      provider (b/scope selection 'provider [0] :module)
      import (b/scope selection 'client [0] :import)
      declarations [{:namespace 'provider :name 'answer :phase 0 :space 'value
                     :kind :function :visibility :public :available-from 0
                     :path [0] :scopes [(:id provider)]}
                    {:namespace 'provider :name 'helper :phase 0 :space 'value
                     :kind :function :visibility :private :available-from 0
                     :path [1] :scopes [(:id provider)]}]
      world (b/world selection [provider import] declarations)
      request {:from 'provider :into 'client :scope (:id import) :phase-shift 1
               :space 'value :only ['answer] :alias 'p}
      imported (b/import-view world request)
      identifier (s/identifier 'p/answer
                   {:world (:key world) :namespace 'client :space 'value
                    :scopes {1 [(:id import)]}})
      result (b/resolve imported identifier 1 0)]
  (assert (= :resolved (:status result)))
  (assert (= 'provider (get-in result [:declaration :namespace])))
  (assert (= 0 (get-in result [:declaration :phase])))
  (assert (= 1 (get-in result [:reference :phase])))
  (assert (= :unbound (:status (b/resolve imported identifier 0 0))))
  (assert (= imported (b/validate-world imported)))
  (assert (= :binding-import-private
             (try (b/import-view world (assoc request :only ['helper])) nil
               (catch error (:kind (ex-data error))))))
  {:visible-name 'p/answer :provider 'provider :definition-phase 0 :reference-phase 1})
#+end_src
#+RESULTS: phase-import
: {:provider provider, :visible-name p/answer, :definition-phase 0, :reference-phase 1}


Declarations and import views in these fixtures are explicit model inputs.
The compiled path derives them from actual Reader units. Serialization
validation checks their structure and indexes; it does not claim that a
caller's hand-built table matches arbitrary source text.
Cross-world views between a preceding compiler phase and candidate source
remain a separate integration gate; they must retain both namespace revisions.

* Keys describe logical inputs; attestations bind physical bytes

=binding/world-key= accepts source namespace/revision pairs, profile and target.
It normalizes finite collections and ordering. Physical artifact hashes and
receipts belong to the separate production attestation, so repackaging does not
alter a binding key. Changed source revisions do alter the logical world.

Scope keys use owner, structural expansion path and role. Declaration keys also
include phase, space, kind and authored coordinates. Process counters, native
references and absolute file locations have no place in these keys. Source
spans remain on syntax nodes for diagnostics and Reader roundtripping.

=binding/validate-world= rebuilds every serialized index before repeated lookup.
Lookup uses the matching bucket and a scope union, avoiding a scan of all
declarations or all pairs of candidates. Inputs are eager and finite. Syntax
work accounts for tree depth, metadata and repeated scope references; template
holes and total substituted output have aggregate bounds.

=syntax/to-datum= explicitly forgets context. Reconstructing syntax with
=syntax/from-datum= requires a chosen context. A map resembling ANF stays
ordinary map data. Record Reader nodes roundtrip through =syntax/to-reader=;
materializing record values belongs to the expander/compiler and is refused
by the pure datum conversion.


* Ordered entry units share the compilation session
The same =expand/prepare-program= entry now accepts an ordered sequence of
phase-zero forms, or a declaration-only entry. It expands every form before any
runtime entry executes. Each form retains its authored position and module
context; siblings do not inherit one another's lexical scopes. Transformer
images, phase values, reference tables, expansion fuel and the bounded constructor
session belong to the complete unit. They are not recreated per form.

#+begin_example
(ns initialization)
(defsyntax answer [form context] (syntax-literal 42))
0
(answer)
(answer)
#+end_example

This entry returns42, records two macro expansions/calls and caches one
transformer image. Putting =(answer)= before its declaration refuses before
runtime effects. A declaration-only entry returnsnil and exports the same
portable phase recipes. Compilation builds one canonical entry declaration;
World analysis and raw artifact emission consume its exact body. A runtime
initializer failure prevents later effects.

This is entry-body integration, not a complete ordinary namespace compiler or
once-per-activation initializer owner. Provider expressions remain unsupported,
and closed-profile values retain their existing restrictions. Physical module
exports, ordinary Source/bootstrap/AOT/reload/JS adapters and verified activation
still require migration. Commitfea2125e and contextual-initialization-checks.json
record202 passing private-component assertions; actual new immutable B/C/SDK
qualification remains required. No alternate language engine or entry mode is
introduced.


* Declaration headers have one compiler owner
=compiler/declaration-source(form, env)= projects a supported declaration into
inert =:kind=, =:name=, =:metadata=, =:visibility= and =:value-form= data. The
normal compiler's value/function publication and prelinking share its header
parsers. The contextual catalog and phase-library validator rederive visibility
from that same owner rather than reading only the defn- spelling. Metadata has
its established precedence: attribute maps override name metadata; defn- privacy
and explicit docstrings apply last. Only a true private flag means private.

#+begin_example
(ns forms)
(begin-for-syntax (def ^:private offset "phase constant" 40))
(defsyntax answer "Documented transformer" {:audit :stored}
  [form context] (syntax-literal (erlang/+ offset 2)))
#+end_example

A Source-free phase archive of this provider supplies42 to a client importing
answer. Its private phase helper remains available to the transformer. Direct
imports of metadata-private functions, values or transformers refuse. Rebuilding
a library's declaration IDs, indexes and digest cannot override private metadata
in its stored recipe; recipe validation rejects the contradiction before use.

Header projection executes neither declaration bodies nor metadata expressions.
Consumption of declaration-name metadata does not permit runtime expression
metadata effects. Per-environment values need runtime lifetime semantics and
refuse in the closed constant profile. These checks provide no SDK provenance or
execution grant. Commita67b1449 passes306 private-component assertions; actual
new immutable bootstrap/SDK qualification and physical namespace export
integration remain separate requirements. See declaration-header-checks.json.


* Logical namespace and physical recursion target are distinct
The canonical declaration owner now accepts an explicit physical module:
=BeamLisp.Compiler/prepare_function_declaration(form, env, module)=. The existing
two-argument adapter selects the namespace module and calls the same owner.
AOT supplies one chosen module to both preparation and body attachment, so
recur does not reconstruct a physical target from the logical namespace.

Two selected revisions may share a logical namespace while their actual code
lives in different modules. The native component demonstrates16/106/16 across
two such modules, variadic tail recursion, and first-class values using the
existing fixed/variadic ABI. Target metadata grants no code origin, publication
permission or Execution admission. With contextual references present,
preparation leaves Env links/definitions untouched.

Commit987b3aa4 passes371 focused component assertions, including the private
retargeted facade ABI differential. It changes the compiler interface to include
arity3; the AOT consumer requires a matching new immutable compiler/facade/SDK.
No old-floor fallback is provided. Complete selected-global lowering, physical
namespace exports and adapter/activation integration remain required. See
physical-declaration-checks.json for exact scopes and retained failures.
