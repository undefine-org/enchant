#+TITLE: Compilation worlds use the ordinary build and shared cache

* One file owner below the CLI

=compile.world= owns bounded manifest/file capture, contextual preparation,
artifact-unit adaptation and build/cache orchestration. =bl.world= remains a
thin CLI and compatibility API. Parsing, expansion, ANF, phase projection and
arity checking keep their existing owners.

Capture reads and hashes physical inputs without expanding providers. The
cache identity records the actual manifest, ordered input digests/sizes,
compiler/build keys, target module and full body/interface identities of the
pipeline's discovered Source dependency closure. Existing content-keyed planner
parts supply those nodes. Interface-only freshness cannot validate phase work.

A world build first verifies native framework/SDK custody and uses the existing
workspace claim. A current local complete unit needs no macro execution. A
shared-cache hit goes through =AOTCache/prepare_fetch=, checks both members'
recorded complete selection, and replays captured BEAMs through AOT's existing
emitter and verifier. Changed input or pipeline data selects new preparation.
No cache result grants execution admission or SDK authority.

The complete pair stays in =artifact-unit/=. Only the runtime member goes to
=ebin/=, where the ordinary app-resource writer records runtime modules. Unit
files publish with their manifest last; actual byte validation refuses partial
or damaged state. A later build can repair known members from the cache. Foreign
members refuse rather than being deleted. Temporary stage creation establishes
cleanup ownership; atomic file writes replace only selected output files.

* Declaration and API

#+begin_example
;; env.bl
{:build {:world "world.bl" :out "build"}
 :app {:name "example" :vsn "0.1.0"}}

;; ordinary command
./bin/bl build

;; existing build API, same workspace claim
(build/run {:world "/project/world.bl" :out "/project/build"})
#+end_example

Explicit PATH arguments keep the existing Source build path. A world manifest
is a complete selection: mixing it with Source roots, exclusions, native or
Elixir substrate stages refuses. Failed world builds publish no app resource.
The optional =:runtime-manifest= and =:runtime-out= result fields identify what
runtime packaging may carry; =:manifest= retains complete paired membership.

* Executable warm build

#+begin_src beam-lisp :id contextual-warm-build
(ns compilation.world.build.walkthrough (:require [build :as build]))
(let [out (Path/join (System/tmp_dir!) (str "world-build-demo-" (erlang/unique_integer (list :positive))))
      opts {:world "test/fixtures/contextual-validation/world.bl" :out out}]
 (try
  (let [first-run (build/run (assoc opts :force? true)) warm (build/run opts)]
   (assert (empty? (:errors first-run))) (assert (empty? (:errors warm)))
   (assert (= 1 (:compiled first-run))) (assert (= 0 (:built warm)))
   (assert (= 1 (count (:modules (first (vals (:runtime-manifest warm)))))))
   {:compiled (:compiled first-run) :warm-builds (:built warm)
    :runtime-modules (count (:modules (first (vals (:runtime-manifest warm)))))} )
  (finally (File/rm_rf! out))))
#+end_src
#+RESULTS: contextual-warm-build
: {:compiled 1, :warm-builds 0, :runtime-modules 1}


* Scope

Actual VM tracing, not a user callback counter, observes constructor-session
macro evaluation. Tests cover unchanged local hits, shared restoration after
output removal, forced rebuild, provider edits, damaged bytes, foreign files,
unevaluated entries, project schema/CLI dispatch and runtime-only app metadata.
Source reads/hashes and cache validation still happen on a hit. No zero-I/O,
RSS, universal proof-cache or whole-repository migration claim follows.

Default Loader execution and broader release/SDK packaging retain their own
activation and cold-consumer gates. A runtime directory is not by itself a
qualified standalone release. Broader forms and remaining execution/analysis /
historical/platform obligations also remain open.
