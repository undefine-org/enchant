#+title: Contextual compilation from a sealed SDK

* One current compiler, two physical representations

A checkout derives its current compiler/build keys from live Source. A wholly
Source-absent SDK derives those same producer identities from its actual floor:
schema, runtime version, bounded complete member bytes and loaded stable MD5s
must agree. The current-key APIs remain uncached freshness checks. Their
VM-lifetime counterparts retain their existing memo. A partial Source tree
uses live hashing; every suffix in Tiers/source_extensions participates.

This applies to an actual sealed SDK with sdk-code.term. A compiled-only runtime
release has a separate runtime-target contract and does not become a compiler
SDK merely because Source is absent. Unsupported compiler backends still refuse.

* Pipeline identity belongs to artifacts

compile.world keeps the existing content-keyed BuildPlan closure in a checkout.
With SDK Source absent, AOT/sdk_pipeline_identity! captures the actual selected
SDK units and floor requirements through the same bounded metadata decoder as
the loader. Every selected unit includes its complete byte-verified membership.
The floor and native runtime target remain compatibility inputs.

The capture uses physical SDK namespace names, independent of the caller's Env
or namespace mappings. It neither loads modules nor initializes providers.
Initializer/lease publication stays with its existing owner. The returned map is
ordinary identity data and grants no execution or resource authority.

Inventory bytes are checked before/after capture, but unrelated rows do not
enter the returned identity. Loaded-namespace flags cannot prune dependencies.
A required row's removal refuses even if its code remains loaded. A selected
body's changed bytes refuse before cache reuse, rather than running an old
cached program against a different compiler.

* Actual Source-absent compiler control

scripts/demo-sdk-artifacts --activation-smoke --source-free --contextual-tests
uses the real BuildPlan resolver and artifact SDK producer. Its image includes
the actual compile.world/build dependency closures, then omits SDK Source and
starts fresh receivers. The receiver prepares a project using quoted world
symbols and a macro provider, builds it, executes 42, takes a warm hit with zero
macro executions, restores complete artifacts from the shared cache without
expansion, and recompiles after the provider changes to produce 43.

The same receiver checks all supported Source suffixes, unsupported backends,
namespace-scope independence and unrelated-inventory independence. It removes
real membership or changes real selected bytes only as denial controls, restores
them in finally, and requires refusal before reuse. It also runs the actual
cross-world import and archived phase-value tests with SDK Source absent.

A diagnostic receiver replay can isolate a test-driver failure without rebuilding
the SDK. It never replaces frozen qualification: the final gate must rerun the
producer and all receivers with unchanged Source/floor/test/native inputs.
Full SDK production, bootstrap reproduction, native packaging and final
regressions remain separate requirements in the canonical completion checklist.

* Scope

This provides a compiler and cache path using sealed SDK pipeline artifacts.
It does not assert standalone dependency/ERTS packaging, optional native closure,
minimal affected-cone compilation for all world providers, or the finite
ownership/deadline/cleanup analyses still tracked in
[[../../!tasks/plans/CHECKLIST-language-execution-completion.org][the completion checklist]].
