* Boundary and APIs
A process mailbox is also an OTP control channel. A Source operation must not
become an arbitrary send to framework processes or an untracked transfer of
callbacks/resources. The required example only needs a self inbox for closed
data. This is one explicit operation in the final architecture; it does not
replace the remaining general actor/callback custody obligations.

=proc.mailbox/context= delegates to =Env.source_mailbox_context!=. The native
owner requires a real active Source execution frame and returns its original
graph marker as an identity selector. The selector alone grants no execution,
lease, context switch, callback invocation or recipient access.

=proc.mailbox/post-self!= delegates to =Env.post_source_mailbox_data!=. It has no
recipient argument. Before sending, it checks the actual Source frame, uses the
existing bounded first-order validator, and rechecks the same frame identity.
It sends a fixed native envelope:
#+begin_src beam-lisp
[:bl_source_mailbox_data instance-selector closed-data]
#+end_src
The actual outer carrier is a native tuple. Payloads admit the existing closed
scalar/list/map/symbol/vector/set domain. Native control tuples, functions, refs,
mutable cells/resources and deferred values are refused. No new validator,
registry, retention owner or privilege flag is introduced. No raw-send grant is
added; raw Source send still fails at preparation.

* Existing contextual syntax
The real SDK selection remains quoted and explicit:
#+begin_src beam-lisp
{:sdk 'proc.mailbox :revision 'selected :only ['context 'post-self!]}
#+end_src
The existing example posts two values and selectively matches them:
#+begin_src beam-lisp
(import-world 'proc.mailbox 'selected :only [post-self!])
(post-self! [:other 7])
(post-self! [:answer 40])
;; Existing await-reply bracket syntax then produces [42 107 99].
#+end_src
The mailbox macro requires proc.mailbox at definition site. It expands to an
ordinary canonical receive guarded by equality with the current inbox selector.
Its temporary names remain hygienic; foreign generation envelopes remain queued.
No runtime parser, matcher or second message queue is installed.
