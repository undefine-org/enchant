#+title: Actual SDK compiler child and alternating edit controls

* Decision

The previous qualified owner-cleanup change is on main (24ce4455d). This
round adds a better benchmark and a qualified parsed-form reuse candidate.
The candidate does not establish a latency improvement and stays on
perf/producer-latency. Do not advertise or merge it as an SDK speedup.
Main removes the extra always-on compilation timing callbacks introduced
while profiling; its unit-store implementation returns exactly to 24ce4455d.
The detailed timings remain diagnostic evidence from the measured variants.
No validation, ownership check, timeout, cache key or coverage is relaxed.

* Method and scope

All heavy work ran serially through the repository Source-described Build
backend, in private checkouts. Memory was inspected first: initially about
20 GiB available and no BEAM VMs. Controllers had an 8 GiB/no-swap ceiling;
public command trees and diagnostic evaluations used smaller caps. Production
guests retained their existing 6144 MiB/four-CPU bounds. max-jobs=1, cores=2
and BEAM scheduler limits were operator environment settings outside the
language. Other station workloads remained active. These are shared-station
observations, not isolated release budgets.

The original baseline freezes 24ce4455d, before the added compilation timers.
The candidate combines guarded reader-form reuse with inline diagnostic
clocks that avoid capturing prepared graphs in extra callbacks. Concurrent
Datom/drop changes on main are not folded into either performance variant.
The earlier three-edit instrumented baseline is retained separately in
benchmark-instrumented-baseline.json and is not the original-main comparison.

paired.py uses AB / BA / AB ordering and new, identical within-pair edit bytes.
Each variant starts each edit from its own fixed predecessor. benchmark.py
runs the actual Source-backed preparation command, verifies exact compiler
and runtime identities, checks every restored unit file, and restores Source
and selection in finally. Tags must be fresh. The harness checks Nix image registration time and
rejects a retained image as a new edit. freshness-proof.json verifies all six
original images were registered during their measured commands and records a
real reused-tag negative control with Source/selection restored. Keep raw logs.
compare.py requires three matching compiled/cache/input-count observations.

Historical image logs never count as work performed by an unchanged command.
Image phases are read from the corresponding edit producer; worker debug
replays are deduplicated. Client time-v RSS excludes independent producers,
coordinators and guests. Compiler memory comes from the actual library child.

profile.py instruments that child, rather than a similarly named outer VM.
The exact selfbuild Source is loaded privately by the diagnostic driver;
compiler inputs remain unchanged. Samples are bounded at 8192 distinct stacks,
with dropped counts, reader counts, selected exact call_time functions and
/proc/self/status. Instrumented wall time is never an optimization baseline.
Every target library unit-store file matches the plain corresponding edit.
The retained producer subtree differs because the diagnostic driver changes
its dependency closure; equivalence is not claimed for that subtree.

Nix's guest shutdown console can interrupt a debug row. sample.py retains
intact rows, validates chunk ordering, sample counts and target inventory, and
reports ambiguous interrupted fragments explicitly. It never invents frames.
Child counters and memory are intact records; interrupted stack captures are
not claimed complete. Earlier failed harness attempts remain in private raw
logs and are excluded from latency comparisons. No production timeouts changed.

preflight, ownership, compiler limits and emission verification all remain.

* Fresh production and remaining bottlenecks

A fresh candidate cohort compiled all 533 units, restoring none. Unit production
took 1174.330 s; child production 1175.058 s. Preparation took 1018.041 s,
emission 136.025 s, and workspace opening 0.449 s. Packing took 16.741 s.
This is a fresh-cohort diagnosis, not a comparison to an older fresh build.

In the original nine-unit trace, constructor_install_kernel! exclusive traced
time was 0.134 s total and Env.fork was 0.000262 s. Rebuilding environments is
not shown to dominate that edit. Reader/lowering and repeated constructor unit
and metadata discovery deserve the next investigation; broad workspace caching
is not justified by this profile. Any reuse must preserve parser/compiler
identity, exact environment, Source receipts, ownership and bounded lifetimes.

nix-unchanged.json separately records three instrumented evaluations of the
same unchanged application product: 3.649–3.827 s, about 1.073 million function
calls, 1.927 million thunks and 5357 derivationStrict calls (not unique derivations).
The capped service peaked at 378.7 MiB. Module evaluation accounts for 325351
function calls. Factoring the fixed VM/worker recipe graph is a plausible next
cut, requiring exact derivation/dependency-context equivalence across changed
requests, native inputs and operator settings. A cached receipt is not a
replacement producer identity. This boundary remains unchanged.

The expensive Source-extent fixtures and full CI coverage are preserved.
This batch does not optimize CI sharding or claim full release qualification.
Full release CI, packaged retention and the repository's wider admission gates
remain required before another release.

* Qualification

The final candidate passed nine affected BL files, 259 assertions: artifact
workspace/emission/host, SDK staging, constructor cache/diagnostics, unit store,
contextual artifact unit and compiler constructor data. Inline timing also
passed all 27 unit-store assertions independently. The cheap discovery audit
covers all 16 boundaries and nine external writers; it is not execution proof.
The reproducibility file passed all seven assertions. Python discovery passed
182 tests with three existing skips. Actual checkout transport controls passed,
including concurrent request environment isolation, cwd/argv, failure recovery,
source/provider edits and reuse of the same owner. Independent P/B/C compiler
proof passed for 141 seed files; only AOT.beam and manifest.term differ from the
original compiler. Compiler and image Nix store verification passed. The restored
production unit-store code independently passed its 27 assertions on the original
SDK. qualification.json retains raw receipt paths and digests.

commands-original.json and commands-candidate.json passed cold/warm eval,
unchanged/edit/fresh-process app builds and unchanged provider-file inventory.
The app edit compiled one/restored one unit and returned 43 in a source-free
receiver. The candidate SDK passed source-free integrity, missing/corrupt-member
controls. unchanged-builds.json records three alternating repeats per variant:
