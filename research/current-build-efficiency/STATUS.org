#+title: Current build efficiency and correctness
#+date: 2026-10-31

* Scope

Fix failures reproduced on the current checkout. Historical audit closure is
not a prerequisite for these changes. The machine-readable checks and immutable
product identities are in =checks.json=.

* Confirmed CI failure

Published main's [[https://github.com/timinou/beam-lisp/actions/runs/41173906180][CI run]] failed before compilation because the source checks
needed Nix and ripgrep. Install both before running those checks. A clean
checkout with system/global Git configuration disabled passed all 54 source checks
(one existing application-output skip); actionlint 1.7.12 also passed;
the hosted workflow has not been rerun from this branch.

* Keep compilation and its artifacts on the station

A collected historical proof occupied 451,296 bytes but referenced a
2,893,979,232-byte SDK closure. Nix fetched those dependencies to collect a log.
The new =scripts/ci-check= runs the selected immutable SDK inside the station's
bounded worker and returns text receipts with zero Nix references. The initial
two-file check passed 14 assertions; its entire output closure was 3,408 bytes.
An injected failing file returned an inspectable failed receipt and client exit
1. Both checks consumed an existing SDK without requesting SDK production.

The command uses the ordinary SDK recipe when production is required. Its
=--previous= input preserves validated namespace units. The first Datom candidate
restored 440 units and compiled 53. The final candidate restored 448 units and
compiled 45. Both reused all seven native products, dependencies and compiler.
Tests share one VM except fixtures that explicitly require
isolation. No local checkout BEAM was started for this work.

* Datom correctness

Equal list/vector values had different ordered keys and same-batch identity
claims. Integers near the float precision boundary also produced incorrectly
ordered keys. Actual ETS/Fjall checks reproduced these failures. The fix
canonicalizes index and temporary transaction keys while preserving separately
encoded payloads. Native scalar lanes retain their existing implementation.

The final candidate passed 627 assertions across 12 targeted files, including
ETS/Fjall identity, exact numeric ordering, range queries, CAS/retraction,
payload preservation, durable reopen, format refusal without writes, native
codec equivalence and analysis-cache reopening. Its frozen SDK source bytes
match the committed files. The complete test receipt has a 15,160-byte output
closure with zero references. These targeted checks do not claim full-suite
coverage.

New stores carry an index-format descriptor. Nonempty unversioned application
stores require explicit offline reindexing into a separate store. No migration
command or automatic data rewrite is included. Codebase and ask caches select
the new =facts-8= generation; old cache files remain untouched. See
[[../../docs/datom-index-key-format.md][the operational format boundary]].

* Runner decision

Keep GitHub Actions as the orchestrator and use the existing build station for
SDK production and qualification. Retain the qualified predecessor and its unit
store outside disposable checkouts. Return only reference-free receipts to
orchestration jobs. The command is working on the station; automatic Actions
access is not configured. It needs an isolated managed client with authenticated
network access and daemon-owned builder credentials. No runner was registered
and no paid provider was activated.

GitHub's [[https://docs.github.com/en/actions/concepts/runners/github-hosted-runners][hosted runner documentation]] treats nested virtualization as
experimental. Its [[https://docs.github.com/en/actions/concepts/runners/larger-runners][larger runners]] require an organization or enterprise on
Team/Enterprise Cloud; this repository is personally owned. More CPU does not
by itself retain SDK units or avoid collecting an SDK closure.

[[https://docs.blacksmith.sh/blacksmith-runners/overview][Blacksmith x64 Linux runners]] explicitly support KVM and are a managed
alternative. That support does not extend to ARM. [[https://namespace.so/docs/integrations/nix][Namespace's Nix cache]] is
early access requiring setup and credentials, and the cache proxy does not
change where builds execute. Neither service was measured or deployed here.

* Remaining deployment boundaries

The GitHub-to-station connection still needs deployment. Hosted end-to-end CI
and release are not qualified by the local source checks or the targeted station
tests. The release matrix still requests targets unsupported by the current
x86_64-linux producer. A readelf inspection of the retained Linux release found
a GLIBC_2.44 requirement while the release text advertises 2.39. Those are
explicit remaining release tasks, not passing results.
