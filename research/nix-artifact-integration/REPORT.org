* Delivered implementation
Native production has an explicit Nix provider shared by Source builds, runtime
native refresh and the pre-BEAM Rust bootstrap. A closed request binds a complete
standalone source snapshot, locked dependencies, target and consumer ABI label.
The pinned platform supplies Rust and Cargo. Final library bytes are verified
against the immutable manifest before publication under existing destination
custody. A failed preparation preserves the prior selection.

Nix owns derivation reuse and immutable products. The adapted Foundry argv
executor carries requests as data, separates machine stdout from progress logs
and bounds client jobs. systemd owns Linux command domains; actual kernel read
loans survive launcher death and descendants. The platform carries an executor
whose digest/protocol is checked before commands. Checkout staging needs no
ambient Cargo. Existing language execution admission remains authoritative.

The global CLI supplies prepare, list, compare and capsule. Capsules retain
artifact/source/derivation identities and record qualification as not-recorded.
The executable Rustler showcase builds and invokes answer() = 42.

* Measurements and implementation findings
The prepared native runtime closure is 51,375,528 bytes. Keeping compiler identity
as a fingerprint, rather than a runtime store reference, reduced the earlier
1,710,284,272-byte closure. The authenticated platform/helper closure is
50,856,984 bytes. These are observed closures on the pinned Linux target.

Source component acceptance took27.024 seconds,157.2M peak,zero swap. Rust
acceptance took7.731 seconds. These observations include specific cached store
inputs and are not full-build benchmarks. native-byte-binding.json verifies the
component's loaded library file equals the Nix-prepared bytes.

Snapshot evaluation must use --read-write-mode so returned store addresses
actually exist. Digests belong after Nix fixup. Manifest heredocs must quote
the delimiter so ABI labels containing shell syntax stay literal data. Flake
request strings require explicit context handling. Source stdout must stay
separate from Nix progress. Each defect has its corresponding actual consumer
or negative control rather than a simulated build result.

* Remaining boundaries
The backend supports standalone locked Rust cdylibs on x86_64-linux. External
workspace/path dependencies, other targets and broader native system packages
need declared recipes and qualification. A label never proves ABI compatibility.

NixOS module evaluation verifies strict sandboxing, build cgroups, one job and
aggregate daemon limits. The module has not been activated on this host.
Client cgroups cannot cap workers in a separate Nix daemon; actual worker/remote
policy remains a deployment qualification. No production service was restarted.

Conservative retention remains explicit. Automatic pruning, crash/GC races,
shared-request subscription cancellation, persistent progress, comparison-realm
orchestration and attached test replay remain separately listed capabilities.
Native runtime authority, callbacks, reload, queues and the 86 historical cases
remain under the canonical execution completion checklist. A complete product
promotion needs the same final candidate's broader regressions and exact-byte
promotion; component results do not close that plan.
