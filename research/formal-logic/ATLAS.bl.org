* The promise
#+begin_lede
Write a contract in Enchant, inspect its terms, ask either solver the same question, and receive a witness or proof result in language values. The portable term graph belongs to Enchant. Native ASTs belong to one owned backend session.

The atlas separates the language we have, the language we may choose, and the machinery that has actually been qualified. A new API can improve semantics while the language is in preview; compatibility is a design input, not a command to preserve an incoherent law.

* What native means for Beam Lisp
The common interface gives Beam Lisp ownership of its symbolic vocabulary, language outcomes, sharing, source maps and evidence. Both native workers can consume that vocabulary: Z3 has native C AST constructors and OxiZ has Rust term APIs. Both still need an adapter from BL data and an owned native lifetime. Native ASTs remain private to the worker while the immutable BL question can travel, be inspected, cached and replayed.

This architecture makes finite maps, tagged outcomes, coverage, permission relations, induction and synthesis reusable language features above either engine. Backend differences remain concrete questions about supported constructors, solver strength, observations, cores and retained artifact behavior. An OxiZ source module or a Z3 theory name alone establishes none of those results; the two corpora below provide the comparison at explicit scopes. Performance and memory advantages require their own measured workload evidence.

* What the exact runtime taught us
#+begin_honest :title "A concrete equality defect, with a small proposed fix"
The pinned SDK returns [true true false] for [(= 1.5M 1.5) (= 1.5 1.50M) (= 1.5M 1.50M)]. This violates transitivity. The cause is the scale-sensitive two-Decimal exception inside an otherwise exact-rational numeric family. The proposed fix removes that exception and exposes representation or quantization equality explicitly. Production runtime source has not been changed by this experiment.

Cross-list/vector value equality is a separate design choice: it can remain useful even when conj and type-sensitive operations distinguish the representations. Compiler rewrites must use a relation that respects the observable context.
#+end_honest

The common facade is formal.api: symbols declares a caller-prefixed schema, question builds a portable obligation from typed values, describe exposes its terms and scope, and check chooses the backend. Pure BL callbacks build the model; executing a callback is not a proof about arbitrary callback implementation code. construction-capabilities exposes the native advertisement, while the retained corpora establish tested capabilities.

This static example documents the implemented low-level interface; it is not an executed document cell or a handwritten solver receipt.

#+begin_src clojure
(ns example.formal
 (:require [formal.term :as t] [formal.query :as q] [formal.logic :as logic]))
(let [x (t/variable "x" t/Int)
      question (q/prove (t/ge (t/add x (t/int 1)) (t/int 1))
                 {:id :increment
                  :profile :math/unbounded-int-v1
                  :assumptions [(t/ge x (t/int 0))]
                  :observe {"x" x}})]
 [(logic/run {:backend :z3} question)
  (logic/run {:backend :oxiz} question)])
#+end_src

The shared layer also implements scalar projection enumeration, bounded integer optimization, finite-grammar synthesis and derived deletion explanations. Passing api/backend assertions cover concrete scenarios; those algorithms do not become native Optimize, MaxSMT, unrestricted synthesis or certificate-producing proof systems.

Advanced value prototypes add bit-field layouts, explicit byte order, pack/unpack lenses and wrapping/checked words. Their floating outcomes use declared binary16 with RNE; all 31 expected advanced results matched on Z3, while OxiZ retained twelve unknowns and two unsupported results. This does not qualify BEAM binary64 source arithmetic. Arithmetic replay limits remain explicit even when the native solver proves an obligation.

A total SMT Array has no finite extent or absence; a finite BL Map needs presence and extent descriptors. A Seq is not an effectful lazy stream. Finite sets, bags, maps and tagged sums are explicit language encodings above primitive terms, so their qualification is separate from native Set/Bag/recursive-datatype APIs. SMT FP equality, IEEE fp-eq and raw bit identity are also different relations: SMT has one NaN value, payload retention needs raw bits, and source-native BEAM floats exclude NaN and infinity.

* Define the boundaries
#+begin_terms
term | immutable typed expression whose meaning is independent of a solver
language value | payload plus runtime-definedness, representation bounds, constraints and decoding domain
native AST | private backend object retained behind an owner and generation
theory | a semantic vocabulary and the laws it denotes
procedure | a verification or search method over terms, such as induction or repair
observation | a captured runtime fact whose freshness and authority remain outside SMT
qualified capability | retained evidence for an operation, sort, result kind, profile and bound
certificate | checkable evidence, separate from a solver verdict or model concreteness
#+end_terms
