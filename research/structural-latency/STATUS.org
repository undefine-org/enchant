* Rejected SDK fusion experiment
Commit 5b4882151 fused copying and Source relocation, keeping input hashes,
unchanged executable MD5, atomic replacement and independent final-byte
inventory authentication. Component checks passed byte equality with the
actual old SDK implementation and corrupt-input refusal without metadata
publication. A compiled-SDK benchmark improved from 51.08 to 35.12 s serial
and 37.95 to 30.25 s with four workers. Reads fell 7080 -> 5089 and writes
4017 -> 2026 while all Source/disassembly/MD5/artifact proof counts stayed equal.

That benchmark did not qualify the production path. A real SDK edit took
321.14 s with fusion, compared with 224.74 s on main and 212.21 s with only
the native snapshot. Production image assembly was 41.51 s versus main's
39.05 s, and several other producer phases also regressed. The precise causal
interaction requires profiling the actual producer's restored driver/callback
execution. The compiled-SDK benchmark cannot stand in for that execution.

Commit 19593f810 removes fusion and restores the original build implementation,
image path and test implementation. No fused optimization ships in this branch.
The experiment, operation counts and qualification receipts remain in the
history/results for further investigation. Their gains are excluded from the
retained improvement table. The final runtime selection is the already tested
native-only SDK a6p1mdrqlgr4v7fx9a08w6l57r4dch59.

The combined experiment passed 15 BL files (78 cases / 589 assertions), all

* Remaining bottlenecks before another release
SDK emission remains expensive on a genuinely new compiler cohort (the prior
round measured about 19 minutes for all units). This branch does not change its
constructor/ownership protocol or narrow its input keys. A native-tool change
also caused full P/B/C qualification even though the resulting SDK BEAM bytes
were unchanged. Separating producer compatibility from broader platform identity
needs an explicit constructor/read-set contract; omitting inputs would risk
stale code or incorrect native authority.

SDK production still authenticates all restored units and assembles/packs a
complete image. The rejected fusion shows why actual producer profiling must
precede further cuts: compiled library execution and producer startup/callback
execution have different costs. Packing and full image materialization remain
material fixed work. Source capture, repeated coordinator startup and Nix
evaluation still add overhead; the evaluation worker can approach 3 GiB.

The warm client still traverses runtime/project paths and checks live generated
and external artifacts. Further reuse must stay within verified lifetime,
including directory membership, physical paths, environment and package changes.
CI's expensive JS macro/differential fixtures retain every source variant and
cross-target check. Their repeated setup needs exact-input reuse, not fewer
fixtures, relaxed validation or larger timeouts.

Complete CI lanes and target-platform release gates remain required before a
release. This is a tested Linux implementation, not a completed release matrix.
No second merge or publication is performed without the requested review.
