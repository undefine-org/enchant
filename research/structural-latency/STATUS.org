repeats. Source fingerprint: 0.20, 0.17, 0.19 s, about 25 MiB peak RSS.
cProfile: 0.174 s total, 0.145 s fingerprint traversal, 951 file hash updates
(0.063 s) and 128 directory walks. The native client then independently walks

The candidate structural cut is one synchronous checked-byte snapshot in the
native checkout client, reused only for the overlapping runtime/project hashes.
Every command still hashes actual source bytes; there is no mtime authorization
cache. The canonical policy and fingerprint format remain shared with the
independent Python producer verifier. Generated files, external paths and
request/environment keys retain their own checks. Final file and directory
stamps must still match before the captured evidence is used.


* Native implementation and controls
Commit a31a515e1 captures the declared engine bytes in the native checkout
client. The existing SDK fingerprint format is unchanged and is cross-checked
against scripts/sdk-inputs. Runtime and project pin formats remain unchanged;
only exact captured-path digests are reused. Metadata is checked again before
using the composed pins. Every next command captures new bytes. Generated and
external files retain their independent live reads; no persistent YES exists.

The full checkout and six edge-case groups pass the independent comparison,
covering Unicode/escaped/non-UTF8 names, executable modes, empty directories,
exclusions, limits, symlinks, special files, missing roots and policy shape.
Three native unit tests cover stale bytes/policy/directory membership, pin
identity equivalence and independent generated/external-file checks. The Nix
drop-tools build runs these checks in its bounded 3072 MiB / one-CPU guest.
The initial platform build completed in 193.15 s. New qualification inputs are
explicit platform and captured-engine dependencies.

The pure native capture took 0.17, 0.16, 0.18 s at roughly 4 MiB peak RSS;
Python took 0.19, 0.20, 0.23 s at roughly 25 MiB. The larger proposed benefit is
sharing the captured hashes with the runtime pin. The baseline warm commands
were 0.616, 0.615, 0.668 s; the traced warm command made 30423 syscalls.

* Image profile and fused assembly
On the exact baseline SDK, 516 restored units contain 1991 image modules.
The successful probe measured 51.076 s serial assembly and 37.949 s with four
workers. The latter made 7080 File.read!/1 calls and 4017 File.write!/2 calls,
with 33 task batches. An earlier reporting error is excluded from timings.

Fused assembly authenticates the actual input object's expected hash, rewrites
only CInf in memory, checks unchanged executable MD5, and atomically writes the
final file once. The existing inventory writer then independently rereads and
authenticates those actual final bytes and Source before metadata publication.
Ownership, complete membership, initial/final Source capture and validation
are unchanged. The first component test passed all 24 assertions, including
byte equality with independent serial assembly and corrupt-input refusal with
unchanged published metadata (440084 KiB peak RSS, zero swap).
