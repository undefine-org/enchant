#+title: Integrate a Foundry-backed artifact and external-job backend
#+date: 2026-10-25
#+state: Proposed redirection, backed by the adjacent experiment; no production migration applied

* Target contract
BL owns source meaning, dependency analysis, compiler/ABI manifests and runtime
admission. Nix owns production of immutable declared filesystem closures.
Foundry coordinates requests and result observations. systemd owns supported
Linux external-job lifecycle/resource boundaries. Stateful application data stays
outside store outputs. Hot reload retains its native in-VM lifetime protocol.

Represent semantic artifact identity separately from operational job identity.
A production request binds source fileset/content, compiler generation, lockfiles,
all codegen options, target, native ABI, toolchain and declared environment.
A result binds request identity, derivation/store outputs, product manifest,
product digests and target/ABI. A store path alone is not a qualification receipt
or a grant to execute privileged runtime code. Qualification receipts bind the
exact output bytes and test identities. Ordinary Nix input addressing does not
itself prove reproducibility or semantic correctness.

No arbitrary caller Nix expression, shell, environment or caller-supplied grant
belongs in this data API. Trusted versioned recipes receive validated data.
Use Foundry's codec for controlled authoring and host configuration editing;
use JSON requests to fixed recipes for the hot artifact boundary. Avoid making
rnix/NIF parsing a preboot prerequisite merely to serialize an artifact request.

* Work around the ongoing session
This research directory is the only addition. Do not modify its active checklist,
receipt, builder or runtime. At handoff, read its newest commit and dirty state;
reconcile Source orphan controls and Cargo metadata changes completed since
6bfb6796. Keep those tests and fixes as comparison evidence. No history rewrite,
reset, blanket case closure, automatic deployment or approval flow is introduced.

Implement in a separate worktree/branch. Run one compiler-heavy job at a time,
check scripts/bl-mem, and stop all owned workers. Reserve full SDK work until a
real narrow artifact-consumer gate passes. The other thread can finish or retain
its current coherent slice before switching the infrastructure implementation.

* Stage 1 — reusable backend seam and closure completeness
Extract/reuse Foundry's executor/result conventions without importing the entire
Foundry app into compiler bootstrap. Add one artifact-provider interface and
one external-job interface, with Nix/systemd implementations for the supported
managed Linux environment. Keep existing providers while consumers migrate.
Choose a finite target policy: this prototype proves Linux only. Preserve current
promised other targets until equivalent backends are qualified or the support
contract is explicitly changed. Do not silently fall back to unsafe execution.

Use the existing flake inputs for tools, natives and dependencies. Replace the
Cargo shim gradually with direct artifact-provider consumption. Source selection
must include build scripts, Cargo config, locks and relevant generated inputs.
Test source/lock/option/toolchain/target perturbations, unexpected environment,
wrong/missing outputs, tampered manifest and library, and preboot/native ABI
mismatch. A change only in BL application code must reuse native/tool derivations.

Exit: one actual mandatory-native consumer uses and verifies the supplied product
without copying it into a shared writable destination. A packaged bootstrap
consumer and the source consumer must agree on that contract.

* Stage 2 — external lifecycle, retention and shared requests
Add explicit states: requested, building, available, failed, cancelling, cancelled;
represent a disconnected requester separately from a cancelled build. Shared
requests need independent subscriber identities: cancelling one subscriber must
not kill a build required by another. Daemon restart/reconnect must not admit an
incomplete output. Fix policy first, then test actual events.

Use cgroup-backed transient services for BL-owned external jobs. Validate
main-exit cleanup versus intentional drain-all behavior, deadlines, owner death,
setsid/double-fork and closed-descriptor children, no-birth failures, and recovery
from a killed coordinator. Inspect worker cgroup/resource ownership inside the
Nix daemon: a client systemd limit is not a build-worker limit. Do not launch
large Nix builds until the chosen worker limits are proven effective.

Root required artifact closures for live realms, releases and qualification jobs.
Use reference-counted or otherwise crash-recoverable retention records tied to
real consumers. Test GC/activation races and last-subscriber death in a private
store/VM. Existence of an open library FD is not the complete artifact-retention
contract. Keep semantic code-generation pins separate from filesystem roots.

Exit: all supported process/lifetime/retention races pass under bounded real jobs;
no child can modify another attempt or selected immutable product.

* Stage 3 — real compiler-generation and qualification slice
Have the existing artifact-only compiler producer emit a generation into the
Nix output contract. First preserve its generation/descriptor algorithms exactly.
Boot a fresh consumer from that output, verify its native identity/descriptors,
and run the smallest relevant Source/sealed consumer profile.

Run independent A -> B -> C reproduction where B actually compiles C. Prevent
cache substitution from replacing the independent reproduction step. Compare
complete inventories and bytes, boot B/C, and bind test identities/results to
those bytes. Include malformed/missing/tampered unit refusals.

Measure cold environment preparation, unchanged request, BL-only edit, native
edit and provider/toolchain change independently. Keep the warm analysis/compiler
VM for interactive work. Do not put every expression or editor request behind a
new derivation or cold VM. Select artifact boundaries from real measurements.

Exit: the current candidate's relevant controls pass on this backend and its
measured workflow is acceptable. Only then propose deleting equivalent custom
publication/cache/custody implementations.

For each old mechanism: retain until superseded, replace with backend acceptance

* Stage 5 — product surfaces after acceptance
Expose ordinary project declarations, artifact identity and preparation states
through existing BL/Foundry interfaces. Users should not write a separate Nix
file for each project action. Preserve current CLI verbs where possible.
Build preparation, activation, runtime readiness and application-data migration
remain separate operations with explicit identities.

Add remote reuse, comparison realms, failure capsules and dependency explanations
only after the backend contract stabilizes. See CAPABILITIES.org. No additional
capability is required to accept the infrastructure migration.

* Stop/go criteria
Proceed with the backend implementation: the narrow experiment passes and real
Foundry plumbing works. Do not replace the whole previous implementation yet:
mandatory-native integration, current-compiler B/C reproduction, shared-cancel,
GC races, daemon worker limits and supported-target parity remain unproved.
If Nix request overhead hurts interactive work, move only immutable artifact
boundaries behind Nix and retain the existing warm analysis path. If deployment
cannot require Nix, keep shipped drops self-contained and qualify the portable
producer/packager path separately. Nix on the build host does not require Nix on
the eventual FHS target; the existing drop build already targets this distinction.
