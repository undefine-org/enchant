#+TITLE: Analyze retained callbacks after fresh admission closes

* Admission and accepted work have different lifetimes

Closing a graph rejects new root admissions. Existing registered callbacks
still retain their original code and context until their own lifetime ends.
Metadata analysis of such work must use that existing native custody. The old
message-proof reader instead restored a captured context through a fresh
=generation/with!=. Owner evolution after retiring the old graph consequently
refused despite retaining the exact old request predicate.

The fixed native command is:

#+begin_example
(BeamLisp.Execution/inspect! registration 'proc.message-domain/capture)
#+end_example

The quoted symbol selects one closed SDK schema. A string, arbitrary symbol,
MFA, context, graph or supplied analysis function cannot select an entry.
Env authenticates the actual callback registration, retains the genuine SDK
reader's modules, then atomically borrows the callback and its context through
the existing acceptance path. Only that reader runs. The application function
is inspected as data and is never invoked by this command.

The fixed SDK reader =proc.message-domain/capture-current!= checks published
arity-one code, exact bindings, body and native identities under the borrowed
frame. Dynamic, captured, higher-order and effectful bodies remain unknown.
No caller-authored proof can authorize an owner change. Direct Source access
to native execution machinery remains denied by the existing critical policy.

=capture-registration!= returns evidence with its opaque registration, without
an executable context. Registration-backed =valid?= recaptures bounded metadata
under the same actual custody and compares the complete evidence. It does not
run a solver or the callback, and a closed registration invalidates its proof.
This costs a bounded metadata traversal; it is not a constant-time stamp check.
Legacy explicit callback/context analysis remains available under real live
admission, reusing an already matching admitted frame where possible.

* Inspect real accepted work after retirement

#+begin_src beam-lisp :id retained-callback-analysis
(ns execution.callback.analysis.walkthrough
 (:require [reload.generation :as g] [proc.callback :as cb] [proc.message-domain :as domain]))
(let [graph (g/prepare! {:application-id "callback-analysis-walkthrough"
                         :sources {"callback.analysis.demo"
                           "(ns callback.analysis.demo) (defn identity-value [value] value)"}})
      registration (g/with! graph #(cb/register!
                     (BeamLisp.Env/fetch_exact! (get (:mapping graph) "callback.analysis.demo") "identity-value")))]
 (try
  (let [retired (g/retire! graph) proof (domain/capture-registration! registration)
        current (domain/valid? proof) value (cb/invoke! registration [42])]
   (assert (= :waiting (:status retired))) (assert (= :proved (:status proof)))
   (assert current) (assert (= 42 value)) (assert (not (contains? proof :environment)))
   {:retirement (:status retired) :analysis (:status proof) :current current :value value})
  (finally (cb/unregister! registration) (g/retire! graph))))
#+end_src
#+RESULTS: retained-callback-analysis
: {:value 42, :current true, :retirement :waiting, :analysis :proved}


* Prove the registrations that will actually serve

Evolution retains its candidate callbacks before proof, then analyzes those
same registrations. The old request predicate is read through its existing
registration too. Domain evidence records these actual lifetimes, so later
adapter validation does not request fresh admission of a retired graph. State
conversion still starts only after the pure domain/state/check proofs pass.
Failure closes the candidate registrations through the existing cleanup path.
No temporary proof registrations, copied execution contexts or new registry
are introduced. Existing exact-target and native transition phase checks still
govern preparation and commit.

This concerns metadata analysis and retained callback lifetimes. It does not
make arbitrary compile-time execution decidable or prove unknown effects pure.
