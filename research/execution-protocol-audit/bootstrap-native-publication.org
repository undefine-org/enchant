#+title: Bootstrap native publication joins Source destination custody

* Reproduce the actual missed writer
The independent Rust bootstrap builds native libraries before a BEAM/NIF exists.
Its previous copy/rename installation never joined claim/artifact-scope. A private
crate retains that exact algorithm, extracted without behavioral changes into
publish_native_artifact. An isolated Cargo target and required compiled-source
fingerprint bind the executable actually used. Against two actual Source workers,
the original publisher returns success while a real Source destination claim is
held. The expected-failure log is preserved; it grants no positive coverage.

* One destination, the same kernel resources
NativePublication::take resolves the destination directory and constructs the
same scope and permanent writer/follower anchors as claim/artifact-scope and
claim/lock-anchor. The integration test asks actual Source for its scope; it does
not reproduce the naming convention in Python. Both publishers use kernel File
locks. Busy writer or surviving follower refuses before observing/installing
artifact bytes. Partial acquisition and I/O failure drop their descriptors.

Under both exclusive guards, Rust removes the previous Source cohort diagnostic.
An old follower cannot enter during publication or after release. Missing text
is acceptable; an actual diagnostic-removal error refuses. This grants filesystem
custody only; Rust does not manufacture a native Source admission resource.

The guards enclose source/destination observation and the complete atomic
replacement. Identical regular-file bytes retain their inode. Directory aliases
share custody; a leaf symlink is replaced without writing through its target.
A unique create_new temporary receives complete checked writes and permissions
before rename. Failure removes only a temporary actually created by this attempt.
Permanent lock anchors remain. build_natives has one publication call site.

* Focused frozen controls
The existing strict Python-unittest selector adapter runs one exact integration
method. Two actual reused BEAM workers and actual Rust subprocesses prove Source
excludes Rust, Rust excludes Source, owner death with surviving Source follower,
late old-cohort refusal, Rust owner SIGKILL recovery, physical directory aliasing,
changed-byte replacement and identical-byte inode retention. Seven real Rust
publication attempts execute. The actual admitted Rust guard is held by the
subprocess in the reverse-direction test; a hand-created generic lock is not
substituted for the production operation.

Four exact Rust selectors pass: the three existing parent-custody controls plus
native_publication_preserves_old_bytes_and_releases_failed_operations. The new
selector covers missing input, failed rename, cohort-invalidation failure,
temporary cleanup, released partial admission, and leaf-symlink target integrity.
Required source attestation covers every Rust source and Cargo inputs. Forty-one
existing affected-boundary, sealed-selection, history and prerequisite controls
pass separately. The external map binds 40 actual references and five selectors.

BL_TEST_TIMES=1 is set. Rust preparation is 3.437s; BEAM worker preparation 8.328s.
Cross-process checks take 0.156s, including 0.109s in publication subprocesses.
The Python selector including startup takes 8.559s. Rust selector execution,
including harness/process startup, is 8.840s, 69ms, 25ms and 22ms respectively; the
retained parent exclusion control is slowest. The capped service takes 21.023s,
395.7M peak,zero swap. All frozen Rust/test inputs remain unchanged. Workers are
stopped; unrelated VMs remain untouched. No SDK/NIF build or broad suite runs.

* Keep the remaining exits explicit
This is Linux Rust-test/Source-component evidence, not release/SDK/floor or other
target qualification. Destination custody does not establish immutable Cargo
input products, surviving external-child custody, supported mixed/legacy
participation, or overlapping workspace hierarchy. Those and central protocol
obligations remain required in 2b. No historical case gains blanket closure.

Installed 141 floor files and 139 build BEAMs remain equal to actual previous C;
the production native identity is unchanged. Boundary-selective sealed checks
and universal integrity controls remain intact. Qualify the completed batch2
artifact once at 2d; retain full final qualification at 6. The canonical checklist
owns the finite seven-batch queue and separates optional improvements.
