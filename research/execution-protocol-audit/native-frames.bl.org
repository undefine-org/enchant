#+TITLE: Native execution frames select graphs; public maps remain views

* Admission, origin and data have different roles

A registration owns a callable/context and retains code. An accepted borrow
owns the code and context for one invocation. A frame records that invocation's
admitted graph, effective context, native parent and depth. Merely copying or
binding a generation map creates none of these lifetimes.

Common callback/task/root entries now put an opaque frame ID in the private
execution-proof slot. Protected records, owned by the existing Env process,
hold graph/context IDs, the actual accepted ticket and the nearest native frame
parent. The Source restriction stack stores scope IDs rather than generation
maps. Binding a public context cannot change these native records or supply a
new origin. Invalid/stale frame evidence refuses producer entry, including when
public generation data is nil.

Frames reuse existing private/protected custody tables and guardian cleanup.
No extra owner server is introduced. Entry acquires its effective context
reference and pushes a bounded frame; exit restores the prior selector and
releases that reference. Worker death releases active frame references before
reclaiming its borrowed callback rows. Code and mutable resource authorization
remain independent checks.

* Nested native entry restores the parent

#+begin_src beam-lisp :id native-frame-parent-restoration
(ns execution.frames.walkthrough)
(let [inner (BeamLisp.Execution/register! #(BeamLisp.Execution/observe))
      outer (BeamLisp.Execution/register!
              (fn []
               (let [before (BeamLisp.Execution/observe)
                     child (:value (BeamLisp.Execution/invoke! inner []))
                     after (BeamLisp.Execution/observe)]
                (assert (= (:id before) (:parent child)))
                (assert (= (inc (:depth before)) (:depth child)))
                (assert (= (:id before) (:id after)))
                {:native-parent true :restored true}))) ]
 (try
  (:value (BeamLisp.Execution/invoke! outer []))
  (finally (BeamLisp.Execution/close! inner) (BeamLisp.Execution/close! outer))))
#+end_src
#+RESULTS: native-frame-parent-restoration
: {:native-parent true, :restored true}


The IDs returned by observation are non-authorizing data. They contain no
callable, context map or executable lease. Env.capture does not convey the
execution proof. Depth is bounded even for unmanaged native nesting; exceptions
unwind the original frame and selector.

* Source observes bounded selected-graph fields

The SDK leaf reload.execution exposes frame, selected-graph-id and graph-field.
The field vocabulary is closed: quoted application-id, digest, scope, cache-key
and source-ingress-version. The accessor validates actual selected execution;
a public bound graph cannot select a native graph. proc.instance now uses this
boundary for application identity rather than reading a process-dictionary map.
Legacy current/capture APIs still materialize their documented data view.

#+begin_src beam-lisp :id source-frame-selected-field
(ns execution.frames.source.walkthrough (:require [reload.generation :as generation]))
(let [graph (generation/prepare!
              {:application-id "frame-walkthrough"
               :stable-namespaces #{"reload.execution"}
               :sources {"frame.walkthrough"
                (str "(ns frame.walkthrough (:require [reload.execution :as execution])) "
                     "(defn callback [] (fn [] {:application (execution/graph-field 'application-id) "
                     ":owned (execution/owned?) :native-frame (= :active (:status (execution/frame)))}))")}})
      registration (generation/with! graph
                     #(BeamLisp.Execution/register!
                        (generation/invoke! graph "frame.walkthrough/callback" [])))]
 (try
  (let [value (:value (BeamLisp.Execution/invoke! registration []))]
   (assert (= {:application "frame-walkthrough" :owned true :native-frame true} value))
   value)
  (finally (BeamLisp.Execution/close! registration) (generation/retire! graph))))
#+end_src

* Freeze preparation once; preserve admission at every root

Preparation authenticates the original SDK graph and freezes native membership
and its shared immutable snapshot. A graph-pin entry can select only that
snapshot; an edited public map cannot reuse a genuine pin. Accepted callback
entry therefore need not call the SDK's preparation registry again. Fresh root
admission still authenticates preparation and checks graph admission closure.
Native physical-ticket compatibility paths retain their original preparation
check until actor migration.

The isolated counter test observes the actual protected SDK MFA with the VM's
call_count facility, then restores tracing. The original floor calls preparation
once for a callback invocation. The native-frame path must make zero calls,
while a fresh root must still increment the counter. This measures actual
calls, not an assumed cache hit or a replacement SDK implementation. See
[[https://www.erlang.org/doc/apps/kernel/trace.html][OTP call-counter documentation]].

* Native ingress cannot invoke the guard it implements

An initial candidate used callable keyword lookups in frame validation. Source
invocation re-entered the same guard and exhausted the capped VM. The critical
helpers now use native Map/BIF operations. check-source-floor disassembles the
actual Env beam before application/user execution and rejects Rt dispatch from
those helpers. The real recursive candidate is the negative control for this
earlier gate. The gate checks direct emitted calls at named critical helpers;
it is not a proof of every transitive runtime dependency.

* Remaining integration

These frames cover common roots, callbacks and owned task/spawn invocation.
Managed actor lifecycle entry still uses its original private physical-owner
proof; scalar graph reads bridge through that attested origin. Complete actor
frames, transition/adoption integration and migration of remaining raw generation
consumers are still required. Parent describes the nearest native protocol
frame, not a complete reconstruction of legacy callbacks or the language stack.
Deadline/target grants, affine analysis, per-owner/epoch cleanup indices and the
wider compiler/phase/archive/release qualification remain independent gates.
