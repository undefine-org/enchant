#+title: Bootstrap commands retain an inherited filesystem lease

* The actual parent boundary
The previous Rust BuildLock protects its parent, but run_logged launches an
external compiler without transferring custody. The exact old runtime, in an
isolated Cargo target, fails the new actual-process control: killing the build
owner leaves its external child alive while an independent kernel observer can
take the child-custody anchor. The failed original and its compiled-source
fingerprint remain preserved. No Source/SDK authority is fabricated by the test.

* Admission precedes both spawn and replacement
BuildLock::take acquires the permanent parent writer, then drains the separate
build.kernel.followers anchor before publishing a diagnostic or returning.
BuildLock::prepare_command borrows shared follower custody while the actual
parent guard exists. Command owns that File before fork; the child's pre_exec
clears CLOEXEC only in the child's descriptor table. The parent retains normal
close-on-exec behavior, so unrelated concurrent spawns cannot retain this loan.
The closure performs only fcntl; all allocation and lock acquisition precede it.

run_logged requires &BuildLock. Native Cargo builds, asset copies, dependency
fetch/compile, selfbuild launch and Git worktree creation use that typed boundary.
Cargo metadata discovery separately prepares its output command and propagates
preparation refusal. It retains the existing metadata fallback; product selection
and immutable Cargo provenance remain required work. Non-Unix preparation has an
explicit refusal implementation; other-target qualification remains batch 5.

This is a filesystem loan, not a Source invocation grant. Descendants that keep
the inherited descriptor retain its shared lease after either ancestor dies.
Only the last close releases it. This follows the open-file-description rule in
[[https://man7.org/linux/man-pages/man2/flock.2.html][flock(2)]] and the child-only closure contract in
[[https://doc.rust-lang.org/std/os/unix/process/trait.CommandExt.html#tymethod.pre_exec][Rust CommandExt::pre_exec]]. Commands that discard unrelated descriptors still
need a separate enforced lifetime relation; inheritance is not a universal
subprocess-tree supervisor or sandbox.
