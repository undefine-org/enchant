* The original process boundary
Rust BuildLock used create_new plus a PID file. Removing that diagnostic while
an actual builder was alive let another actual process enter the same build.
An unreadable marker was also treated as stale. Acquisition I/O errors were
retried forever. The original two-second poll requires a longer negative-control
window: the first100ms test was inconclusive and is retained as such.

The unchanged original implementation fails the corrected actual-process test.
A private old-source crate and separate Cargo target reproduce it without
restoring or editing the checkout. No BEAM, SDK, NIF or real native build runs.

* Open kernel state is authority
BuildLock::take now returns Result<BuildLock,String>. The one production caller,
build_tree, propagates refusal before stamping inputs or starting commands.
A permanent store/locks/build.kernel inode owns exclusion. The open File remains
inside the lexical guard; owner death closes it. store/locks/build stays readable
PID data and is atomically replaced under custody; diagnostic symlinks are not
followed. Release removes only matching diagnostic text and never the anchor.
Malformed/missing text cannot admit another current-protocol builder. Anchor or
publication I/O errors return promptly, releasing partial custody and temporary
files. This parent lease does not yet protect a surviving compiler child.
