#+title: Complete conversations and owned starts

* One command owns its acknowledgement
The old command reader checked for its constant marker before inspecting error
lines. A combined error/marker chunk could report success; a split error could
return before consuming the acknowledgement. The repaired reader consumes a
complete marker line, then reports any preceding error. Each actual command
chooses a fresh128-bit random delimiter after receiving its SMT input.

* Source workers use the owned start
Raw erlang/spawn does not convey a Source environment. The qualifier caught a
pool test whose144 requests all returned undefined-handler errors, plus a
deadline test that counted undefined-var child death as a successful timeout.
The supported spawn/spawn-monitor APIs already retain executable code and bind
the actual caller context before entry. They require no hand-built context map.

#+begin_src beam-lisp :id owned-worker-sees-its-world
(let [scope (BeamLisp.Env/fork (BeamLisp.Env/env_id)) parent (erlang/self)
      marker (erlang/make_ref)]
 (try
  (BeamLisp.Env/with_env scope
   (fn []
    (BeamLisp.Compiler/eval_string "(ns documented.worker.world) (def VALUE 42)")
    (let [[pid monitor] (spawn-monitor
                         (fn [] (erlang/send parent
                                  [marker (BeamLisp.Env/fetch_exact! "documented.worker.world" "VALUE")]))) ]
     (assert (= 42 (receive [seen value] :when (= seen marker) value (after 5000 :missing))))
     (assert (= :normal (receive [:DOWN seen :process child reason]
                          :when (and (= seen monitor) (= child pid)) reason (after 5000 :missing))))
     {:owned-start true :caller-environment-preserved true})))
  (finally (BeamLisp.Env/destroy scope))))
#+end_src

* One owner and one deadline for an incomplete conversation
The current Source repair checks the native port's connected PID before every
public I/O operation. Native port connectivity alone does not prevent another
process from sending or closing: the driver API must enforce this explicitly.
No Env map or public tag substitutes for actual connected ownership.

One internal conversation scope gives status, model/core/reason and command ACK
the same absolute monotonic deadline. Receiving another chunk does not renew
it. Writes use nosuspend, replies are bounded at16MiB, and timeout, EOF or an
incomplete model retires the transport. Closing affects only the actual owner's
port and drains only its tagged messages. Scope/monitor cleanup preserves the
caller and unrelated mailbox traffic. A complete rejected command can still be
followed by a reset; an incomplete exchange cannot be followed by another query.

The SDK actor reports a retired conversation by failing, so OTP replaces its
port owner. It never retries the accepted command: its effect may have happened
before the missing acknowledgement. The causal actor test records exactly one
effect, sees the replacement acknowledge a later reset, then disables only the
retirement check and observes a live actor holding a dead port.
