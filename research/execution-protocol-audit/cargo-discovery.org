#+title: Cargo metadata is a checked descriptor, not a target-directory hint

* Two original failures and their real consequence
cargo_target_dir previously ignored Cargo's exit status and guessed crate/target
on failure. Its string scanner also selected the first target_directory anywhere
in the response. Real Cargo emits package.metadata before the top-level field;
a package's ordinary nested value could therefore nominate an unrelated path.

Actual Cargo controls reproduce both failures against the original function.
The full native producer then demonstrates the consequence without fake Cargo:
a tiny real crate compiles successfully, its build script removes the already
parsed private fixture manifest, and subsequent real metadata fails. With an
unrelated library waiting at the old guessed path, the original build_natives
returns success after publication. This is a preserved expected original failure.
Private old-function copies have isolated targets and required compiled-source
attestation over all Rust and Cargo inputs; no cached executable is assumed.

* Refusal propagates before publication
The existing Result API now requires successful cargo metadata --locked. Start
and exit errors retain their actual cause. The response is decoded as JSON, and
only its top-level string target_directory may supply an absolute address.
Missing, malformed, relative or wrong-shaped descriptors refuse; there is no
guessed-directory fallback. build_natives propagates refusal before calling the
admitted destination publisher. Metadata cannot modify a lock file implicitly.

serde_json supplies the actual JSON decoder, replacing the inappropriate flat
string scan at this boundary. It remains a pure Rust launcher dependency, pinned
in Cargo.lock and included in compiled-source/frozen-input identity. The separate
release-tag scanner is unchanged; this is the native producer boundary's fix.

The same full real producer now refuses after successful compilation, retaining
both the old installed library and the unrelated guessed product. Real nested
package metadata is ignored, paths with spaces work, the lock file remains exact,
and valid discovery compiles no product. Existing command no-birth/failed-spawn,
real Cargo-orphan and atomic destination-publication controls remain included.

* Keep the remaining provenance/lifetime obligations
Correct target-directory discovery does not prove that a selected shared-target
library belongs to this invocation or stays immutable until copied. Compiler
artifact receipts and custody through publication remain required 2b work, along
with supported mixed/legacy writers, workspace hierarchy and central obligations.

The Source orphan control is independently still red. Its stronger version proves

after both BEAM and Cargo die. See source-command-custody-checks.json; do not use
these passing Rust discovery controls as evidence for that unfixed lifetime path.

log identities. No historical case gains blanket closure. Keep one completed
