#+title: External command lifetime is a supervised filesystem loan

* The retained failure now has a passing counterpart
The original actual Source producer admits replacement while its orphan writes
inside the same Cargo OUT_DIR. That failed receipt remains unchanged. The same
real Cargo/compiled-build-script regression now passes after both BEAM and Cargo
die. A separate actual Source control closes every inherited descriptor and kills
both BEAM and the native launcher; the descendant still retains workspace and
read exclusion through the manager, then releases both at its last exit.

* What holds the loan
claim/command! first requires real current native ownership via follower-context.
Source read loans are bounded, acquired before launch and unwound on failure.
The native command route precedes checkout/payload/SDK resolution. On this Linux
backend, a transient OS service has ExitType=cgroup and a descriptor store. Its
main helper takes shared follower custody and checks the actual current cohort,
then borrows additional read anchors. It transfers those actual open descriptions
using SCM_RIGHTS, waits for a notification barrier and verifies the actual stored
descriptor count. Only then may the user program start; helper-local copies drop.

The manager retains custody until the cgroup empties. Caller disappearance,
launcher death, setsid and descriptor filtering cannot discard those stored
leases. Native writer/follower/clear/generation consumers see their existing
kernel locks; no new Source grant or fake SDK authority row is introduced.
Read/follower contexts remain nonauthorizing data, not native writer resources.

Control tools and the local manager endpoint are independent of request-local
PATH/bus variables. The requested argv/cwd/environment remain per invocation.
The full environment travels through a sealed memfd loaded as a private service
credential, never a secret-bearing command-line JSON object. Manager notification
and inherited-FD control variables are removed from the user program's environment.
Actual main-process/policy checks and count verification precede program birth.
Missing/incompatible executors and unsupported backends refuse without a raw
command fallback.

The OS deadline and control-group stop cover descendants which changed session
and ignore TERM. Captured output is bounded; overflow stops the whole domain.
A disconnected caller does not falsely certify cancellation: accepted work keeps
its loan and deadline. Shared capped test slices include both the test VMs and
the managed command services; no forgotten background executor is installed.

Cargo and selfbuild use the shared Source entry. Selfbuild also supplies its
generation read anchor before the new VM starts, and resolves Elixir through the
request environment. No mandatory NIF/host ABI changed.
