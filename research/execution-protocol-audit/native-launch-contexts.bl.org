#+TITLE: Native startup shares bounded context data

* One launch owns one reference

The native Server/Supervisor entry attests the genuine caller and current class
bytes, then captures the ordinary overlay through the same bounded context
capture used by managed starts. Env interns it in its existing private context
pool while retaining the class. The launch row stores a context ID. The owned
child receipt stores only code and provenance; it owns no duplicate reference.

Actual generated init receives a fixed =:native-context= marker. Claiming the
one-shot launch selects its original context ID; the child restores the overlay
outside the serialized custody turn, before user init. Neither the marker nor
a context ID grants a managed graph, Root identity or execution admission.

The real parent's successful OTP result follows completed child init. It drops
the launch's data reference while independently retained child code/provenance
remains live. Failed init preserves uncertain provenance. A later genuine start
may prune it only after native process state establishes actual child death.
That cleanup says nothing about completion of external work performed by init.

* Coverage boundary

Actual VM call tracing observes native actor and native supervisor init fields,
returning only marker/map booleans. A held initializer exposes the genuine
pending row for ownership checks. Tests check successful context reclamation,
restored namespace, failed init followed by actual death pruning, oversized
overlay refusal before user init, copied-envelope refusal and class custody.

Native supervisor restart descriptors carry the same fixed marker. Actual
native supervisor init restores the launch overlay before starting children;
restart wrappers use those existing process bindings and restore them after
each start. This needs no permanent global token or per-child retained copy.
Managed generations refuse this native marker path. Actual kill/restart tests
check the original namespace and successful calls after the caller has left it.

A descriptor used with a raw Elixir supervisor still carries its compatibility
data, since that foreign supervisor did not restore a native launch overlay.
Legacy data-only packets also remain compatibility data. This change claims no
measured RSS or IPC byte improvement and no whole-system completion.
