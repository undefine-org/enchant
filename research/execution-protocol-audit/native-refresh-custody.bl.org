#+title: One native producer; receipts observe bytes under publication custody

* Remove the competing writer
vm.native/build! previously implemented its own cargo/metadata/copy/rename path.
It could publish while the content-addressed producer owned that crate, and did
not use its destination scope. It now delegates stale work to
build/build-native-crate(root, crate, log), the same native-one implementation
used by build-native. The checked single-crate entry refuses escaping names and
missing declarations before mutation. An unrelated crate is never selected.

The fresh runtime return remains a stat-only, read-only fast path; it grants no
custody or publication authority. Existing missing/failed/lockfile freshness
controls remain. The removed cargo-target-dir and built-cdylib implementations
have no remaining consumers in vm.native.

claim/artifact-scope(destination) owns the shared destination address.
claim/with-artifacts!(destinations, description, action) holds those scopes in
stable order, deduplicates destinations, preserves existing actual ownership
and unwinds newly acquired scopes on refusal or exception. build's publisher
uses the same scope helper. No new namespace or SDK authority row is introduced.

* A refresh receipt and its files are one observation
refresh-native-root holds its per-root receipt claim and all selected artifact
claims before hashing, checking a receipt, invoking the producer or publishing a
new receipt. A cache hit cannot inspect/accept an artifact currently owned by a
foreign publisher. Nested producer publication is reentrant in the same actual
process. Inputs changed during work or a failed producer never gain a receipt;
exceptions release every newly acquired scope.

The actual original refresh forms are retained verbatim from9a5d9b6d under a test
namespace. With a foreign publisher holding the destination, the original accepts
its cached receipt and the current consumer refuses. Executable scenarios are
in test/bl/vm/native_refresh_test.bl (7 tests/43 assertions) and
test/bl/native_runtime_custody_test.bl (2 tests/17 assertions). Selected existing
native and build-operation controls bring one frozen component run to16 tests/
95 assertions. This includes a real tiny Rust build/cache reuse, output inode
controls, invalid crate refusal and post-failure custody cleanup.
