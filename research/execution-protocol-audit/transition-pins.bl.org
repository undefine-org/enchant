#+TITLE: Frozen graph custody for transitions and control bundles

* Keep the original graph until accepted work finishes

A pending owner transition owns one Env-held graph pin. A control bundle owns
an independent pin plus its fixed SDK receiver and explicit outside dependencies.
The frozen graph includes managed code, native grants and intrinsic membership.
Neither path reconstructs this membership from a caller's module inventory.

=begin_owner_transition!(pid)= derives components from the actual admitted
candidate before its private turn. The turn still authenticates the exact
target, application, creator, guardian and transition phase. It takes fences
without waiting inside Env and inserts the actual Env-owned custody ticket.
Accepted work may drain after graph retirement. Existing abandonment, guardian,
uncertain-work and completed-receipt rules retain their meaning.

=Execution.register-bundle!(grant, 'proc.evolve/spec, entries)= retains the
actual admitted graph through =retain_execution_code!=. It additionally retains
the genuine SDK entry, Execution module and explicitly declared dependencies
outside that graph. It rechecks admission after retention before branding the
metadata. The receiver still requires the exact live target ticket and schema;
a graph pin is code custody, not permission to run an arbitrary callback.

=proc.evolve/prepare-spec= captures its native context ID without expanding
=:modules= to the graph inventory. That field now describes only explicit
outside dependencies. Current-rehearsal still compares the exact installed
callback identities, context ID, version, digest and declared dependencies.

* Replay a plan through its actual native context

The previous replayable plan retained physical modules but no executable context.
Its later =validate!= ran in the ambient caller and tried to build a candidate
bundle there. An actual native exception trace shows
=execution_bundle_spec!: unadmitted_execution_bundle=. The unchanged preceding
floor reproduces the same owner-transition failures; the refusal was sound,
but the plan lacked an admitted entry for its own later work.

=proc.transition/prepare!= now registers one SDK closure containing the actual
immutable plan through the existing =Execution.register!=. The closure accepts
the closed operation vocabulary =validate/recheck/activate/adopt/retire/close=.
Public operations invoke that registration; Env accepts its code and privately
selects its original context before running the SDK operation. The public map
does not contain a physical lease, executable context or the mutable closed/
receipt cells. Its copied descriptor
fields do not select the stored work. Cleanup also uses the private plan, so a
modified public closed flag cannot suppress it.

Closing future plan admission does not revoke independent owner/queue custody.
Creator death closes its registration through existing native owner monitoring;
accepted owner work still reconciles using the original transition ticket.
No additional registry, evaluator or context-selector API is introduced.

#+begin_src beam-lisp :id transition-and-bundle-graph-pins
(ns execution.transition.pins.walkthrough
 (:require [reload.generation :as g] [reload.state :as state] [proc.evolve :as ev]))
(let [source "(ns transition.pin.demo)
              (defn accepts [x] (erlang/is_binary x))
              (defn valid [x] (erlang/is_integer x))
              (defn identity-value [x] x)
              (defn handler [message value] {:reply message :state value})
              (defn spec [version digest]
               {:version version :digest digest :handler handler :accept? accepts :check-state valid
                :migrate-state identity-value :upcast identity-value})"
      graph (fn [revision] (g/prepare! {:application-id "transition-pin-demo" :resources {:revision revision}
                                        :native-modules #{"erlang"} :sources {"transition.pin.demo" source}}))
      old (graph 1) fresh (graph 2)
      spec (fn [graph version] (g/with! graph #(ev/prepare-spec
                           (g/invoke! graph "transition.pin.demo/spec" [version (:digest graph)]))))
      owner (atom nil) grant (atom nil) held (atom nil)]
 (try
  (g/with! old #(state/bind! {})) (g/inherit-runtime! fresh old)
  (reset! owner (g/with! old #(ev/start! (spec old 1) 7 {:managed true})))
  (let [value (spec fresh 2)
        marker (BeamLisp.Env/source_policy_row (tuple :execution_graph_marker (:scope fresh)))]
   (reset! grant (g/with! fresh #(BeamLisp.Env/begin_owner_transition! @owner)))
   (reset! held (g/with! fresh #(BeamLisp.Execution/register-bundle! @grant 'proc.evolve/spec value)))
   (let [rows (fn [owner] (ets/match_object :beam_lisp_code_leases (tuple (tuple marker owner :_) true)))
         transition (count (rows (Process/whereis :Elixir.BeamLisp.Env)))
         bundle (count (rows (erlang/self)))]
    (assert (= 1 transition)) (assert (= 1 bundle)) (assert (empty? (:modules value [])))
    {:transition-pins transition :bundle-pins bundle :declared-outside (:modules value [])}))
  (finally
   (when @held (BeamLisp.Execution/close! @held))
   (when @grant (BeamLisp.Env/abandon_owner_transition! @grant))
   (when @owner (GenServer/stop @owner)) (g/retire! fresh) (g/retire! old))))
#+end_src
