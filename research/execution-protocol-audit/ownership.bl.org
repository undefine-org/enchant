#+TITLE: Execution ownership has one witness
#+DATE: 2026-10-23

* Preparation, retention and entry are different facts

A prepared graph identifies code. A registration keeps code available. An
accepted native frame permits this invocation to execute. Neither a graph
value nor a process-dictionary marker establishes that third fact.

=reload.execution= previously maintained a separate
=:reload.generation/execution= marker. Its ownership query accepted that marker
even when =BeamLisp.Env/executing_generation?= rejected the same context. Its
nested named-call shortcut also trusted the marker. The regression reproduced
both the false ownership answer and the later native context mismatch.

The facade now delegates both decisions to the existing native admission
check. It no longer creates, reads or restores its own ownership marker.

#+begin_example
;; Assume an actually prepared graph, as in execution_marker_test.bl.
(Process/put :reload.generation/execution
 (tuple (:scope graph) (:digest graph) (:state graph)))
(execution/owned?)                          ; false outside native admission
(generation/with! graph #(execution/owned?)) ; true inside the admitted extent
#+end_example

The [[file:../../test/bl/reload/execution_marker_test.bl][native regression]] also checks nested ticket reuse, retained callbacks and
an accepted callback that waits while its registration closes and its graph
starts retiring. Its nested named call completes under the accepted frame;
it does not acquire a new registration against the retiring graph. Cleanup
releases the final borrow and permits retirement.

* What this checkpoint proves

Eighteen assertions cover the new regression. Existing retained-execution,
actor-entry and execution-origin files pass 548 more assertions against the
same runtime source. The [[file:native-owner-checks.json][receipt]] records exact inputs and logs. The combined
control run also contained an additional test fixture whose raw send was
correctly refused as an unmanaged producer; that fixture was changed to use
the existing fixed observer helper, then passed separately. The receipt keeps
that distinction rather than labelling the original combined run green.

This is one adapter simplification, not completion of the native protocol.
=Env= still owns native custody and fences. The unified =BeamLisp.Execution=
handoff API, constant-size graph pins, adapter consolidation and affine
ownership analysis remain pending. The current native origin check can inspect
the graph's modules; this checkpoint makes no constant-time lookup claim.

* Native registration commands

=BeamLisp.Execution= now owns the native registration command surface:
=register!=, =invoke!=, =close!= and =observe=. It uses the existing Env custody
table and module fences. Registration checks the actual executable/context,
retains code, binds the callback privately, then brands that exact custody row.
The returned ticket contains no function, context or physical module list.
Supplying a fabricated ticket or the ticket of a legacy callback grants no
registration. A borrowed invocation copies the original branding; its fresh
execution ticket therefore cannot be upgraded into a registration.

#+begin_src beam-lisp :id native-registration
(let [registration (BeamLisp.Execution/register! (fn [x] (erlang/+ x 40)))]
 (try
  (assert (= :active (:status (BeamLisp.Execution/observe registration))))
  (let [result (BeamLisp.Execution/invoke! registration [2])]
   (assert (= {:status :completed :value 42} result))
   (BeamLisp.Execution/close! registration)
   (assert (= {:status :cancelled} (BeamLisp.Execution/invoke! registration [2])))
   result)
  (finally (BeamLisp.Execution/close! registration))))
#+end_src
#+RESULTS: native-registration
: {:status :completed, :value 42}


The native command always returns an admission envelope. A user callback
returning =:cancelled= is still =:completed=; its exception cannot become a
pre-entry =:busy= response. Argument containers must be eager native lists or
vectors, with at most 16,384 elements. The count is checked before vector
conversion, and no lazy argument continuation is forced. Closing or owner
death prevents future acceptance; independently accepted work drains.

This is the first kernel slice. =proc.callback= still uses its compatibility
carrier until native handoff and metadata conversion are ready. Native custody
still performs existing module retention and private-owner queries; graph pins
and their performance/lifetime gates remain pending. Both =Env= internals and
=Execution= commands are critical native targets for the existing Source
preparation/runtime policy, rather than new arbitrary native grants.
