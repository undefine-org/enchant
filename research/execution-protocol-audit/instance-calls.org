#+title: Instance calls: qualify the application boundary

* The contract
=proc.instance= resolves a logical keyword in the caller's application. Its
identity excludes the code-generation digest: publishing another generation
must find the same owner, while another application must find a different one.
Isolated development environments also have distinct names. The global legacy
environment keeps its ordinary name contract.

Both call arities use the SDK Server boundary. An explicit timeout expires the
caller's wait; it does not stop the owner. A caller-supplied global reference is
not a logical keyword and is refused before process lookup.

The existing implementation already satisfies these selected contracts. This
slice changes tests and historical evidence, not runtime implementation.

* Reproduce the actual historical seam
The E13 transcript says Core's generic call formerly lowered to raw GenServer.
Current Core instead names =BeamLisp.Server= in its primitive table. Changing
the implementation of a trusted SDK function to use raw OTP is therefore not
the original application admission failure: that development mutation survives
both original selectors. Replacing the application call with current generic
=call= also succeeds. Neither experiment is a causal closure.

The control now derives the actual application Source from =probe-proposal= in
=test/bl/proc/instance_test.bl=. It changes exactly one call site:

#+begin_src diff
-(instance/call :instance-test/service :value)
+(GenServer/call (instance/name :instance-test/service) :value)
#+end_src

This restores the former lowered target. Normal preparation succeeds; the
changed application refuses =:undeclared-dependency= during preparation, before
any owner is started. The ordinary instance and current generic calls both
succeed in the separate real-actor regression. Its generated class exports also
exclude raw call/cast/stop adapters. The baseline belongs to this application
consumer, not a supposed removal of SDK implementation privilege.
