#+TITLE: Actor callbacks enter the common native execution protocol

This records the =f6e1cc88= frame checkpoint. The subsequent
[[file:actor-pins.bl.org][actor/starter graph-pin migration]] removes its physical module tickets and adds
the wider starter/host qualification. The evidence below remains scoped to this
checkpoint.

* One entry, distinct lifetimes

A generated server owns its existing monitored code ticket. Each accepted
init, message or terminate callback enters a fresh native execution frame using
that ticket. The compiler emits a fixed =BeamLisp.Execution/invoke-actor!= call;
=BeamLisp.Server/bind_init= installs ownership through =install-actor!=. Neither
entry takes a caller-selected context, graph, evaluator or admission flag.
Env remains the custody owner. Actual starter evidence, indexed membership,
callback module and physical ticket are checked before executing the body.

The frame stores graph/context IDs, the actual ticket, entry kind, nearest
native parent and depth. Actor initialization selects the existing shared
immutable graph snapshot once. Message entry does not repeat the SDK graph
preparation check. Public context maps remain observations: binding one cannot
supply an actor frame or native owner proof.

Accepted work and termination retain their original physical lifetime through
logical close. Business entry still requires live membership and open ownership.
Termination restores its original cleanup context, then enters a distinct frame;
it does not reopen business admission. Actor tickets still retain the physical
module closure in this checkpoint; graph-pin migration is a separate change.

* Observe real generated callbacks

#+begin_src beam-lisp :id actual-actor-frame-lifecycle
(ns execution.actor.frames.walkthrough (:require [reload.generation :as generation]))
(let [graph (generation/prepare!
             {:application-id "actor-frame-walkthrough"
              :stable-namespaces #{"reload.execution"}
              :sources {"actor.walkthrough"
                (str "(ns actor.walkthrough (:require [reload.execution :as execution])) "
                     "(defserver counter (init [_] (ok 0)) "
                     "(handle-call :next [_ state] "
                     "(reply {:value (inc state) :frame (execution/frame)} (inc state)))) "
                     "(defn start-counter [] (start counter nil))")}})
      actor (generation/invoke! graph "actor.walkthrough/start-counter" [])]
 (try
  (let [first (call actor :next) second (call actor :next)]
   (assert (= [1 2] [(:value first) (:value second)]))
   (assert (= :handle_call (get-in first [:frame :entry])))
   (assert (= :active (get-in first [:frame :status])))
   (assert (not= (get-in first [:frame :id]) (get-in second [:frame :id])))
   (assert (= (get-in first [:frame :graph-id]) (get-in second [:frame :graph-id])))
   {:values [(:value first) (:value second)] :fresh-invocations true :same-graph true})
  (finally (stop actor) (generation/retire! graph))))
#+end_src

* Adoption changes the baseline

Adoption of a genuine fixed-SDK actor commits an independent application
lifetime and clears Source generation authority. A private native revision
changes at that commit. Dynamic unwind restores an older execution proof only
when its revision still matches. A finally from before adoption therefore
cannot revive Source origin or replace the new baseline. Ordinary callback
nesting keeps its revision and restores its exact native parent.

This revision is absent from capture/convey and Source cannot write the private
process dictionary. It is a native unwind rule, not a Source-provided epoch or
an application registry. Existing owner membership and physical retention keep
their separate responsibilities.

* Recovery judges custody, not idle bookkeeping

Native compiler callbacks also use the common protocol. Completed callbacks
leave monitored owner bookkeeping and a zero-byte context accounting row.
A bare recovery VM can therefore have nonempty tables with no live frame or
Source authority. Recovery checks active stacks/frames, orphan frame/selectors,
actual context records, SDK leases and native commands. It permits only empty
owner stacks and zero accounting, alongside the previously admitted compiler
metadata caches. It never erases live custody to manufacture freshness.

The bootstrap regression enters a real native frame, requires recovery to
refuse while it is active, releases the real ticket, and requires recovery to
succeed afterward. Actual SDK retention must still refuse independently.

The reload producer and server-body analyzer use the compiler's
=server-execution-target?= predicate for the emitted entry target. Each still
checks the exact class, callback kind, zero-argument action and body shape;
recognizing the target alone grants no exemption to a nested or forged call.
