* Qualified component changes
The checkout's cold path obtains its fingerprint under the preparation lock.
Only the warm transport lookup pays a preliminary scan. The locked current
scan and comparison with captured immutable engine bytes remain in force.

Constructor lookup consumes the exact rows from its own complete-unit proof.
Every following lookup rereads inventory, artifacts and Source; selected live
MD5 and export checks remain. There is no process-global authorization cache.
A graph discovery captures its shared source-resolution context once. Every
namespace retains its own live package-provider key, and each new graph
recaptures its roots/environment even inside a shared content snapshot.

Forwarder route verification and passive literal-definition validation consume
one disassembly of the same actual bytes. Both validations, including on_load
refusal, remain. Inventory generation captures one physical Source/digest per
complete unit and independently rereads/re-resolves Source before accepting it.
The complete-unit/owner checks and single metadata publication remain intact.

* Safety and validation
Heavy commands run on Build using the repository backend, not the swapped Work
host. Parent qualification trees have an 8 GiB memory limit and zero swap;
Nix evaluation workers have a 4 GiB limit and zero swap. Compiler generations
and SDK production are serial native guests capped at 6144 MiB / four CPUs.
All scopes have finite wall ceilings. No ceiling was increased. Private test
VMs terminate, and qualification cleanup targets only its owned runtime path.

The runtime-host checker now creates writable private copies of immutable SDK
images without changing symlink targets, and retains the selected SDK's sibling
dependencies. This repairs the actual checker path; it does not bypass runtime
validation. Python tests cover permissions and symlink ownership.

Boundary consumer discovery was regenerated for the real new helpers and line
positions; all 16 boundaries and nine external writers remain checked. The
new cost tests join the existing metadata and constructor boundary tests.

* CI investigation and remaining release work
The recorded slow fixtures include js_macro_build (266.888 s, nine public
builder calls), mcp_z3_port (237.054 s, isolated owner-death/port controls),
js_diff (219.620 s, three actual JS targets), evolve_retirement_stress
(195.815 s, isolated), aot_implicit_dependencies (165.810 s), and
continuity_demo (162.441 s, isolated). Their different source variants, native
owner transitions and cross-target equivalence checks retain their coverage.
Removing repeated public builds safely needs an exact-input JS artifact cache
with the same macro/read-set and environment ownership checks; this change
makes no unmeasured shortcut there.

The remaining cold-preparation fixed work includes immutable source capture,
three Source-based coordinator commands and Nix evaluation (about 3 GiB peak
worker memory). A reusable precompiled coordinator must preserve its existing
bootstrap/native compatibility and custody boundaries. A stale-input hint or
an mtime-only fingerprint would weaken the current contract and is excluded.

The first changed-compiler SDK still spends about 19 minutes emitting 515
units. Steady-state images still validate all restored units, assemble the full
metadata/image and pack a complete native drop. Further cuts need measured
immutable-byte reuse and image-copy evidence. Runtime lookup now avoids repeat
work inside one proof only; it deliberately does not keep authorization after
source, loaded code, inventory, package context or lifetime may change.

Complete CI lanes and all target-platform release gates remain required before
release. The evidence here qualifies these changes and the actual produced
Linux SDK; it does not claim that the entire release matrix ran.
