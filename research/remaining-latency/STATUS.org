* Baseline
Base: main 9d628c6e0. Branch: perf/remaining-latency.
Build placement uses the operator's Source-described backend and its compiled
evaluation transport. The isolated Build checkout is beam-lisp-latency; no other
checkout or VM is modified. Builds run serially with finite memory/swap/time caps.

Initial SDK selection on Build: 143.612 seconds. The immutable image was already
available; capture, coordinator preparation/startup and Nix selection still ran.
Foundry worker: 3 GiB peak, 73.652 CPU seconds, 89.583 wall seconds. SDK:
/nix/store/57l1pabcx2p6x7yyvja68grc9mqn3rzp-beam-lisp-sdk-selection.
This is a cache-hit baseline, not a newly compiled SDK timing.

Work-host cProfile of scripts/sdk-inputs: 4.061 seconds, including 3.866 seconds
in buffered reads over 950 selected files. Work was already using 25 GiB swap;
Build had 18.5 GiB available RAM and zero swap use. An unrelated model server
uses eight Build CPU threads, so wall comparisons need phase counts as well.

Eight CI partitions contain 156--158 files each. Their recorded file-time sums
are 1955.51--1955.79 seconds, but isolated VM counts are 2,6,2,3,4,4,5,1.
All conventional files have duration entries. File-only balancing omits the
extra initialization for each isolated VM.

* Measurement protocol
profile.bl reports wall time, VM memory and operation counts for repeated SDK
constructor validation, SDK input snapshot/comparison and closure hashing.
Production logs retain SDK-PHASE, SDK-UNIT-PHASES, SDK-PARTS-RESULT and
SDK-IMAGE-RESULT. Compare complete output bytes and constructor-input evidence;
unchanged, edited, fresh-process and warm commands must preserve their normal
cache/admission and ownership contracts.

The first profiling attempt failed reader validation before executing its
measurements; it is excluded from performance results.
