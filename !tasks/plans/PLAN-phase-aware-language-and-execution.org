* Objective and present evidence
Build one language pipeline whose identifier meanings, expansion dependencies,
artifact inventories and execution obligations remain explicit across phases,
compiler generations and process boundaries. Take Racket's syntax/phase model
as the primary frontend inspiration; reuse this repository's ANF, constructor
machine, analysis engines and native custody mechanisms.

This refines [[file:PLAN-artifact-only-compiler-production.org][artifact-only production]] and
[[file:PLAN-enforced-execution-protocol.org][the execution protocol]]. The 30-case
[[file:../../research/execution-protocol-audit/staging-architecture.org][initial staging investigation]] established Rt/Core blockers and loss
of invocation identity. Initially eleven of thirteen existing floor units independently
emit byte-identical artifacts across fresh traced/untraced VMs. This is not a
passing complete bootstrap, a hygienic expander or a native protocol migration.

This plan adds frontend hygiene and finite phase/ownership analyses to that
direction. Implementation began after approval.
Existing datum macros and dynamic Source programs retain their supported
semantics during migration; stronger closed profiles require complete evidence.

* Opportunities opened by the design
1. Hygienic domain languages. Actor clauses, queries, UI bindings and build rules
   can expand into the same checked kernel without accidentally capturing user
   variables. A restricted module profile can limit available forms/imports.
   A language profile alone is not a native-effect sandbox.
2. Semantic tooling. Rename, references and impact queries can distinguish the
   same symbol in two scopes, phases or generations. Macro-generated bindings
   retain an origin chain back to the user's form.
3. Replayable expansion. Record immutable macro inputs, provider identities and
   actual dependency reads; reproduce a failed expansion and show each step
   without rerunning runtime initialization or arbitrary effects.
4. Independent phase packages. A dependency can ship a verified macro/helper
   bundle separately from its runtime modules. Target execution need not carry
   unused compiler machinery. Imported macros can retain private lexical helper
   bindings while their callers see only the exported syntax.
5. Safer hot reload. Determine whether an edit changes expansion outputs,
   runtime implementations, actor contracts or retained captures. Rebuild the
   appropriate cone and keep already accepted execution on its retained graph.
6. Deliberate language evolution. Multiple language/ABI generations can be
   prepared and qualified separately. A compiler can compile a different target
   generation without silently adopting its unfinished runtime.
7. Multiple backends and specialization. Expand a frontend once into explicit
   kernel operations, then analyze/lower for BEAM or another supported backend.
   Macro evaluation belongs to the producing kernel; target adapters and
   generated dependencies remain separate qualification obligations.

These are enabled directions, not claims that every DSL, migration or
specialization is automatically correct. Initial delivery demonstrates hygienic
expansion, exact impact, replay and full bootstrap before adding broad DSL APIs.

* Soundness and decidability contract
Racket-style bindings make name/phase structure explicit. They do not make
arbitrary macro execution, program equivalence, termination or effects decidable.
Separate three kinds of question:

| Question | Method and limit | Gate behavior |
|----------+------------------+---------------|
| Which declaration does this expanded identifier name? | Finite scope/phase/import lookup; unique most-specific applicable binding. Index by symbol/phase/space, compare candidate scope sets. | Exact answer, unbound or ambiguous error. Never select by visited units. |
| Is a declared import/phase transition available and ABI compatible? | Finite manifest and readiness-state checks. Relative phase shifts compose; phase depth has a resource ceiling. | Exact for the selected manifest; unsupported/missing evidence stays explicit. |
| Is the observed expansion/value demand cyclic? | Per-kind demand stack and finite dependency SCCs; graph traversal O(V+E). | Refuse eager evaluation cycles with a path; allow recursive function groups. This does not detect all nontermination. |
| Does a closed expanded entry stay within an effect profile? | Monotone worklist over a finite effect/callee lattice; opaque targets join to top. | Prove containment only with complete transfers/adapters; otherwise unknown or a runtime obligation. |
| Are supported local resource transitions legal on every CFG path? | Finite typestate dataflow with conservative alias/merge rules. | Prove supported cases, refuse illegal protocol states; unresolved escape/alias needs native enforcement. |
| Can a macro finish? | Execute in the existing bounded constructor machine; count steps, bytes, atoms and expansion size. | Completed expansion or resource-limit refusal. A timeout is not proof that the macro diverges. |
| Are actors safe/deadlock-free for all possible executions? | Existing finite models, explicitly bounded exploration or a proved sound abstraction. | State bounds/assumptions. A finite trace search alone cannot prove an unbounded system safe/live. |
| Does a dynamic callback still have authority and live code? | Native admission under the actual ownership/publication fence. | Runtime check; static evidence can establish requirements, not future physical custody. |

Finite does not imply cheap. Bound graph size, lattice height, candidate target
sets, scope count, expansions and solver time. With finite height h and bounded
transfer cost C, a monotone worklist has a budget proportional to its graph and
state changes, commonly O((V+E)hC); do not claim unrestricted linear analysis.
Budget exhaustion is :unknown or a resource refusal, never :proved. SMT remains
optional fragment-specific escalation through system.decide/system.smt.

Every result carries :status proved/refused/unknown/error, subject identity,
scope, assumptions, coverage, remaining obligations, witnesses and diagnostics.
Refused can mean the profile's proof requirement was not met; distinguish that
from a concrete counterexample. Proved means the named property under the named
semantics/assumptions, not correctness of arbitrary code or the compiler itself.

Write small concrete/abstract transition specifications and check each transfer
rule's over-approximation: alpha(post(S)) <= post#(alpha(S)). Unsupported behavior
maps to unknown/top. Differential/property tests support the implementation;
they do not replace the soundness argument. Native adapters, code generation
and entry-hook enforcement belong to the explicit trusted/qualified boundary.

* Canonical frontend model
Use distinct identities for:
- A symbol: quoted name data, e.g. 'rt/empty?.
- An identifier: symbol plus lexical scopes and source/expansion origin.
- A binding: declaration identity, namespace, phase, binding space/kind and
  revision in an immutable compilation world.
- A transformer: a bounded macro/helper recipe with its definition world and
  evaluation phase.
- An artifact entry: actual emitted clause/initializer/lambda identity and ABI.
- A registration/frame: a private native runtime record holding admitted origin,
  restrictions, graph retention and lifetime ownership.

A macro keyword is bound at its use phase p; the transformer expression/body
is evaluated at p+1. Syntax it returns can contain references intended for p.
Compiler generation/world identity is independent of these relative phase
numbers. Runtime mutable var lookup also remains independent of frozen
compile-time selection; worlds do not freeze every application value.

Separate canonical binding-world identity from compilation input attestation.
The implemented =:world= and =:phase-world= records attest exact physical
providers. In the B/C reproduction receipts all 85 input-attestation IDs differ,
although every emitted file matches; Core/Sugar phase bundles themselves are
equal in B/C. These records currently remain outside executable artifacts.

Define binding-world keys from normalized source/declaration identities,
relative scope/phase/import references, language profile, schemas and target
ABI. Phase bundles serialize self/relative helper references before attaching
their physical container hash. A separate attestation binds those keys and
provider interfaces to exact selected artifacts and compiler inputs. Matching
logical keys alone never authorizes an artifact or asserts semantic equivalence
of arbitrary programs. Artifact/custody validation remains mandatory.

Before embedding binding keys in emitted code, gate identity convergence:
repackaging unchanged canonical declarations must preserve their logical keys;
changed provider bytes must still invalidate the physical attestation; a fresh
generation must not inherit an endlessly changing previous-container hash in
its own semantic identity. Run reproduction again with the binding/phase
metadata embedded. No recursive binding/artifact hash equation is acceptable.

Keep the current reader grammar and reader-node accessors. Add a versioned
syntax envelope/tree above them with per-identifier context. An expansion has
a definition context and a use context; introduced identifiers receive a fresh
introduction scope, while substituted user syntax retains its own context.
Binding lookup follows the specified scope-subset/most-specific rule, rejecting
incomparable candidates. Module/import scopes and declaration positions account
for aliases, refers, exports, privacy, local shadowing and authored macro order.

Normalize scope/declaration IDs deterministically for serialization without
merging distinct scopes. Public counters/pretty names are not semantic identity.
Compilation accepts only references validated against its selected world and
expansion context. Neither scope tokens nor syntax provenance grant SDK origin.

Preserve defmacro as datum-v1. An explicit adapter applies its existing
datum/syntax-quote qualification and caller-context rules; record its legacy
coverage. Do not advertise full hygiene for arbitrary datum macros. Add an
opt-in defsyntax form with syntax-v1 input/output for hygienic transformers.
Its Source surface and serializable descriptor use the same evaluator and
declaration inventory; the reader needs no new lexical grammar. Mixed calls
cross a visible versioned conversion boundary. syntax/to-datum intentionally
forgets lexical context; syntax/from-datum requires an explicit context.
Phase availability, authority, bytes and budget checks apply to both kinds.
Macro output re-enters syntax validation and binding resolution; a returned map
that resembles ANF remains literal data. Macros cannot inject a resolved native
entry by forging :op, :world or provenance fields. Exposed form/environment
metadata is bounded first-order context, never the private controller, native
leases, live Fns or runtime frame. Verify this boundary with raw-lookalike cases.

* One lifecycle, with separate data and authority
#+begin_example
actual Reader forms
  -> contextual syntax + selected world
  -> expanded core forms + actual dependency/origin trace
  -> canonical ANF + entries + initialization plan
  -> scoped phase/type/effect/ownership evidence
  -> complete emitted artifacts and portable phase bundle
  -> fresh verification/qualification
  -> guarded activation and native entry registration
  -> admitted execution / retained graph / explicit owner handoff
#+end_example

Keep the implemented AOT workspace API; add prepare_host_unit and a next-version
manifest with language profile, phase imports and ABI selections. Namespace
arguments stay quoted symbols. No trusted/sdk/skip-validation flag is added.
The namespace additions are source/internal APIs; pinned host entry names keep
their existing naming convention.

A language profile selects initial bindings, supported core operations,
transformer protocols and required analysis obligations. It can request tighter
restrictions; only the existing authenticated controller can grant available
native capabilities, and effective restrictions compose monotonically. The
closed kernel-operation schema has one versioned owner alongside canonical ANF;
its evaluator implementations and analysis summaries are checked against the
same operator/arity inventory. No user-written profile introduces a new native
primitive by naming an MFA or supplying an effect annotation.

Prepared unit v2 records selected sources, world/phase/import identities, ordered
expanded declarations, semantic ANF, entry inventory, initializer plan, recipes,
dependencies, assumptions and coverage. Artifact unit v2 additionally binds
actual bytes, roles, complete membership, target ABI and replay/phase schemas.
Qualification binds exact candidate bytes, input/toolchain/platform identities,
requirements and executed checks. Serialized reports and hashes grant nothing.

Execution registration binds the actual loaded callable/entry and immutable
dependency graph to a restriction profile and lifetime owner. Invocation takes
a separate executing borrow; close/cancellation cannot revoke already accepted
work by purging its code. A fixed fence atomically validates owner epoch, live
code and admission before side effects. Handoff prepares an inactive receiver
ticket, publishes it into a bounded receiver-owned slot, then accepts under the
same native fence. Death at every boundary must reclaim or preserve the exact
accepted lifetime correctly. User callbacks never execute inside registry turns.

Ownership analyses prove protocol requirements only for their covered CFG.
Native checks handle dynamic targets, concurrent mutation, raw platform calls,
receiver death and physical code retention. Supported Source/SDK interfaces are
the enforcement boundary; arbitrary privileged native code is an explicit escape
from that model, not made safe by a syntax annotation or language profile.

* Compatibility, bootstrap and delivery sequence
1. Contract and oracle corpus. Specify scope/phase resolution, core syntax,
   abstract transfer rules, entry inventory and native transition semantics.
   Convert the research cases into desired-behavior tests: implicit invoke 42,
   explicit source invoke 99, source helper 2, unused require no redirection,
   ordinary recursion, witnessed value cycles and authored local macro order.
   Compare equivalent Racket syntax/phase examples where semantics match; keep
   explicit BL differences and legacy datum controls.
2. World-bound core. Introduce world/declaration IDs and explicit :invoke / bound
   calls together; update all ANF consumers and schema/cache versions. Preserve
   argument order/once-only, dynamic argument lists, shadowing, callable kinds,
   guards and existing runtime mutable-var behavior. Batch coupled boot edits.
3. Contextual expansion. Deliver syntax/binding/expand with legacy adapters and
   opt-in syntax transformers. Gate introduced-name capture, definition helper
   shadowing, nested macros, phase shifts, aliases/privacy, recursive expansion,
   exact origin diagnostics and explicit context-erasing conversions. Keep
   kernel special forms fixed initially; extensible module profiles follow
   tested binding/expansion semantics instead of weakening this boundary early.
4. Phase library and bootstrap. Export bounded first-order macro/helper ANF,
   literal/closure recipes and dependencies. Qualify a legacy-floor transition
   via coherent recovery if the current floor lacks that data; a source digest
   cannot reconstruct old source. Bind preceding-phase macros while preparing
   the Rt1/Core1 foundation; advance explicitly to candidate helpers. Gate all
   new/existing boot units and pinned hosts without intermediate publication.
5. Analysis gates. Add system.phase and system.ownership; extend existing
   type/effect/impact/report APIs. Deliver conservative closed profiles with
   explicit dynamic obligations. Gate unknown native calls, capped fixpoints,
   changed providers, policy/ABI drift, missing generated entries and false
   empty coverage. Test abstract transfer semantics, not only expected warnings.
6. Complete generation qualification. Migrate build/cache consumers to the
   producer. Assemble all generated units/phase bundles before fresh consumers.
   Run A -> B -> C reproduction (extra comparison stage where ABI changes need
   it), native-only startup, no-source consumption, changed-helper semantics,
   once-only initialization, tampering and interrupted-install recovery. Reused
   floor artifacts never satisfy from-scratch reproduction.
7. Enforced execution. Implement Execution using existing Env custody/fences;
   migrate callback, actor/task/initializer, reload and control adapters in
   semantic commits. Gate direct/wrapped parity, no exposed callback bypass,
   accepted-work draining, receiver/owner death at every handoff point,
   cancellation, stale epochs, graph retention and cleanup. Add native/platform
   and backend checks from the existing 86-family ledger; a frontend proof
   cannot replace those controls.
8. Demonstrate the new avenues. One hygienic actor/query DSL under a closed
   module profile, replayable expansion with source origins, binding-aware
   rename/impact and a macro-only dependency omitted from the runtime package.
   These reuse the pipeline, not parallel parsers/checkers or a new runtime.

Each milestone has semantic commits, focused native regression files and its
own exact input/coverage receipt. Earlier steps may keep compatibility adapters;
delete them only after every named consumer migrates and parity gates pass.
Do not start all feature avenues before the binding/bootstrap foundation works.

* Efficiency obligations
- Parse each changed source once per validated world revision; retain bounded
  immutable syntax/ANF/recipes and use small scope IDs. Repeated validation may
  read/hash files for drift; do not claim zero I/O merely because parsing caches.
- An unchanged cached preparation repeats no macro execution. Record actual
  provider reads and declared inputs; undeclared time/file/env/network reads
  refuse or use an explicit value/digest adapter. Branch changes invalidate
  results through their changed inputs.
- Reanalyze the affected dependency/phase cone. Each lattice fact changes only
  finitely; target explosion becomes top/unknown, not unbounded enumeration.
- Keep immutable graphs owned/shared through controlled storage; messages carry
  small IDs/requests. BEAM term/ETS copying can lose structural sharing: measure
  copied bytes rather than assume immutable maps make handoff cheap.
- Validate/cache evidence before activation; ordinary calls do not invoke the
  database, solver, source resolver or compiler. Constant-size graph retention
  is an implementation target; input validation and dynamic dispatch still have
  their own costs. Measure them separately.
- Track cold generation startup, warm unchanged prep, changed-provider cone,
  macro/effect node visits, emitted byte determinism and peak/retained memory.
  Use the current roughly 18-second 30-case research VM as a measured baseline,
  not a claimed speedup or a required universal wall-clock threshold.
- Use one serial capped VM for focused files, one fresh VM per whole bootstrap
  generation, private runtime directories and monitor-based cleanup. No cold
  VM per helper/file, forgotten daemon or unbounded global world cache.

* Primary grounding
- [[https://docs.racket-lang.org/reference/syntax-model.html][Racket syntax model]]: syntax objects, lexical scope sets, unique binding
  selection, transformer binding versus evaluation phase, expansion contexts.
- [[https://docs.racket-lang.org/guide/phases.html][Racket phases]]: relative phase levels and shifted imports; this plan adds
  separate compiler-generation/world and native-authority identities.
- [[https://docs.racket-lang.org/guide/module-languages.html][Racket module languages]]: selecting initial bindings provides language
  variation; native authority/effect enforcement remains a separate obligation.
- [[https://www.di.ens.fr/~cousot/COUSOTpapers/POPL77.shtml][Cousot and Cousot, 1977]]: abstract interpretation and sound approximation
  of fixpoints; finite analyses can over-approximate with explicit precision loss.
- [[https://theory.stanford.edu/~trevisan/cs172-07/turing36.pdf][Turing, 1936]]: no general decision procedure for arbitrary computation.
- [[https://www.erlang.org/doc/system/eff_guide_processes.html][OTP process efficiency]]: message/ETS copying and loss of sharing inform
  the graph/data lifetime and measured-cost requirements.
