#+date: 2026-11-05
#+status: Approved sequence; implementation in progress

* Contract

Main is the integration target. Port selected changes; retain existing native
ownership and build paths. Format-preserving improvements ship first. The
canonical-key cutover waits for a usable, qualified migration and deployment
path. Production data is never an implementation fixture.

Datom key format and application dataVersion are separate. A release binds both
to its exact runtime. Matching versions need no conversion or full scan.
Unknown/partial formats and collisions refuse activation; no relabeling.

Implement a supported legacy snapshot reader, separate absent destination,

*** DONE Reject malformed batches before publication
One operation validator covers ETS, map, Fjall and speculative overlays. Unknown
operation names and missing/extra fields refuse; they cannot become deletes.
Fjall validates during its existing encoding pass; memory stores publish only
after validation. ETS still has its documented process-death atomicity limit.

*** DONE Refuse incompatible storage before initialization
Connection admission, Db construction and direct index writes check the reserved
format descriptor. Unknown/partial/malformed descriptors refuse without schema
or counter initialization. Nil metadata is distinguished from absence. Legacy
stores remain unversioned and unchanged; no format conversion is enabled.
Matching descriptors use one point read; absence needs an exact-key probe.
Transaction side operations cannot modify this descriptor. The supported encoder
version owns the descriptor version; unimplemented encoders fail closed.

*** DONE Harden authoritative counter recovery
Validate counter types and detect missing transaction metadata in a nonempty
database before treating it as fresh. Preserve legitimate unused entity
allocators and exact high-water gaps; do not infer counters from maximum facts.

*** DONE Check counters before any writer-turn effects
The common writer boundary validates both counter types and compares the
transaction high-water mark with the published basis before allocation, bulk
load, excision or speculation. Atomic reservation rechecks remain pure.
The runtime never guesses a replacement counter.

*** DONE Recheck format before live writer effects
The shared writer entry rechecks the format before counter validation or any
operation effects. Incompatible metadata cannot cause tempid allocation, bulk
load or excision to change rows before reporting refusal. This logical guard
is not a deployment fence; generation selection and offline verification remain
mandatory before a format conversion.

*** DONE Bounded raw reads and explicit offline source audit
Raw pages preserve mixed legacy/packed slot bytes and enforce row/byte budgets.
The explicit format-2 encoder is available to offline tooling; normal writes
remain format 1. Source audit verifies all keys and mandatory index copies,
counters, recovered schema, provenance and recognized metadata without Conn or
application callbacks. Partial optional backfills stay distinguishable from
complete indexes. Supported payloads are bounded first-order data in current
lanes or retained-runtime default uncompressed ETF; unsupported encodings refuse.
The coordinator must still bind this logical pass to a sealed whole-root snapshot.

*** DONE Historical canonical uniqueness policy
A bounded streamed event fold checks every transaction boundary, including
historical conflicts that have disappeared by the final state. Same-turn
retractions win and legal owner transfers remain valid. Conversion and
verification must build independent event witnesses from the bound source.

*** DONE Bounded private store conversion
The converter's page data, private uniqueness events and cursor live in one
Fjall batch in the destination. This avoids requiring a transaction spanning a
second progress database. A building descriptor refuses ordinary readers and
writers. Independent verification rereads the sealed source and destination;
it does not accept builder counts or cursors as proof. The coordinator binds
both passes to the snapshot, manifest, runtime/tool identities and complete root.

*** DONE Independent logical destination verification
Reread source and destination, compare required rows and reject extra rows, then
replay a fresh source-derived uniqueness witness. Logical proof remains separate
from whole-root READY. The verifier reconstructs all required rows, rejects
extras and stale caches, and rereads the source digest before persisting proof.

*** DONE Pinned filesystem substrate
Native capabilities pin canonical directories/regular files, reject links and
observed identity replacement, inherit source read-only access, bound directory
pages and file streams, and sync atomic copy/metadata publication. Native error
tuples are checked before any higher-level success decision. These capabilities
must still be composed with the app-wide owner fence and manifest.

*** DONE Declared physical application-root capture
A strict versioned storage manifest accounts for control/library engines, FS
tiers, additional files and empty directories before copying. Source engines
are directory-locked without opening them. Framed tree hashes match before,
after and at the fresh destination. Orphan bytes survive; undeclared content
refuses before effects. This is a physical capture, not logical validity or READY.

*** DONE Historical FS blob verification
Recover historically file-typed attributes, including removed declarations,
and inspect nested DFile records. Stream SHA-256 and size checks for assertions
and retractions, with a fresh disk witness to hash each content once. A bounded
closed-ETF reader explicitly admits inert DFile data without rewriting bytes.
Missing/corrupt blobs, malformed descriptors and staged bodies refuse. Whole
tree conservation separately retains orphan and unclassified blob bytes.

*** DONE Scoped supported extraction reader
Native job capabilities bind the owned durable marker and fixed extraction,
target and scratch roles. Extraction is logically read-only through every
native mutator; ordinary opens cannot enter a marked job or initialize its
children. Existing physical engine version/partition markers are required
before recovery. Closed/changed claims refuse; native error replies propagate.
Unscoped checkpoint exports cannot escape the job owner.

*** DONE Verified private store header publication
Reverify with fresh scratch, remove temporary witness pages durably, recheck
the complete data digest, then atomically publish format 2 plus truthful AVET
coverage and remove private state. Certificate batches obey the raw operation/
byte limits; oversize schemas refuse. Reconcile a lost reply by reconstructing
the published store from source with a new witness, never by trusting a receipt
or relabeling data. No additional permanent per-store migration journal.

*** DONE Seal closed targets through accepted publication
Native sealing claims every declared target engine, rejects omitted openings,
and blocks further target file/engine mutations. The seal pins job custody
through async no-clobber rename and both parent-directory durability boundaries;
caller death cannot release accepted work. This filesystem primitive is not
READY verification or deployment authority.

*** DONE Retain original generation custody
The job binds an actual native read-only source and every declared original
store flock without opening engines. Bound capture keeps these claims after
return; sealed/accepted publication inherits them. Copied path/access flags
cannot substitute for the source, and source custody cannot detach early.

*** DONE Close engines before physical publication
A fixed monitored SDK worker owns each store conversion/verification and blob
checks. Only bounded first-order proofs leave the worker; exit plus actual
directory-flock acquisition proves engine retirement. Reconciliation opens a
disposable prepared-engine copy, preserving the actual target physical hash.

*** DONE Durable private preparation progress
A bounded version1 job record binds source/code/tool/manifest intent and
compares exact prior bytes for allowed durable transitions. Recorded snapshots
are immutable; corrupt/missing/unknown state refuses without repair. This job
record is subordinate progress for Foundry, never a second activation decision
or evidence substituting for independent whole-root READY verification.

*** DONE Whole-root conversion and READY coordinator
One SDK coordinator owns control/library stores and all declared FS bytes.
It derives its tool identity from the selected SDK closure and native library,
converts each store, closes engines, then independently verifies disposable
copies while holding every actual target store flock. READY binds exact
code/runtime/tool/manifest, original snapshot, logical proofs and physical tree.
Only two fixed protocol files can be written through the data freeze; the
no-clobber publisher retains claims through both parent-directory syncs.
Repeated publication adopts the existing inode and redoes verification under
actual ownership, without opening the published engines or trusting READY.

Store header publication follows independent verification and a final data-hash
check. Root recovery independently reconciles an already prepared store after
a lost reply; no blind overwrite or second permanent per-store journal.
