#+TITLE: Artifact-only compiler production, staging, and bootstrap qualification
#+DATE: 2026-10-22
#+STATE: IMPLEMENTING — source workspace and artifact verification; bootstrap migration pending

* Outcome and approval scope
Implement one complete production path: immutable selected sources -> prepared
units -> complete emitted artifacts -> independent qualification -> guarded
publication/installation. Demonstrate macros, compile-time values, generated
declarations, runtime initialization, cache replay, and actual compiler
self-reproduction. Preserve the existing language's evaluation semantics.

This implements the production/qualification contracts in
[[file:PLAN-enforced-execution-protocol.org][the execution protocol plan]]. It does not claim to implement native execution
registration, callback/reload migration, affine lifetimes, or O(1) graph pins.
Those retain their own acceptance gates. The 86-finding ledger must distinguish
production coverage from still-pending native/backend/platform obligations.

* Invariants
1. Preparation/emission never replace target modules, publish target bindings,
   mark target namespaces ready, run target initializers, or issue SDK/runtime
   authority. Private compiler metadata and bounded caches are permitted.
2. Workspace namespace tables are metadata isolation, not physical module
   isolation. No target code/load_binary call is hidden behind an Env fork.
3. Source-selected compile-time helpers resolve in the staged source world;
   executing compiler internals remain bound to the verified compiler kernel.
4. Every selected definition, action, generated member, closure/lambda and
   initializer has an accounted-for result or explicit unresolved obligation.
   Empty collectors and truncated traversal are never successful coverage.
5. Prepared maps, manifests and quoted symbols carry data, not SDK authority.
   Consumers validate bytes, identities, context and applicable native policy.
6. Failures leave the running publication unchanged and no installable partial
   candidate. Arbitrary runtime effects are not claimed to be rollback-safe.
7. A qualification result binds exact inputs, artifacts, requirements, toolchain,
   platform and executed checks. Reusing a floor is not self-reproduction.

* API surface (proposed, names to be fixed in the schema commit)
Keep the low-level implementation in BeamLisp.AOT/Emit/Env/AOTCache and the
controller in existing build/seed owners. Do not add a new pinned host ABI or
compiler boot dependency merely to package these operations.

| Operation | Contract |
| AOT/open_workspace(input-manifest, limits) | Validate frozen inputs and actual seed/kernel; return bounded private workspace handle. |
| AOT/prepare_unit(workspace, namespace-symbol) | Resolve selected namespace from frozen inputs; return complete prepared unit or explicit failure. No caller-supplied alternate source body. |
| AOT/prepare_host_unit(workspace, host-spec) | Same preparation contract, exact validated host module/ABI; retain existing pinned-host restrictions. |
| AOT/emit_unit(prepared-unit, output-directory) | Derive descriptors and compile bytes without target publication. Return complete artifact-unit manifest. |
| AOT/close_workspace!(workspace) | Release private state and kernel borrows; monitor-based cleanup handles owner death. |
| build/qualify(candidate, requirements) | Run scoped checks, including isolated consumers; return explicit result envelope and evidence. |

These low-level host APIs retain host naming conventions. Namespace arguments
at the new public boundary are quoted symbols, e.g. 'prototype.compiler; normalize
once to the current internal namespace representation and check the declared ns.
Existing string-taking APIs retain compatibility. Pinned host module identifiers
retain their existing exact module-atom ABI.

Existing compile_file/compile_source/compile_host_file remain compatibility
entry points with documented execution behavior. After migration they compose
the shared producer and existing guarded publication/initialization operations
where semantics are equivalent. Effectful interactive source keeps an explicit
execute-and-collect mode; it cannot masquerade as artifact-only preparation.
No new public :trusted, :sdk, :allow-replacement or :skip-validation option.
Document :load? false as artifact-only on the migrated host path, and test that
it no longer causes the accidental intermediate namespace publication. This is
an intentional correction, not a compatibility promise to preserve that bug.

* Canonical data and states
The subsequent [[file:../../research/execution-protocol-audit/staging-architecture.org][staging investigation]] identifies the exact Rt macro/helper
compilation cycle, an independent Core macro-order blocker, and loss of source
versus language-invocation identity in ANF. Its recommended refinement is explicit
compilation worlds, preserved binding/invocation operations and a qualified
bootstrap phase library. This is research/design, not an implemented phase
system or a passing self-reproduction gate. Its ordered gates refine the
compile-time and bootstrap portions of this plan.

The proposed [[file:PLAN-phase-aware-language-and-execution.org][phase-aware language and execution plan]] extends that refinement
with Racket-inspired contextual syntax, opt-in hygienic transformers, finite
phase/ownership checks and an explicit namespace migration/deletion sequence.
Those frontend additions remain proposed; existing datum-macro semantics have
an explicit compatibility boundary.

Replace internal positional unit interpretation with a versioned named record,
initially adapting the existing six-tuple at one boundary. Required fields:
- Input identity: source bytes/digests, root-relative attribution, selected
  provider/resolution manifest, compiler semantic/schema keys, actual producing
  kernel identity, target ABI/backend, declared compile-time input digests.
- Ordered expanded declarations, exact function clauses/dispatch, captured value
  recipes, generated class/protocol/server definitions, and initialization plan.
- Complete expected inventory and dependency edges, including macro expansion,
  compile-time evaluation, runtime calls, captures, generated members and native
  dependencies. Preserve unresolved targets and source spans.
- Source/expansion order and coverage/budget results. Shared data is stored once;
  phase-specific bytes and observed runtime outcomes are separate fields.

The artifact record binds module names, roles, bytes/digests, unit membership,
entry descriptors, declaration evidence, replay/schema versions and ABI. Derive
membership from the actual producer; independently reconcile it against planned
declarations/expanded forms and emitted metadata. Missing/extra members refuse.

State progression is selected -> prepared -> emitted -> verified -> activated.
Failures are terminal for that attempt; retries use a new attempt identity.
Workspace handles/private controller state enforce phase ordering. Serializable
phase/status maps do not authorize transitions. Offline consumers revalidate
actual bytes and applicable native ownership; qualification JSON is audit data.
The installer rechecks source/candidate identities under its install lock and
consumes the controller's completed checks for those exact identities; supplying
a caller-written :proved report is insufficient. Manifest-last is fail-closed
detection, not a multi-file transaction. Retain a complete recoverable previous
floor and a tested interrupted-install recovery path; use an existing immutable
generation/atomic-reference facility where the checkout layout supports it.
Existing result categories remain proved/refused/unknown/error with explicit
scope, coverage, obligations, witnesses and closed diagnostics. Only complete
required coverage satisfies a gate.

* Compile-time and runtime semantics
- Expand through the actual Compiler and shared ANF grammar. Extend the existing
  constructor evaluator for required real-source operations with differential
  semantic cases; unsupported operations retain precise refusals.
- Resolve imported/local macros, private helpers, alias/refer/core exclusions,
  shadowing and newly generated declarations against the frozen source world.
  Preserve lexical/source order; invalidate staged lookup caches as declarations
  change. A same-spelled native/global call cannot inherit Core authority.
- A def needed for expansion is evaluated in the compile-time world. Its runtime
  definition retains normal initialization and per-env semantics. Do not turn
  all defs into serialized compile-time constants or add a new language phase
  feature as part of this work.
- Distinguish ordinary recursive function dependencies from cyclic value or
  macro evaluation. Schedule by actual expansion/evaluation dependencies, not
  only :require edges; report the cycle and exact demand path.
- Staged Rt/Core/helper changes must affect subsequent staged computations where
  source semantics require it. Add a changed-runtime fixture that would fail if
  source evaluation accidentally continued using the old seed's helper.
- Pure data can become literal data; interpreted closures keep explicit validated
  capture recipes. Do not serialize live Fns, PIDs, references, ports, resources,
  compiler handles, leases or authority. Runtime closures are emitted normally.
- Top-level runtime actions and initialization remain ordered deferred code.
  Preparation never starts servers or executes their init callbacks. Runtime
  initialization runs in the normal loader's guarded attempt, once per applicable
  environment/artifact. Failure never marks the namespace ready.
- Compile-time file/env inputs enter through explicit supplied immutable input
  adapters, recorded by value/digest. No ambient time/random/network/write/spawn
  fallback. Existing dynamic Source behavior remains available outside hermetic
  preparation. If real bootstrap demands a missing operation, implement its
  explicit semantics or report the blocker; do not silently skip that source.
- Apply cumulative depth/node/byte/macro/atom budgets across the workspace, not
  merely per helper. Budget exhaustion reports incomplete coverage. Cache hits
  must consume/validate appropriate accounting and cannot bypass input checks.

* Implementation sequence and semantic commits
Each phase has a focused executable gate. Commit coherent source/floor batches;
do not leave a committed runtime that cannot bootstrap. Intermediate recovery
from a coherent older compiler may provision development, but is labeled recovery
and never substituted for the final current-compiler gate.

Gate: finite fixture suite covers every selected construct; unsupported/dead or

** 6. Genuine current compiler bootstrap
Commit: fix(bootstrap): produce coherent compiler candidates before cutover
Migrate both host and boot source generation, including current build-driver
inputs. Stop loading fresh hosts into the producing VM on this path. Supply
complete OTP app/native asset/dependency context to each fresh candidate image;
never hotload a NIF wrapper across incompatible native lifetimes.
Run current selected sources through the full from-scratch path, without AOT or
floor reuse. Candidate starts with only its own coherent host/boot set plus
explicit platform dependencies. Re-run SDK/custody/descriptor startup gates.
Gate: all expected real host/boot sources and companions accounted for; no
:sdk_forwarder_route_changed; no guard relaxed; actual current compiler rebuilds.
Exercise installer identity rechecks and interruption/recovery separately from
fresh-VM activation; initializer failure never implies rollback of arbitrary
external effects or a multi-namespace hot-upgrade transaction.

Bootstrap identity rule: seed -> A -> B -> C may require the transition build A
to differ. Require two consecutive self-built generations B/C to have identical
deterministic payload manifests and bytes. For an unchanged qualified compiler,
also require the committed floor to reproduce directly. No hidden extra rebuild
loop or normalization that erases meaningful differences. Keep actual producer
image identity in external qualification provenance (avoid recursively embedding
the entire producing image hash into its own output). Semantic compiler/schema
keys and target/source identities remain enforced artifact inputs.

** 7. Build/cache/SDK integration and deletion
Commit: refactor(build): share prepared units across bootstrap and SDK production
Migrate build-one-unfenced, seed host generation, selfbuild and AOT cache writes.
Cache identity includes verified source/provider/expansion/value input closure,
compiler semantics, platform ABI/backend and schema. Conservative invalidation
wins over incomplete dependency knowledge. Bootstrap reproduction bypasses reuse.
Gate: fresh cache consumer retains behavior/declarations/privacy; second unchanged
build performs zero source compiles; changing a macro/value invalidates consumers;
partial/foreign cache units refuse. Ordinary Source APIs retain their documented
execution and exception behavior. Remove duplicate assembly/SDK-registration
routes only after their consumers have migrated.

** 8. Qualification, evidence and performance
Commit: test(build): enforce production and bootstrap qualification gates
Wire gates into the existing regeneration/build CI entry points. Extend the
86-case ledger with exact fixture/check bindings and remaining unknowns.
Record source commit+diff, actual seed/candidate/compiler identities, manifests,
commands, phase times, compile/parse/cache counts, peak process-tree memory,
outcomes and scope. Commit source and coherent floor together after qualification.
Gate: documented commands reproduce results from a clean Work checkout and
cannot select an installed drop or accidental host cache as the tested compiler.

* Verification and operating budget
Do not launch BEAM for planning. During implementation inspect scripts/bl-mem
before each owned run; use ./bin/bl, focused files batched into one VM, private
runtime/cache directories, and cleanup. Default prototype cap: 6G RAM, 0 swap,
4 schedulers, explicit per-stage timeout; measured pressure can justify a
documented change. Run candidate VMs serially under the same controller limit.
Runtime edits replace the compiler VM as required; reuse it for unaffected source
analysis. Batch boot changes before expensive rebuilds. No agent test farms.

Order checks: schema/source/API arity -> focused emitter/workspace behavior ->
miniature consumer -> real bootstrap -> fresh SDK/cache -> reproduction/relocation.
Stop a failing expensive phase; record the exact failure before changing code.
No repeat full suite without a new change or unresolved concern.

Performance acceptance uses measured work first: no per-definition target shim
publication; one preparation per unchanged demanded unit in a workspace; no
repeated complete SDK traversal per unit; zero source compiles on full cache hit;
changed inputs invalidate a complete conservative affected cone. Report wall time
and memory against the old path, without promising an unmeasured speedup.

* Completion and remaining work
Complete only when real from-scratch current-compiler reproduction, relocated
reproduction, complete fixture/native consumer checks, SDK/cache migration and
boundary failure cases pass; the old partial-publication production routes are
removed or explicitly isolated to ordinary interactive execution.

This does not prove arbitrary macro termination, absence of compiler/native bugs,
unimplemented JS/backend correctness, cross-platform equivalence, rollback of
external runtime effects, or native execution ownership. Each remains an explicit
separate gate/scope rather than an implied benefit of consolidating production.
