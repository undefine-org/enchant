* Cutover policy
The provider is explicitly selected with BL_NATIVE_PROVIDER=nix. Existing local
producer behavior remains available for declared portable environments.
BL_ARTIFACT_PLATFORM names the trusted recipe/lock checkout. Each successful
request owns its root, and immutable selection stays under destination custody.
The build platform never treats a manifest or store path as Source execution
authority. Missing prerequisites and unsupported providers/targets refuse.

The opt-in NixOS artifacts module selects Nix and the immutable platform path
when deployed through the accepted host configuration. The managed environment
can select it once the combined candidate is accepted.
Shipped FHS drops remain self-contained. Desktop native dependencies, non-Linux
products, workspace/path dependency closures and remote worker guarantees need
explicit recipes and target qualification before being advertised.
