* The defect, measured

Every `lazy-seq` element is one native shared memo cell (`BeamLisp.LazyMemo`,
native/lazy_memo). Before this plan, realising ONE element did
create → read(:pending) → CAS claim → read → CAS publish → read(:completed).
Every create/exchange ran `dependencies/1` (the Elixir `walk/4` over the thunk's
closure environment through `:erlang.fun_info(f, :env)`) and `estimate_bytes`
(`:erts_debug.flat_size`), copied the state term into an OwnedEnv, and compared
the old state structurally. All of it is O(size of what the thunk captured).

Component costs with an 8k-element list captured (drop 725ed831, this host):
walk 105 µs · flat_size 21 µs · copy-in 114 µs · copy-out 92 µs · per element
realised ≈ 1.2 ms. With 100 captured elements: 16 µs.

Two producer families existed:
- rt.bl prims (map, filter, take-while, range, concat …) normalise input with
  `LazySeq/input` — a native cursor, O(1) to copy — and emit 32 elements per
  cell. Linear.
- core.bl producers (interleave, partition, distinct, dedupe, interpose,
  repeatedly, keep, keep-indexed, map-indexed, partition-by) and the `for`
  macro walk `(rest s)` over the RAW input, so each per-element thunk captures
  the unconsumed tail → O(n²).

whose environment is empty. That verdict is corrected in FUP-112 by this plan.

* Waves

** W1 — one lazy engine (priv/boot/core.bl)
Every core.bl producer and `for` normalise input once through the rt cursor and
emit chunks of `LazySeq/chunk_size` through `LazySeq/chain`, via ONE shared
chunked-step helper. No thunk captures the raw unconsumed input.
Gate: test/bl/lazy_producers_test.bl (equivalence vs eager reference at sizes
0/1/31/32/33/100/1000; ≤ one chunk of over-realisation on infinite inputs; `for`
nesting/modifiers/destructuring); bench ratios ≤ 2.6.

** W2 — a fold path with no cells (priv/boot/rt.bl, lazy_seq.ex)
A pending lazy seq built by a producer that knows its source carries a fold
recipe; `reduce`/`into`/`count`/`vec`/`mapv`/`frequencies`/`group-by` fold the
source directly and allocate no memo cells. A seq that has been (partly)
realised keeps using the memo walk, so f never re-runs for realised elements.
Gate: test/bl/lazy_fold_test.bl (equivalence, `reduced` stops the source,
memo-cell count ≤ 2 for an 8k fold that allocated 501).

** W3 — a slim memo cell (native/lazy_memo, lazy_memo.ex, lazy_seq.ex)
The thunk moves out of the cell into the `%LazySeq{}` wrapper; control states
(`:pending`, running/waiters, terminal) are tiny. CAS compares a version
counter, not the old term. The per-transition environment walk is deleted;
cycle rejection runs once, on the value being published. Atoms' `swap!` moves
to version CAS.
Gate: lazy_memo_native_test.exs, wave23_lazyseq_test.exs, deferred_test.bl
unchanged in meaning; cargo tests; bench/memo_cell.bl before/after.

** W4 — keep the class out
- test/bl/lazy_scaling_test.bl: every lazy producer at n and 2n; fails when the
  ratio exceeds 3 (a quadratic producer shows 4+).
- `bl lint`: a hand-written `lazy-seq` whose thunk walks `(rest …)` of a
  collection it did not pass through the rt input normaliser is reported.
- FUP-112 corrected (verdict measured on an empty environment).

** W5 — what remains: a captured environment still costs one copy per cell
After W1–W3 the one cost left is inherent to a SHARED memo: publishing a value
into a native cell copies it, and a chunk's continuation closure is part of the
published cons tail. Mitigation in this plan: keep continuation closures small
(W1's helper threads only the cursor and O(output) state) and publish chunks,
not elements. The alternative — process-local memo — is a semantic change and
is a research spike: FUP-129.

* Risks and interactions
- PLAN-150 (concurrent) ports lib/beam_lisp/*.ex to .bl. W2/W3 edit
  lazy_seq.ex and lazy_memo.ex; whichever lands second rebases onto the other.
  The native cell (Rust) is unaffected by that port.
- Chunking changes observable realisation granularity for core.bl producers
  from 1 to 32 — the same contract rt.bl's map/filter already have and
  Clojure's chunked seqs have. Side-effecting producers (`repeatedly`) realise
  up to one chunk ahead of demand; documented in each docstring.
- A fold that bypasses the memo re-runs f for a consumer that folds a seq
  another process is concurrently realising; identical to Clojure's reduce over
  a LazySeq built from a reducible. Documented in lazy_seq.ex.

* NOTE (2026-09-28) — residuals closed: laziness regression, `distinct` O(n), reference types leak-free

** 1. Laziness regression found and fixed (16e7cfa2)
The chunk engine sealed a chunk after 32 OUTPUTS and filtering steps looped
until an output, so over an infinite input with sparse outputs a chunk never
sealed. None of the gates caught it; found by probing.
| expr | main 4da5c8d7 | 85533dd0 | 16e7cfa2 |
|------+---------------+----------+----------|
| (first (keep f (range))) | 0 | HANG | 0 |
| (first (distinct (cycle [1 2 3]))) | 1 | HANG | 1 |
| (first (dedupe (cycle [1 1]))) | 1 | HANG | 1 |
| (first (for [x (range) :when (< x 3)] x)) | 0 | HANG | 0 |
| (first (filter #(< % 3) (range))) | HANG | HANG | 0 |
Chunks are now bounded by INPUTS walked. lazy_scaling_test gained
`sparse-producers-over-infinite-input-terminate` (each case under a deadline).

** 2. `distinct` O(n) (6ffd6f4b)
The seen set is a native `Seen` resource (native/lazy_memo/src/seen.rs)
captured by handle; keys are admitted once per chunk AFTER every fallible
step, so a throwing chunk admits nothing.
| n → 2n (bench/lazy_scaling.bl -- 4000) | before | after |
|---------------------------------------+--------+-------|
| distinct | 54 → 204 ms (3.8) | 26 → 47 ms (1.8) |
FUP-129's residual budget is gone; distinct is a linear case again.

** 3. Reference types leak-free (7869969d)
Trial-deletion cycle collector over memo cells, cursors and Seen sets
(native/lazy_memo/src/collector.rs; soundness argument in its header). ERTS
has no refcount API: offsets are CALIBRATED at load and the collector stays
off if calibration fails (`LazyMemo/collector_status`). Promises and
volatiles became ref cells (were: a never-stopped process per promise, a
never-deleted pdict key per volatile).
| 20× probe, left after GC | before | after |
|--------------------------+--------+-------|
| atom holding itself / via watch / via swap fn | 40 cells each | 0 |
| atom → lazy seq → atom | 60 cells | 0 |
| a ↔ b atoms | 80 cells | 0 |
| delay reaching itself | 20 cells + 20 procs | 0 |
| promise (any) | 20 procs | 0 |
| volatile!/transducer | 1 pdict key each | 0 |
Semantics change: a volatile is readable from another process (as in
Clojure). A revived ETF handle to a COLLECTED cycle reads as reclaimed.
