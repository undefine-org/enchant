* Architectural conclusion
Three cooperating contracts are needed:
1. Execution: one registration/admission/frame/ownership protocol.
2. Production: one authenticated entry/dependency/declaration description shared
   by compiler emission, staging, publication, AOT replay and cache validation.
3. Qualification: immutable candidate/test identities and a complete early
   inventory, including separate compiler/native/backend/platform controls.

The execution protocol removes inconsistent combinations through supported
interfaces. It cannot alone prevent wrong arithmetic inference, JS emission,
GC wakeup logic, solver framing, cache lock races, or CI packaging mistakes.
Those ledger rows require independent executable gates before broad assembly.
P in the ledger means the supported representation/entry rule removes that
invalid combination after migration. It is conditional on correct native
enforcement and complete adapter migration, not a mathematical claim that
arbitrary native code or the compiler cannot contain bugs. E means earlier
checking/qualification is required.

* Compiler and publication contract
Define one versioned entry descriptor in priv/boot/anf.bl and generation in
priv/boot/compiler.bl plus priv/host/emit.bl. The descriptor contains:
- Exact emitted entry identity and accepted arities, including fixed/variadic.
- Entry kind: Source, fixed SDK implementation, actor lifecycle, native adapter
  or authorized control. A declaration tag alone is not authentication.
- Physical body/provider/shim/immutable initializer identities; actual compiler
  input-guard key and native prologue are distinct from application body.
- Code dependency edges, captures and fixed SDK lookups with their evidence;
  initialization operations in source order, including nested defining macros.
- Source spans, schema version, producer/codegen input identity and target ABI.

Data collection kinds have one schema. Consumers do not re-create clause keys,
mistake vectors for native maps, use legacy lambda indices, or independently
guess permitted metadata attributes. The SDK kind requires artifact/declaration
evidence, never __bl_init__ existence or a self/path prefix.

system.publication snapshots bind this to actual published code. Emission,
staging, AOT/source loading and replay must produce equivalent descriptors;
the collector checks a manifest of expected definitions/initializers so an
empty/incomplete collector is not a success. Complete artifact-unit validation
includes every companion, replay version, class schema and declaration row.
Expected cache publication rejection is returned with its exact reason; an
SDK producer whose purpose is cache publication fails on rejection.

The compiler establishes descriptor shape and fixed-entry identity. Semantic
equivalence still needs small differential tests: argument order/once-only,
shadowing, input guard preservation, macro helper arities, Unicode/span fidelity
and JS/BEAM output. system.tier/alpha= is an available structural comparison,
not proof of arbitrary external behavior.

* Native protocol and API
NEW priv/host/execution.bl emits BeamLisp.Execution. It owns the protocol
implementation, but initially retains Env as the existing private-table owner:
no new per-invocation server, second owner registry, immortal context cache or
duplicate authoritative state. Env keeps ordinary binding APIs and delegates
execution bookkeeping. Registry owner requests are fixed validated operations,
never arbitrary caller thunks executed inside the Env/connection owner.
Existing module -> scope lock order stays intact. Private registry turns must
not wait for callbacks or reacquire outward module/namespace locks. Acceptance
and physical custody are committed under the same appropriate fence.

Three private records:
1. Registration: callable/bundle identity, graph ID, immutable context ID,
   restriction profile, owner epoch and retained-lifetime reference.
2. Invocation: accepted registration epoch, receiver PID, executing borrow and
   outcome state. A retained registration alone is not an invocation.
3. Frame: admitted origin and effective restrictions, dynamic binding overlay,
   parent frame and invocation. Only native admission establishes origin.

Opaque public handles select private records; their fields or source type tags
do not authenticate anything. A graph, context, owner PID or callback metadata
map cannot nominate an execution origin. Ordinary context data remains data.
Resource write/Conn/Root grants remain separate from code custody.

Internally, frames carry graph/context IDs, not the full graph maps currently
copied through capture/bind. Migrate direct Process/get :bl_generation reads
outside the compatibility bridge to bounded selected-graph/field accessors.
Legacy current/capture APIs may still materialize their documented data view
when explicitly called; that cost must not be hidden in every admission or
creator check. A private registry reply must not copy the whole graph back to
the worker on each invocation. Capture validation must also distinguish immutable
values from actual mutable/native resource handles; earlier validation is not
permission to skip required per-use checks on mutable arguments or resources.

Public compatibility surface:
- proc.callback/register!, invoke!, try-invoke!, active?, unregister! remain.
  Existing register! extra-module declaration is checked against exact dependency
  evidence; it never grants native privilege by module name.
- try-invoke! keeps completed/value, cancelled and pre-entry busy envelopes.
  Application throws/exits/errors preserve their original class and stack;
  an application code_lease_capacity exception is not translated into busy.
- Existing prepare-transfer!/commit-transfer!/transfer! become adapters over
  offers and indexed receiver acceptance. Internal users migrate to explicit
  offer acceptance. Old owner epochs cannot close the accepted new registration.
- reload.execution/with!, invoke!, current and owned? keep their roles but
  obtain execution evidence from the common native frame. No separate private
  EXECUTION-KEY becomes an alternative source of authority.
- Ordinary actor/task/callback language APIs keep their surface. No new public
  API permits binding an arbitrary generation and asking to be trusted.

State rules:
- Registration open -> closing -> closed. Closure stops NEW admission.
- Invocation not-accepted -> accepted -> completed/raised/worker-dead.
- Handoff offered -> receiver-indexed -> accepted, or cancelled/receiver-dead.
- Owner transition pending -> prepared -> committed/cancelled; a lost reply
  after an effect reports uncertain and is resolved by its receipt, never replay.
- Accepted work survives registration owner death/unregister while its worker
  lives. Worker death releases its executing custody through native monitoring.
- Framework baseline and each application callback have independent lifetimes.
  A PID change is not itself a privilege change; an in-process native control
  call can also be a domain transition and requires its explicit grant.

Binding/restoration is one frame push/pop. Comparable caller restrictions are
preserved/narrowed; cross-domain control requires its own target-bound grant,
not a naive intersection of incompatible generations. User code cannot replace
the admitted origin through Env.bind. Adoption changes the owning baseline at
the lifecycle commit point; nested dynamic restoration cannot undo it.

* Efficiency model and measurable limits
Source/dependency indexing walks N definitions and M edges once per identity;
analysis then uses explicit bounded fixpoint rounds and existing incremental
dirty reverse cones. There is no claim that every recursive/higher-order
analysis completes in a single linear pass. Pass-local
tables are immutable/native and discarded at end; cache keys retain bounded
identities, not full environments/ASTs. No repeated transitive closure per file.

Graph pin: register a verified immutable graph and reverse module membership
once. Registrations/invocations borrow its live graph reference. Physical purge
and graph retirement consult the SAME pin ledger under publication fences.
The existing per-module ticket scheme remains until this is proved equivalent;
it cannot be removed before retirement/publication have migrated too.
Register graph membership once and retain edges; do not materialize the full
transitive closure separately for every entry. A worker enters using small IDs
and dynamic overlays, not a registry round-trip returning graph-sized payloads.

Acceptance, unregister and owner death must be linearizable with respect to the
graph pin. If graph closure wins, new borrows refuse; if admission wins, its pin
prevents purge. An O(1) graph borrow needs changing existing per-module retain
accounting, not merely extracting helper functions. Do not introduce a single
global lock that serializes unrelated graph invocations.

Target hot path (to be measured, not already achieved):
- Same-domain direct/recur calls: no extra frame, graph traversal, lease rows,
  Source capture walk, registry RPC, solver or compiler work per iteration.
- Actor message: reuse native owner ticket; bounded entry/frame lookup.
- Deferred callback: O(1) graph borrow/frame bookkeeping in graph size; required
  argument/resource checks still cost O(argument data), not magically O(1).
- No full dependency list copied/inserted per invocation. No callback dispatch
  is allowed to initialize an unprepared SDK dependency.

Counters: preparations, analyzed nodes/edges, graph membership rows, registration
rows, accepted borrows, frame pushes, owner RPCs, argument visits, source parses,
compiler invocations and retained bytes. Compare graphs of 16/256/4096 modules,
fixed-size arguments and 100,000 same-domain calls. Require flat invocation
membership work and bounded retained rows/bytes after close, exception and DOWN.
Measure cold startup and preparation separately; do not call count reductions a
wall-time speedup without before/after timing and the same result identity.

* Mechanical protocol conformance, not a second handwritten toy
The native kernel exposes a nonauthorizing versioned transition description.
system.execution/model projects it into system.model/facts/knowledge and
system.step. Actual native adapter traces must refine this description; a model
passing by itself is not implementation evidence. New runtime transitions change
the model version and require new trace/conformance evidence.

For bounded finite instances enumerate two owners, two graph identities, close,
accept, nesting, handoff, owner/worker death, upgrade and observation. Check:
- Effects require an accepted invocation, with matching origin, graph pin and
  receiver; a source context or type annotation cannot manufacture it.
- Restriction composition cannot widen ordinary caller authority.
- Every pending/live reference is owned by a live registration/worker/monitor;
  old epochs cannot close a newer owner; no leaked private context metadata.
- Accepted calls remain executable after registration closure; new calls refuse.
- Frame exit restores exact parent state; adoption only changes owning baseline
  through its outer authorized commit.
- No extra effect on rejection, no diagnostic initializer replay, no callback
  executed to infer a proof, no claim that lost acknowledgements cancel work.

Use system.step/path-to for counterexamples; system.gfp for finite safety/drain
regions; system.core/SMT only for supported translated obligations. Explicitly
bound model results. Actual native schedules use fixture-owned barriers, not
sleeps or arbitrary new privileged callback hooks. Inductive/unbounded claims
require separate invariant-preservation evidence for every real kernel rule.
