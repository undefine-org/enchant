** Common execution and stopping rule
For each batch: capture Source/floor/native/toolchain/selector identities; develop
with only affected component tests in one capped VM; minimize original failures
and retain their negative controls. Freeze once focused checks pass and qualify
one resulting artifact for that batch's affected consumers. A failed candidate
stays failed; retain its logs, fix on new inputs, then freeze a new candidate.
Do not keep rerunning an unchanged broad suite after small edits. Boundary-map
drift checks are cheap and run whenever an API/metadata producer changes.

A boot/native edit needs a coherent private candidate and focused preboot checks;
reproduce B/C before qualifying its final bytes. A stdlib-only edit does not
justify a floor rebuild. Broad integration milestones are completion of batch 3
and the single final candidate in batch 6. A metadata change still requires the
small real sealed-image consumer gate before any full SDK assembly. Every batch
ends with a semantic commit, scoped receipt and updated case/checklist statuses.

beyond correct conservative invalidation; more precise recursive-group,
pattern/guard and non-tail ownership proofs beyond safe unknown plus required
runtime checks; termination proofs; broader abstract domains and all-interleaving
exploration; additional actor/query/UI/build DSLs, specialization and replay UX;
extra targets/minimal-target optimization beyond the declared supported release.

supported-platform/native gates remain required. Optional precision must not
replace a required runtime check or weaken an original regression. If a required
case needs one of these techniques, move that technique into its owning batch
explicitly rather than expanding the roadmap silently.
