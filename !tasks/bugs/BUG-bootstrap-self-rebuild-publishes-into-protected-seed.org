#+TITLE: Bootstrap self-rebuild publishes incomplete definitions into protected seed namespaces
#+STATE: OPEN
#+DATE: 2026-10-22

* Reproduction
From a coherent source application with a seed matching its compiler key:
#+begin_src sh
BL_REGEN_FROM_SCRATCH=1 scripts/regenerate-seed /tmp/self-floor
#+end_src
Fresh host compilation and native recovery preflights succeed. The first boot
unit, priv/boot/rt.bl, fails with =:sdk_forwarder_route_changed=. No candidate
floor is installed. The execution-protocol Work run records this in
research/execution-protocol-audit/descriptor-checks.json.

* Mechanism
build/build-one-unfenced calls AOT/compile_file. Its load_unit path evaluates
definitions, and Link/defvar publishes intermediate shims before the complete
unit has been emitted. Env/unretained_sdk_forwarders! correctly protects the
current, attested seed when its compiler key matches. Replacing an existing
protected route during this intermediate source load is refused.

An older coherent compiler can generate a candidate for changed inputs; the
regenerator can also reuse verified complete boot units for runtime-only host
changes. Both are useful recovery paths. Neither demonstrates that the current
compiler reproduces its own floor from scratch.

* Required production boundary
Bootstrap artifact preparation must collect and emit complete units without
publishing intermediate definitions over the executing compiler's protected
namespace surfaces. Publish/install only after the artifact inventory and fresh
boot gates pass. Keep physical custody and SDK route checks intact. A caller
flag, erased native rows or manufactured stale compiler key is not a fix.

This is a remaining production-contract obligation in
[[file:../plans/PLAN-enforced-execution-protocol.org][the execution protocol plan]], not evidence of native protocol qualification.
